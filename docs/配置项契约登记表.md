# R101-S2-02 配置项契约登记表

> **依据**：凌舟裁定 R101-S2-02 护栏②（契约先行）—— 每项配置须登记 **key / 值结构 / 默认值语义 / 未配置时的界面行为**。
> **存储口径（口径 X）**：配置以 JSON 包写入**既有**存储（平台级 `t_platform_config` 整包一行；租户级 `t_sys_config` 唯一键 `(config_key, tenant_id)`），**零新建业务表**。
> **权威实现**：
> - 组1 套餐类 → `backend/src/schemas/plan.schema.ts` + `backend/src/controllers/admin/subscription-plan.controller.ts`；前端唯一事实源 `saas-admin/src/constants/plan-features.ts`
> - 组4① 全局功能开关 → `backend/src/services/platform/platform-sys-config.service.ts`；前端 `saas-admin/src/views/Settings.vue`
> **变更记录**：新增条目须同步本节与《数据库变更清单》；DDL 一律先登记后执行。

---

## 一、通用语义（适用于本表全部条目）

| 语义 | 约定 |
|---|---|
| **已配置** | 该键在库中存在（JSON 包内 `hasOwnProperty` 为真） |
| **未配置** | 键不存在。后端以 `null` 或省略表示；`GET` 响应以 `_unconfigured: string[]` 明确列出「未落库的顶层键」 |
| **DEFAULTS** | 仅作**表单初值 / 空态展示**，**禁止回写**（`PUT` 过滤 `null` 值与 `_` 前缀元字段） |
| **前端义务** | 未配置项一律**置灰阻断 + 提示原因**，不得以任何默认值冒充「已生效配置」 |
| **version** | 每个 JSON 包携带 `version`（组1 策略包 / 组4① 设置包当前均 = `1`），结构变更时递增 |
| **留痕** | `updated_by` / `updated_at` 由存储表列承担（`t_platform_config` 152 迁移已加 `updated_by`） |

## 二、组1 套餐类

**页面**：03 套餐管理（`saas-admin/src/views/Packages.vue`、`PackageForm.vue`）
**存储**：
- 结构化配置项 → `t_subscription_plan` 既有列（`plan_type` / `price` / `max_users` …）
- 功能开关矩阵 → `t_subscription_plan.module_access`（JSON 数组）
- **策略类配置项**（升级 / 降级 / 续费 / 扩展额度 / 限时活动）→ `t_platform_config`
  `platform='SAAS'`、`tenant_id='platform'`、`config_key='plan_policy:<planId>'`、`category='plan'`

**端点**：
- `GET/POST/PUT/DELETE /api/platform/subscriptions-management/plans`、`PUT .../:planId/features`
- `GET /api/platform/subscriptions-management/plans/:planId/policy`（读取策略包）
- `PUT /api/platform/subscriptions-management/plans/:planId/policy`（整包保存，zod 校验）

> ⚠️ **`features` 列禁止用作配置包容器**（2026-09-14 修正，原设计已回退），两条硬理由：
> 1. 该列生产语义是「功能特性码数组」——种子数据即
>    `'["basic_sales","basic_inventory","basic_report"]'`（`docs/migrations/016_phase9_tenant_subscription.sql:172`）；
> 2. 公开端点 `listPublicPlans()`（`backend/src/services/platform-miniapp.service.ts:139`）**原样透出**该字段，
>    塞入 API 日额度 / AI 月额度 / 升降级策略会**泄露给未鉴权调用方**。
>
> 因此策略类配置改落 `t_platform_config`（口径 X：不新建业务表、零 DDL）。

### 2.1 定价与周期

| key | 存储 | 值结构 | 默认值语义 | 未配置时界面行为 |
|---|---|---|---|---|
| `planCode` | `plan_code` VARCHAR(32) | 字符串 | **无内建默认**；前端留空时以 `PLAN{ts}` 生成，仅作唯一标识 | 不阻断（自动生成） |
| `planName` | `plan_name` VARCHAR(64) | 字符串 | 无 | 必填，空则 `ElMessage.warning('请输入套餐名称')` 并阻断提交 |
| `planType` | `plan_type` VARCHAR(32) | 枚举 `MONTHLY` / `QUARTERLY` / `YEARLY` / `PERMANENT` / `CUSTOM` | 无（表单初值 `""`） | **不送该键**（不写占位值） |
| `durationDays` | `duration_days` INT | 整数 ≥1 | 月/季/年由 `PLAN_TYPE_DAYS` 推导（30/90/365）；`CUSTOM` 取表单值 | 周期未选时**不上送** |
| `price` | `price` DECIMAL | 数值 ≥0 | 无 | 表单初值 0（数值输入，非「已配置」语义） |
| `promoPrice` | 策略包 `promo.price` | 数值 | 无 | `promo` 整体省略 |
| `promoStart` / `promoEnd` | 策略包 `promo.start` / `promo.end` | 字符串 | 无 | 同上 |

### 2.2 功能开关矩阵

| key | 存储 | 值结构 | 默认值语义 | 未配置时界面行为 |
|---|---|---|---|---|
| `moduleAccess` | `module_access` JSON | 字符串数组，元素 = 开关条目文案 | **无**：前端**不预置任何勾选**（`checked[name] = false`） | 未勾选即未配置；总数由 `TOTAL_FEATURE_COUNT` 动态计算（当前 **23 项**，页面禁止写死数字） |
| `features` | `features` JSON | **字符串数组**，元素 = 功能特性码（如 `basic_sales`） | 无 | 对外可见（公开套餐列表），**不承载任何内部配额 / 策略**；当前 UI 不写该列 |

**矩阵定义唯一事实源**：`saas-admin/src/constants/plan-features.ts` 的 `FEATURE_GROUPS`（5 组 / 23 项）。

### 2.3 资源配额

| key | 存储 | 值结构 | 默认值语义 | 未配置时界面行为 |
|---|---|---|---|---|
| `maxUsers` | `max_users` INT | 整数 ≥1 | 无（表单初值 `null`） | **不上送**；页面显示「未配置」提示 |
| `maxProducts` | `max_products` INT | 整数 ≥1 | 无 | 同上 |
| `maxStores` | `max_stores` INT | 整数 ≥1 | 无 | 同上 |
| `maxStorageMb` | `max_storage_mb` INT | 整数（MB） | 无 | 前端以 `GB` 录入、提交时 ×1024；未配置则不上送 |
| `apiQuota` | 策略包 `quota.apiDaily` | 整数 ≥0（次/日） | 无 | `quota` 整体省略 |
| `aiQuota` | 策略包 `quota.aiMonthly` | 整数 ≥0（次/月） | 无 | 同上 |

> 说明：`api_quota` / `ai_quota` **无结构化列**，按口径 X 承载于策略包 `quota`（零 DDL）。

### 2.4 升降级与续费规则

| key | 存储 | 值结构 | 默认值语义 | 未配置时界面行为 |
|---|---|---|---|---|
| `upgradeMode` | 策略包 `upgrade.mode` | 枚举 `IMMEDIATE`（立即生效·按天折算补差） / `NEXT_CYCLE`（周期结束生效） | 无 | `upgrade` 整体省略；规则区显示「未配置」 |
| `downgradeMode` | 策略包 `downgrade.mode` | 枚举 `NEXT_CYCLE` / `IMMEDIATE_NEXT_PRICE` | 无 | `downgrade` 整体省略 |
| `renewPolicy` | 策略包 `renew.policy` | 枚举 `FORBID_GUIDE_UPGRADE` / `ALLOW_LAST_YEAR` / `AUTO_RECOMMEND_PLAN` | 无 | `renew` 整体省略 |
| `status` | `status` VARCHAR(16) | 枚举 `DRAFT`（草稿·仅平台可见） / `ACTIVE`（已上架） / `INACTIVE`（停售） | 后端 zod `default('ACTIVE')`（**仅当请求体未带 status 时**） | 表单三态循环；「存为草稿」固定送 `DRAFT` |

### 2.5 策略包（`plan_policy:<planId>`）存储契约

**实现**：`backend/src/services/platform/plan-policy.service.ts`（zod：`backend/src/schemas/plan.schema.ts` 的 `planPolicySchema`）

```
{
  version: 1,                                   // 护栏③：恒带版本号
  quota?:     { apiDaily?: number, aiMonthly?: number },
  upgrade?:   { mode: 'IMMEDIATE' | 'NEXT_CYCLE' },
  downgrade?: { mode: 'NEXT_CYCLE' | 'IMMEDIATE_NEXT_PRICE' },
  renew?:     { policy: 'FORBID_GUIDE_UPGRADE' | 'ALLOW_LAST_YEAR' | 'AUTO_RECOMMEND_PLAN' },
  promo?:     { price?: number, start?: string, end?: string }
}
```

| 项 | 约定 |
|---|---|
| **键隔离** | 每个套餐一行，`config_key = 'plan_policy:<planId>'`，互不覆盖 |
| **DDL** | **零新增**：复用 `t_platform_config` 既有列（`config_key` / `config_value` / `category` / `updated_by` 由 `152_business_columns_fill.sql` 补齐） |
| **校验** | `PUT` 前经 `planPolicySchema.parse()`；越界枚举 / 负数额度直接 400，不落脏配置 |
| **未配置** | 库中无该行 → `GET` 返回 `{ version:1, _unconfigured:['quota','upgrade','downgrade','renew','promo'], _configured:false }` |
| **清空** | 全部策略项为空时写入 `{version:1}`（null 与 `_` 前缀元字段不落库）→ 等价于「未配置」，不会固化占位值 |
| **留痕** | `updated_by` = 操作人 `req.user?.username ?? 'system'`；`updated_at` 由 SQL `NOW()` 写入 |
| **前端** | `PackageForm.vue` 保存主记录后单独 `PUT` 策略包；失败时**不跳转**，在内容区显示错误态（不重复弹 toast） |

> `POST /plans` 现返回 `{ plan_code, id }`（新增 `id`，向后兼容），否则新建后拿不到主键无法保存策略包。

## 三、组4① 全局功能开关（含新租户默认值）

**页面**：08 系统配置（`saas-admin/src/views/Settings.vue`）
**存储**：`t_platform_config` 内 `config_key = 'saas_settings'` 的 JSON 包
**端点**：`GET /api/platform/config/sys-config`、`PUT /api/platform/config/sys-config`

### 3.1 结构

```
switches: {
  <switchKey>: {
    enabled: boolean,             // 全局开关
    newTenantDefault?: boolean,   // 新租户默认值；键不存在 = 未配置，与 false（已配置为关闭）语义不同
    countLabel: string            // 全平台启用统计（依赖调用量统计接口，未接通为空）
  }
}
```

`switchKey` 集合（6 项，定义于 `Settings.vue` 的 `switchDefs`）：
`multiWarehouse` / `multiUnit` / `memberMarketing` / `miniProgram` / `openApi` / `reportCenter`

### 3.2 契约

| key | 值结构 | 默认值语义 | 未配置时界面行为 |
|---|---|---|---|
| `version` | 整数，当前 `1` | 无；`PUT` 时缺省/非法值规范为 `1` | 恒随包返回（历史包无 version 时按 `1` 呈现） |
| `switches` | 上表对象 | **无内建默认**：`DEFAULTS.switches = null`，后端 `_unconfigured` 含 `'switches'` | 顶部 `tipbar` 提示「全局功能开关尚未配置…系统不内置任何预设值」；每行统计位显示「**未配置**」；`newTenantDefault` 显示「**未配置（点击配置）**」；**保存不回写该组** |
| `switches[x].enabled` | boolean | 无 | 开关点击即视为配置意图（`switchesConfigured = true`），方可上送 |
| `switches[x].newTenantDefault` | boolean \| 不存在 | 无 | 点击循环：**未配置 → 开启 → 关闭 → 未配置**（第三态删除该键，回到未配置） |
| `switches[x].countLabel` | string | 无 | 未配置时显示「未配置」，已配置但无统计数据显示「—」 |

### 3.3 元字段（只读，禁止回写）

| key | 含义 | 说明 |
|---|---|---|
| `_unconfigured` | `string[]` | `GET` 响应附加，列出「库中无该键」的顶层字段；`PUT` 时过滤（`_` 前缀不得回写） |
