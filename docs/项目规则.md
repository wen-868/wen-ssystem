## 十一、核心决策记录（与规则同等约束力）

> 以下决策经过项目实践验证，写入此文档确保各端执行一致，不产生偏差。

### 决策 1：只用 main 分支

- **时间**：R8（2026-07-05）
- **原因**：多人多分支导致合并冲突（踩坑 [3]），本项目为单人操作模式，无需分支隔离
- **规则**：`git branch -r` 只能有 `origin/main`

### 决策 2：单一任务文件

- **时间**：R8
- **原因**：多任务文件导致成员读错任务（踩坑 [10]）
- **规则**：只读 `current-tasks.md`，禁止从旧文件、记忆、聊天记录获取任务

### 决策 3：controller 禁止 try-catch

- **时间**：R9
- **原因**：try-catch 绕过全局 errorHandler，飞书告警失效（踩坑 [9]）
- **规则**：业务代码中禁止 try-catch，统一走全局错误处理中间件

### 决策 4：表单校验三件套

- **时间**：R8
- **原因**：只加 rules 不加 ref 导致 TS 报错（踩坑 [12]）
- **规则**：ref + :model + :rules 缺一不可

### 决策 5：保留 auto-routes.ts

- **时间**：R8
- **原因**：阿坚手动注册方案与子目录模块化路由不兼容（踩坑 [2]）
- **规则**：路由注册统一使用 auto-routes.ts 自动注册机制

### 决策 6：vitest 替代 jest

- **时间**：R8
- **原因**：jest 不兼容 ESM（踩坑 [5]）
- **规则**：测试框架只用 vitest，全局搜索 `jest.` 替换为 `vi.`

### 决策 7：覆盖率标准 100%

- **时间**：R13（2026-07-07），用户明确要求
- **原因**：80% 遗留随时爆发，修更麻烦
- **规则**：shared/、middleware/、以及所有已编写测试的文件，覆盖率必须 100%。不允许以"阶段性目标"为由降低
- **阈值配置**：`vitest.config.ts` 中 thresholds 永远为 100

### 决策 8：测试不允许跳过

- **时间**：R22（2026-07-11），用户明确要求
- **原因**：skip 掩盖真实问题，导致覆盖率虚高
- **规则**：it.skip / describe.skip 违反规则。只有修复一条路。不能把 it.skip 改为 describe.skip，不能标记"暂时跳过"

### 决策 9：全部通过后直接安排下一轮

- **时间**：R13，用户授权
- **原因**：减少等待，提高效率
- **规则**：凌舟核查全部通过后直接规划下一轮、更新文件、提交推送，不等用户确认

### 决策 10：验收不信任原则

- **时间**：R12
- **原因**：苏然 877 个误报教训
- **规则**：任何人的报告结论，凌舟必须独立用 grep/tsc/eslint/vitest 跑命令验证。不信任口头声明

### 决策 11：记忆文件统一管理

- **时间**：R15（2026-07-08）
- **原因**：跨环境迁移需要记忆连续性
- **规则**：全员记忆文件放在 `docs/memories/` 目录，文件名格式 `{成员名}-记忆.md`。每次轮次结束必须同步更新

### 决策 12：多实例记忆同步

- **时间**：R22（2026-07-11）
- **原因**：当前存在两个凌舟实例（TRAE Work + 另一个环境），记忆不同步会导致决策冲突
- **规则**：每次任务变更、核查结论、核心决策，两个实例必须同步更新 `docs/memories/凌舟-记忆.md`

### 决策 13：pino 替代 console.log

- **时间**：R12
- **原因**：console.log 无法按级别过滤、无法输出到文件、影响性能
- **规则**：后端日志统一用 pino。禁止 console.log/console.error/console.warn（main.ts 的 DEV 模式 console.error 除外）

### 决策 14：烟草类目仅本地同步

- **时间**：R22（2026-07-11），用户明确要求
- **原因**：烟草属于特许经营类目，禁止通过网络平台销售/展示，必须与普通酒水商品隔离
- **规则**：商品分类表 `t_product_category` 新增 `sync_policy` 字段（1=允许同步 0=仅本地）。烟草分类（烟草/卷烟/雪茄/烟丝/其他烟草）`sync_policy=0`。所有同步服务（小程序缓存、即时零售、价格同步、全链路同步）在同步前必须检查分类的 sync_policy，为 0 时跳过该商品。admin-web 分类管理页面必须显示同步策略选项。
