## 三、文档语言规则

1. **所有文档、任务文件、注释一律使用中文**
2. 不要使用英文写文档内容
3. 文件名可以包含 `v7` 等版本号，但内容必须中文
4. 数据库字段注释用中文（`COMMENT '字段说明'`）

---

## 四、任务文件规则

1. **任务文件统一放在 `docs/tasks/` 目录下，这是唯一合法位置**
2. 每人一个文件，格式：`{成员名}-tasks-v{版本号}.md`
3. 当前有效的任务文件：
   - `docs/tasks/ajian-tasks-v7.md`（阿坚）
   - `docs/tasks/mo-tasks-v7.md`（墨）
   - `docs/tasks/ache-tasks-v7.md`（阿澈）
4. 总体规划文件：`docs/task-plan-v7.md`
5. 详细分解文件：`docs/task-breakdown-v7.md`
6. **每次生成新任务文件后，立即删除旧任务文件**
7. **绝对禁止**在以下位置创建任务文件：
   - `/tasks/` 目录
   - 工作区根目录（如 `/workspace/xxx-紧急任务.txt`）
   - `/docs/superpowers/` 目录
   - 任何 `docs/tasks/` 以外的位置
8. 团队成员只读取 `docs/tasks/` 下的文件，其他位置的任务文件视为无效

---

## 五、代码提交规则

1. **收到任务立即执行，不要等待**
2. **完成任务检查通过，立即提交并推送到远程仓库**
3. 提交信息格式：`type: 中文描述`
   - `feat: 新功能描述`
   - `fix: 修复描述`
   - `docs: 文档更新描述`
   - `chore: 清理/维护描述`
4. 每次提交前确认 `git status`，不要提交无关文件

---

## 六、命名规则

1. 数据库表名：`snake_case`（如 `sale_bill_item`）
2. 后端文件：`kebab-case`（如 `sale-bill.service.ts`）
3. 前端组件：`PascalCase`（如 `SaleBillView.vue`）
4. API路径：`kebab-case`（如 `/api/admin/order-sync-logs`）
5. 文档文件：中文或 `kebab-case`（如 `项目规则.md`、`task-plan-v7.md`）

---

## 七、文档同步规则

1. 数据库有变更 → 同步更新 `docs/init_database.sql`
2. 新增表 → 创建 `docs/migrations/` 迁移文件
3. API有变更 → 同步更新 `docs/product-spec-v6-adapted.md`
4. 任务完成 → 更新 `docs/task-plan-v7.md` 中的状态

---

## 八、禁止事项

1. **禁止**在多个位置创建同名任务文件
2. **禁止**使用英文写文档内容
3. **禁止**把竞品名称（掌盘）当项目名使用
4. **禁止**给已离开的成员分配任务
5. **禁止**在文档中使用 `$TRAE_REF` 引用（这是AI内部标记）
6. **禁止**在代码中硬编码敏感信息（密码、密钥、Token）
