## 三、分支规则（最重要）

**1. 只有一个分支：`main`**

- 所有提交直接推送到 `main`，不使用 feature 分支
- 不创建 `trae/solo-agent-*` 分支
- 不创建 `feat/*` 分支
- 不创建 `phase*-dev` 分支

**2. 禁止保留旧分支**

- 任务完成后，凌舟立即删除所有远程和本地分支
- 任何时候 `git branch -r` 只应看到 `origin/main` 一条
- 任何时候 `git branch` 只应看到 `main` 一条

---

## 四、任务文件规则（最重要）

**1. 只有一个任务文件**

- 路径：`docs/tasks/current-tasks.md`
- 这是唯一合法位置，唯一的任务文件
- 所有团队成员读取这一个文件获取任务

**2. 禁止多人多文件**

- 不再创建 `ajian-tasks-*.md`、`mo-tasks-*.md`、`ache-tasks-*.md` 等独立文件
- 不再创建 `task-plan-*.md`、`task-breakdown-*.md` 等分解文件
- 所有任务集中在 `current-tasks.md` 一个文件中

**3. 轮次编号**

- 每次凌舟分派任务为一个轮次，格式：`R1`、`R2`、`R3`...
- 轮次信息包含：日期、来源、状态
- 示例：`### R1 — 2026-07-02 合并后问题修复 [已完成]`

**4. 任务格式（固定，不可变）**

每个任务必须包含以下字段：

```
#### [编号] 简短标题
- 优先级：P0 / P1 / P2
- 负责人：阿坚 / 墨 / 阿澈
- 预计：0.5天 / 1天 / 2天
- 状态：待开始 / 进行中 / 已完成 / 阻塞
- 文件：`精确的文件路径`
- 问题：[一句话描述问题]
- 修复：[具体修复方向]
```

**5. 测试报告规则**

- 测试报告统一放在 `docs/reports/` 目录
- 格式：`docs/reports/test-report-YYYY-MM-DD.md`
- 凌舟收到报告后，提取问题写入 `current-tasks.md` 对应轮次

## 六、代码提交规则

1. **提交信息格式**：`type: 中文描述`
   - `feat: 新功能描述`
   - `fix: 修复描述`
   - `docs: 文档更新描述`
   - `chore: 清理/维护描述`
2. 每次提交前确认 `git status`，不要提交无关文件
3. 完成任务检查通过后，立即提交推送

---

## 七、命名规则

1. 数据库表名：`snake_case`（如 `sale_bill_item`）
2. 后端文件：`kebab-case`（如 `sale-bill.service.ts`）
3. 前端组件：`PascalCase`（如 `SaleBillView.vue`）
4. API路径：`kebab-case`（如 `/api/admin/order-sync-logs`）
5. 文档文件：中文或 `kebab-case`

---

## 八、文档语言规则

1. **所有文档、任务文件、注释一律使用中文**
2. 数据库字段注释用中文（`COMMENT '字段说明'`）

---

## 九、禁止事项

1. **禁止**创建多个分支，只使用 `main`
2. **禁止**创建多个任务文件，只有 `docs/tasks/current-tasks.md`
3. **禁止**在 `docs/tasks/` 以外的位置创建任务文件
4. **禁止**使用英文写文档内容
5. **禁止**给已离开的成员分配任务
6. **禁止**在代码中硬编码敏感信息（密码、密钥、Token）
7. **禁止**创建 `MEMORY.md`、`WORKING-MEMORY.md` 等记忆文件

---

## 十、凌舟工作流程

**收到新任务/反馈时：**
1. 排查问题 → 定位根因 → 确认负责人
2. 在 `current-tasks.md` 中新增轮次，按固定格式写入任务
3. 提交推送，通知相关成员
4. 成员提交后，合并审查，更新任务状态
5. 每轮结束后，删除所有远程/本地分支，保持只有 `main`
