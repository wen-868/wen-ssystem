## 三、分支规则（最重要）

**1. 只有一个分支：`main`**

- 所有提交直接推送到 `main`，不使用 feature 分支
- 不创建 `trae/solo-agent-*` 分支
- 不创建 `feat/*` 分支
- 不创建 `phase*-dev` 分支

**2. 禁止保留旧分支**

- 任务完成后，凌舟立即删除所有远程和本地分支
- 任何时候 `git branch -r` 只应看到 `origin/main` 一条
- 任何时候 `git branch` 只应看到 `main` 一条

---

## 四、任务文件规则（最重要）

**1. 只有一个任务文件**

- 路径：`docs/tasks/current-tasks.md`
- 这是唯一合法位置，唯一的任务文件
- 所有团队成员读取这一个文件获取任务

**2. 禁止多人多文件**

- 不再创建 `ajian-tasks-*.md`、`mo-tasks-*.md`、`ache-tasks-*.md` 等独立文件
- 不再创建 `task-plan-*.md`、`task-breakdown-*.md` 等分解文件
- 所有任务集中在 `current-tasks.md` 一个文件中

**3. 轮次编号**

- 每次凌舟分派任务为一个轮次，格式：`R1`、`R2`、`R3`...
- 轮次信息包含：日期、来源、状态
- 示例：`### R1 — 2026-07-02 合并后问题修复 [已完成]`

**4. 任务格式（固定，不可变）**

每个任务必须包含以下字段：

```
#### [编号] 简短标题
- 优先级：P0 / P1 / P2
- 负责人：阿坚 / 墨 / 阿澈
- 预计：0.5天 / 1天 / 2天
- 状态：待开始 / 进行中 / 已完成 / 阻塞
- 文件：`精确的文件路径`
- 问题：[一句话描述问题]
- 修复：[具体修复方向]
```

**5. 测试报告规则**

- 测试报告统一放在 `docs/reports/` 目录
- 格式：`docs/reports/test-report-YYYY-MM-DD.md`
- 凌舟收到报告后，提取问题写入 `current-tasks.md` 对应轮次

## 五、踩坑日志规则（重要）

**1. 文件位置**

- 路径：`docs/踩坑日志.md`
- 所有团队成员踩过的坑、犯过的错、解决方案都记录在此

**2. 必须记录的情况**

- 代码 Bug 导致的线上问题
- 配置错误导致的功能异常
- 合并冲突中踩到的坑
- 前后端不匹配导致的接口问题
- 第三方库兼容性问题
- 任何花超过 30 分钟才定位的问题

**3. 执行纪律**

- **每次执行任务前，必须先读 `docs/踩坑日志.md`，避免重复踩坑**
- 任务完成后，如果踩了新坑，立即更新踩坑日志
- 凌舟每次合并审查时，将新发现的坑补充进去

**4. 格式（固定）**

```
### [序号] 简短标题
- 日期：YYYY-MM-DD
- 踩坑人：姓名
- 关键词：tag1, tag2
- 现象：[一句话描述遇到的问题]
- 原因：[根因分析]
- 解决：[具体修复方法]
- 教训：[以后怎么避免]
```

## 十一、凌舟工作流程

**收到新任务/反馈时：**
1. 先读 `docs/踩坑日志.md`
2. 排查问题 → 定位根因 → 确认负责人
3. 在 `current-tasks.md` 中新增轮次，按固定格式写入任务
4. 提交推送，通知相关成员
5. 成员提交后，合并审查，更新任务状态
6. 将新发现的坑写入 `docs/踩坑日志.md`
7. 每轮结束后，删除所有远程/本地分支，保持只有 `main`

---
## 十二、强制闭环流程（全员必遵守，红线）

**每位成员每次执行任务，必须走完以下闭环，缺一不可：**

```
读取任务 → 执行 → 验证 → 总结 → 提交 → 更新踩坑日志 → 推送
```

| 步骤 | 必须做的事 | 不允许 |
|------|------|------|
| **1. 读取任务** | 打开 `docs/tasks/current-tasks.md` 确认自己的任务 | 从旧文件、记忆、聊天记录中获取任务 |
| **2. 执行** | 按任务描述和标准文档修改代码 | 跳过标准文档，凭感觉写 |
| **3. 验证** | 跑 `tsc --noEmit` / `npm run build` / `grep` 确认 | 不验证就提交；声称"已完成"但没跑过命令 |
| **4. 总结** | 在自己的任务文件中标注完成状态 + 证据 | 只标"已完成"三个字，无代码证据 |
| **5. 提交** | `git add` + `git commit` + 写清楚提交信息 | 提交无关文件；提交信息写"update"敷衍 |
| **6. 更新踩坑日志** | 如果踩了新坑，立即写入 `docs/踩坑日志.md` | 踩了坑不说，让下一个人再踩一次 |
| **7. 推送** | `git push` 到 `main` 分支 | 推到其他分支；push 完不通知凌舟 |

**违反闭环流程 → 视为任务未完成，返工重做。**

**特别强调：验证步骤必须用实际命令跑出结果，不能凭"我觉得应该没问题"就跳过。**
