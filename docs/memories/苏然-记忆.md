## 二、测试流程（必须遵守）

### 2.1 验收三步法

每次验证必须执行以下三步，缺一不可：
1. **读代码** — 打开文件，看实际内容
2. **跑命令** — `tsc --noEmit`、`npm run build`、`grep`、`vitest run --coverage`
3. **看结果** — 每条结论附代码证据或命令输出

### 2.2 测试范围（R14/R15 标准）

| 项目 | 命令 | 验收标准 |
|------|------|----------|
| 后端 | `npx tsc --noEmit --strict` | 0 错误 |
| 后端 | `npx vitest run src/__tests__/shared/ --coverage` | shared/ 行/分支/函数/语句均 100% |
| 后端 | `npx vitest run src/__tests__/middleware/ --coverage` | middleware/ 行/分支/函数/语句均 100% |
| admin-web | `npx vue-tsc --noEmit` | 0 错误 |
| admin-web | `npx eslint src/` | 0 error 0 warning |
| store-terminal | `npx eslint src/` | 0 error（warning 允许） |
| app-mobile | `npm run build:h5` | Build complete |
| app-mobile | `grep -rn "功能开发中" src/pages/` | 0 匹配 |

### 2.3 环境准备

```bash
# 根目录（workspaces）
cd /workspace && npm install --legacy-peer-deps

# app-mobile（独立项目，不在 workspaces 中）
cd /workspace/app-mobile && npm install
```

**关键提示：** 根目录使用 `--legacy-peer-deps` 是因为根 `package.json` 的 ESLint 10 依赖与子项目 ESLint 8 有 peer 冲突，属环境配置问题，非代码缺陷。

### 4.1 测试命令速查

```bash

cd backend && npx tsc --noEmit --strict

# 后端单元测试（shared + middleware）

# 前端 admin-web
cd admin-web && npx vue-tsc --noEmit && npx eslint src/

# 前端 store-terminal
cd store-terminal && npx eslint src/

# app-mobile
cd app-mobile && npm run build:h5
```

## 五、踩坑记录（苏然相关）

### 坑 [17] 未安装依赖就跑测试

- 现象：877 个模块未找到误报
- 原因：未 npm install
- 教训：**执行任何需要解析 node_modules 的命令前，必须先 npm install**

### 坑 [11] subagent 漏项

- 现象：批量任务遗漏字段和校验
- 教训：subagent 输出必须逐项核对，不能直接信任

### 坑 [5] vitest 与 jest 不兼容

- 现象：jest.fn() 报 jest is not defined
- 解决：替换为 vi.fn()
