## 六、核心决策记录

### 6.1 为什么用 Pinia 而非继续用 localStorage

**决策时间：** R10  
**原因：** 
- localStorage 分散在 5 个文件中，难维护
- token 过期检查逻辑重复
- Pinia + pinia-plugin-persistedstate 自动持久化，代码更简洁
- 符合项目统一标准第十七章（状态管理规范）

### 6.2 为什么路由名从 PascalCase 改为 kebab-case

**决策时间：** R11  
**原因：**
- 项目统一标准第十六章要求路由名用 kebab-case
- 全部使用 path 跳转（非 name），改名无运行时影响
- 113 条路由名统一格式

### 6.3 为什么 mock 数据声明为 any[]

**决策时间：** R13  
**原因：**
- `Array.from()` 生成的 mock 数据，TS 会推断出过窄的类型
- `productId: number` 与 form 中的 `number | null` 不匹配
- `scope: "ALL"|"CATEGORY"|"PRODUCT"` 与 form 中的 `string` 不匹配
- 声明为 `any[]` 最简洁，不影响运行时

### 6.4 为什么 console.error 用 `if (import.meta.env.DEV)` 而非删除

**决策时间：** R14  
**原因：**
- 全局错误捕获的 console.error 在开发环境调试时非常有用
- 生产环境不需要输出
- `import.meta.env.DEV` 是 Vite 内置的环境变量，构建时自动替换
- 配合 `eslint-disable-next-line no-console` 消除 ESLint warning

## 七、踩坑教训（我的 8 条，全项目 54 条）

### 11 号坑：依赖子任务输出导致任务漏项
- **现象：** R4-1 用子任务并行处理 10 个子任务，凌舟审查发现大量遗漏
- **原因：** 子任务只做表面工作，我直接信任输出未做最终核对
- **教训：** 子任务的输出必须由我逐项核对。涉及多文件的任务，完成后必须用 grep/统计数量等方式做完整性验证

### 12 号坑：表单校验只加 rules 不补 ref 声明
- **现象：** 批量给表单补校验时，直接在 el-form 上加了 :rules 和 ref，但 script 里没声明对应的 ref 变量
- **原因：** 只改了模板部分，漏了 script 里的 ref 声明
- **教训：** Element Plus 表单校验三件套（ref + :model + :rules）必须同时存在。批量修改后必须跑 vue-tsc 验证

### 13 号坑：修复任务只做一半 — 超时处理只加拦截器忘了配 timeout
- **现象：** R5 要求补超时错误处理，只加了 ECONNABORTED 拦截分支，但 axios.create 里没配 timeout: 30000
- **原因：** 只看了"错误处理"四个字，没理解超时机制需要两端配合
- **教训：** 修复功能要理解完整链路。涉及"错误处理"时要同时检查"触发条件"和"捕获处理"两端

### 14 号坑：表单校验只补 rules 不检查 model 和 prop
- **现象：** InventoryBatchPrice.vue 声明了空 FormRules 和空 model，加了 rules 也不会生效
- **原因：** 只 grep 了空规则的情况，没检查 model 对象里有没有对应字段、el-form-item 上有没有 prop
- **教训：** model 字段、prop 属性、rules 规则三者缺一不可。检查表单校验完整性要三个地方都看

### 36 号坑：manualChunks 过度拆分第三方库导致循环依赖警告
- **现象：** 拆分 element-plus/echarts 到子 chunk 后出现大量 "Circular chunk" 警告
- **原因：** 库内部存在循环依赖，强行按目录切割破坏了内部依赖关系
- **教训：** 有内部循环依赖的库用粗粒度拆分，UI 组件库优先用按需导入插件

### 48 号坑：Element Plus CheckCircle 图标不存在
- **现象：** 导入 CheckCircle 导致 vue-tsc 报错
- **原因：** 项目依赖版本中没有 CheckCircle，只有 Check
- **教训：** 使用 Element Plus 图标前先检查依赖版本支持的图标列表

### 51 号坑：后端返回下划线字段名，前端期望驼峰字段名
- **现象：** "仅线下"徽标永远不显示，分类树结构不工作
- **原因：** 后端 SQL 返回原始下划线字段名（allow_online_sale），前端期望驼峰（allowOnlineSale），无中间层转换
- **教训：** 对接 API 时先检查后端返回的字段名格式，前端做字段映射

### 52-54 号坑：后端 list 只返回根分类 + 前端 sortOrder vs 后端 sortNo + tsconfig 版本
- **现象：** 分类树只显示根分类 / 排序号始终为 0 / vue-tsc 报 baseUrl 弃用错误
- **教训：** 树形 API 要确认是否一次返回所有层级 / 前后端字段名必须严格对照 / TypeScript 升级后 ignoreDeprecations 需同步更新

## 十二、工作习惯

### 个人专属操作习惯

1. **Git 推送** — TLS 经常失败，用 `GIT_SSL_NO_VERIFY=1 git push origin main`
2. **Git 身份** — 需要设置 `git config user.email "mo@zhixiang-system.com"` 和 `git config user.name "墨"`
3. **依赖安装** — 用 `npm install --legacy-peer-deps`（有 peer dependency 冲突）
4. **ESLint 执行** — 用 `npx --no eslint src/` 确保使用本地 node_modules 中的 eslint
5. **任务执行流程** — 读任务 → 读踩坑日志 → 读统一标准 → 执行 → 自查清单 → 提交推送 → 更新任务状态
6. **新建页面** — 必须同时：创建 .vue 文件 + 添加路由 + 确保三件套
7. **API 函数** — 统一放在 api.ts，格式：`export async function funcName(params?: any) { const { data } = await api.get('/admin/path', { params }); return data.data; }`
8. **Mock 数据** — 声明为 `any[]` 避免 TS 类型推断过窄

### 常用命令

```bash
# 类型检查
cd admin-web && npx vue-tsc --noEmit

# ESLint 检查
cd admin-web && npx --no eslint src/
cd store-terminal && npx --no eslint src/

# 构建
cd admin-web && npx vite build

# Git 提交推送
git add <files> && git commit -m "type: 中文描述" && GIT_SSL_NO_VERIFY=1 git push origin main
```

### 页面开发模板要点

新建 .vue 页面时必须包含：
1. `<el-form ref="formRef" :model="form" :rules="formRules">` — 三件套
2. `<el-form-item label="xxx" prop="xxx">` — prop 属性
3. `const formRef = ref<FormInstance>()` — ref 声明
4. `const formRules: FormRules = { xxx: [{ required: true, message: "...", trigger: "blur" }] }` — 规则声明
5. `const valid = await formRef.value?.validate().catch(() => false); if (!valid) return;` — 提交前校验
6. 路由配置含 `meta: { roles: ["BOSS"], title: "中文标题", icon: XxxIcon }`
