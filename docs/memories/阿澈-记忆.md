## 三、核心技术沉淀

### 3.1 通用表单校验 composable

**文件：** `app-mobile/src/composables/useFormValidation.ts`

为 uni-app 提供类似 Element Plus el-form 的三件套能力：`ref + :model + :rules`

**用法：**
```typescript
import { useFormValidation, type Rules } from '@/composables/useFormValidation'

const formRef = ref<any>(null)
const formModel = reactive({ name: '', phone: '' })
const rules: Rules = {
  name: [{ required: true, message: '请输入姓名' }],
  phone: [
    { required: true, message: '请输入手机号' },
    { pattern: /^1[3-9]\d{9}$/, message: '手机号格式不正确' },
  ],
}
const { errors, validate, clearError } = useFormValidation(formModel, rules)
```

**Rule 支持的属性：**
- `required: boolean` — 必填校验
- `message: string` — 错误提示
- `minLength: number` — 最小长度
- `maxLength: number` — 最大长度
- `pattern: RegExp` — 正则校验
- `validator: (value, model) => boolean` — 自定义校验函数

**返回值：** `{ errors, validate, validateField, clearError, clearAllErrors, formRef }`

### 3.2 批发价权限统一工具

**文件：** `app-mobile/src/utils/price.ts`

**核心函数：**
- `isWholesaleCustomer()` — 判断当前用户是否批发客户
- `isRetailCustomer()` — 判断当前用户是否零售客户
- `getVisiblePriceFields()` — 获取可见价格字段列表
- `isPriceFieldVisible(field)` — 判断某价格字段是否可见

**铁律：** 禁止在业务代码中手写 `customerType === "WHOLESALE"`，统一调用工具函数。

### 3.3 请求封装与错误处理

**文件：** `app-mobile/src/api/request.ts`

**6 种错误处理：**
1. 401 — Token 过期，跳登录
2. 403 — 无权限
3. 404 — 资源不存在
4. 500 — 服务器错误
5. 超时（ECONNABORTED）— 超时提示
6. 网络错误 — 网络异常提示

**返回体适配：** 统一使用 `resData?.msg`（不是 `message`）

**BASE_URL 处理：** 使用 IIFE 包裹 `#ifdef H5` / `#ifndef H5` 条件编译，避免 vue-tsc 重复声明报错

### 3.4 uni-app 类型补充

**文件：** `app-mobile/src/types/uni-app.d.ts`

使用 `declare module '@dcloudio/uni-app'` 补充导出缺失的生命周期钩子类型：
- `onLoad`
- `onLaunch`
- `onShow`
- `onHide`
- 等...

### 3.5 数据库迁移文件规范

**目录：** `docs/migrations/`

**命名格式：** `编号_中文名.sql`（如 `068_银行费用发票.sql`）

**标准注释头：**

## 四、我踩过的坑（必须记住）

### 坑 #15：uni-app 条件编译导致 vue-tsc 误报重复声明

- **现象：** `#ifdef H5` / `#ifndef H5` 定义不同 `const BASE_URL`，vue-tsc 报 TS2451
- **原因：** vue-tsc 不识别 uni-app 预编译指令，两个分支同时存在
- **解决：** 用 IIFE 包裹 return 语句，合并为一个 `const` 声明
- **教训：** 条件编译的 `const` 声明用 IIFE 或函数包裹多分支

### 坑 #16：@dcloudio/uni-app 类型定义不导出生命周期钩子

- **现象：** 20+ 页面从 `@dcloudio/uni-app` 导入 `onLoad` 等，vue-tsc 报 TS2305
- **原因：** 类型定义文件未导出这些钩子（运行时由 uni-app 编译器注入）
- **解决：** 创建 `src/types/uni-app.d.ts` 用 `declare module` 补充类型
- **教训：** uni-app 项目初期就建立类型补充文件

### 坑 #50：烟草类目前端对接三连坑（接口路径+字段命名+商品API缺字段）

- **现象：** products.vue 模板已写好"仅线下"标识逻辑，但实际运行标识永不显示
- **原因：** ①前端分类接口路径 `/admin/product-categories` 与后端 `/admin/products/categories` 不匹配；②后端返回下划线 `allow_online_sale`，前端期望驼峰 `allowOnlineSale`，request.ts 无转换；③后端商品列表 SQL 漏 select `pc.allow_online_sale`，商品对象不带该字段
- **解决：** 前端独立兜底——products.ts 修正路径+做字段映射（下划线→驼峰、records→list、spuId→id 等）；products.vue 构建 categoryId→allowOnlineSale 映射，isOfflineProduct() 优先取商品字段兜底用分类配置
- **教训：** 前端写标识逻辑前必须 grep 后端 SQL 确认实际返回字段名；前端 API 模块应承担字段映射职责；后端缺字段时前端可用关联数据构建映射兜底，但需记录遗留问题通知后端

### 其他必须记住的坑（别人踩的，但我要避免）

- **坑 #12：** 表单校验只加 rules 不补 ref → 批量改完必须跑 vue-tsc
- **坑 #13：** 超时处理只加拦截器不配 timeout → 检查"触发条件"和"捕获处理"两端
- **坑 #14：** 表单校验只补 rules 不检查 model 和 prop → 三件套缺一不可
- **坑 #11：** subagent 输出必须逐项核对，不能直接信任
- **坑 #17：** 跑 tsc/eslint/vitest 前必须先 npm install

## 五、表单校验三件套铁律

**Element Plus / uni-app 表单校验三要素，缺一不可：**

| 要素 | 位置 | 说明 |
|------|------|------|
| `ref="formRef"` | 模板 `<form>` / `<el-form>` | 引用表单实例 |
| `:model="formModel"` | 模板 `<form>` / `<el-form>` | 绑定数据对象 |
| `:rules="rules"` | 模板 `<form>` / `<el-form>` | 绑定校验规则 |

**script 中必须有：**
- `const formRef = ref<any>(null)`
- `const formModel = reactive({...})`
- `const rules: Rules = {...}`
- `const { errors, validate } = useFormValidation(formModel, rules)`

**验证方式：**
```bash
# 统计有多少页面有三件套
grep -rn "formRef.*=.*ref" app-mobile/src/pages/*.vue
grep -rn ":model=" app-mobile/src/pages/*.vue
grep -rn ":rules" app-mobile/src/pages/*.vue
```

**合理例外：** 纯展示页面（home、profile、notifications 等）无表单交互，不需要三件套。

## 八、错误责任制（三条红线）

**层面一：核心原则**
> 错误面前没有"不是我引入的"。遇到 TS 报错、构建失败、测试不过，不允许以"这是预存的""这是第三方库的问题""这不是我改的"为由推卸。

**层面二：提交门禁**
> 每条错误只有三种归宿：修复、记录到踩坑日志、报告凌舟。没有第四种选择。

**层面三：红线**
> 不记录、不报告、不修复，直接提交 → 代码回退。
