## 三、核心技术沉淀

### 3.1 通用表单校验 composable

**文件：** `app-mobile/src/composables/useFormValidation.ts`

为 uni-app 提供类似 Element Plus el-form 的三件套能力：`ref + :model + :rules`

### 3.2 批发价权限统一工具

**文件：** `app-mobile/src/utils/price.ts`

统一批发价/零售价判断，不手写 `customerType === "WHOLESALE"`

### 3.3 错误责任制（三条红线）

**层面一：核心原则**
> 错误面前没有"不是我引入的"。遇到 TS 报错、构建失败、测试不过，不允许以"这是预存的""这是第三方库的问题""这不是我改的"为由推卸。

**层面二：提交门禁**
> 每条错误只有三种归宿：修复、记录到踩坑日志、报告凌舟。没有第四种选择。

**层面三：红线**
> 不记录、不报告、不修复，直接提交 → 代码回退。

### 3.4 saas-admin 认证体系

**正确的认证体系（体系 B）：**
- `stores/auth.ts` — 用 `platform_token` 存储 token，`adminInfo` 存储用户信息
- `api/auth.ts` — 调 `/platform-auth/login`（平台登录接口）
- `views/login/PlatformLogin.vue` — 平台登录页
- `utils/request.ts` — 通过 authStore 获取 token

**已废弃的错误体系（体系 A）：**
- `saas_token` / `saas_user` — 旧 token key
- `saasLogin()` — 调 `/admin/auth/login`（商家登录，不是平台登录）
- `views/LoginView.vue` — 旧登录页（已删除）

## 七、代码提交规范

**提交信息格式：** `type: 中文描述`

| 类型 | 说明 |
|------|------|
| `feat:` | 新功能 |
| `fix:` | 修复 |
| `docs:` | 文档更新 |
| `chore:` | 清理/维护 |

**分支规则：** 只有 `main` 分支，不创建任何 feature 分支。

**命名规则：**
- 数据库表名：snake_case（如 `sale_bill_item`）
- 前端组件：PascalCase（如 `SaleBillView.vue`）
- API 路径：kebab-case（如 `/api/admin/order-sync-logs`）
- 后端文件：kebab-case（如 `sale-bill.service.ts`）
