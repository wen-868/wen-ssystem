## 一、卡面与实现的一处取舍（必须先说清，属"改动依据"）

**只改 `platform-rbac.ts` 会得到一个静默失效的接线**：`PLATFORM_PERMISSIONS` 只决定"码能不能被端点引用"，
而"码能不能被**授予**"由平台角色矩阵端点的合法域集合决定 —— 该集合派生自 `PERMISSION_CATALOG`：

```
// backend/src/services/platform/platform-role.service.ts（replaceRolePermissions → normalizeMatrix）
const moduleCodes = new Set(catalogModuleCodes());
if (!moduleCodes.has(moduleCode)) {
  throw new AppError(`功能域不在权限点目录内：${moduleCode}`, 400);
}
```

⇒ 若只把 `catalogReady` 置 true 而不扩目录，平台角色页保存 `library` 域会 **400**，
该码**永远无法被任何角色持有** ⇒ 这 28 条端点对**除超管外的所有账号**永久 403。
这属于"看着接好了、实则只有超管能过"的假接线，故本单一并扩平台侧目录（**不越红线**：
红线 ① 保护的是**商家侧** `backend/src/shared/user-permissions.ts`，本次 0 改动）。

## 二、实际改动（两处，逐行）

### ① `backend/src/services/platform/platform-role.service.ts` — `PERMISSION_CATALOG` 18 条 / 8 域 → 21 条 / 11 域

```diff
   { moduleCode: "ticket", moduleName: "工单系统", permCode: "ticket:category:config", permName: "工单类型配置", permLevel: "BUTTON" },
+  { moduleCode: "library", moduleName: "商品库", permCode: "library:manage", permName: "商品库管理", permLevel: "BUTTON" },
+  { moduleCode: "open", moduleName: "开放平台", permCode: "open:manage", permName: "开放平台管理", permLevel: "BUTTON" },
+  { moduleCode: "review", moduleName: "平台评价与审核", permCode: "review:manage", permName: "平台评价与审核", permLevel: "BUTTON" },
```

命名沿用目录既有规范 `<moduleCode>:<action>`（与 `ticket:reply` / `ticket:close` 同形），
`permLevel = BUTTON`（与"写码 = 按钮级 `can_page_btn`"一致）；`moduleCode` 逐字对齐
`t_platform_role_permission.module_code`（迁移 179，`VARCHAR(32)`，无枚举约束，取值域由本常量决定）。

### ② `backend/src/middleware/platform-rbac.ts` — `catalogReady` 由手写布尔改为**派生**

```diff
-const PLATFORM_WRITE_CODES: ReadonlyArray<{ code: string; moduleCode: string; catalogReady: boolean }> = [
-  { code: "library:manage", moduleCode: "library", catalogReady: false },
+const PLATFORM_WRITE_CODES: ReadonlyArray<{ code: string; moduleCode: string }> = [
+  { code: "library:manage", moduleCode: "library" },
 ];
+const CATALOG_MODULE_CODES: ReadonlySet<string> = new Set(
+  PERMISSION_CATALOG.map((entry) => entry.moduleCode)
+);
   ...
-      catalogReady: item.catalogReady,
+      catalogReady: CATALOG_MODULE_CODES.has(item.moduleCode),
```

**为什么改派生而不是手改 3 个 `false → true`**：手写布尔与目录是**两份真相**，
漂移时表现为"码已接线但永远无法被授予"（本次 library/open/review 之前正是这个状态）。
派生后二者不可能漂移，且该不变量已被用例机器化（见 §三.3）。
