## 二、回答卡 §四 的问题：**不会 403**（四条依据）

问：「新增 `library:manage` 后，**今天能打开商品库页面的平台角色**会不会因为不持有该码而 403？」

| # | 依据 | 可核对出处 |
|:--|:--|:--|
| 1 | **判据只有两条路**：`t_platform_admin.role ∈ {PLATFORM_SUPER_ADMIN, SUPER_ADMIN}` ⇒ 全通放行；否则按 `t_platform_role` + `t_platform_role_permission.can_page_btn` 判定 | `backend/src/middleware/platform-rbac.ts` `checkPlatformPermission()`（`isPlatformSuperRole` 分支在查矩阵之前 return） |
| 2 | **生产唯一平台管理员 = 超管**：种子 `admin`，`role='PLATFORM_SUPER_ADMIN'`，且 `ON DUPLICATE KEY UPDATE role=VALUES(role)`（重跑也强制为超管） | `docs/migrations/081_platform_admin_seed_and_fix.sql:46-58`（`role` 列注释见同文件 `:20`） |
| 3 | **生产平台角色矩阵为空**：`t_platform_role` = **0 行** ⇒ 今天**没有任何角色持有任何 module_code**，也就没有"因不持有新码而被拒"的主体 | 凌舟只读探针记录 `docs/tasks/R101-总进度与推进计划.md:2057`（"生产 `t_platform_role` = 0 行"）与 `:2059`（零副作用快照：`t_platform_admin`=1 / `t_platform_role`=0） |
| 4 | **页面侧不受影响**：商品库菜单是**静态配置**，平台菜单**不按 module_code 过滤** ⇒ "能打开商品库页面" = "能登录平台后台" = 上面那唯一的超管 | `saas-admin/src/config/platform-menu.ts:81`（`{ title: '商品库', path: '/library/spus', icon: Goods }`）；同文件头注释说明菜单来自设计稿 NAVS，7 组 22 项，无权限过滤 |

**结论**：新增 `library:manage` 在生产上 **影响面 = 0**（唯一账号走全通分支，且无任何非超管平台角色）。
本单的效果是**对未来新建的非超管平台账号生效**——这正是第 67 项要的"平台侧写端点要有权限粒度"。
