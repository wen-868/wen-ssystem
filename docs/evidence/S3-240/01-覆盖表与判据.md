## 一、判据（唯一判据点，逐条同源）

| 层 | 实现 | 说明 |
|:--|:--|:--|
| 匹配 | `admin-web/src/config/permission-gates.ts#matchPermissionCode` | 后端 `backend/src/services/admin/rbac.service.ts:295` `matchPermission()` 的**逐条镜像**（`*` / `<dom>:*` / `*:<action>` / 精确码），与手机端 `app-mobile/src/config/permission-gates.ts` 同形 |
| 判定 | `admin-web/src/stores/app.ts#hasPermissionCodes` | 单一判据点：门码**全部持有**才通过；`permissions` 为 `null`/`undefined` ⇒ **失败关闭** |
| 门 | `admin-web/src/config/permission-gates.ts#BUTTON_GATES` | 「按钮 ↔ 码」声明式注册表（唯一真相源，15 项：gated 13 / registered 2） |
| 取用 | `admin-web/src/composables/usePermissionGate.ts#canGate(id)` | 页面只写门 id；未登记 id ⇒ 失败关闭 + 控制台报出 |
| 取值 | 登录响应 `permissions`（`LoginView.vue` 两处登录路径）＋ `GET /api/admin/auth/me`（`stores/app.ts#ensurePermissions`，仅"未取到"时拉一次，并发去重，失败关闭） | 与后端同源：`backend/src/services/admin/auth.service.ts:190/:252` |

**为什么必须通配匹配**：生产 `SUPER_ADMIN` / `OPERATION_ADMIN` 的角色权限串是 `["*"]`
（`docs/evidence/_shared/prod-roles-20261016.txt` §一）⇒ 若沿用 `permissions.includes(code)`，
会把**店主**判成"不持码"，把删除/新增按钮从老板界面上藏掉（假回归）。

**「未取到权限码」= 失败关闭**（同 S3-231 F3 裁定 5）：`null`/`undefined`（升级前老缓存）与**空数组**一律**不显示**，
避免把"无码角色"放进一个必 403 的界面；老缓存由 `ensurePermissions()` 补拉 `/admin/auth/me` 后填实。

| 入口 | 为什么只登记 |

| 员工管理 / 组织架构 · 新增/编辑弹窗 · 保存 | 同上：按模式分别走 `system:user:create` / `system:user:edit`（一次只打一个） |
