## 0. 元结论（先看这 6 条）

1. **扫描范围 = 5 个 workflow 文件 / 7 个 job / 57 个步骤**（枚举脚本 `tools/probe-workflow-steps.mjs`，输出 `outputs/workflow-steps.txt`）。
2. 57 步里**真正需要"会红"证明的门禁类步骤 31 个**；其中**已有步骤级红测记录 7 个**、**本地等效反测已证会红但缺 CI run 记录 8 个**、**无任何红测记录 5 个**、**结论冲突待核对 1 个**、**记录互斥待核对 3 个**、**假门禁 6 个**（已判定"不能红"）、**结构上无法分支反测 1 个**（详见 §3 与未闭环清单）。
3. **假门禁 6 个**：`Dependency audit` / `Duplication check`（`continue-on-error: true`）、`migration-check` 的迁移校验步骤（**恒红无分辨力**）、`CodeQL` 的 `Initialize CodeQL` 与 `Perform CodeQL Analysis`（只增量不存量、不阻断）、观察期 `a11y sampling x10`（步骤级 `continue-on-error: true`，由下一步兜底）。
4. **收口发现一（对 G-2 的更正）**：`Shell script syntax check` 并**不是**"从未见红" —— 它早在 2026-09-17 就有**步骤级红测**：**run `35126489677`**（PR #7 / 分支 `verify/s3-49-red`，坏 `deploy/rollback.sh`（glob 末尾）→ 该步骤 failure，日志 `已语法检查 12 个 shell 脚本` + `deploy/rollback.sh: line 85: syntax error: unexpected end of file`）。G-2 卡把它列入"未闭环"属**漏记**。
5. **收口发现二（口径必须钉死）**：历史卡片里的"step N"用的是 **GitHub run 页面序号**（含 `Set up job`，有 service 容器的 job 还多一个 `Initialize containers`），**比 workflow 文件里的步骤序号大 1（或 2）**。本表同时给两个序号，避免再出现"同一句话两个数"（对应派单规范 R8 取样必须可核对）。

## 1. 判定口径（先钉死再判定）

### 1.1 四档定义

| 档位 | 判定标准 | 说明 |
|---|---|---|
| **真门禁** | 该步骤的失败会**使 job 失败**，且**有"故意制造失败证明它会红"的记录**（优先 run id + 步骤名；无 run 时至少要有本地等效反测，并单独标注证据等级） | 只有真门禁才允许进 required |
| **假门禁** | **结构上不能红**（`continue-on-error`、后台 `&` 恒 0）、或**恒红无分辨力**、或**只增量不存量** | 红/绿都不改变合并结论者一律算假 |
| **从未运行** | 至今**没有一次 run 记录**，或**从未在真实分支上跑到该步骤** | 反测路径不存在的也归此类 |
| **盲区** | 有 run、也会红，但对**某一类破坏不敏感**（覆盖缺口） | 需登记覆盖边界，不得当成"覆盖到位" |
| **非门禁**（第五类，本表显式标注） | `actions/checkout`、`setup-node`、起服务、上传产物等 **setup/产物步骤** | 对它们要求"会红"证明没有意义；但**若其后无任何兜底**，则要按"掩蔽风险"记账（本表逐条写明） |

**证据等级（本表统一标注，不许混用）**：
`A` = CI run id + 步骤名（最强）；`B` = 本地等效反测（同脚本/同配置/同输入，本卡新做，输出在 `outputs/`）；`C` = 仅静态推理或仅有 job 级红（**不得当作步骤级闭环**）。

### 1.2 步骤序号口径（本表给两列）

| 列 | 含义 | 怎么得到 |
|---|---|---|
| `文件步骤` | workflow 文件里 `steps:` 下的第 N 项（1-based） | `outputs/workflow-steps.txt`（1-based，按 `      - ` 项计数） |
| `run 页面` | GitHub Actions run 页面左侧步骤列表里的序号 | = 文件步骤 + 1（含 `Set up job`）；**该 job 有 `services:` 时再 +1**（`Initialize containers`）。本仓只有 `migration-check` 有 `services:` |

> ⚠️ 该换算由 5 处历史引用反推一致（e2e `Run E2E tests`=页面 11、`saas-admin a11y gate`=页面 12、a11y `verdict`=页面 10、ci `Build admin web`=页面 14、`Build saas admin`=页面 15；`migration-check` 页面 7 需 +2）。**jobs API 的 `steps[]` 数组不含 `Set up job`**，故用 API 核对时**以步骤名匹配为准，不要用序号**。

### 1.3 触发条件与阻断关系（判定真门禁的前提）

| workflow | 触发 | 是否阻断合并 |
|---|---|---|
| `ci.yml` | `push main` + `pull_request` | 仅 `build-and-test` 是 required；`migration-check` 非 required |
| `e2e.yml` | `push main` + `pull_request` | 仅 `e2e` 是 required；`a11y` 非 required（观察期） |
| `codeql.yml` | `push main` + `pull_request(main)` + 每周一 02:00 | 非 required（弱门禁） |
| `deploy.yml` | `push main`（paths-ignore：`docs/**`、`**.md`、`.github/**`、`e2e/**`）+ `workflow_dispatch` | 非 required；**部署动作本身不受 CI 结果约束** |
| `build-exe.yml` | `push main`（paths `admin-web/**`）+ `workflow_dispatch` | 非 required |

> required 集合＝`build-and-test`、`e2e`（来源：`AGENTS.md`「分支保护与 required checks」；远端实测记录见 `docs/reports/R101-G2-redtest-evidence.md` §0）。**本沙箱无 GitHub 访问**（见 `outputs/rt-env.txt`），故 required 集合与 run id **均以仓库内已落卡记录为依据**，不新增远端取样。
