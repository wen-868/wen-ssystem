## 二、机制（新增 2 个文件 + 3 处接线）

| 文件 | 作用 |
|:--|:--|
| `app-mobile/src/config/permission-gates.ts`（新） | ① `matchPermissionCode()` = 后端 `matchPermission()`（`backend/src/services/admin/rbac.service.ts:295`）的**逐条镜像**；② `hasPermissionCodes()`（**全部持有**才算通过）；③ `ENTRY_GATES` 声明式注册表（入口 → 码 → 端点 → 依据 → 状态），**runtime 与证据脚本共用同一份** |
| `app-mobile/src/composables/usePermissionGate.ts`（新） | `can(code)` / `canEntry(id)` / `canAnyEntry([ids])`；`permissions` 取 `stores/user` |
| `app-mobile/src/stores/user.ts` + `api/modules/auth.ts` + `api/storage.ts` | 登录响应与 `/admin/auth/me` 下发的 `permissions`（S3-203 起后端已同源下发）此前被**丢弃**，本单存下来并持久化（入口门判定输入）；`ProfileResult` / `UserInfo` 补字段 |
| `app-mobile/src/config/function-menu.ts` | `FunctionItem.permCodes`（该页写端点用的码）+ `filterItemsByPermissionGate` / `filterGroupsByPermissionGate`（**菜单 code 之外的独立第二道闸**） |
| `pages/functions/functions.vue`、`pages-sub/admin/more/more-functions.vue` | 功能中心 / 更多功能：在原有"菜单 code 过滤"之外再套一层权限门过滤 |

**口径（写死，避免两端口径分叉）**

1. 判定 = 后端 `matchPermission` 同规则：`*` 全通 / `模块:*` 前缀 / `*:动作` 后缀 / 精确码；
2. 一个入口若承载**多个不同码**的写端点 ⇒ **全部持有**才显示（任一持有即显示 = 等于没补门）；
3. `permissions` 为 `null/undefined`（尚未取到，老版本本地缓存）⇒ **放行**（维持改造前可见性）；
   `permissions` 为空数组（取到了、确实无码）⇒ **不显示**（失败关闭）——与 `stores/menu.ts` 的 null / 空集口径一致；
4. `SUPER_ADMIN` 持 `["*"]` ⇒ 任何门都可见（与后端 `requirePermission` 的 SUPER_ADMIN 直通一致）；
   `READONLY` 持 `["*:view"]` ⇒ **写门一律不可见**（观察员语义，写 403 本属期望）。
