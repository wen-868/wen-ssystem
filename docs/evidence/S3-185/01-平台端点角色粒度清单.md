## 三、为什么本单「落地 0 处」（机制缺失证据，逐条可复跑）

| # | 结论 | 证据（可复跑） |
|--:|:--|:--|
| M1 | 平台路由**没有任何**端点级权限机制：29 个文件 `requirePermission` 命中 0 | `rg -n --glob 'platform*.routes.ts' 'requirePermission' backend/src/routes` → 0 命中 |
| M2 | 既有 `requirePermission` 是**租户域**中间件，不能直接搬：它读 `req.user.roles`，而平台 JWT 里没有 `roles` | `backend/src/middleware/rbac-auth.ts:11`（`user.roles.includes("SUPER_ADMIN")`）＋ `backend/src/middleware/auth.ts:166-171`（`requirePlatformAuth` 把 `req.user` 设为 `{type,id,tenantId}`） |
| M3 | 平台侧权限数据（`t_platform_role` / `t_platform_role_permission`）**没有任何运行期消费者**：只有角色矩阵 CRUD 控制器读写它 | `rg -n 'can_page_btn|platform-role.service' backend/src --glob '*.ts'` → 仅 `services/platform/platform-role.service.ts`、`controllers/platform/platform-role.controller.ts`、其单测 |
| M4 | 平台管理员与平台角色**没有绑定字段** ⇒ 即便写出中间件也无「给谁查」 | `docs/migrations/080_平台管理员.sql:17` / `081_platform_admin_seed_and_fix.sql:20`：`role VARCHAR(32) ... 'PLATFORM_ADMIN / PLATFORM_SUPER_ADMIN'`，无 `role_id` |
| M5 | 平台 JWT 里也没有角色位 ⇒ 无法用「现有角色字段」做零风险灰度 | `backend/src/middleware/auth.ts:166`（decode 结果只有 `type/id/tenantId`）；`platform-auth.service.ts:193-205`（`/me` 只回 `id/username/realName/mfaEnabled/csrfToken`） |
| M6 | 目录里**只有 ticket 域**有端点级（BUTTON）码，其余 6 域只有 MENU 级码 | `PERMISSION_CATALOG`（`platform-role.service.ts:131-150`）：MENU 7 条 + ticket BUTTON 7 条 + DATA 4 条 |
