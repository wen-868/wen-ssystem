口径三步：

1. **表集合（DDL 依据）**：`docs/migrations/*.sql` + `docs/init_database.sql` + `backend/src/shared/migration.ts` 里
   "有 `tenant_id` 列"的表（`CREATE TABLE` 含该列，或 `CALL add_column_if_not_exists(...,'tenant_id',...)` / `ALTER TABLE ... ADD COLUMN tenant_id`）。
2. **写路径（代码依据）**：`backend/src/**/*.ts` 里所有 `INSERT INTO <表>(<列清单>)`，判断列清单是否含 `tenant_id`。
3. **静默条件**：该表的 `tenant_id` 列定义必须是 `NOT NULL DEFAULT 'default'`——只有这种列，漏列才**不报错、不落空**，而是静默写 `'default'`。

## 四、同族但**不构成**静默写 `default` 的路径（列无 `DEFAULT 'default'`）

扫描器同时输出 `excludedNoDefault`（64 条），共涉及 44 张表，例如：
`t_cart_item` / `t_platform_order` / `t_flash_sale` / `t_group_buy` / `t_promo_stack_rule` / `t_sys_role_menu` /
`t_order_timeout_config` / `t_print_record` / `t_push_token` / `t_tenant` / `t_platform_config` / `t_coupon_template` /
`t_points_record` / `t_stock_check` / `t_retail_product` / `t_transfer_order` / `t_sale_bill_item_archive` / `t_purchase_order_item_archive` …

**排除理由**：这些表的 `tenant_id` 列**没有** `DEFAULT 'default'`（多为 `VARCHAR(36) NOT NULL` 无默认值，或 `DEFAULT NULL`）。
漏列时 MySQL 会**报错**（NOT NULL 无默认值）或落 NULL，**不会静默写 `'default'`**，与本卡缺陷（静默写错租户）不是一类问题；
不得混进本卡修复范围（否则就是"扩大改动范围"）。如需治理，应另立卡（属"约束缺失"类）。
