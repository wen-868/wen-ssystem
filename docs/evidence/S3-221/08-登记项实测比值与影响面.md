## 二、影响面初判

- `--sidebar-text-active`：**2 处**引用，作用于工作台侧栏「当前所在菜单项」的文字（用户高频看到的激活态）。
  只改这一个 token 的取值即可修，无外溢（该 token 不被 saas-admin / 其他端引用）。
- `--text-link`：**0 处**引用 ⇒ 本单不改它不会造成任何视觉/可达性回归；
  但它是"下一个作者会拿来当链接色"的坑（`--text-link` 这个名字就是通用链接语义），
  要么修值、要么删定义，都需裁定。

## 三、修复候选（**未落地**，供裁定）

同一个文件里已经有现成的、逐面达标的**品牌蓝文本变体**：`--color-primary-text: #365FCE`
（`tokens.css:16`，注释写明「S3-66.1 / H-1：AA 达标**文本**专用变体」）：

| 面 | `#3F6FEF`（现值） | `#365FCE`（候选） |
|:--|:--|:--|
| 白底 `#FFFFFF` | 4.44:1 ❌ | **5.70:1** ✅ |
| `#f7f7f7` | 4.14:1 ❌ | **5.32:1** ✅ |
| `#F7F8FA`（真实侧栏底） | 4.18:1 ❌ | **5.36:1** ✅ |
| `#f0f0f0` | 3.89:1 ❌ | **5.00:1** ✅ |
| 激活态合成底 `#E1E8F9` | 3.62:1 ❌ | **4.64:1** ✅ |

**取舍（须你定，不由我定）**：`#365FCE` 会让"激活态导航文字"比品牌蓝 `#3F6FEF` 略深一档，
属**可感知的色相/明度变化**（这正是派单卡 §四.2 禁止我在本单动值的原因）。
替代方案：① 改激活态**底色**（把 12% 合成底调深，让 3.62 → ≥4.5）而不动文字色；
② 认下"共享同一非达标色"的现实，维持登记不阻断；③ 另立单由林夕（设计）出值。

## 四、技术债标注（AGENTS.md「绕过 ≠ 修复」铁律）

- **未根治**：本单把 2 个 token 纳入矩阵**输出**（可见、可追溯、带 `::warning`），
  但**未纳入失败判定** ⇒ 今天把 `--text-link` / `--sidebar-text-active` 改成任意坏值，
  本门禁**仍会绿**。这是**已知且明示的覆盖缺口**，不是"已解决"。
- **为何不直接判红**：本单红线是"只扩覆盖面、不得改 token 取值"，纳入失败判定会让门禁**常红**、
  把 main 的 required check（e2e，含本步骤）永久堵死 —— 那是"改值/设计裁定"层级的决定。
- **后续任务号**：**待凌舟编号**（我无编号权）。裁定后由后续单修值并把这 2 个 token
