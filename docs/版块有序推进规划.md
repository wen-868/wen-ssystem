# 智享全链 · 版块有序推进规划

> 制定人：凌舟（总负责人）
> 制定日期：2026-08-06
> 来源：用户明确要求——**小程序建设需系统完善到 100% 后再做；一个版块一个版块地完善，完成一个再进入下一个，有序推进，不做半成品**

---

## 一、原则与定义

1. **一个版块 100% 完成，才进入下一个版块**；禁止跨版块并行铺开。
2. **版块"100% 完成"标准（缺一不可）**：
   - 功能完整：无"敬请期待/开发中"占位，核心流程可走通
   - 无已知 bug：本版块 P0/P1 问题清零
   - 测试覆盖：相关 services/controllers 测试存在且全通过（按项目统一标准推进 100%）
   - UI 一致：符合 R74 设计标准（品牌蓝+灰阶+token 化）
   - 回归通过：`typecheck + build + vitest` 0 错误，浏览器走查无 console 报错
   - 文档同步：API 契约已录入、任务文件状态已更新
3. **每个版块推进闭环**：核查现状 → 差距清单 → 派单修复（按职责）→ 凌舟独立复核 → 标记完成。

## 三、执行方式

1. 每阶段开始前：凌舟核查现状 → 输出差距清单（写入 docs/reports/）
2. 按职责派单（墨=admin-web、阿坚=后端、阿澈=移动端、苏然=QA、林夕=设计），文件信箱协议
3. 每版块完成：凌舟独立复核（git log + grep + 构建 + 走查）→ 标记完成 → 再进下一版块
4. 版块进度在 `docs/tasks/current-tasks.md` 的 R 轮次中持续记录
