# 智能助手轻量版设计规格

## 结论

第 1 阶段只加入“智能助手轻量版”，不加入完整 AI 智能识别开单，也不加入营销中心能力。

本轮目标是增加演示亮点，同时不拖慢 MVP 收尾。智能助手轻量版使用规则计算，不依赖 OCR、语音识别、微信截图识别、营销中心或外部大模型。

## 明确不做

以下内容不进入第 1 阶段：

- 手写单据拍照识别
- 微信聊天记录截图识别
- 语音录入识别
- 95% 识别准确率承诺
- 自动生成正式销售单
- 真实大模型多轮问答

这些能力保留到第 2 阶段，在商品 SKU、客户、数据库、文件上传和支付链路稳定后再做。

## 第 1 阶段做什么

智能助手轻量版包含 3 个能力：

1. 库存问答
   - 用户输入商品关键词，系统返回匹配商品的当前可用库存。
   - 使用现有 `inventory_balance` 和商品 SKU 数据。

2. 毛利润计算
   - 根据商品成本价、销售价、数量计算毛利和毛利率。
   - 支持单商品和简单订单维度。

3. 简单经营建议
   - 基于销售额、待收款、库存预警、热销商品生成规则化建议。
   - 不做复杂预测模型。

以下能力不进入第 1 阶段：

- 营销文案模板
- 朋友圈推广语
- 商品推广素材
- 活动话术
- 客户分群营销建议
- 销售机会预测
- 库存健康度评分

其中营销文案类能力后续放入“营销中心”；销售机会预测和库存健康度评分放入“智能经营助手增强版”。

## 接口设计

新增后端路由建议：

```text
POST /api/admin/assistant/ask
POST /api/store/assistant/ask
```

### ask 请求

```json
{
  "intent": "INVENTORY_QUERY | PROFIT_CALC | BUSINESS_ADVICE",
  "keyword": "五粮液",
  "skuId": 1,
  "qty": 2,
  "unitPrice": 129
}
```

### ask 返回

```json
{
  "answer": "示例白酒 53度 500ml 当前可用库存 120 瓶。",
  "cards": []
}
```

## 前端设计

### 管理后台

新增“智能助手轻量版”卡片，放在首页看板下方。

内容：

- 库存问答
- 毛利润计算
- 经营建议

### 门店端

新增“门店生意助手”卡片，靠近快速收银页。

内容：

- 库存问答
- 毛利润速算
- 简单经营建议

### 小程序

第 1 阶段不新增小程序智能助手页面。小程序只保留后续入口设计空间。

## 数据依赖

优先复用现有表：

- `product_sku`
- `product_spu`
- `product_price`
- `inventory_balance`
- `sale_bill`
- `sale_bill_item`
- `member`

第 1 阶段不新增数据库表。

## 错误处理

- 未匹配到商品：提示用户换关键词。
- 商品缺成本价：返回“成本价未维护，无法计算毛利”。
- 库存数据为空：提示先维护库存。

## 测试策略

新增测试：

- 智能助手规则单元测试
- Mock 模式接口自测
- UI 契约测试补充智能助手入口
- 全链路自测增加库存问答、毛利润计算、经营建议

验收标准：

- 后端单测通过
- 三端构建通过
- `SELF_TEST_PASS`
- `UI_CONTRACT_PASS`
- 智能助手不影响已有开单、库存、收款流程

## 阶段边界

智能助手轻量版是第 1 阶段增强项，不是 AI 识别开单系统，也不是营销中心。

第 2 阶段再设计：

- 销售机会提醒
- 库存健康度评分
- 复购提醒
- 补货建议

第 3 阶段再设计营销中心：

- 营销文案模板
- 朋友圈推广语
- 商品推广素材
- 活动建议
- 客户分群营销

更后期再设计：

- OCR 开单
- 语音开单
- 微信截图识别
- SKU 别名库
- 识别置信度
- 草稿确认页
