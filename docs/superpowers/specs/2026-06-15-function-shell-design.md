# 智享全链管理系统正式可用壳设计

## 背景

线上 `admin.onepan.cn` 和 `store.onepan.cn` 已能打开，后端 API、登录、库存、销售单和收款链路也已通过生产验收。但当前前端把所有模块堆在一个页面里，左侧导航只是静态文字，登录入口弱，操作反馈不明显，用户会感知为“只是个页面，没有功能”。

本设计按已确认的 A 方案执行：在不重写后端业务的前提下，把后台和门店端升级为“正式可用壳”，让每个主要入口都能点击、切换、加载、反馈和验收。

## 目标

1. 未登录时只显示清晰登录页，不再展示一堆 `暂无 / 0 / No Data`。
2. 登录成功后进入工作台，自动加载真实数据，并显示当前账号与退出登录入口。
3. 左侧菜单真实可点击，点击后切换到对应功能模块，active 状态同步变化。
4. 后台端模块可用：工作台、商品、订单、销售单、库存、客户、门店、收款、报表。
5. 门店端模块可用：工作台、快速收银、销售单、接单履约、库存查询、分享收款。
6. 所有关键按钮都有明确反馈：加载中、成功、失败、空数据、未登录。
7. 增加验收脚本，验证 admin 和 store 的登录、导航切换、关键数据加载和主要操作入口。

## 非目标

1. 不重写全部后端业务接口。
2. 不引入复杂权限配置后台。
3. 不做小程序新功能扩展。
4. 不做大型视觉重设计，优先解决功能可用和用户可感知反馈。
5. 不把当前系统拆成完整多文件页面架构，除非实现中发现单文件已无法稳定维护。

## 方案选择

采用 A：正式可用壳。

原因：

1. 改动集中在 `admin-web/src/App.vue`、`store-terminal/src/App.vue` 和少量验收脚本，风险可控。
2. 保留现有 API、数据模型和线上验收基础，不破坏刚上线的后端链路。
3. 能最快解决用户当前真实痛点：页面看起来没有功能、按钮点了像没反应。

不采用 B：最小按钮修复。它只能补提示，仍会把全部模块堆在一页，后续继续完善困难。

不采用 C：完整重构。它更干净，但工期更长，适合作为第二阶段。

## 后台端设计

后台端保留现有数据加载函数和业务弹窗，增加页面状态：

- `activeNav`：当前菜单。
- `isAuthenticated`：是否已登录。
- `pageLoading` 或沿用 `loading`：当前操作加载状态。
- `lastError`：最近一次错误提示。

菜单映射：

- 首页：工作台指标、库存预警、销售趋势、订单状态、门店业绩。
- 商品：商品列表、新增演示商品、上下架、改价。
- 订单：小程序订单搜索、详情、导出 CSV、分页。
- 销售单：销售单列表。
- 库存：库存总览、库存流水、库存预警。
- 客户：客户管理、新增客户、绑定销售员。
- 门店：门店管理、新增门店。
- 收款：分享收款、支付记录、退款记录。
- 报表：近七天销售趋势、订单状态分布、门店业绩。

登录前只渲染登录卡片和产品说明。登录成功后：

- 保存 `admin_token`。
- 自动加载后台所有首屏所需数据。
- 显示成功提示。
- 隐藏登录卡片，进入菜单壳。

退出登录：

- 清理 `admin_token`。
- 清空 token 状态。
- 回到登录页。

## 门店端设计

门店端同样保留现有快速收银和业务函数，增加真实菜单切换。

菜单映射：

- 工作台：销售指标、库存预警、近七日销售趋势。
- 快速收银：商品搜索、客户搜索、购物车、创建销售单、线下收款、挂单。
- 销售单：销售单列表、详情、分享收款。
- 接单履约：小程序订单列表、详情、接单、完成。
- 库存查询：库存查询、库存调整、库存流水。
- 分享收款：分享收款记录、支付记录、退款记录。

登录前只显示门店登录页。默认账号提示使用 `store_operator / admin123`。登录成功后：

- 保存 `store_token`。
- 自动加载门店所需数据。
- 显示当前门店账号和退出登录。

## 错误处理

所有调用后端的用户动作必须有反馈：

- 成功：使用 `ElMessage.success` 明确告知。
- 失败：捕获异常，优先展示后端 `message`，否则显示通用错误。
- 未登录：提示重新登录并返回登录页。
- 空数据：表格保留明确空状态文案，不误导为“未加载”。
- 加载中：按钮保持 loading，避免重复点击。

## 验收标准

本地验收：

1. `npm --workspace admin-web run build` 通过。
2. `npm --workspace store-terminal run build` 通过。
3. `npm run test:ui` 或更新后的 UI 契约测试通过。
4. 新增或更新验收脚本，覆盖以下断言：
   - 后台登录入口存在。
   - 后台登录后，商品、订单、销售单、库存至少一个真实数据区可见。
   - 后台菜单文案和关键按钮存在。
   - 门店登录入口存在。
   - 门店登录后，快速收银、销售单、库存查询等入口存在。
   - 门店端关键按钮存在并不再是静态导航。

线上验收：

1. `https://admin.onepan.cn` 登录后能切换各后台菜单。
2. `https://store.onepan.cn` 登录后能切换各门店菜单。
3. 后台账号 `admin / admin123` 可登录并加载数据。
4. 门店账号 `store_operator / admin123` 可登录并加载数据。
5. 浏览器端点击菜单、刷新、搜索、详情、新增、收款等入口均有响应或明确提示。

## 风险和控制

风险：当前 `App.vue` 文件较大，直接修改可能引入模板错误。

控制：

- 优先做状态和模板分区，不动后端 API。
- 每次改完先跑对应 workspace build。
- 不删除已有业务函数，只改变显示和入口组织。

风险：线上服务器目录不是 git 仓库，部署时不能依赖 `git pull`。

控制：

- 本地提交后再同步到服务器。
- 使用现有 `SKIP_GIT_PULL=true` 部署方式。
- 部署后必须跑生产验收。
