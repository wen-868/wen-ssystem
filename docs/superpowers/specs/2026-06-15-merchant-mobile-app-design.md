# 商家移动端 App 主应用与线上线下一体化履约闭环设计

## 背景

智享营销系统不再按“单店自用工具”理解，而是定位为品牌方对外销售的 SaaS 产品，订阅卖给线下批发和零售商家。商家使用这套系统管理自己的商品、价格、库存、客户、订单、收款、应收和报表，品牌方提供系统能力，不参与商家的经营数据。

这套产品的核心差异不是“有 PC 后台”或“有小程序商城”，而是打通线上线下一体化运营。线下开单、收银、库存、客户和线上小程序下单、支付、确认收货，必须进入同一套订单、库存、客户、收款和报表体系。

上一阶段已经上线 PC 管理后台、门店端 Web/PWA、小程序分享收款等基础能力。下一阶段需要正式启动商家移动端 App 主应用，并围绕批发/零售双场景补齐线上线下一体化订单履约闭环。

## 产品定位

一句话定位：

> 手机经营，PC 管理，小程序接客。

三端分工如下：

| 终端 | 定位 | 使用者 | 核心职责 |
|---|---|---|---|
| PC 端 | 大脑 | 商家老板、财务、管理员 | 商品资料、价格、员工、权限、仓库、支付、财务规则、复杂报表、批量管理 |
| 手机端 App | 高频经营主应用 | 老板、业务员、收银员、库管、配送员 | 看经营、开单、收银、收款、客户、库存、配送、应收、轻配置 |
| 小程序 | 客户入口 | 商家的批发客户和零售客户 | 零售下单、批发订货、在线支付、订单查询、确认收货 |

手机端不拆老板版、员工版或库管版，只做一个完整 App。用户登录后，系统按角色权限和数据范围展示可见菜单、按钮和数据。

## 目标

1. 新建商家移动端 App 主应用，作为商家日常经营的最高频终端。
2. 手机端 v1 覆盖经营动作和轻配置，不做 PC 功能的简单缩小版。
3. 小程序同时支持批发生意和零售生意：绑定批发客户只能看批发价，其他客户看零售价。
4. 批发客户在小程序提交订货单后，直接进入商家配送流程，不再需要商家确认。
5. 批发订单按可售库存进行部分占用，配送完成后正式扣减实际库存。
6. 支持批发客户按客户配置结算方式：现结或账期。
7. 账期客户完成配送后生成应收账款，进入手机端和 PC 端的收款/对账体系。
8. 一客一价不做固定客户价目表，只在开单时自动带出该客户该商品的上次成交价作为参考。

## 非目标

1. 不做多个手机端 App，不拆老板版、员工版、库管版。
2. 不把 PC 端所有复杂配置完整搬到手机端。
3. 不做客户专属固定价目表，因为批发价格随行情变化。
4. 不在批发小程序订单里加入“商家确认”步骤。
5. 不做复杂授信额度、逾期利息、账期天数自动风控，第一版只保留现结/账期结算方式。
6. 不在第一版实现复杂部分发货、拆单、多批次配送的完整财务核算，只保留可扩展状态和数量字段。

## 已确认业务规则

### 商家与租户

系统是品牌方 SaaS。每个商家是独立租户，商家自己维护商品、价格、库存、客户、员工和经营报表。不同商家的数据必须严格隔离。

### 手机端 App

手机端只做一个完整应用，不按角色拆版本。老板、业务员、收银员、库管、配送员使用同一个 App，但只看到自己权限范围内的功能和数据。

手机端 v1 选择“经营动作 + 轻配置”：

| 类型 | 手机端 v1 范围 |
|---|---|
| 经营动作 | 看经营、开单、收银、收款、查库存、查客户、订单处理、配送、应收、报表 |
| 轻配置 | 新增商品、拍照建档、新增客户、调价、调库存 |
| 复杂配置 | 角色权限、支付参数、仓库规则、税率规则、复杂财务规则留在 PC |

### 小程序客户身份

小程序既做批发生意，也做零售生意。同一个手机号在同一个商家下只能有一个身份。

| 客户身份 | 价格规则 | 下单规则 |
|---|---|---|
| 批发客户 | 只能看批发价，不能切换零售价 | 提交订货单后直接进入商家配送流程 |
| 零售客户 | 看零售价 | 直接在线下单并支付 |
| 未绑定客户 | 默认按零售客户处理 | 看零售价，走零售流程 |

批发客户由商家在客户档案中绑定。绑定后，该客户在该商家的小程序内只展示批发价。

### 一客一价

不做客户专属固定价目表。批发价格随行情变化，提前设定客户固定价会误导开单。

开单时选择客户和商品后，系统自动带出该客户该商品的上次成交价：

| 信息 | 用途 |
|---|---|
| 当前批发价 | 本次报价基础 |
| 上次成交价 | 业务员判断本次供货价的主要参考 |
| 上次成交日期 | 判断价格是否仍有参考价值 |
| 历史最高/最低成交价 | 辅助识别异常报价 |
| 本次成交价 | 允许业务员手动填写 |

如果没有历史成交价，则默认使用当前批发价。

## 手机端 v1 模块

| 模块 | 功能范围 |
|---|---|
| 首页 | 今日销售、今日收款、待配送、待收款、库存预警、快捷入口 |
| 开单 | 选择客户、选择商品、自动带出上次成交价、手动改价、生成销售单 |
| 收银/收款 | 现金、转账、扫码、在线收款链接、现结/账期 |
| 订单 | 线下销售单、小程序零售订单、小程序批发订货单统一查看 |
| 配送 | 待配送、配送中、已完成、拒收、取消；商家员工或客户都可确认完成 |
| 库存 | 实际库存、占用库存、可售库存、库存调整、库存流水 |
| 客户 | 新增客户、批发/零售身份、结算方式、历史成交价、欠款情况 |
| 应收 | 账期客户收货后生成应收，支持收款、结清、欠款统计 |
| 报表 | 日/周/月销售、收款、欠款、库存预警、热销商品 |
| 轻配置 | 新增商品、拍照建档、调价、调库存、新增客户 |

## 批发与零售订单流程

### 零售订单

零售客户在小程序按零售价直接下单并在线支付。订单进入待配送或待自提流程。配送完成或自提完成后，正式扣减库存并完成订单。

### 批发订单

批发客户在小程序按批发价提交订货单。订货单不需要商家确认，提交成功后直接进入商家配送流程。

批发订单流程：

1. 批发客户提交订货单。
2. 系统根据当前可售库存占用库存。
3. 可售库存不足时，只占用当前可售数量，剩余数量保留为未占用数量。
4. 订单进入待配送。
5. 商家可延迟配送，也可私下与客户沟通数量、时间或替代方案。
6. 商家员工在手机端开始配送，订单进入配送中。
7. 商家员工或客户任意一方确认完成后，系统正式扣减实际库存，并释放对应占用库存。
8. 如果客户拒收或商家取消订单，系统释放已占用库存，不扣减实际库存。

## 库存模型

库存分三种口径：

| 口径 | 含义 |
|---|---|
| 实际库存 | 仓库/门店真实库存 |
| 占用库存 | 已被订单占用但尚未完成扣减的库存 |
| 可售库存 | 实际库存 - 占用库存 |

批发订单提交时，如果订货数量大于可售库存，只占用当前可售库存。

示例：批发客户订 100 箱，当前可售库存 30 箱。

| 项目 | 数量 |
|---|---:|
| 订单数量 | 100 箱 |
| 已占用库存 | 30 箱 |
| 未占用数量 | 70 箱 |

商家可以先配送 30 箱，也可以等补货后再统一配送，或私下沟通修改订单。第一版界面必须让商家看到订单数量、已占用数量和未占用数量，避免误以为全部有货。

## 配送与扣库存

配送完成才能正式扣减实际库存。确认完成的来源可以是商家员工，也可以是客户。

| 操作 | 操作端 | 结果 |
|---|---|---|
| 开始配送 | 手机端 App | 订单进入配送中，占用库存保持 |
| 确认完成 | 手机端 App 或小程序 | 扣减实际库存，释放占用库存，订单完成 |
| 客户拒收 | 小程序或手机端 App 代记录 | 释放占用库存，不扣实际库存，订单进入拒收 |
| 商家取消 | 手机端 App 或 PC | 释放占用库存，不扣实际库存，订单取消 |

系统必须记录确认人、确认端、确认时间和操作备注，便于后续对账和追责。

## 收款与应收

批发客户按客户档案配置结算方式。

| 客户类型 | 结算方式 | 财务处理 |
|---|---|---|
| 零售客户 | 在线支付 | 支付后进入履约，完成后归入销售和收款报表 |
| 批发客户：现结 | 先款后货或配送前收款 | 支付/收款后配送，完成后归入销售和收款报表 |
| 批发客户：账期 | 先货后款 | 配送完成后生成应收账款 |

第一版应收只做基础台账：客户、订单、应收金额、已收金额、未收金额、状态、最近收款时间。复杂授信额度、账期天数、逾期利息后续再做。

## 权限模型

手机端按权限展示功能，不按角色拆 App。后端需要支持角色、权限点和数据范围。

第一版最少需要以下权限点：

| 权限点 | 控制范围 |
|---|---|
| dashboard.view | 查看首页经营数据 |
| sale.create | 手机端开单 |
| sale.change_price | 开单时改价 |
| order.view | 查看订单 |
| order.deliver | 操作配送 |
| order.complete | 确认完成 |
| order.cancel | 取消订单 |
| inventory.view | 查看库存 |
| inventory.adjust | 调库存 |
| customer.view | 查看客户 |
| customer.create | 新增客户 |
| customer.edit_type | 标记批发/零售身份和结算方式 |
| receivable.view | 查看应收 |
| receivable.collect | 登记收款 |
| product.create | 新增商品 |
| report.view | 查看报表 |

数据范围至少支持：全部门店、指定门店、本人客户、本人订单。

## 后端改造范围

下一阶段后端需要补齐以下能力：

1. 租户隔离：所有核心表都应具备商家/租户维度。
2. 客户身份：客户支持批发/零售身份、结算方式、绑定手机号。
3. 价格参考：开单接口返回客户上次成交价、成交日期、历史高低价。
4. 订单统一：线下销售单、小程序零售订单、小程序批发订货单进入统一订单中心。
5. 库存占用：新增或扩展库存占用记录，支持实际库存、占用库存、可售库存。
6. 配送履约：支持待配送、配送中、完成、拒收、取消状态和操作日志。
7. 应收账款：账期客户完成配送后生成应收记录。
8. 权限控制：手机端菜单、按钮和数据范围由后端权限返回。

## 第一版交付边界

必须完成：

1. 商家移动端 App 主应用基础工程。
2. 登录、权限菜单、首页经营看板。
3. 手机端开单和上次成交价自动带出。
4. 批发客户小程序订货单直接进入配送流程。
5. 库存实际/占用/可售三口径。
6. 可售库存不足时只占用当前可售库存。
7. 配送中、完成、拒收、取消流程。
8. 商家员工或客户均可确认完成。
9. 账期客户完成配送后生成应收。
10. 手机端客户、库存、订单、配送、应收、报表核心页面。

暂缓：

1. 客户专属固定价目表。
2. 复杂账期、授信额度、逾期利息。
3. 多批次拆单、复杂部分发货核算。
4. 蓝牙打印、扫码枪、推送等原生增强能力。
5. 多 App 拆分。

## 验收标准

1. 商家员工登录手机端后，只能看到自己权限内的菜单、按钮和数据。
2. 批发客户在小程序只能看到批发价，零售客户只能看到零售价。
3. 同一手机号在同一商家下只能有一个客户身份。
4. 手机端开单选择客户和商品后，可以看到该客户该商品的上次成交价。
5. 批发客户小程序提交订货单后，订单直接出现在商家手机端待配送列表。
6. 订单数量大于可售库存时，系统只占用当前可售数量，并显示未占用数量。
7. 配送完成前不扣减实际库存。
8. 商家员工或客户确认完成后，系统正式扣减实际库存，并释放占用库存。
9. 拒收或取消订单时，系统释放占用库存，不扣实际库存。
10. 账期客户配送完成后，系统生成应收账款，并能在手机端查看和登记收款。

## 设计自检

1. 本设计未包含客户专属固定价目表，符合“行情天天变化，不能设定价格”的业务规则。
2. 批发订单没有“待确认”状态，符合“提交订货单后直接进入配送流程”的业务规则。
3. 库存不足时采用部分占用，符合“商家可延迟配送或私下沟通”的业务规则。
4. 手机端只做一个 App，所有角色通过权限控制，不拆多版本。
5. 第一版边界聚焦移动端主应用和履约闭环，没有把 PC 复杂配置全部搬到手机端。
