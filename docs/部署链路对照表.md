## 一、为什么要这张表

已连续两次因"副本分叉"改错地方：

- **踩坑 [47]**：本机存在 4 个 `wen-ssystem` 副本，其中会话默认目录那份是旧副本（缺 `views/ops/*`）。
- **2026-09-16 S3-35**：ai-base 的 listen 安全收敛改动误落在 `wen-ssystem/backend/ai-base`
  （提交 `828ea48f`，无 `.git` 的非部署副本），对生产完全无效，
  不得不在权威仓库 ZXQL-AI 重做（`8884b8c`）。
- **同日（二期）**：该副本目录已**物理删除**（源码归档到仓库外）。删除时发现它还被
  `.github/workflows/ci.yml` 的 `ai-base` job 守护 —— **一个测不部署代码的假门禁**，
  已一并移除；由此暴露的真实缺口是：**AI 底座至今零 CI 门禁**。

**判定原则**：一个服务"部署自哪个仓库"由**生产检出目录的 origin** 决定，
不看代码长得像不像、也不看它在哪个仓库里有个同名目录。

## 四、动手前的三步自检

1. **这一步要改的服务，权威仓库是哪个？** 查本表第二节；本表没有就先查生产 `git remote -v` 再动手。
2. **本地打开的路径，其 `git remote -v` 是否指向该权威仓库？** 不是就换目录。
3. **该目录有没有 `.git`？** 没有 = 副本，改了不生效（ai-base 就是这个坑）。
