## 一、设计稿理解（16 板块核心设计意图）

| # | 板块 | 核心设计意图 |
| --- | --- | --- |
| 01 | 运营大盘 | 平台首屏驾驶舱：6 项核心指标卡（租户总数/今日新增/有效租户/本月收入/平台订单总量/大模型消耗）+ 租户增长趋势 + 套餐分布 + 收入构成 + 右侧常驻「待办事项」「系统健康」+ v1.5 新增底部「报表导出」卡（租户财务报表 / 资源消耗报表）。指标只聚合不下钻，页脚固定口径声明 |

| 04 | 租户账单计费 | 「能收费、能对账、能催缴」资金闭环：账单总览 3 指标 + 4 Tab（账单流水 / 欠费管理 / 对账中心 / 增值扣费 v1.5）；日对账差异 <0.1% 告警 |

| 09 | 模板中心 | 一键开店支撑层：初始化模板（编号规则/单位换算/打印模板/默认仓库账户）**值复制**给租户（不回写）；公共打印模板可供全租户选用；导入模板 4 + 导出模板 3；开户一键套用；含版本记录 |

| 14 | 开放平台 | 生态能力：租户 API 密钥治理（签发/轮换/吊销，Secret 仅签发时可见，计入套餐额度）+ Webhook 事件订阅（HMAC-SHA256 签名、时间戳 ±5 分钟防重放、失败重试 1/5/30 分钟退避、连续失败自动暂停） |
| 15 | 登录页 | 分栏式：左侧品牌区（logo + slogan + 网格插画）+ 右侧表单（账号密码 + 图形验证码，预留短信登录/2FA）；5 次失败锁 15 分钟、空闲 30 分钟登出 |
| 16 | 代理商管理（v1.3 新增） | 渠道伙伴现金分佣：①代理商配置（列表/开通表单/授权区域/层级权益）②代理商分润（比例矩阵/模式开关/台账/结算/冲回）；分润比例平台手动配置、未配全则整体不生效；分润基数 = 订单实收现金（积分抵扣与平台券不计入） |

## 二、现有能力底盘

### 2.1 平台侧后端路由（16 个，`platform-*.routes.ts`）

`app-version`（版本）、`applications`（租户注册审核）、`auth`（平台认证）、`config`（平台配置）、`dashboard`（大盘）、`error-log`、`library`（商品库）、`miniapp`（小程序配置）、`monitor`（系统监控）、`msg-config`（短信/邮件）、`plans`（套餐）、`reconciliation`（结算）、`review`（评价）、`subscription-applies`（订阅申请）、`tenant`（租户）、`platform`（综合）

控制器（`backend/src/controllers/platform/`，共 13 个）：`app-version`、`dashboard`、`error-log`、`library`、`msg-config`、`platform-auth`、`platform-manage`、`platform-monitor`、`platform-reconciliation`、`platform-subscription-apply`、`platform`、`tenant-usage`、`tenant`；统一前缀 `/api/platform/*`。

**AI 相关能力位置**：saas-admin 的 AI 配置页面（模型/用量/计费套餐/认知层）通过 `VITE_AI_BASE_URL` 直连独立服务 **ai-base（3016）**，接口为 `/api/admin/ai-config/*`；ai-base 现有 brain/gateway/providers/tools 等模块，**不含模型单价计量与积分抵扣**。

**缺口细分（后端零支撑项）**：欠费策略（宽限期/降级/冻结分级）、增值扣费（超额 API/存储/AI 出账）、营销渠道与老带新、平台 RBAC、模板中心、工单、开放平台 Webhook、代理商分润、AI 积分抵扣与模型单价管理。

### 2.2 总后台页面（32 个）

平台看板、租户管理（列表/详情/新增）、注册审核（列表/详情）、套餐管理（列表/表单）、订阅管理（列表/详情）、订阅申请、财务结算、租户使用统计、平台公告、平台评价、平台配置、消息配置、系统监控、操作日志、错误日志、版本发布、AI 配置 5 页（平台默认/租户配置/用量统计/计费套餐/认知层）、商品库 5 页（SPU/品牌/审核/导入/API 密钥）、移动端预览、登录/注册页

### 2.3 数据表基础

已有：`t_platform_announcement`（平台公告）、`t_print_template`（打印模板）、`t_sms_template`（短信模板）、`t_tenant`、`t_tenant_register_application`、`t_subscription*`、`t_reconciliation*`、`t_app_version`、平台配置与 AI 配置表

确认缺失：代理商、工单、初始化模板、推广码/邀请台账、Webhook 订阅、平台侧角色权限 均无对应表

## 六、实施建议与风险

### 6.1 建议

1. **先对齐、后新建**：P0 全部是对现有板块的升级（改动局限在前端版式 + 少量接口字段），能最快让总后台「看起来像设计稿」，同时风险最低。
2. **共用组件沉淀**：指标卡、状态标签、Tab 面板、详情抽屉、SLA 倒计时条在 4 个以上板块复用，建议抽成共享组件（`StatCard` / `StatusTag` / `DetailDrawer` / `SlaBar`）。
3. **后端按域分批**：每期结束跑全量测试 + 平台侧接口冒烟，避免一次性大改导致的回归面。
4. **与现有功能衔接**：注册审核、订阅、评价、商品库保留；导航按「运营 / 租户 / 计费 / 服务 / 生态 / 系统」六组重排，把设计稿板块与现有功能并入统一分组。

### 6.2 风险

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 分润/结算金额口径 | 代理商分润基数=订单实收现金，需与现有结算、积分抵扣逻辑严格对齐 | 先做口径评审，落库前用真实账单跑对账样例 |
| 模拟登录安全 | 平台代登录租户涉及数据越权 | 走审批 + 限时会话 + 全量留痕 + 独立审计 Tab |
| 开放平台鉴权 | 密钥/Webhook 涉及外部调用与重放风险 | Secret 一次性展示、HMAC-SHA256 + 时间戳校验、限流与自动暂停 |
| 灰度发布耦合 | 版本灰度需客户端配合版本检查接口 | 复用现有 `t_app_version` 与启动检查链路，先小范围试点 |
| 设计稿数据为样例 | 指标口径、状态色、SLA 时间需与业务确认 | 每期开始前与需求方确认口径清单，写入口径声明 |

### 10.2 执行硬约束（来自规划，任何批次不得违反）

1. **"三不"边界**：不改租户业务数据（唯一可写的是租户元数据：状态/配额/套餐开关）、不看业务明细（大盘只聚合不下钻）、不干预商户内部权限（冻结/注销作用于整租户空间，不篡改其角色配置）。落地方式=权限配置 + 接口层拦截 + 流程规则三道硬约束。
2. **两条合法例外通道**：① 租户主动授权（限定范围+时限）；② 平台代登录（申请→审批→限时会话 30 分钟→全程留痕→可回放，日志留存 ≥180 天，月度抽检 ≥10%）。
3. **数据隔离五条铁律**：存储行级 tenant_id、访问强制租户上下文（总后台账号不在业务接口白名单）、展示只给聚合值、导出分级管控（元数据可导；业务数据需授权/工单依据 + 双人审批 + 水印加密）、总控库与业务库分离。
4. **敏感操作二次确认清单**：租户注销/数据重置（输入租户全名+短信验证码+双人复核）；套餐价格与矩阵变更（密码二次输入+新旧快照，仅财务与超管）；配额临时扩容 >30 天（审批+到期回收）；AI/支付/短信密钥变更（密码+验证码双因子）；批量公告 >50% 租户（预览+二次点击+10 分钟可撤回）；API 密钥吊销（审批+提前 7 天通知租户）。
5. **账号与会话策略**：密码 ≥8 位含三类字符、不得与最近 3 次重复；首次登录强制改密；连续 5 次失败锁定 15 分钟并通知超管；空闲 30 分钟自动登出。
6. **非功能目标**：首屏 P95 <2s、列表查询 P95 <1s；大盘常规指标 T+1、当日收入/新增付费租户 5 分钟级；平台可用性 99.9%；配额 100% 硬拦截（误拦截 <0.1%）；账单与流水差异 <0.1% 且日对账自动校验；P0 告警 5 分钟内触达值班人；备份 RPO ≤15 分钟、RTO ≤1 小时，每日备份留 30 天、月末留 12 个月、年度 3 年。
