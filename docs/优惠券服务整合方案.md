# 优惠券服务整合方案（验收检查项：重复代码率）

> 更新：2026-08-15 ｜ 目标：消除 marketing-coupon.service 与 marketing-new-coupon.service 两套并存，降低重复率

## 一、现状审计

| 服务 | 对应控制器/路由 | 使用方 | 表结构 |
|---|---|---|---|
| `marketing-coupon.service`（旧） | marketing-coupon.controller | admin 优惠券模板 CRUD + **门店优惠券列表/详情（store/coupon.controller，核销入口依赖）** | t_coupon_template（total_count/claimed_count/used_count 列） |
| `marketing-new-coupon.service`（新） | marketing-new.controller | admin 新优惠券模板 CRUD + 发行/用户券 | t_coupon_template（total_quantity/issued_quantity/used_quantity 列） |

**核心问题**：两套服务操作同一张 `t_coupon_template` 表但使用**不同列命名**（旧：total_count/claimed_count；新：total_quantity/issued_quantity）。真实库表以 035 迁移为准（total_quantity/issued_quantity/used_quantity），**旧服务的查询存在列名不匹配风险**，且与新服务字段冲突。

## 二、整合目标

以 `marketing-new-coupon.service` 为唯一实现（列名与真实表一致），旧服务废弃。

## 三、整合步骤（建议分批执行）

1. **迁移适配**：门店核销入口（store/coupon.controller → listCouponTemplates/getCouponTemplate）改指向 marketing-new-coupon.service（字段已对齐，前端已按新字段解析）
2. **路由收敛**：admin 优惠券模板路由统一到 marketing-new.controller，旧 marketing-coupon.controller 路由下线（保留 1 个发布周期灰度）
3. **发行/核销对齐**：核销服务（coupon-verify.service）已用新表列 used_quantity，确认与 new 服务一致
4. **清理**：旧服务文件删除 + 依赖引用清理 + 测试替换
5. **验收**：优惠券全链路回归（模板 CRUD/发行/门店列表/核销/统计）

## 四、风险控制

- 分批执行：先切引用（步骤 1-2）→ 观察 1 个发布周期 → 再删代码（步骤 4）
- 涉及支付/核销敏感链路，每步有独立提交 + 全量测试 + 门店核销 E2E 冒烟
- 旧列（total_count 等）若已无代码引用，可后续迁移清理

## 五、预期收益

- 消除 2 套 400+ 行重复服务 → 降低重复代码率
- 消除列名双轨（total_count vs total_quantity）带来的隐性不一致风险
