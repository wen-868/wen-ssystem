## 1. 测试概述

### 1.1 测试目标

验证 Phase 2 新增模块的功能正确性，确保：
- 供应商管理（CRUD、编码生成、联系人管理）
- 采购订单（创建、审核、取消、金额计算）

## 2. 测试策略

### 2.1 测试层级

```
┌─────────────────────────────────┐
│  E2E 集成测试（S104）            │  ← 全流程串联
├─────────────────────────────────┤
│  接口自动化测试（S102）          │  ← 单接口 + 业务逻辑
├─────────────────────────────────┤
│  单元测试                        │  ← 金额计算、状态机
└─────────────────────────────────┘
```

### 2.2 测试方法

1. **接口自动化测试**：使用 Jest + Supertest 对所有 API 接口进行自动化测试
2. **功能手动测试**：对前端页面进行手工功能验证
3. **边界值测试**：针对金额、数量等关键字段进行边界值验证
4. **状态流转测试**：验证各单据状态转换的正确性
5. **并发测试**：模拟同时审核、同时收款等并发场景

### 2.3 测试类型

| 类型 | 说明 | 工具 |
|------|------|------|
| 接口测试 | REST API 功能验证 | Vitest + Supertest |
| 金额精度测试 | 边界值 + 浮点误差 | Vitest + toBeCloseTo |
| 状态流转测试 | 单据状态转换路径 | Vitest |
| 并发测试 | 同时审核/同时收款 | 手动 + 脚本 |
| 前端功能测试 | 页面交互 + 数据展示 | 浏览器手动 |

### 2.4 测试覆盖原则

- **正常流程**: 100% 覆盖
- **异常流程**: 至少覆盖参数错误、权限不足、数据不存在等场景
- **边界值**: 覆盖最小/最大值、空值、异常值

### 2.5 测试数据管理

- 每个测试用例独立，不依赖其他测试数据
- 使用 `beforeEach` 重置 Mock DB
- 测试数据在 `afterEach` 清理

### 2.6 测试环境配置

- 后端：Node.js + Express + mock-db
- 测试框架：Vitest
- 数据库：内存模拟（mock-db）
- 认证：JWT Bearer Token

## 5. 测试规范

### 5.1 接口测试规范

- 每个测试文件独立，使用 `resetMockDb()` 隔离数据
- 测试命名：`模块 - 场景 - 预期结果`
- 金额断言使用 `toBeCloseTo(2)` 避免浮点误差
- 状态断言使用精确匹配

### 5.2 测试命名规范

```
{模块名}.test.ts - 测试文件
{功能}_正常流程
{功能}_异常_参数错误
{功能}_边界值_xxx
```

### 5.3 金额精度规范

- 所有金额单位为元，精确到分（2 位小数）
- 比较时使用 `Math.abs(actual - expected) < 0.001` 或 `toBeCloseTo(2)`
- 边界值：0.01 元、99999999.99 元、负数
- 使用 `toBeCloseTo` 或精确比较（乘以 100 转为整数），避免浮点误差

### 5.4 状态流转规范

```
采购订单：DRAFT → PENDING → APPROVED → PARTIAL → COMPLETED
                                    ↘ CANCELLED
采购入库：PENDING → COMPLETED
                  ↘ VOIDED
采购退货：PENDING → COMPLETED
                  ↘ VOIDED
销售退货：PENDING → COMPLETED
                  ↘ VOIDED
客户对账：DRAFT → CONFIRMED → PAID
```

## 6. 风险评估

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 金额计算精度问题 | 财务数据错误 | 使用 BigDecimal 或整数运算，测试覆盖边界值，统一使用 DECIMAL(12,2) |
| 并发操作数据不一致 | 库存/金额错误/超卖/重复审核 | 使用数据库事务，测试并发场景，增加并发测试用例 |
| 状态流转异常 | 业务流程中断 | 全面测试状态转换路径 |
| 接口返回格式不一致 | 前端解析错误 | 严格按照 OpenAPI 规范验证响应结构 |
| 接口变更频繁 | 测试用例需同步修改 | 与阿坚保持沟通，及时更新 |
| mock-db 与真实 DB 差异 | 测试通过但生产报错 | S104 增加集成环境验证 |
