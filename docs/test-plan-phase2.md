## 1. 测试概述

### 1.1 测试目标

验证 Phase 2 新增业务模块的功能正确性、数据一致性和金额精度，确保：
- 供应商管理 CRUD 及联系人功能正常
- 采购全流程（订单→入库→退货→付款）状态流转正确
- 销售退货流程（创建→审核→退款）库存回滚正确
- 客户对账/收款金额计算准确
- 库存预警阈值触发正确

### 1.2 测试范围

| 模块 | 接口数 | 优先级 |
|------|--------|--------|
| 供应商管理 | 4 | P0 |
| 采购订单 | 5 | P0 |
| 采购入库 | 5 | P0 |
| 采购退货 | 4 | P0 |
| 采购付款 | 3 | P1 |
| 销售退货 | 5 | P0 |

| 客户收款 | 3 | P1 |

### 1.3 不在范围内

- 小程序前端 UI 交互（S106 覆盖）
- 性能/压力测试（后续专项）
- 安全渗透测试（后续专项）

## 2. 测试策略

### 2.1 测试层级

```
┌─────────────────────────────────┐
│  E2E 集成测试（S104）            │  ← 全流程串联
├─────────────────────────────────┤
│  接口自动化测试（S102）          │  ← 单接口 + 业务逻辑
├─────────────────────────────────┤
│  单元测试                        │  ← 金额计算、状态机
└─────────────────────────────────┘
```

### 2.2 测试类型

| 类型 | 说明 | 工具 |
|------|------|------|
| 接口测试 | REST API 功能验证 | Vitest + Supertest |
| 金额精度测试 | 边界值 + 浮点误差 | Vitest + toBeCloseTo |
| 状态流转测试 | 单据状态转换路径 | Vitest |
| 并发测试 | 同时审核/同时收款 | 手动 + 脚本 |
| 前端功能测试 | 页面交互 + 数据展示 | 浏览器手动 |

### 2.3 测试环境

- 后端：Node.js + Express + mock-db
- 测试框架：Vitest
- 数据库：内存模拟（mock-db）
- 认证：JWT Bearer Token

## 5. 测试规范

### 5.1 接口测试规范

- 每个测试文件独立，使用 `resetMockDb()` 隔离数据
- 测试命名：`模块 - 场景 - 预期结果`
- 金额断言使用 `toBeCloseTo(2)` 避免浮点误差
- 状态断言使用精确匹配

### 5.2 金额精度规范

- 所有金额单位为元，精确到分（2 位小数）
- 比较时使用 `Math.abs(actual - expected) < 0.001`
- 边界值：0.01 元、99999999.99 元、负数

### 5.3 状态流转规范

```
采购订单：DRAFT → PENDING → APPROVED → PARTIAL → COMPLETED
                                    ↘ CANCELLED
采购入库：PENDING → COMPLETED
                  ↘ VOIDED
采购退货：PENDING → COMPLETED
                  ↘ VOIDED
销售退货：PENDING → COMPLETED
                  ↘ VOIDED
客户对账：DRAFT → CONFIRMED → PAID
```

## 6. 风险评估

| 风险 | 影响 | 应对 |
|------|------|------|
| 接口变更频繁 | 测试用例需同步修改 | 与阿坚保持沟通，及时更新 |
| mock-db 与真实 DB 差异 | 测试通过但生产报错 | S104 增加集成环境验证 |
| 金额浮点精度 | 对账不平 | 统一使用 DECIMAL(12,2) |
| 并发操作 | 超卖/重复审核 | 增加并发测试用例 |
