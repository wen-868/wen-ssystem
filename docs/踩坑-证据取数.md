# 踩坑 · 证据取数（凌舟维护，2026-10-19 立）

> 适用：任何"用命令输出当验收证据"的场合。**这些坑的共同点是：命令跑成功了，但读数不是真的。**

## P1 · Git Bash 会把以 `/` 开头的 `rg` 参数当 MSYS 路径转换 ⇒ **假 0 命中**

- 现象：`rg -n "/platform/applications" app-mobile/src` 在 Git Bash 下返回 **0 命中**，但同样的串确实存在（`rg` 报"没有匹配"而不是报错）；
- 根因：MSYS 把 `/platform/applications` 当成**绝对路径**做了转换（`C:/Program Files/Git/platform/applications`），于是实际检索的是一个不存在的路径；
- 正确姿势（三选一）：
  1. `MSYS2_ARG_CONV_EXCL='*' rg -n "/platform/applications" app-mobile/src`
  2. 用 `--` 明确分隔：`rg -n -- "/platform/applications" app-mobile/src`
  3. 改用 PowerShell / `node` 读文件判断（本仓多数门禁脚本已如此）；
- **采信规则**：凡"0 命中"类证据，必须写明**是否已排除 MSYS 转换**；未写明的，**不采信**（按"证据不足"处理）。

## P2 · 过期基线假象：`origin/main..HEAD` 会把主仓新提交算成"你删了东西"

- 现象：分支基于旧 main，`git diff --name-only origin/main HEAD` 显示一堆"删除"（其实是 main 后来加的）；
- 正确姿势：**一律用 `git merge-base origin/main HEAD`**：
  ```bash
  mb=$(git merge-base origin/main HEAD); git diff --name-only "$mb..HEAD"
  ```

## P3 · 零字节证据 ≠ 没跑

- `tsc --noEmit` 成功时**没有输出**；`> file` 得到 0 字节文件；
- 规则：零字节证据必须配 `<同名>.note.txt`，写明**命令、退出码、为何零输出**，否则无法与"命令没跑"区分（校验器已按此判红）。

## P4 · 冲突标记残留

- rebase/merge 后**先** `rg "<<<<<<<|>>>>>>>|=======" <改动文件>` 再 `git add`；带标记提交后表现为"测试 no tests"（文件语法坏）而不是明确报错。

## P5 · 同一 P0 被两条线并行各做一遍

- 跨仓（如 `ZXQL-AI`）派单前必须先问"对方是否已在做"；否则出现两份实现、工作树冲突、结论口径分裂（AI-TOOLS-REG 已发生一次）。

## P6 · autocrlf 下 Git blob SHA 与工作树 SHA 不可直接混比

- `git show <rev>:<path> | sha256sum` 计算的是仓库内 **LF blob**；`sha256sum <工作树文件>` 在 Windows autocrlf 下通常是 **CRLF 文件**，同一内容也会得到不同哈希。
- 证据必须标注哈希形态：`git-blob-lf` / `worktree-crlf` / `normalized-both-lf`。
- 只有同形态哈希可直接判等；跨形态比较前必须统一换行后再计算。

## P7 · 反测注入器未执行时，"期望红却绿"不是断言失效

- 反测必须同时记录 `INJECT_EXIT=0`、注入后目标片段回读、反测退出码和复原 SHA。
- 参数带值必须与脚本接口完全一致；例如脚本只接 `--case date`，写成 `--case=date` 可能被拒绝并返回非 0。
- 注入器非 0 ⇒ 测试未发生，本次结果作废，不得解释为门禁失效或通过。
