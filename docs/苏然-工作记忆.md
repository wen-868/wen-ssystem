## v7.0 监控告警功能测试报告（2026-07-04）

**背景**：用户告知"自动收集错误信息已开发好"，对应任务是阿澈的 Phase 18-C 监控告警。

### 发现的 5 个严重问题

| # | 问题 | 严重度 | 详情 |
|---|------|:---:|------|
| 1 | **后端路由未注册** | P0 | `server.ts` 没有 `app.use("/api/admin/monitor", ...)`，4 个 API 全部 404 |
| 2 | **缺少 monitor.routes.ts** | P0 | 只有 `monitor.service.ts`，没有对应的路由文件 |
| 3 | **前端路由未注册** | P0 | `saas-admin/src/router/index.ts` 没有 MonitorView 的路由，页面无法访问 |
| 4 | **侧边栏无入口** | P1 | `MainLayout.vue` 没有监控告警菜单项 |
| 5 | **API 统计是假数据** | P1 | `getApiStats()` 用 `Math.random()` 生成 QPS/响应时间/错误率，不是真实收集 |

### 测试结果（4 个 API 全部 404）

```
GET  /api/admin/monitor/db-status         → 404 Cannot GET
GET  /api/admin/monitor/api-stats         → 404 Cannot GET
GET  /api/admin/monitor/expiring-tenants  → 404 Cannot GET
POST /api/admin/monitor/notify-expiring   → 404 Cannot POST
```

### service 层问题分析

- `getDbStatus()` — 查询真实数据库状态 ✅（但路由未挂载，无法调用）
- `getApiStats()` — **返回随机数**，不是真实错误收集 ❌
- `getExpiringTenants()` — 查询真实到期租户 ✅（但路由未挂载）
- `notifyExpiringTenants()` — **模拟发送**，只返回 `{ notified: count }` ❌

### 根本原因

"自动收集错误信息"功能**只写了 service 层和前端页面**，但：
1. 没有创建 `monitor.routes.ts` 路由文件
2. 没有在 `server.ts` 注册路由
3. 没有在 saas-admin 路由表注册 MonitorView
4. 没有在侧边栏添加菜单入口
5. API 统计用随机数而非真实埋点

**结论**：功能未完成，无法使用。需要阿澈补全路由注册和真实错误收集逻辑。

## 我踩过的坑

### 1. mock-db 参数索引
- SQL 字面量（`'DRAFT'`、`0`）不算参数，参数索引会偏移
- tenant_id 在不同 INSERT 里位置不同，永远取 `params[params.length - 1]`
- 供应商 INSERT 之前漏了 tenant_id 字段

### 2. 测试环境限流
- `server.ts` 里必须 `if (process.env.NODE_ENV !== "test")` 包裹 rateLimit
- 否则并发请求触发 429，测试大面积失败
- 每次合并远程代码都要检查这个有没有被覆盖

### 3. vitest ≠ jest
- `jest.fn` 不存在，用 `import { vi } from "vitest"`
- 测试文件里如果有 `jest.fn` 会直接报 "no tests"

### 4. 字段命名蛇皮骆驼混用
- 采购订单创建：camelCase 请求 → 返回 `purchaseNo`（注意是 camelCase!）
- 采购入库/退货：snake_case 请求 → 返回 `stock_no`, `return_no`
- 客户付款：返回 `receipt_no`（不是 `payment_no`）
- 销售退货状态：返回 `return_status`（不是 `returnStatus`）
- 写测试前先跑一个看实际返回什么

### 5. 退款方式枚举
- 只支持 `CASH`, `WECHAT`, `BANK`
- `ALIPAY` 会报 400

### 6. 分支合并
- main 和 trae 分支历史独立，必须 `--allow-unrelated-histories`
- 冲突用 `-X theirs` 以 trae 分支为准
- 合并后必须跑全量测试

### 7. queryWithTenant 的 mock 过滤
- 生产环境通过 SQL 注入 tenant_id 条件
- 测试环境需要手动 `result.filter(row => row.tenant_id === tenantId)`

### 8. 测试污染
- mock-db 状态跨测试持久化，`resetMockDb()` 只在 `beforeAll` 调用一次
- 测试跑不过时，先单独跑那个测试看是不是污染问题

### 9. Controller 导出格式
- 全部用 `export const xxx = asyncHandler(...)` 格式
- 不是 `export function xxx`，检查脚本必须匹配 `export const`

### 10. 脚本文件类型
- 项目 `package.json` 有 `"type": "module"`
- `.js` 文件会被当 ESM 处理，`require` 不可用
- 用 CommonJS 的脚本必须 `.cjs` 后缀
