# 环境隔离说明（验收检查项：环境 dev/staging/prod 完全隔离）

> 更新：2026-08-15

## 一、当前环境矩阵

| 环境 | 数据库 | 后端模式 | 前端基址 | 部署位置 | 用途 |
|---|---|---|---|---|---|
| dev（本地） | USE_MOCK_DB=true 内存 mock | NODE_ENV=development | /api（vite 代理到 8080） | 本机 | 开发调试、单测 |
| dev（本地真实库） | 本地/开发 MySQL | NODE_ENV=development | /api | 本机 | 联调 |
| prod | 生产 MySQL（服务器） | NODE_ENV=production | /api（nginx 反代） | admin.onepan.cn 等 | 商用运行 |
| staging | ❌ 未独立搭建 | — | — | — | **缺口：生产预发布验证环境** |

## 二、隔离保障（已具备）

1. **数据隔离**：所有业务表带 tenant_id + `queryWithTenant` 自动注入租户条件（mock 模式也校验），跨租户访问被拒绝（有专项测试）
2. **密钥隔离**：.env 不入库（gitignore），生产 .env 由 auto-deploy 校验占位符并动态生成 JWT/CSRF 密钥
3. **模式隔离**：`USE_MOCK_DB` 开关使测试/开发与真实库完全分离，CI 全量测试跑 mock，迁移验证跑真实 MySQL 容器
4. **域名隔离**：admin/saas/m/app 各自独立子域，nginx 反代 /api 到同一后端

## 三、staging 环境搭建计划（P2）

1. 复用生产部署脚本（deploy/03-deploy.sh + auto-deploy.sh），目标目录 /var/www-staging/、PM2 进程 zhixiang-api-staging（端口 8091）
2. 独立 staging 数据库（每日从生产备份恢复或独立种子数据），严禁与生产数据互通
3. nginx 加 staging.onepan.cn 或 IP+端口访问，仅内网/白名单开放
4. CI 可选：main 合并后自动部署 staging + 冒烟，人工确认后手动触发生产部署
