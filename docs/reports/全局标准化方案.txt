# 开发大型20万行SaaS项目：全局统一标准化完整方案

适配你的进销存多租户系统（后端 \+ uni\-app 小程序 \+ 独立数据库 \+ 追溯码 \+ 分级价格体系），解决分段写代码出现架构混乱、命名不统一、逻辑冲突、权限规则不一致、存储规范割裂问题。
核心思路：**先定全局基准文档 → 固化永久记忆约束 → 分模块强制复用公共层 → 每段生成自动校验全局规范**

## 一、前置：制作全局统一基准文件（最核心，一次性做完）

把所有全局规则写成固定文档，每次开发前先粘贴，所有代码生成强制遵循，分为 5 份固定文件

### 1\. 全局架构规范文档（架构统一）

1）分层固定标准（后端 Node\.js）

```Plain Text
项目固定分层，禁止新增/合并层级
1. config 全局配置：数据库连接、租户配额、API计费、微信支付、权限开关
2. middleware 全局中间件：租户隔离校验、价格权限拦截、存储容量校验、token鉴权
3. model 数据模型：统一数据表字段、索引、租户关联外键、追溯码存储结构
4. service 业务逻辑层：所有库存/销售/批发对账逻辑写在此处，controller只做参数接收
5. controller 接口层：统一请求响应格式，禁止直接操作数据库
6. common 公共工具：扫码解析、税率计算、单据生成、本地归档工具、API调用统计
7. uni-admin PC后台 / uni-mini 小程序前端：前后端分离，接口名称统一映射
```

2）存储全局规则（你的专属约束）

- 每个租户独立数据库，配额固定 10G，超容量弹窗提醒，**禁止自动删除历史单据**

- 结构化业务数据全部存入 MySQL，图片 / 单据附件仅本地归档，不上云 COS

- 租户数据强隔离：供应商 / 二批 / 零售仅可见交易双方价格，禁止跨层级展示上游底价
3）功能全局开关
追溯码总开关、批发价查看权限开关、单据微信分享开关、API 按量计费开关，全部统一放在 config，禁止硬编码

### 2\. 命名统一规范（杜绝命名混乱）

#### 后端统一规则，强制遵守

1. 数据库表：`t_模块_功能`，例：t\_goods\_trace（商品追溯码）、t\_sales\_order（销售单）

2. 字段命名：下划线小写，租户 ID 统一字段名 tenant\_id，所有表必带

3. 接口地址：RESTful 标准
查询 GET /api/ 模块 / 功能；新增 POST；修改 PUT；删除 DELETE
批发相关接口统一前缀 /api/wholesale，零售 /api/retail

4. 变量 / 函数：小驼峰；常量全大写；

5. 单据编号全局规则：XS2026070500001，生成单据编码必须复用公共工具函数，禁止自己写生成逻辑

#### uni\-app 小程序前端统一规范

1. 页面文件：pages / 模块 / 页面\.vue

2. 请求封装：统一使用 common/request\.js，所有接口携带租户 token、客户身份标识

3. 批发价渲染统一判断函数：isWholesaleCustomer \(\)，不得自行写权限判断代码

### 3\. 全局返回体统一（前后端交互标准）

强制所有接口输出固定格式，写任何接口都不能改动结构

```json
{
  "code": 0, //0成功，-1权限不足，-2容量超限，-3参数错误
  "msg": "提示文字",
  "data": {}, //业务数据
  "traceId": "", //全局日志ID，用于API计费统计
  "apiCost": 1 //本次调用消耗token计量数
}
```

### 4\. 公共底层代码包（全局复用核心）

提前生成全套公共工具层代码，固化，后续所有模块**禁止重写同类逻辑**
包含：

1. 租户数据库动态连接工具

2. 10G 存储容量检测工具

3. 追溯码（箱码 / 瓶码）扫码解析通用方法

4. 价格权限过滤工具（控制批发价可见性）

5. 单据生成、微信分享、在线支付通用封装

6. API 调用次数统计、按量扣费公共逻辑

每次开发新模块，强制第一句话：**复用 common 下所有公共方法，禁止重复开发工具类**

### 5\. 业务硬性约束文档（商业逻辑全局统一，防止写出漏洞）

固定约束，每次生成代码前置粘贴：

1. 价格隔离：零售商只能看二批供货价；二批只能看上游供应商价；上游看不到下游成交零售价

2. 追溯码支持单商品 / 分类启停，出入库必须绑定追溯码记录流水

3. 销售中心统一合并批发、零售开单，不拆分两套单据体系

4. 历史单据仅支持导出本地 PC 归档，不自动删除旧单据释放容量

5. 小程序批发价仅绑定批发客户身份后展示，普通客户只显示零售价

## 二、开发工具操作流程：三段式标准化开发，保证全局统一

以 Trae 为例（20 万行项目主力工具，Cursor/Claude 通用）

### 步骤 1：初始化全局记忆（永久绑定规范）

第一次新建项目，一次性上传 5 份全局基准文件 \+ 完整公共底层代码，下达固定指令：

```Plain Text
你后续所有代码生成、修改、重构，必须严格遵循附件内《全局架构规范》《命名规范》《业务硬性约束》，
1. 任何功能不得新增分层，所有逻辑复用common公共工具，禁止重复开发；
2. 接口、变量、数据表命名严格按照文档标准；
3. 租户隔离、价格权限、存储容量逻辑必须调用全局工具函数，禁止手写；
4. 所有接口返回固定统一JSON结构；
5. 每次写完代码，自检是否违反全局规则，列出违规点并自动修复。
后续每一轮对话永久生效，无需重复粘贴完整规范。
```

系统会缓存整套全局规则，后续分段开发不用重复上传全部文档。

### 步骤 2：分模块增量开发，每段强制关联全局

拆分 20 万行项目为独立模块（底层→库存→销售→小程序→计费），每个模块下发指令模板：

```Plain Text
基于现有全局架构、公共工具、命名规范，开发【XX模块】
1. 严格复用common已封装方法，不得重新编写扫码、权限、存储检测逻辑；
2. 数据表新增必须携带tenant_id，遵循t_xxx命名规则；
3. 价格过滤使用全局isWholesaleCustomer权限函数；
4. 接口输出统一返回体；
5. 完成后自检：架构分层、命名、业务隔离规则、公共代码复用四项是否合规，不合规自动修正。
```

每完成一个模块，将模块代码存入项目仓库，同步，读取完整现有代码库，保证下一段开发兼容历史代码。

### 步骤 3：全局校验（每 3 个模块执行一次统一扫描）

每开发完一批模块，下发全局校验指令，自动遍历全部代码，统一修正所有不规范点：

```Plain Text
读取当前项目全部代码，做全局标准化整改：
1. 统一所有变量、数据表、接口命名，修正不符合规范名称；
2. 替换所有重复手写工具逻辑，改为调用common公共函数；
3. 检查所有租户、价格权限逻辑，修复数据泄露风险；
4. 统一全部接口返回格式；
5. 输出整改清单+修正后完整代码。
```

作用：消除分段开发带来的碎片化、逻辑不一致问题，保证 20 万行代码全局统一。

## 三、解决常见全局混乱问题的配套方案

### 1\. 问题：分段开发，重复写工具类，代码冗余

对策：公共层固化 \+ 强制复用校验，每次生成代码自动检索现有公共方法，存在则直接调用，禁止重写。

### 2\. 问题：多租户、价格隔离逻辑每个模块写法不一样

对策：权限、数据过滤全部封装为全局中间件 / 工具函数，业务代码仅调用，不实现底层逻辑，全系统只有一套过滤规则。

### 3\. 问题：前端 uni\-app 和后端接口命名、参数不匹配

对策：全局接口映射文档，统一前后端参数名称，同时读写前后端代码时强制对照映射表。

### 4\. 问题：存储容量、追溯码逻辑各模块实现不一致

对策：扫码、容量检测全局唯一实现，所有出入库、销售单据统一调用同一套方法。

### 5\. 问题：后期新增功能打破原有架构分层

对策：全局架构文档永久置顶，新增功能前先校验分层规则，违规自动调整代码分层。

## 四、大型项目长期维护全局统一机制（20 万行代码后期）

1. **全局变更统一入口**
所有底层规则（配额大小、价格逻辑、追溯码规则）仅修改 config 全局配置，业务代码无需改动；修改功能时禁止硬编码业务参数。

2. **定期全仓重构标准化**
每开发 5 万行代码，使用 Claude Code 读取完整仓库，全局统一梳理依赖、清理冗余代码、对齐编码规范。

3. **规范版本锁死**
全局文档版本跟随项目迭代，任何规则修改同步更新文档，同步喂给，保证新旧代码遵循同一套标准。

## 五、极简总结落地顺序

1. 编写 5 套全局标准文档（架构 / 命名 / 返回体 / 公共工具 / 业务约束）

2. 生成并固化公共底层代码包

3. 初始化，绑定全部规范永久记忆

4. 分模块分批开发，每段强制复用全局能力

5. 阶段性全局扫描整改，统一全部代码

6. 所有底层配置统一放在全局文件，避免代码逻辑分裂
