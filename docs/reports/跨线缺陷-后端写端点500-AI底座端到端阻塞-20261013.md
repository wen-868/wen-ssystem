# 跨线缺陷报告：管理系统后端写端点 500 ⇒ AI 底座写链路在生产不可用

> 报告人：凌舟（AI 底座侧）｜2026-10-13
> 呈送：**codex（管理系统 backend 线）**
> 性质：**跨仓缺陷** —— 缺陷在管理系统后端，阻塞了 AI 底座的写链路
> 状态：**待 backend 修复**

---

## 一、一句话结论

AI 底座调管理系统后端的**写端点**（销售单 `/api/store/sale-bills`、客户 `/api/admin/members`）时，后端返回 **HTTP 500**。
AI 底座侧行为**全部正确**（带 CSRF、带 Authorization、如实把后端错误转为 `success:false`），**缺陷在后端**。
⇒ **AI 底座的写链路在生产实际不可用**（读链路完全可用）。

---

## 二、现象（真实生产，可复现）

### 2.1 AI 底座侧（走完整写全审核流程）

触发写意图 → AI 调 `createSalesOrder` / `createCustomer` → 返回预览并挂起（这一步**正确**）：

```json
{"type":"tool_result","tool":"createCustomer","success":true,
 "preview":{"operation":"创建客户","summary":"新建客户「幂等验证专用客户A」…",
 "details":{"name":"幂等验证专用客户A","phone":"13900000001","customerType":"批发客户"}},
 "confirmationId":"wg_22830566-99dc-4969-a890-3eaef47a9150"}
{"type":"pending_write","token":"wg_22830566-…","writeType":"createCustomer"}
{"type":"await_confirm","token":"wg_22830566-…"}
```

用户确认后（`POST /api/ai/agent/confirm`，`action=confirm`）⇒ 后端报错：

```
创建客户失败：后端 HTTP 500：服务器内部错误（path=/api/admin/members）
创建销售单失败：后端 HTTP 500：服务器内部错误（path=/api/store/sale-bills）
```

**两个不同写端点都是 500** ⇒ 不是单个端点的偶发问题。

### 2.2 后端直调对照（确定归属）

我直接用同一演示账号 JWT 打后端（**手工构造，未算 CSRF**）：

```
POST https://admin.onepan.cn/api/store/sale-bills
→ HTTP 403  {"code":"403","msg":"CSRF token 无效或缺失","traceId":"4b875409-…"}

POST https://admin.onepan.cn/api/admin/members
→ HTTP 403  {"code":"403","msg":"CSRF token 无效或缺失","traceId":"bd3b74e2-…"}
```

⇒ **后端能正常响应**（返回了结构化的 403 + traceId，服务是活的）。
而 AI 底座那条请求**带了正确 CSRF**（由 `service-client.ts` 计算）却得到 **500**。

**归属判定**：AI 底座发起的请求格式合规（CSRF/Authorization/X-Tenant-Id 都带），后端在处理时抛了未捕获异常 ⇒ **缺陷在后端**。

---

## 三、AI 底座侧已自查排除（避免误报）

我已逐项核实 AI 底座**没有问题**：

| 检查项 | 结论 |
|---|---|
| CSRF 是否注入 | ✅ `service-client.ts:370-374` 按 `HMAC-SHA256(CSRF_SECRET, userId)` 计算并注入 `x-csrf-token`（与 backend `csrf.ts` 对齐） |
| Authorization 是否透传 | ✅ `service-client.ts:377-379` 透传 `context.authToken` |
| 租户头 | ✅ `X-Tenant-Id` 已注入（`:365`） |
| 头是否被覆盖 | ✅ `:386-394` 强制合并（防调用方 config 覆盖身份头） |
| 错误处理 | ✅ 后端 500 被如实转为 `success:false` + `error` + `suggestion`，未吞异常、未伪造成功 |
| 用户对话链路 | ✅ `POST /api/chat` 完整跑通：AI 自主调 `checkInventory` ⇒ **success:true** ⇒ 生成回答 |
| 写全审核门 | ✅ 写操作正确挂起等待确认（preview + confirmationId + await_confirm） |

**⇒ 读链路 100% 可用，写链路卡在后端 500。**
