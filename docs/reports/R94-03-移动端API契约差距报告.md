# R94-03 移动端 API 契约差距报告

> 日期：2026-08-07　负责人：凌舟（核查）→ 阿澈（修复）
> 方法：登录 store_manager 账号，对 `app-mobile/src/api/modules/` 全部 312 处 API 调用逐一实测本地后端（USE_MOCK_DB），按响应区分路由级 404 / 403 / 200。
> 结论：**路由级 404 共 82 处（后端路径不存在）**；403 共 127 处（绝大部分为店员角色的写操作权限拦截，属预期设计）；另发现 3 处响应结构不匹配（后端 `records` vs 前端 `list`）。

## 一、响应结构不匹配（页面直接报错）

| 页面 | 前端模块 | 后端返回 | 前端取值 | 影响 |
|------|----------|----------|----------|------|
| 订单管理 | `orders.ts` | `data.records` | `result.list` | `.length` 崩溃，页面空白 |
| 客户管理 | `customers.ts` | `data.records` | `result.list` | `.length` 崩溃，页面空白 |
| 价格管理 | `price.ts listLevels` | `data.records` | `rows.map`（res 为对象） | "rows.map is not a function" |

修复方向：前端适配 `records`（与 admin-web 对齐），或后端补 `list` 别名（需与 PC 端统一，建议以前端适配为准，最小改动）。

## 三、403 权限说明

- 127 处 403 中绝大多数为 POST/PUT 写操作，store_manager（店员）无权限属预期设计，**不修**。
- 例外：`GET /admin/prices/batch/logs` 403（price-guard 限定管理员/店长/财务）。当前价格管理页对店员展示「调价记录」入口，点击即 403。修复方向：按角色隐藏入口或点击时给出「仅管理员/店长/财务可用」提示，不编造数据。

## 四、修复原则（沿用 R94-01 口径）

1. 后端存在等价接口 → 前端改路径并适配返回结构（最小改动，不碰布局/样式/逻辑无关部分）。
2. 后端确实无此能力 → 保留「开发中」占位或隐藏入口，注释标注 R94-03 核实结论，**不编造**。
3. 只改 API 模块与受影响页面取数逻辑，禁止顺手改其他无关代码。
4. 修复后必须复跑 `npm run build:h5` + `build:app`（exit 0）并重新走查 12 个核心页面（控制台 0 error，预期 403 除外）。

## 五、验收标准

- 走查 12 页控制台不再出现结构崩溃（orders/customers/price-manage）；
- inventory/finance/reports 页面数据接口不再 404（返回 200 或空数据均可）；
- 无能力接口完成降级并注释结论；
- `build:h5`、`build:app`、`vue-tsc` 全过。
