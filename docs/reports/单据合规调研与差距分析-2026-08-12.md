# 销售单据合规排版与业务逻辑调研报告

> 日期：2026-08-12 | 负责人：凌舟（AI 协助）| 范围：同行进销存/ERP 单据合规标准 vs 本项目差距

## 一、调研范围

同行对象：管家婆、秦丝进销存、金蝶/用友（畅捷通 T+）、SAP ERP、商陆花、通用进销存软件；以及国家税务/发票开具规范。
调研维度：单据合规排版、业务逻辑合规、表单样式合规、内容排列。

## 二、销售单据合规排版标准（同行共识）

### 2.1 单据三段式结构

```
┌─────────────────────────────────────────┐
│ 表头（单据头）：单号、日期、客户、门店、业务员、结算方式 │
├─────────────────────────────────────────┤
│ 表体（商品明细）：编码/条码、品名、规格型号、单位、数量、单价、折扣、金额、备注 │
├─────────────────────────────────────────┤
│ 表尾（结算区）：商品金额合计、优惠、抹零、价税合计、大小写金额、应收/实收 │
└─────────────────────────────────────────┘
```

### 2.2 单据必备要素（法规层面）

依据《中华人民共和国发票管理条例》及税务开票规范，销售单据必须包含：

- 商品名称（品名，须真实准确，不得只写款号）
- 规格型号
- 计量单位
- 数量
- 单价
- 金额（小写前用 ¥ 封顶；大写在合计数前用符号封顶）
- 大小写金额（财务合规：大写金额+封顶符）
- 客户名称、开单日期、单据编号
- 备注（客户可见/内部备注分离）

### 2.3 单据状态流（业务逻辑合规）

行业标准状态流：

```
草稿(Draft) → 已提交/待审核(Pending) → 已审核/已过账(Posted/Approved)
    → 已完成(Closed/Completed)
    → 作废(Cancelled/Voided) / 红冲(Red-flag, 保留原始凭证)
```

- 单据状态与库存/应收联动：审核过账才扣减库存、生成应收
- 红冲保留原始凭证（redFlag 标志），不允许直接删除
- 收款状态独立跟踪：未收/部分/已收/逾期

### 2.4 表单样式与内容排列（UX 合规）

- 客户选择：下拉+搜索（名称/手机号/速查码），默认加载常用客户
- 商品录入：扫码枪扫描 + 模糊搜索（编码/名称/拼音/规格/条码）双通道
- 明细列标准顺序：条码 → 品名 → 规格 → 单位 → 数量 → 单价 → 折扣 → 金额 → 备注
- 结算区固定于单据最底部，应收金额醒目（大字号）
- 开单后立即生成单据，支持查看/打印/分享收款

### 2.5 商品详情页标准（同行共识）

- 页面结构：**TAB 页签**（商品信息 / 规格与SKU / 商品详情富文本），避免单页长表单
- 商品主图：必传，建议 1:1（≥800×800），高清无水印；主图与详情图分离
- SKU 列表：SKU 是库存与销售的最小单元，每行可维护**条码、规格、单位、各级价格、箱瓶比**
- 信息一致性：标题/主图/详情/属性前后一致（平台规范强制）
- 详情页富文本独立展示，不混入基础信息

### 2.6 酒水追溯码（一物一码 / 序列号，行业标准）

用友好业财 / 智慧商贸 / 秦丝对高档白酒的追溯做法：

- **一物一码**：每瓶或每箱一个唯一 SN/追溯码，防止跨区串货、支持验真
- 流程：商品档案**启用序列号/追溯**（启用后不可中途关闭）→ 采购入库扫码录入 SN → 调拨/盘点扫码核对 → **销售出库自动消减对应 SN** → 可查每箱/每瓶的来源（供应商/入库日期）与去向（客户/销售价格）
- 追溯码可复用为序列号字段存储（长字符）

## 三、本项目差距分析

### 3.1 数据库结构差距（t_sale_bill / t_sale_bill_item）

| 合规要素 | 现状 | 差距 |
|---------|------|------|
| 品名/数量/单价/金额 | ✅ sku_name / total_bottle_qty / unit_price / subtotal_amount | 无 |
| 规格型号 | ❌ 明细无 spec 快照 | **补 sku_spec 快照** |
| 计量单位 | ⚠️ 仅箱/瓶数量（box_qty/bottle_qty） | **补单位快照（箱/瓶切换）** |
| 条码 | ❌ 明细无 barcode 快照 | **补 barcode 快照** |
| 行备注 | ❌ 无 | **补 item remark** |
| 行折扣 | ❌ 无（只有整单折扣） | **补行折扣率/折扣额** |
| 金额大写 | ❌ 无 | 展示/打印层计算大写金额（财务合规） |
| 价税字段 | ❌ 无 | 涉税场景补 tax_rate/tax_amount（可选） |
| 配送方式 | ❌ 开单页有 delivery_type，表无字段 | **补 delivery_type** |
| 销售员 | ⚠️ 有 operator_id（开单人） | 补 salesman_id/name（可选） |
| 状态流 | ✅ DRAFT/CREATED/COMPLETED/VOIDED/RETURNED + 作废原因 | 补充红冲语义（red_flag） |
| 追溯码 | ⚠️ 有 trace_enabled/trace_required 基础字段 | **明细无追溯码存储列，开单无录入/展示区** |

### 3.2 前端界面差距

| 项目 | 现状 | 目标（行业标准） |
|------|------|------|
| 客户选择 | remote 搜索，默认无数据，且用 `c.id`（接口返回 `memberId`）导致选中失效 | 默认加载客户列表 + 下拉搜索 + memberId 对齐 |
| 商品明细列 | 商品/单位/数量/单价/折扣/小计 | 补条码、规格、备注列；商品下拉显示名称+规格+条码 |
| 结算区 | 右侧独立卡片 | 移至单据最底部，应收金额大字 |
| 单据列表 | 详情为弹窗 | 整行点击进独立详情页 |
| 单据详情 | 无独立页 | 单据头+明细+底部金额汇总+收款状态 |
| 开单后跳转 | 提交后重置表单 | 跳转刚创建的销售单详情 |
| 金额大写 | 无 | 详情/打印显示大写金额 |
| 打印样式 | 无 | 销售单打印模板（按 2.2 要素） |
| 商品详情页 | 单页混排（SPU编码/主图URL/富文本同在基本信息 Tab） | TAB 重构：商品信息 / SKU（条码可编辑）/ 商品详情富文本；SPU 编码移出；主图图片化展示 |
| 商品 SKU 条码 | 列表只读 | **条码列可录入**（每个 SKU 可维护条码） |
| 销售单追溯码 | 无 | **明细行追溯码录入区 + 单据详情展示区**（扫码批量录入） |

## 四、调整规划（按调研修订）

### P0 销售单据全链路（业务闭环）
1. 开单页重构：底部结算栏、明细列补全（条码/规格/备注）、客户下拉修复（memberId）
2. 销售单详情页（独立路由）：单据头 + 明细 + 底部汇总 + 收款状态 + 金额大写
3. 单据列表：整行点击进详情
4. 提交后跳转当前销售单详情
5. 商品详情页重构：TAB（商品信息/商品详情富文本）、SPU 编码移出、SKU 条码可编辑、主图图片化展示与上传
6. 销售单明细追溯码：开单行内追溯码录入区（支持扫码/粘贴批量）、单据详情追溯码展示区

### P1 数据合规与品牌
7. 明细表迁移补列：sku_spec / unit / barcode / item_remark / item_discount / trace_codes（JSON）（幂等 129 迁移）
8. 商品 SKU 条码维护接口（PUT /skus/:id/barcode）
9. 追溯码数据源：商品档案启用追溯 → 采购入库录码 → 销售自动消减（与库存/单据联动）
10. 销售单打印模板（含大小写金额、封顶符、签章位）
11. 通知真实数据源（订单/预警/公告写入 t_notification）
12. 左侧 LOGO 全局替换

### P2 AI 结果型体验
9. AI 报表：结果卡片 + 跳转报表中心
10. AI 创建销售单后：跳转/查看单据按钮

## 五、说明

- 金额大写采用"零壹贰叁肆伍陆柒捌玖拾佰仟万亿元角分整"标准写法，小写前 ¥ 封顶、大写前符号封顶。
- 红冲语义：作废保留原单（void_reason），不物理删除，符合财务审计要求。
- 本报告为后续单据模块调整的基线，实施时逐项对照。
