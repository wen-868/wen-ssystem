无障碍设计规范（WCAG 2.1 AA）

Accessibility Design Specification — 确保供应链管理系统对所有用户可用

1. 合规目标

本系统以 WCAG 2.1 等级 AA 为最低合规标准，关键交互路径争取 AAA。

可感知 (Perceivable)

信息与UI组件必须以用户可感知的方式呈现

可操作 (Operable)

UI组件与导航必须可操作，支持键盘访问

可理解 (Understandable)

信息和UI操作必须可理解，错误提示清晰

健壮性 (Robust)

内容必须足够健壮，可被多种用户代理解析

3. 键盘导航规范

所有交互功能必须可通过键盘操作，无需鼠标

键盘操作快捷键适用场景

焦点后退Shift + Tab在可交互元素间向后移动焦点
激活/点击Enter 或 Space激活按钮、链接、开关等
关闭弹窗Escape关闭Modal、Dialog、Dropdown
列表导航↑ ↓在Select、Menu、Listbox中导航
表格导航Ctrl + ↑ ↓ ← →在数据表格单元格间移动
跳至主内容Skip Link页面加载后第一个Tab焦点，跳过导航栏

焦点指示器要求

焦点样式演示（点击下方元素后按Tab键测试）

焦点指示器：outline: 3px solid #4F46E5; outline-offset: 2px; — 确保清晰可见的3px品牌色轮廓

5. 屏幕阅读器适配

图片Alt文本

所有 <img> 必须有 alt 属性：

  • 信息性图片：描述性alt文本
  • 装饰性图片：alt=""（空字符串）
  • 复杂图表：alt简述 + 正文详细说明
  • SVG图标：role="img" aria-label="..."

动态内容通知

使用ARIA Live Regions通知屏幕阅读器：

  • Toast通知：role="status" aria-live="polite"
  • 表单错误：role="alert"（立即播报）
  • 搜索建议：aria-live="polite"
  • 倒计时/进度：aria-live="assertive"

表单辅助

表单字段必须提供完整上下文：

  • <label> 显式关联每个输入框
  • 错误信息用 aria-describedby 关联
  • 帮助文本用 aria-describedby 关联
  • 必填字段用 aria-required="true"
  • 输入格式提示用 aria-describedby

7. 多媒体与动效无障碍

要求标准实现方式
自动播放禁止自动播放音频/视频autoplay 默认关闭，用户手动启动
闪烁内容禁止每秒闪烁超过3次避免使用快速闪烁动画
动效减弱尊重系统偏好@media (prefers-reduced-motion: reduce)
动画时长≤ 5秒自动停止CSS动画设置合理的持续时间
暂停控制自动播放动效需可暂停提供暂停/停止按钮
动效减弱CSS示例
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}

8. 错误识别与恢复

原则要求实现
错误识别自动检测到的输入错误必须用文本描述错误信息用红色文字 + 图标表示，非仅依赖颜色
标签说明提供输入格式说明placeholder + aria-describedby 关联帮助文本
错误建议提供修正建议（如可能）"请输入有效的手机号，如 13800138000"
错误预防法律/财务数据提交前可复查确认弹窗、二次确认机制
可逆操作删除/提交操作可撤销Toast提示"已删除，点击撤销"
