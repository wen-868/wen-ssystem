## 二·补、为什么是"加 2 人"而不是"加 5 人"（编制算法，可复核）

| 端 | 并行开工所需角色 | 现有人 | 缺口 |
|:--|:--|:--|:--|
| 总台 | 后端/数据 + 界面 | 阿坚、林夕 | 0 |
| 工作台 | 前端 | 墨 | 0 |
| 移动端 | 前端 | —（上一轮被并入工作台） | **+1（阿潵）** |
| AI 底座 | 集成 + 工具/迁移 | 阿澈 | **+1（阿洲）** |
| 跨端 | 测试与门禁（**1 人统一口径**，不按端拆） | 苏然 | 0 |
| 全局 | 总负责/验收 | 凌舟 | 0 |
| **合计** | | | **+2** |

> 反例（为什么不按"每端配齐后端+前端+测试"= 12 人）：① 测试按端拆会出现 4 套回归口径（本项目已因口径分裂踩过坑）；
> ② 小仓（移动端/工作台）单人即可覆盖前端，配 3 人会造成**等待与互相踩工作树**；③ 需要更多人时应"按端扩容单个角色"
> （例如移动端并行两单 ⇒ 再给移动端加 1 名前端），而不是把四端都堆满。

2. **回传**：端 owner 回传；`docs/tasks/派单规范.md` §三「十项」不变；结论与证据进入
   `docs/tasks/cards/R101-<单号>-<端owner>回传.md`。
3. **验收**：凌舟逐条**亲跑判据**（不采信自述）；门禁与反测口径照 §九.1。
4. **变更**：任何角色/端调整**只改本文件**，并同批同步三处副本（成员记忆 §一 / ACTIVE.md / ends.json），
   漏同步即视为配置漂移（纳入门禁自查项）。
