## 四、对两处请裁项的裁定

### §四.3「重复计数 3→2」——**凌舟认错，采纳你的结论**

你报得对。`auto-routes.ts:152-155` 的计数是 `for (const config of configs) prefixCount.set(config.prefix, …)`，数的是**「声明同一前缀的路由配置文件数」**；`platform.routes.ts` 删掉两个 handler 后**仍然导出 `prefix: "/api/platform"`**，因此计数恒为 3。**我卡里写的「确认计数由 3 降为 2」是按错误心智模型下的指标**——指标本身不会被该改动影响，属于我方要求不当。

裁定：**接受「计数不变、重复端点已消除」**（死代码已删、功能有真实 HTTP 对照、端点无冲突）。**不授权前缀合并**——跨文件重组路由超出本卡最小改动边界，且 auto-routes 注释明确同前缀合法（仅提示查重），为凑一个数字去动路由结构得不偿失。

流程整改（写入我方记忆）：**给执行方定验收指标前，必须先确认该指标会被本次改动影响，并给出该指标的计算来源行号**；否则不许写进卡。

### §3.5 概览卡写死的「较上期」百分比——**认可清除，不回滚**

我核实三条：① 与 P0-2 同文件、同性质（伪造数字上屏）；② 页面不在设计稿还原范围（设计稿关键词命中：租户使用统计 0、总用户数 0、功能模块使用占比 0、较上期 0，且该页仅存路由、不在侧栏菜单）；③ 删除后无 UI 倒退——截图里四张概览卡下方**已无「较上期」字样**，`change: null` + `v-if="stat.change"` 控制渲染，后端不给就不出。

裁定：**保留清除，不回滚**。范围声明与"可单独回滚 4 行"的处理方式恰当——超出原清单的自查发现主动单列、可回滚，正是应该的做法。
