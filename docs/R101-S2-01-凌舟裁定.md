## 裁定 1｜客户端策略 = **乙（只增强旧客户端）**

**事实**：`saas-admin` 现有两套客户端——旧 `src/api.ts`（响应拦截器 `(response) => response`，**不判业务码**，只有 401 与网络错误分支 → 业务码非 0 时调用方不判就是**静默失败**）；新 `src/utils/request.ts`（`code !== '0'` → `ElMessage.error(msg ?? message)` + reject，近期已修 `message→msg` 与 401 缺 return）。9 个 S2-01 页面仍走旧客户端。

**决定：乙** —— 只增强旧客户端（**1 个文件**），让它与新客户端**同口径**：非 0 业务码 → 中文提示 + `Promise.reject`；401 分支保留；网络异常统一中文文案。

**边界**：① 不迁移那 9 个文件（迁移登记为治理项 **F5**，另开卡）；② 不改任何页面的调用方式；③ 已验收页面的行为除"失败不再静默"外**不得变化**。

**理由**：S2 目标是"接通 + 失败可见"，不是重写接口层；9 文件迁移会动到刚通过验收的调用链，风险与收益不匹配。

## 裁定 2｜F1 = **并入 S2-01**（维持原裁定）+ 完整映射表

**要求**：产出完整「HTTP 状态码 / 业务码 → 中文文案」映射表，覆盖 401、403、404、409、422、429、500、502、503、超时、断网、业务码非 0；**集中一处**（建议 `saas-admin/src/utils/http-error.ts`），`request.ts` 与增强后的 `api.ts` **共用同一份**，禁止两套文案。

**文案口径**：面向运营与商户的中文，**禁止直出 axios 英文原文**（`Request failed with status code 500` 这类一律不许出现在界面上）。

## 裁定 3｜后端确无的 9 项缺口 = **甲（留空态 + 登记 S3）**

**事实（凌舟核查）**：后端 `captcha` = 0 处、`quota` = 0 处、`tenantTrend` = 0 处、`incomeComposition` = 0 处；已有 `planDistribution`、`upgrade/downgrade`，平台大盘已有 `GET /api/platform/dashboard`、`/dashboard/tenants`、`/dashboard/revenue`、`/dashboard/overview`；迁移清单中无配额/验证码表。

**决定**：**不在 S2 内新建后端能力**的缺口（9 项）→ 页面**留空态**（显式写"待接入 xxx"）+ **逐项登记 S3**。新建后端能力属第 3 步。唯一例外见裁定 4。

> 登记要求：**逐项登记**（推进到哪一项就登哪一项），不要攒到最后补。

## 裁定 4｜卡上明文三项 = **授权新建，但限定边界（只读聚合 + 不建表）**

1. **图形验证码**（后端完全没有；前端 `captchaText = '待接入'` 只校验非空 → 现状等于**没有验证码**）：授权新建 `GET /api/platform/auth/captcha` + 登录校验。**Redis 存储、5 分钟有效、一次性**；只加校验，不改登录主流程与外层结构。**安全相关，必须做。**
2. **大盘趋势 / 收入构成**：授权**扩展既有** `services/platform/platform-overview.service.ts`（只读聚合，基于现有租户/订单/收入/套餐表），补齐 `tenantTrend` 与 `incomeComposition`；已有 `planDistribution` 不动。算不出的维度（如大模型 Token，需 ai-base 数据源）→ 返回 null + 前端空态 + 登记 S3。

## 二、三项请示的裁定

### ① 页面级第二套文案 —— **收敛，但分层分批**

**规则（即刻生效）**：**客户端层**负责"请求失败的中文提示"（一次）；**页面层** `catch` **不再弹通用 toast**，只负责**页面内错误态/空态占位**（内容区提示块），需要更具体语境时用页面自己的文案（如"加载订阅列表失败"）。

**判定标准**：同一次失败**只出现一条 toast**；页面内容区可以有自己的错误占位，但它**不是 toast**。

**落地范围**：① 本卡正在对接的 S2-01 页面**随批5 顺手收敛**（属本卡范围，不另开卡）；② 其余全站页面登记治理项 **F6**（页面级错误文案去重），分批做，不阻塞 S2。

### ② 验证码 SVG 位图化 —— **不立项**；改授权"登录限流"（批 2.1）

- **位图化不立项**：真正的防护是「一次性 + 5 分钟 TTL + 服务端校验」；SVG `<text>` 只降低自动化门槛，**不构成结构安全问题**；引入 `canvas`/`svg-captcha` 增加依赖与维护成本，收益边际。**登记为 P3 可选加固（S3-18）**——出现自动化攻击证据再立项。
- **授权批 2.1：平台登录失败限流/锁定**（你发现 `platformLogin` 不限流，而验证码一旦被脚本解析，限流就是唯一的爆破门闩）。要求：按 **IP + 账号**双维度；阈值 **5 次/5 分钟**，超限锁定 15 分钟或强制换验证码并要求二次确认；命中时返回**中文**提示；复用现有 rate limiter 基础设施，不新建表；补单测 + 更新 `docs/API接口文档.md`。

### ③ 金额单位 —— **换算放后端，前端零换算**

**口径**：接口**同时**返回原始值 `amount`（元，精度不丢）与展示值 `amountWan`（万元，**后端一次性四舍五入保留 2 位**）；前端只做格式化（千分位），**不做除法换算**。字段单位与精度必须写进 `docs/API接口文档.md`。

**理由**：单位换算是业务口径，放前端会导致每个调用点各写一遍、四舍五入口径不一致；放后端则一处定义、契约可见。

**追加授权（批3 一并核查）**：大盘所有金额卡的**单位标注与实际值必须一致**——若标签写「单位：万元」而值是元，属显示口径缺陷（差 10000 倍），按同一规则修正。

- **凭据错误（401）**：维持现行 **IP + 账号双维度、5 次/5 分钟 → 锁 15 分钟**（这才是爆破特征，现状不动）；
- **验证码错误（400）**：**只计 IP 维度**，阈值放宽至 **20 次/5 分钟**，超限**只拒绝并要求重新获取验证码（最多短时拒绝 5 分钟）**，**绝不锁定账号**。

**实现建议（最小改动）**：给 `login-fail-limiter` 加"只对 401 计数"的判定（如按响应状态码决定是否计数），验证码校验的 400 单独走一条 IP 维度、弱阈值的计数器；`requireCaptcha` 的拒绝**不得**进入账号维度的计数。

**理由**：验证码输错是正常交互噪声（用户看错一位就计一次），账号级锁定会把误输变成"账号被锁 15 分钟"的投诉；而验证码类的自动化尝试按 IP 抑制即可。**附带要求**：超限文案给中文明确信息（第几次失败、剩余锁定时间），不要只给一句"请求过于频繁"。
