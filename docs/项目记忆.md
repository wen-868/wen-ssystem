## 八、提交前自查清单（铁律）

所有成员提交代码前必须确认：

- [ ] `npx tsc --noEmit` → 0 错误（后端）
- [ ] `npm run build` → 成功
- [ ] `npm audit` → 0 漏洞（前端）
- [ ] 返回格式使用 `msg`（非 `message`），含 `traceId` 和 `apiCost`
- [ ] controller 没有直接操作数据库
- [ ] 没有手写编号生成逻辑（只用 `shared/id.ts`）
- [ ] 没有手写价格判断（只用 `middleware/price-guard.ts`）
- [ ] 前端表单含 `ref` + `:model` + `:rules` 三件套
- [ ] 没有硬编码敏感信息

## 九、10 条红线（违反立即回退）

1. TS 错误不为 0 就提交代码
2. 构建失败就提交代码
3. 直接 `res.json({...})` 绕过 `ok()`/`fail()` 统一返回
4. Controller 直接操作数据库
5. 手写价格判断逻辑绕过 price-guard
6. 手写编号生成逻辑绕过 `shared/id.ts`
7. 创建多个分支（只保留 main）
8. 创建多个任务文件（每人一个，固定位置 `docs/tasks/`）
9. 在代码中硬编码敏感信息
10. 使用英文写文档内容
11. **推卸错误责任。** 遇到错误以"不是我引入的""是预存的""是第三方库的问题"为由不处理。每条错误只有三种归宿：修复、记录到踩坑日志、报告凌舟。

## 十、历史踩坑摘要（关键 5 条）

| 编号 | 标题 | 教训 |
|:---:|------|------|
| 1 | vitest ESM 下 isRouter() 失效 | 路由注册不要依赖 typeof 检测第三方库实例 |
| 4 | 路由注册顺序导致认证失效 | Express 路由顺序就是中间件执行顺序 |
| 9 | try-catch 绕过全局 errorHandler | controller 禁止 try-catch，用 async-handler 传递 |
| 11 | subagent 输出导致任务漏项 | subagent 输出必须逐项核对，不能直接信任 |
| 13 | 超时处理只加拦截器不配 timeout | 功能修复要理解完整链路，触发条件+捕获处理两端 |

完整记录见 `docs/踩坑日志.md`。
