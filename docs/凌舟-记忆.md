## 六、验收方法论（我的核查流程）

每次核查严格执行以下步骤：

1. **git pull** 拉取最新代码
2. **npm install** 安装依赖（否则所有检查结果无效）
3. **grep 验证** — 每个声明都要有代码证据
   - console 残留：`grep "console\.(log|error|warn)" src/`
   - try-catch：`grep "try\s*{" controllers/`
   - 表单校验：`grep ":rules" pages/`
   - 覆盖率：`npx vitest run --coverage`
4. **tsc / eslint** — 编译检查
   - 后端：`npx tsc --noEmit`
   - 前端：`npx vue-tsc --noEmit` + `npx eslint src/`
5. **对比报告** — 不信任任何人，独立验证
6. **更新任务文件** — 标注完成状态 + 凌舟核查证据
7. **提交推送** — `git add -A && git commit && git push`
8. **如果全部通过 → 直接规划下一轮**

## 七、踩坑日志摘要（20 条关键教训）

| 编号 | 关键词 | 一句话教训 |
|:---:|------|------|
| [1] | vitest ESM + isRouter | vitest 模块转换影响 typeof，不要依赖 typeof 检测第三方库实例 |
| [2] | auto-routes vs 手动注册 | 两人方案方向不同时，选兼容性更好的 |
| [3] | package-lock.json 冲突 | 合并前先检查 package.json 差异 |
| [4] | 路由注册顺序 | Express 路由顺序 = 中间件执行顺序，认证路由必须在 auth 之后 |
| [5] | jest.fn vs vi.fn | 迁移 vitest 后全局搜索 `jest.` 替换为 `vi.` |
| [6] | 品牌字段类型 | 增加独立实体表后必须同步修改引用该实体的所有表 |
| [7] | 成本价硬编码 0 | 涉及金额的字段绝不能用硬编码默认值 |
| [8] | API 路径不匹配 | 以前端路由注册代码为准，不要在 api.ts 自行加路径段 |
| [9] | controller try-catch | 先建全局错误处理，再写业务代码 |
| [10] | 多任务文件混乱 | 任务管理必须集中化，一个文件一个位置 |
| [11] | subagent 输出不核对 | subagent 输出必须逐项核对，涉及多文件必须 grep 验证 |
| [12] | 表单 ref 未声明 | 三件套（ref+:model+:rules）缺一不可 |
| [13] | 超时只加拦截器没配 timeout | 修复要理解完整链路，触发条件 + 捕获处理两端都要看 |
| [14] | 空 rules 和空 model | 校验完整性要检查 model/prop/rules 三处 |
| [15] | uni-app 条件编译 vue-tsc | `const` 声明用 IIFE 避免重复声明 |
| [16] | uni-app 类型缺失 | 早期建立 uni-app.d.ts 类型补充文件 |
| [17] | 未 npm install | 先确认 node_modules 存在再跑检查命令 |
| [18] | re-export v8 覆盖率 0% | `export { x } from` 改 `export * from` |
| [19] | NaN ?? 0 仍为 NaN | `Number()` 可能返回 NaN 时用 `|| 0` 不用 `?? 0` |
| [20] | `||` 链分支爆炸 | 超 5 个 `||` 改数组 + `.some()` |

## 十、工作习惯（凌舟专属）

1. **每次任务分派前** → 先读 `踩坑日志.md`，避免派发重复/已解决的问题
2. **每次核查** → git pull → npm install → grep/tsc/eslint → 独立验证 → 写结论
3. **全部通过后** → 直接规划下一轮、更新文件、提交推送，不等确认
4. **发现踩坑** → 立即写入 `踩坑日志.md`，编号递增
5. **发现违规分支** → 立即删除，`git branch -r` 只能有 `origin/main`
6. **发现旧文件** → 立即清理（旧任务文件、MEMORY.md、WORKING-MEMORY.md 等）
7. **苏然的报告** → 必须检查：是否 npm install、是否读了 current-tasks.md、是否推到 main
8. **墨的代码** → 必须 grep 逐项验证，不能只看提交信息
9. **阿坚的 console** → 每次 grep 确认零残留
10. **质量标准** → 100%，没有例外
