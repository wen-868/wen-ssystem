## 一、要补的门（三类码）

后端**已挂码**、但页面按钮对**不持码**的在用角色仍可见 ⇒ 点了必 403。按不变量 **I1'② / D4**，前端必须**按码显隐**：

| 码 | 典型入口（请逐条落地核实，勿凭猜） |
|:--|:--|
| `goods:delete` | 品牌管理 / 商品标签 / 单位管理 的**删除**按钮（`Brands.vue`、`ProductTags.vue`、`Units.vue` 一带） |
| `system:user:create` `system:user:edit` | 员工/账号页的**新增/编辑**按钮 |
| `system:role:create` `system:role:edit` | 角色页的**新增/编辑**按钮 |

## 二、做法（唯一允许的形态）

1. **复用既有判据源**：权限串来自登录态/`/admin/auth/me`（与 `app-mobile` 的 `permission-gates` 同源口径），**不要新造一套判定**；
2. 按钮级：`v-if`/`v-show` 按码显隐（**隐藏**而非置灰——置灰属"可见但不可用"，不等于补门）；
3. 若某页是"单按钮多码"（一次保存打多码）⇒ **只登记**，在回传卡写清并交凌舟裁定（**照 S3-231 的粗粒度门先例**，不要自创规则）。

## 三、判据（逐条给原始输出）

1. 覆盖表：**码 × 页面 × 按钮 × 判定点行号**逐条列出（一行一条，不许只给数量）；
2. **两侧反测**：把某个码从测试账号权限串里去掉 ⇒ 对应按钮**必不渲染**（给装置原始输出）；恢复 ⇒ 必渲染；
3. `npx vue-tsc --noEmit`（admin-web）⇒ 0 新增；`npx eslint` ⇒ 0 error；构建 EXIT=0；
4. 不回归：`guard-rbac-wiring --strict` 仍 EXIT=0（本轮**只改前端**，不得动后端与基线）。

只改 `admin-web/src/**`；不得改后端、`app-mobile/**`、迁移、`.github/**`；不得用"后端再放宽"来绕过；证据不得含口令明文。
