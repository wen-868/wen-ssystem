## 一、现象（凌舟在生产只读实测，勿再求证）

```
t_sys_role  : default 12 行 / demo 12 行            ← 只有这两个租户有角色
t_sys_menu  : default 89 行 / demo 89 行            ← 只有这两个租户有菜单
t_sys_user  : default 5 / demo 1 / f0cbfe78-… 1
受害租户 f0cbfe78-… 的管理员（13410954557）：
  绑定  bind_tenant = f0cbfe78-… ／ role_code = SUPER_ADMIN ／ **role_tenant = default**（不匹配）
```

⇒ 该账号登录后：`getUserPermissions()` 的 `JOIN … AND r.tenant_id = ur.tenant_id` **命中 0 行** ⇒ `permissions=[]`；
`getUserMenus()` 的 `AND r.tenant_id = ?` **命中 0 行** ⇒ 直接 `return []` ⇒ **功能中心 / 侧栏整屏空白**（能登录，但什么都看不到）。

**并且这是通病**：平台开通租户的链路**从不克隆角色与菜单** ⇒ **每个新租户一出生就是坏的**
（`demo` 那套是 S3-174 的迁移 197 手工补的，不是开通链路给的）。

## 二、交付物（4 件）

### ① 开通链路：克隆角色 + 菜单（口径照 197，不得另造一套）

先**取证定位**：找出所有"创建租户"的落点（`services/platform/tenant-ops.service.ts`、`platform-tenant.service.ts`、`services/tenant-register.service.ts` 等，用 `rg` 列全并逐个说明哪个是生产在用的），然后在**真正建租户的那一处**（若多处则都覆盖）补两步：

1. **克隆角色行**：从 `t_sys_role WHERE tenant_id='default'` 克隆到新租户，**带上 `permissions`/`role_name`/`description`/`data_scope`/`status`**；幂等判据 `(role_code, tenant_id)`；
2. **克隆菜单行**：从 `t_sys_menu WHERE tenant_id='default'` 克隆（先顶级后子级，子级 `parent_id` **重指向本租户的父行**，按 `menu_code` 对齐）；幂等判据 `(menu_code, tenant_id)`；
3. 新租户的第一个管理员**绑定到本租户自己的** SUPER_ADMIN 角色行（不是 default 的）。

🔴 **写法参照 `docs/migrations/197_演示租户隔离.sql`**（那里已跑通并生产验证）：同样用 `SELECT … WHERE NOT EXISTS` 做幂等、**不用 `INSERT IGNORE`**、写语句不要写成"注释开头的整块"（踩坑[63]）。

### ② 存量修复迁移 `docs/migrations/198_租户角色菜单补全.sql`

对**所有**"缺角色或缺菜单"的租户（含 `f0cbfe78-…`）执行与 ① 等价的克隆，并把这些租户里**指向别租户角色行的绑定**改成本租户自己的角色行（按 `role_code` 对齐；**原地 `UPDATE`，不得先插后删** —— `uk_sys_user_role (user_id, role_id)` 不含 tenant_id，先插后删会把绑定归零，见 #276 判红）。

- 迁移**只碰** `t_sys_role` / `t_sys_menu` / `t_sys_user_role` 三张系统表；**零业务表、零 `DELETE`**；
- 文件头按仓库惯例写清：编号/单号/依据/幂等口径/回滚口径/执行方式（提示：写语句会被 MIG-4 写闸门跳过，**必须**用 `node scripts/run-migration.mjs` 或 `MIGRATION_WRITE_GATE=allow`）；
- **必须**同步 `EXPECTED_MAX_MIGRATION` 快照（197→198，规则见派单标准头第 7 条）。

### ③ `demoLogin()` 的 roles 查询补租户过滤（第 17 项）

`services/admin/auth.service.ts` 里 `demoLogin()` 用的 roles 查询（约 `:421-427`）目前 `JOIN t_sys_role r ON r.id = ur.role_id` **没有** `r.tenant_id = ur.tenant_id` ⇒ 一旦存在跨租户绑定，登录返回的 roles 会出现**重复的 SUPER_ADMIN**。
补上该过滤。⚠️ 前提是 ② 已把绑定指到本租户角色行 —— **两件必须同批**，否则加过滤会把当前可用的 demo 登录打空。回传里要给出"加过滤前后 demo 登录 roles"的原始输出。
