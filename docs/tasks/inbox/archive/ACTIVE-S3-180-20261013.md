## 一、现状（凌舟实测，勿再求证）

## 二、交付物（3 件，顺序不可换）

### ① 新建门禁 `backend/scripts/guard-rbac-wiring.mjs`（**只报告，不阻断**）

- 扫描 `backend/src/routes/*.routes.ts`，对**每个写端点**判定处理链上是否有 `requirePermission(...)`（同行内联 / 同 scope 的 `router.use(..., requirePermission(x))` 均算；`routeConfig` 声明式不携带权限 ⇒ 记"无"）。
- 输出两部分：**人读清单**（按文件分组，逐条 `METHOD /prefix/path ⇒ 无权限检查`）＋ **机读**（`--json` 输出 `{file, method, path, hasPermission}[]`，便于后续回归对比）。
- **默认退出码 0（报告模式）**；提供 `--strict`（存在未登记项则 exit 1）。
- 脚本头必须写明：**本门禁当前是"报告器"，未接 CI**；接 CI 的前置是"缺口清零或逐条登记"。
- **要求先让它红一次**：挑一个已知无权限的写端点，贴命令与原始输出，证明它不是恒绿摆设。

### ② 出分域缺口清单 `docs/tasks/R101-RBAC接线缺口清单.md`

把 144 个文件按**域**归类（商品/库存/销售/采购/客户/报表/员工/系统设置/营销/门店/平台…），每域给出：

- 文件数、写端点数；
- 每个端点：`METHOD 路径` ⇒ **该不该要权限**（管理面 vs 自服务/本人数据）、**建议权限码**；
- 🔴 **权限码一律从既有目录挑**（`docs/migrations/079_权限矩阵.sql` + `t_platform_permission_catalog`），**禁止新造码**；挑不出来就写"无现成码 ⇒ 需先立权限点（另立单）"。
- 表尾给**域汇总数字**：`共 N 域 / M 文件 / K 端点，其中 X 需权限、Y 属自服务、Z 需新权限点`。

### ③ 选**一个试点域**真正落地（我指定：**报表域**）

范围钉死这三个文件：`admin-report.routes.ts`、`custom-report.routes.ts`、`custom-report-v2.routes.ts`。

- 给该域**管理面**写端点补 `requirePermission("<既有码>")`；自服务/本人数据端点若无合适码，进清单但不硬加（写明理由）。
- 🔴 **加之前必须验证权限码已授予**：查出该码在权限矩阵里授给了哪些角色，并确认这些角色正是会用该页面的角色；**若某端点加了码会让现有角色 403 ⇒ 不许加**，改为登记"需先补授权"。

## 三、验收标准（机器可判，**必须给原始输出**）

1. `node backend/scripts/guard-rbac-wiring.mjs`（报告模式）**EXIT=0** 并输出缺口总数；`--strict` 在有缺口时 **EXIT=1**。
2. ① 的反测：脚本对**已知无权限端点**必须报出（贴原文），证明有分辨力。
3. 清单文件存在且含**域汇总数字**；144 个文件逐个出现（用 `rg -c` 自证）。
4. 试点域：`cd backend && npx vitest run` ⇒ **全量 0 failed**；`npx tsc -p tsconfig.json --noEmit` ⇒ **EXIT=0**；`guard-route-auth` / `guard-tenant-status` ⇒ 均 **EXIT=0**。
