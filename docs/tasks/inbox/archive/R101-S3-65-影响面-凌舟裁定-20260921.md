## 二、争议行裁定（`services/instant-retail/product-sync.service.ts:75`）

代码事实（凌舟亲验，`product-sync.service.ts:66-79`）：

```
66: const fields: string[] = ["sync_status = ?"];          // SET 恒含 1 个占位符
73: values.push(platform, localSkuId);
74: if (tenantId) { values.push(tenantId); }
75: const tenantCondition = tenantId ? "AND tenant_id = ?" : "";
77: await queryWithTenant(`UPDATE ... SET ${fields.join(", ")} WHERE platform = ? AND local_sku_id = ? ${tenantCondition}`,
78:   values, tenantId || "");                                // ← 传给 helper 的实参
```

裁定依据（**口径互斥**）：同一变量 `tenantId` 既决定 SQL 里是否出现 `tenant_id`，又决定传给 helper 的实参：

- `tenantId` 为真 ⇒ SQL 文本含 `tenant_id` ⇒ 条件②（SQL 不含 `tenant_id`）**不成立** ⇒ 注入被短路；
- `tenantId` 为假 ⇒ SQL 不含 `tenant_id`，但实参恒为 `""` ⇒ 条件④（tenantId 可真值）**不成立**，且修复后下发 `tenant_id = ''` **仍是 0 行** ⇒ 不构成"修复后首次真正生效"。

⇒ ② 与 ④ 在该调用点**不可能同时成立** ⇒ 判**不命中**（复核方的 39 不采纳；但其"首轮给的排除理由（WHERE 前占位符为 0）与源码不符"这一条**成立**，首轮 §7.3 的该句理由作废）。

**附带登记（另立，不在本卡）**：该函数 `tenantId` 为可选参数 + `tenantId || ""` 的写法，会产生 `tenant_id = ''` 的越界匹配语义（若库中存在 `tenant_id=''` 的历史行，修复后会被误更新）；列为部署前冒烟项。
