## 背景与依据（凌舟 2026-09-25 复核，可复跑）

1. 现状：`backend/src/shared/migration.ts:911 / :1057` 只做 `return !t.startsWith("DELIMITER ")` —— **把 DELIMITER 行删掉，但没有 BEGIN…END 边界感知**；`:140` 注释自己写着"调用方需先移除 USE / DELIMITER 行"；`:1066-1071`（第 8 步外部迁移）与 `:918-924`（5.5.8 AI 底座建表）对**含 `CREATE PROCEDURE` / `DROP PROCEDURE` 的块直接 `continue`**。
2. 后果一（拆散）：含过程体的迁移被按 `;` 拆散 ⇒ 过程体残片当独立语句执行（`safeExec` 只记日志、不抛出），过程**从未被创建**；MIG-1 演练里 `ER_SP_DOES_NOT_EXIST` **29 条**属这一类（`CALL` 依赖的存储过程不存在）。
3. 后果二（DROP 从未生效）：`092_租户ID.sql:282-283` 的两条 `DROP PROCEDURE IF EXISTS` 因 `:1068` 被跳过 ⇒ 生产库至今残留 3 个辅助存储过程（`add_column_if_not_exists` / `add_index_if_not_exists` / `add_col_if_not_exists`），其中第三个**仓内不存在**。

## 交付物

1. runner 支持 `DELIMITER <符号>` 语义（或至少按 `BEGIN…END` 维持块边界），使过程/函数/触发器体被**作为完整语句下发**；唯一允许改的源文件：`backend/src/shared/migration.ts`。
2. 单测（**先红后绿**）：构造含过程体的迁移文本 ⇒ 断言过程体完整成块；落 `backend/src/__tests__/shared/migration*.test.ts`（可新增 `migration-delimiter.test.ts`）。
3. 反测**两层**：
   - 3a（本工作区**必须**跑通）：以 `092_租户ID.sql` 真实内容为输入，断言 ① 两个 `CREATE PROCEDURE` 块各作为**一条**语句下发（不是被 `;` 拆成多条、也不得被整块丢弃）；② 文件末尾 `:282-283` 两条 `DROP PROCEDURE` **被下发**（不再被 `:1068` 跳过）；
   - 3b（真库空库 092 ⇒ `information_schema.ROUTINES` 无残留辅助过程）：本工作区无 MySQL/网络，**本单不作"必须通过"**，但必须交付①可直接复跑的脚本或命令（含建空库、跑 runner、查询 `information_schema.ROUTINES` 三段）与②期望输出，标注"待凌舟在本机/服务器执行"，**不得声称已通过**。
4. 影响面数字（可复跑命令 + 数字）：受影响迁移文件数 / `CREATE PROCEDURE` 块数 / `DROP PROCEDURE` 条数 / `CALL` 条数。
