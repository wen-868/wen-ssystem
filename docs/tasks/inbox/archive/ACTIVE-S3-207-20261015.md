## 一、四件事（**①是根因，必须做**）

### ① 根治：收紧 `injectSelectTenant/Update/Insert` 的短路判据

现状（`backend/src/config/database.ts:215-218`）：**只要 SQL 字符串里出现过 `tenant_id` 就跳过注入** ⇒ `JOIN … AND o.tenant_id = a.tenant_id` 这种**跨表同租户匹配**会让注入被静默跳过、**隔离整体失效**。

**要求**：改成"只有存在**绑定到调用者租户**的条件时才跳过注入"的可判定判据，例如：
- 存在形如 `tenant_id = ?`（带参，且该参数由注入器管辖）**或** `tenant_id = :调用者` 的写法；**或**
- **显式白名单/显式标记**（如调用方传入 `{ tenantChecked: true }` 或 SQL 里带专用注释标记），让"我已经自己写了租户条件"成为**显式声明**而不是字符串碰巧出现。

**必须在回执里给出你选的判定方式与理由**（含：为什么它不会误放行、误拦时的行为是什么）。**不得**用"更复杂的正则"糊过去而不说清边界。
