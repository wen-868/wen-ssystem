## 二、判定口径（逐字执行，不得自行加严或放宽）

对 `backend/src/**`（**排除 `__tests__`**）中每个 `queryWithTenant` / `queryOneWithTenant` / `executeWithTenant` 调用：

1. SQL 是否 `UPDATE`（`DELETE` 顺带列出）；
2. SQL 文本（含模板字符串拼接，**要展开变量构造**，如 `${sets.join(", ")}`、`${updates.join(", ")}`）是否**已含 `tenant_id`**；
3. `SET` 子句（UPDATE）在 `WHERE` 之前是否**出现了 `?` 占位符**；
4. 调用传入的 `tenantId` 实参是否**可能为真值**（如来自 `req.tenantId`、函数参数；若恒为空串/`undefined` 则不受影响）。

**命中集定义**：①UPDATE ②SQL 不含 `tenant_id` ③SET 含 `?` ④tenantId 可真值 —— **四条同时成立**才算"曾静默失效"。

补充要求：

- 先写清三个 helper 的定义位置（`backend/src/config/database.ts` 内的函数与行号）与各自的注入分支（含 WHERE / 不含 WHERE / SQL 自带 `tenant_id` 短路），判定必须引用这些行号；
- `WHERE` 出现多次（子查询、`ON DUPLICATE KEY UPDATE`、`WHERE EXISTS`）时，按 `lowerSql.indexOf('where')` 的**首次**出现位置认定，与实现一致，并在报告里注明该行用的是首现位置；
- UPDATE 语句里的 `?` 若在 `SET` 之前出现于其他位置（如 `UPDATE (SELECT ...)`），逐条注明。
