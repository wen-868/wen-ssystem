## 一、缺陷（CI 真信号，凌舟已核原始日志）

CI 的 `migration-check`（`mysql:8.0` 容器，**全新空库**）跑完迁移后，日志里出现：

```
016_phase9_tenant_subscription.sql 失败: Referencing column 'tenant_id' and referenced column 'id'
    in foreign key constraint 't_tenant_admin_ibfk_1' are incompatible.
016_phase9_tenant_subscription.sql 失败: … foreign key constraint 't_tenant_module_access_ibfk_1' are incompatible.
017_phase10_instant_retail.sql   失败: Referencing column 'order_id' and referenced column 'id'
    in foreign key constraint 't_delivery_record_ibfk_1' are incompatible.
017_phase10_instant_retail.sql   失败: … foreign key constraint 't_retail_order_item_ibfk_1' are incompatible.
032_add_tenant_module_access.sql 失败: … 't_tenant_module_access_ibfk_1' are incompatible.
034_add_tenant_admin.sql         失败: … 't_tenant_admin_ibfk_1' are incompatible.
```

- 原始出处：CI job **115489212715**（PR #305 的 run 38453231950）。
- 这是 **MySQL 8 的 errno 3780**：外键两侧的**列类型 / 字符集 / 排序规则**必须完全一致，`t_tenant.id` 与 `t_*.tenant_id`（及 `order_id`）不一致时直接拒绝建表。
- **为什么以前没看见**：本机验证一直用 **MariaDB 11.4.5**，它对此更宽容 ⇒ 空库能跑通；而 CI 用 **MySQL 8**（更贴近生产）⇒ 一换就暴露。**这也是本项的方法论要点（见 §五）。**

## 二、要交付的东西

2. **修法**：只改**迁移语料**（含必要的 `CREATE TABLE` 列定义/字符集声明），使**全新 MySQL 8 空库**能一次跑完；不得用"跳过外键"、不得 `SET FOREIGN_KEY_CHECKS=0` 绕过、不得删掉约束来换绿——**外键是数据完整性约束，要保留**。
