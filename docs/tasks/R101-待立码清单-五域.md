## 〇、口径与本单边界（先读，否则会误读下面的数字）

1. **本单只"立码"**：把码本身立起来（目录 + 迁移 + 断言 + 前端入口登记），**不接任何业务路由**
   ⇒ 零 `routes/` / `middleware/` / `services/` 改动（自证命令见 §四）。
2. **命名规范**（提案 §三）：`模块:子域:动作`，模块名取 `docs/migrations/079_权限矩阵.sql` 的既有模块码
   （`dashboard/goods/sale/purchase/customer/finance/marketing/store/trace/report/system`，本批另用既有码族
   `miniapp`——079 的角色种子已用 `miniapp:*`）；**禁止 `xxx:manage` 万能码**；同一语义跨端点同名同码。
3. **"码"与"条"不是一个数**：台账按**端点条数**数（如系统设置域 22 条），本清单按**端点条数**给表，
   并另给**码数**（一个码可覆盖语义相同的多个端点）。两个数都给，避免"加起来对不上"。
4. **台账数字要叠加 S3-205 §10.3 的改判**：台账 §三 的逐行判定是**规则化产出**（§六 已自述"用于直接接线不足"），
   其中小程序/通知类端点已在 **S3-205（总清单第 68 项）** 改判为"消费者端保护形态 ⇒ 不适用商家权限码"。
   本清单凡引用该改判处，逐条标 `§10.3`。
5. **卡外纪律**（卡 §六）：与台账判定不符的，**只登记、不实现**，并在回执 §六 汇总给凌舟。
