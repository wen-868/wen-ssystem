## 二、"怎么拿到带 token 的 URL"（回答 2026-09-21 提问）

已核实的协议事实：host 是 **CodeBuddy Code Remote Control**（`/` 返回其 Web UI）；API 需 `Authorization: Bearer <token>`（实测 `/health`、`/api`、`/openapi.json`、`/docs` 全 401）；**token 来源 = URL 参数 `?token=`**（前端 bundle `URLSearchParams(...).get("token")`）。

token **不在**这些地方（均已实测）：`sessions/*.json`（只有 pid/url/kind/meta，meta 是命名管道 `\\.\pipe\codebuddy-prewarm-*`）、`workbuddy.db`（表：sessions/workspaces/automations/automation_runs/automation_runtime_state/automation_delivery_outbox/buddy_snapshots，无 token 列）、`~/.workbuddy` 顶层小文件、`%TEMP%` 近 6h 小文件。

三条获取路径（按省事排序）：

1. **A（最快，5 秒）**：在 WorkBuddy 里打开那个 Remote Control 页面，**复制地址**（含 `?token=`）给凌舟；若地址被 iframe 藏住，用它自带的分享/扫码入口（侧栏有「扫码 WorkBuddy 小程序」「分享任务」）。
2. **B（不需人工，需一次逆向）**：解析应用自有的 KV 存储 `~/.workbuddy/local_storage/entry_*.info`（bundle 里 token 键为 `Jo`，`jS()` 仅在登出时删除）或用 Chromium/Electron 的 LevelDB 读取器（若 profile 目录存在）。**风险**：版本升级后键名/格式可能变。
3. **C（不推荐）**：`POST /api/v1/auth/login`（需登录口令，凌舟不知道，也不应索取）。

## 三、L2 的安全边界（未做之前不许绕过）

- `automations` 表结构已只读核对：`id/name/prompt/status/schedule_type/next_run_at/last_run_at/cwds/rrule/scheduled_at/model_id/permission_mode/...`。
- 🔴 **禁止直接写 `workbuddy.db` 插入任务**：应用运行中写它的 SQLite 可能冲突/损坏，且绕过应用的校验。
- 正确做法：**先用 UI 建一次一次性任务验证链路**（prompt=派单摘要、cwd=项目、permission=fullAccess），然后只读核对 `automation_runs` / `automation_delivery_outbox` / `%TEMP%\workbuddy-prompts` 三处回执，确认后再谈自动化。

## 四、每次派单的固定动作（无论走哪条通道）

1. **L1 必做**：写卡 `docs/tasks/cards/…`（含回传格式块 + 派单人署名）→ 提交推送；
2. **L1 记忆追加**：在 `D:\Users\ZXQL\.workbuddy\memory\<date>.md` 追加派单摘要（指出卡路径为权威）；
3. 需要即时触达时再用 **L2/L3**，并在卡内记录"用了哪条通道 + 回执证据"；
4. 回传仍按 S1–S6；**证据只认可复跑**（命令/行号/run id/落盘文件），界面截图不作证据。

## 五、与既有规则的关系

- 本文件是《派单规范》R1–R8.2 的**通道补充**，不替代任何规则；
- 内部派单（我方执行方 + 内容已在卡里）**不需要业主确认**；对外/敏感/不可逆/与卡不一致的发送仍需业主决策；
- Computer Use 红线不变：不碰终端类应用、不碰 ChatGPT/Codex 自身窗口、不按 Windows 键、不自动化登录/密码/验证码。
