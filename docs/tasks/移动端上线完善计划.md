## 一、目标（上线门禁）
109 页全部满足：**布局对齐 / 全局 token / 单标题栏 / 图标正确 / 真实数据 / 空态正常 / 入口可达 / 角色可见 / 无回归 / build 全绿**。任何一项不达标 → 打回，不允许带上线。

## 二、每页必查 10 维（禁应付）
| # | 维度 | 检查点 | 手段 |
| --- | --- | --- | --- |
| 1 | 布局对齐 | 卡片/列表/表单 左右·上下间距统一（左 32rpx、卡距 20、圆角 16 等 token 观感） | 真载截图目检 |
| 2 | 全局 token | 写死 间距/圆角/阴影/颜色 是否清零（受保护选择器除外） | `rg` 写死值 + build |

| 6 | 真实数据 | 无 mock/假数据；接口已接；无数据处显示空态/`—` | 代码审 + 真载空态 |

## 三、需重点专项（已知风险，单独列）
1. **参数化详情页**（直连 `#/` 会被重定向，截图失真）：`orders/order-detail`、`notifications/notification-detail`、`products/product-detail`、`member-detail`、`batch-detail`、`check-detail`、`loss-gain-detail`、`group-buy-detail`、`seckill-detail`、`bargain-detail`、`role-edit`、`audit-detail` 等 → 需**带参数真载**或用真实列表点击进入验证，不能只截直连空页。
2. **入口一致性**：功能注册表 45 条 path 必须全部命中真实页面；缺失页面（客户授信/对账/拜访/收款、采购付款、门店管控、追溯召回、用户/租户/订阅/审批等）要么补页、要么明确不展示、不得留"开发中"占位。
3. **数据链路**：46 个 api/module 是否都有对应页面消费；接口返回结构 vs 页面绑定是否一致（不臆造字段）。
4. **标题栏全局去重**：历史遗留的"双标题栏"是否在所有子页清除。

## 四、验证方法（真载，非代看）
- `ui-shot.mjs`：`SHOT_VIEWPORT=319x645` + `store_manager` 演示号，全量真载截图。
- **详情页专项**：脚本注入查询参数（如 `?id=xxx`）或从真实列表点击进入截图；无真实数据时确认空态而非报错。
- 改前/改后对照，逐张人工目检（重点：对齐、间距、标题栏、图标、拍平）。
- `npm run build:h5` 全绿。
- 真机/浏览器走关键路径：登录 → 首页 → 功能 → 高频各子页 → 返回 → 我的 → 退出。
