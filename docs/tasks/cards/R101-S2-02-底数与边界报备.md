## 二、取证结论（三条硬事实，均可复核）

### 2.1 仓库已有「一个 config_key = 一个 JSON 包」的**既成用法**（非本次发明）

- `backend/src/services/platform/platform-sys-config.service.ts:12-14` 常量：`CONFIG_KEY="saas_settings"`、`PLATFORM="SAAS"`、`TENANT_ID="platform"`；
  `:46-64` GET 读 `config_value` 反序列化 + 缺省用 `DEFAULTS`（`:17-35`）补齐；`:67-102` PUT **整包 JSON upsert**（有则 UPDATE，无则 INSERT）。
- 前端 `saas-admin/src/api.ts:216-222` 的 `getPlatformConfig/updatePlatformConfig` 正是打 **`/platform/config/sys-config`**；`saas-admin/src/views/Settings.vue` 的「保存全部」用的就是它。
- 结论：**JSON 包塞 KV 在本仓库已上线运行**，且是 08 系统配置页当前的唯一真实保存通道。

### 2.2 现有 KV 存储两张，各有边界

| 表 | 唯一键 | 能否承载多配置域 | 定义位置 |
|---|---|---|---|
| `t_sys_config` | `(config_key, tenant_id)` ✅ | 一维 KV；`config_group` 只是分组标签，非业务维度 | `docs/init_database.sql:31-44` |
| `t_platform_config` | `(platform, store_id, tenant_id)` ❌ **不含 config_key** | 同键只能存一行 → 只能整包 JSON | 建表 `docs/migrations/074_即时零售表.sql:7-26`；加列 `docs/migrations/152_business_columns_fill.sql:84-88` |

- `t_platform_config` 现列 = 074 的 14 列 + 152 的 5 列（`category/config_key/config_value/description/updated_by`），**共 19 列**。
- 要在它上面存**多个**配置域，须补唯一索引（`ALTER ... ADD UNIQUE`，**非新表**）或改走 `t_sys_config`；矩阵类（套餐×28 开关、层级×档位分润）无论哪条路都只能**序列化进 JSON**。

### 2.3 有结构化列可直接复用的，只有「套餐」一项

`t_subscription_plan`（`docs/migrations/030_add_subscription_plan.sql:2-25`）已有：
`plan_code/plan_name/plan_type/price/original_price/duration_days/max_users/max_stores/max_customers/max_products/max_storage_mb/features(JSON)/module_access(JSON)/sort_order/status`；
端点已存在：`GET/POST/PUT/DELETE /api/platform/plans`、`PUT /api/platform/plans/:planId/features`（`backend/src/routes/platform-plans.routes.ts:12-27`）。
**缺**：`api_quota`/`ai_quota` 两列（设计稿 03 资源配额需 6 项）、升降级与续费规则字段。
