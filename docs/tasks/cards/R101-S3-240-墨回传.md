## 六、风险与自我报备

1. **`permissions` 语义由 `[]` 改为 `null`**：老版本本地缓存（`admin_app` 里 `permissions: []`）在升级后首屏会**先把按钮藏掉**，导航触发 `ensurePermissions()` 拉 `/admin/auth/me` 后恢复。若该接口不可达（离线/后端异常），按钮会**保持隐藏**（失败关闭）——这是与 S3-231 F3 一致的有意选择，但**属于可感知的行为变化**，报备。
2. **`hasPermission()` 语义变化**：由 `includes()` 改为通配匹配。全仓**当前无其它调用点**（`rg hasPermission admin-web/src` 仅 store 自身定义），故无连带影响；但后续若有人依赖"严格等于"语义，需知会。
3. **登录响应字段路径**：`LoginView` 同时兼容 `user.permissions` 与顶层 `permissions`（`res.data?.user?.permissions ?? res.permissions ?? res.data.permissions`）；后端当前是 `data.user.permissions`（`auth.service.ts:190`）与 `/me` 的 `data.permissions`（`:252`）⇒ 两条路径都覆盖。
4. **`ensurePermissions()` 只在"未取到"时发请求**：一旦成功即置 `permissionsLoaded` 并持久化 ⇒ 正常会话**零额外请求**（不引入每次导航的 `/me` 轮询）。
