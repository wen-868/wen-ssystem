## 一、裁定 1：剩余 6 处漏点（webhook 4 / 订阅申请 1 / 报表权限矩阵 1）——**按三类分别处置**

依据：`docs/evidence/B-2b/影响面清单.md` 第三节第 16–21 行；`docs/evidence/B-2b/其他漏点处理建议.md` §二。
事实前提（凌舟已复核）：这 6 处的卡点**不是授权**，而是"**该单据的租户取值来源在现有代码里不存在**"（函数无 `tenantId` 形参 / 配置解析不带租户 / 同事务主表 `t_platform_order` 本就无该列）。

### 1.1 `t_miniapp_order` / `t_miniapp_order_item`（即时零售 webhook，4 处）⇒ **采方案 A（显式声明平台级）**

- 位置：`backend/src/services/admin/instant-retail.service.ts:307/324`、`backend/src/services/instant-retail/platform-integration.service.ts:102/119`。
- **裁定**：明写 `tenant_id` 并取平台租户值（`'default'`），**同时补中文注释**说明"外部平台 webhook 无租户上下文，统一落平台租户；按门店/租户归属属功能变更，见 S3-87"。
- **性质声明**：这是**把隐式行为变显式**（改前落库值同为 `'default'`），**不是数据修复**，不得记为"修复了跨租户数据"。
- **实施归属**：随 **B-2c** 小卡（P2，边界=上述 4 处 INSERT + 注释）执行；**不并入 B-2b 的验收口径**。

### 1.2 `t_platform_subscription_apply`（`backend/src/services/platform-miniapp.service.ts:172`）⇒ **采方案 A 同型**

- **裁定**：同上（显式平台租户值 + 注释 + 登记 S3-87 的真归属议题）。随 **B-2c** 执行。

### 1.3 `t_report_permission_matrix`（`backend/src/services/admin/report-permission.service.ts:27`）⇒ **单独立卡 S3-86，本轮不动**

- 事实：`getMatrix()` 用普通 `query()` **无任何租户条件**；`saveMatrix()` 先 `DELETE FROM t_report_permission_matrix WHERE 1=1`（**跨租户清全表**）再重插。
  ⇒ 现状是"**全局唯一一份矩阵**"，单点补 `tenant_id` 会制造"写带租户、读/删不带"的自相矛盾。
- **裁定**：属**租户隔离缺口**（性质重于本条 B-2b 的"漏列静默写默认值"），须**读 / 写 / 删 / 控制器传参四处一起改 + 反测**，另行立卡 **S3-86**（P1）。
- **禁止**在本轮以"补一列"方式糊过去；也不得为过验收而放宽 `DELETE` 条件。
