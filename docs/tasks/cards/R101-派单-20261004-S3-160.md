# 【派单 S3-160】（P0）登录支持「记住我」= 长效 token（商家端），不再每次打开都要重登（后端）
（落卡时间：2026-10-04｜凌舟）

```
【派单 S3-160】商家端登录接口支持 rememberMe：勾选 ⇒ 下发**长效 token（30 天）**，不勾 ⇒ 维持现状 4h。**不得**全局把 4h 改成 30 天（那等于对所有会话放松安全边界）；**不改表、不加 refresh 机制**（refresh 属新机制，另立项）。

一、事实（凌舟已核实，不得再自拟）
  ① 商家端 JWT 有效期 = **4h**：`backend/src/middleware/auth.ts:71-78` `signToken()` 里 `expiresIn: "4h"`（平台端 `signPlatformToken` 为 8h，**本单不动**）。
  ② 登录入参目前**只有** username/password：`backend/src/controllers/admin/auth.controller.ts:8-12`（zod `{username, password}`）→ `authService.login(username, password)`；`server.ts:219-221` 注册了 `/api/admin/auth/login` 与 `/api/store/auth/login` 两条路径（同一 controller）。
  ③ 前端过期行为**正确**（401 ⇒ 清 token + 跳登录，`app-mobile/src/api/request.ts:103-118`）⇒ 症状根因就是**token 太短**，不是前端错了。
  ④ 全仓**无 refresh token** 机制（`rg refresh` 在 routes/service 0 命中）⇒ 本单不引入。

二、范围（钉死）
  **做**：
   · ① `signToken` 增**可选** TTL 参数（默认保持 `"4h"` 不变，不传参数时行为与现在**逐字一致**）。
   · ② 登录链（`auth.controller.login` → `authService.login`）接受可选 `rememberMe?: boolean`；`true` ⇒ 用**30 天**签发，`false`/缺省 ⇒ 4h。
   · ③ 响应里如实回一个字段说明本次签发的是长效还是短效（例如 `rememberMe: true` 或 `expiresIn`），便于前端与验收核对；**不得**回传任何密钥类信息。
   · ④ 单测：`rememberMe=true` ⇒ 解出的 `exp` ≈ 30 天；`false`/缺省 ⇒ ≈ 4h（**两条都要**，且用真实 `jwt.verify` 解，不许只断言 mock 调用参数）。
  **不做**：不改表、不加 refresh、不改平台端 TTL、不改密码策略、不改前端（前端另单 S3-161）、不改其它接口。
```
