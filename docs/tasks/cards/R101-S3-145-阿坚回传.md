## 一、方案选择与理由（派单「二选一」）

**选方案甲**（交接班列表改读 `t_shift`，与详情/统计/盘点同源），**不选方案乙**（详情端点兼容两种编号源）。

理由（语义边界见「附 B」）：

1. `t_shift`（交接班记录，`shift_no` = `JB…`，`status` = OPEN/CLOSED，含 `operator_name`/`start_time`/`end_time`/`opening_cash`）与 `t_daily_settlement`（班结/日结快照，`shift_no` = `BJ…`，唯一键 `(settle_date, store_id, tenant_id)`，含 `total_sales`/`cash_amount`/`wechat_amount`…，`status` 恒 `COMPLETED`）**不是同一个对象**：一个是"一次交接班过程"，一个是"某日该门店的结算快照"。
2. 方案乙要把两类记录混进同一组端点，正是派单要防的"用兼容掩盖语义差异"；且 `t_daily_settlement` 的行在 `t_shift` 侧无对应主键（只能靠日期猜拼），会造出"列表能点、详情是拼的"的新假象。
3. 方案甲只需 1 个只读端点（凌舟附注 1 的授权范围：**至多 1 个只读列表端点 `GET /api/store/shifts`**），且列表字段在 `t_shift` 上都有对应列（`shift_type` 除外，见「附 A」缺口②）。

**端点预算**：本次**只新增 1 个只读端点** `GET /api/store/shifts`（`store-shift.routes.ts:15`）。除此之外**零新增端点**；未造假数据、未桩化业务分支。

## 附 B：语义边界（`t_daily_settlement` 班结 vs `t_shift` 交接班）

| 维度 | `t_daily_settlement`（班结 / 日结快照） | `t_shift`（交接班记录） |
|:--|:--|:--|
| 是什么 | 某门店**某日**的收款/销售**结算快照** | 一次**交接班过程**（谁接班、何时开始、何时结束、备用金） |
| DDL | `docs/migrations/124_drift_tables_fill.sql:108` | `docs/migrations/148_shift_stock_check.sql:1` |
| 关键列 | `settle_date`、`shift_no`、`total_sales`、`total_received`、`cash_amount/wechat_amount/alipay_amount/transfer_amount/other_amount`、`status` | `shift_no`、`operator_id`、`operator_name`、`start_time`、`end_time`、`status`、`opening_cash` |
| 唯一键 | `uk_daily_settlement_date (settle_date, store_id, tenant_id)` | `uk_shift_no (shift_no, tenant_id)` |
| 状态取值 | `status` 恒 `'COMPLETED'`（写入即终态） | `OPEN` / `CLOSED`（有生命周期） |
| 编号前缀 | `BJ…`（`settleShift`：`makeBizNo("BJ")`，`shift.service.ts:130`） | `JB…`（`createShift`：`makeBizNo("JB")`，`shift.service.ts:281`） |
| 写入方 | `settleShift`（`POST /store/shift/settle`）；`daily-settlement.service.ts` 亦写 | `createShift`（`POST /store/shifts`） |
| 读取方 | `getShiftHistory`（`GET /store/shift/history`）；`admin/daily-settlements`（日结页） | `getShiftList`（`GET /store/shifts`）、`getShiftDetail`、`getShiftSalesStats`、`getShiftStockCheck`/`submitShiftStockCheck` |
| 入口区分 | 工作台**日结**入口走 `/admin/daily-settlements`；`/store/shift/history` 保留为班结历史（工作台"交接班管理"页已不再使用它） | 工作台**交接班管理**页 → `GET /store/shifts` |

**结论**：两者**不是同一个对象**（"一次交接班过程" vs "某日结算快照"；唯一键、状态语义、编号前缀、写入方均不同）⇒ 按派单"若语义不同，不得用兼容把两者混为一谈"，**不做方案乙**。两表之间目前**没有**可直接对齐的外键（`t_daily_settlement.shift_no` 存的是 `BJ…` 自身单号，不是 `t_shift.shift_no`）——这也正是原缺陷的成因。
