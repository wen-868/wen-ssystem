### 1.1 改了什么（哪里有问题 → 改了什么 → 为什么）

**问题一：丢块（仍在 main）**

* 哪里有问题：外部迁移段按 `;` 切块后 `.filter((s) => s.length > 0 && !s.startsWith("--"))` —— **块首是注释、其后是真实语句**的块被**整块**丢弃（第 8 步，HEAD 行号 `:1028-1031`；5.5.8 AI 底座兜底建表 HEAD 行号 `:881-884` 同一缺陷）。
* 改了什么：抽出具名函数 `splitSqlStatements(sql)`，**先剥离块首整行注释（`/^(\s*--[^\n]*(\n|$))+/`）再判空**，剥离后为空的纯注释块仍然丢弃；语句中间/末尾的行内 `--` 一律不动（不做行内 `--` 解析，保守）；两个调用点统一改用它。
* 为什么：只改"判定是否为空"这一步，不碰 `USE`/`DELIMITER` 预处理、不碰 `CREATE PROCEDURE`、不碰 `DROP TABLE` 生产保护 —— 把改动面压到"切分判空"一处，反测可逐条对应（详见 §2.4）。

**问题二：`addTablePrefix` 同族（#14 漏模式 + #17 过宽）**

* 哪里有问题：① 无 `REFERENCES` 模式 ⇒ `FOREIGN KEY (x) REFERENCES tenant(id)` 里的 `tenant` 不加前缀（全新/灾备库报 `Failed to open the referenced table 'tenant'`）；② 通用 `/(INTO\s+)(...)/` 过宽 ⇒ `SELECT COUNT(*) INTO col_count`（092 过程变量）被误改成 `t_col_count`（`Undeclared variable`）。
* 改了什么（**只动这三条模式，其余 8 条模式与替换体一字未改**）：`INSERT_INTO` 补 `(?:IGNORE\s+)?`、通用 `INTO` 收窄为 `REPLACE_INTO`、新增 `REFERENCES`；全套模式保持"反引号 + 裸名"双形态（MIG-2 形态）。
* 为什么：`INSERT IGNORE INTO x` 过去**依赖那条过宽的通用 INTO** 才被加前缀，收窄前必须先补上它，否则会"修一个洞、开一个洞"（全仓 `INSERT IGNORE INTO` 实测 **31 处**）；`REPLACE INTO` 作为被收窄模式的补偿项保留（全仓 0 处，属防回归而非新增改写）。
