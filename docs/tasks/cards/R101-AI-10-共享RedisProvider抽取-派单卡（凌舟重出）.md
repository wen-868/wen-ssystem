背景与依据（**凌舟已在 `3ea5c34` 上独立复核**，非估算）：
全仓 `new Redis(`（排除 spec）**恰好 5 处**：

| 位置 | 用途 | retryStrategy | 降级行为 |
|---|---|---|---|
| `src/brain/graph/checkpointer.service.ts:45` | 图状态持久化 | `times > 3 → null`（停止重连） | 内存降级：跨进程不可续跑 |
| `src/brain/write-guard.service.ts:267` | 写审核令牌互斥 | `times > 3 → null` | 内存降级：令牌不跨进程 |
| `src/common/rate-limiter.ts:129` | 限流令牌桶 | `times > 3 → null` | 内存令牌桶 |
| `src/brain/memory-manager.service.ts:75` | 对话记忆 | `Math.min(times*500, 5000)`（**持续重试**） | 记忆降级 |
| `src/gateway/admin.controller.ts:457` | 健康检查探针 | `() => null` + `connectTimeout: 3000` | **每次调用新建再销毁** |

**目标**：抽出**一个** Redis 连接来源供上述模块共用，**连接数 5 → 1**，且**每个模块的降级行为一字不变**。
**不做的后果**：幂等键落地后变 6 份独立连接池（各自 `maxRetriesPerRequest`、各自重连风暴），`/api/admin/ai/health` 的 Redis 健康检查同时失真。

交付物（逐条可核对）：
1. 共享 Redis provider（建议落在既有 `src/common/` 或 `src/database/` 邻近层），**支持调用方各自的重试策略**（上表 3 种语义必须都能表达）
2. 5 处调用点改为取用共享实例；**`src/gateway/admin.controller.ts:457` 的"每次新建"语义需显式评估**：若改共享，必须说明对健康探针的影响或保持原语义
3. 全仓 `new Redis(`（排除 spec）应降为 **1**（provider 自身）；若保留 2 处，逐条说明理由
4. 各模块**降级路径**（Redis 不可用 → 内存/跳过）保持不变，且有断言覆盖

验收标准（硬）：
1. `tsc -p tsconfig.json --noEmit` exit 0；`eslint "src/**/*.ts" --max-warnings=0` exit 0；`jest --ci` 全绿且套件/用例数**不低于 133 / 1448**
2. **反测（必做）**：任取 2 个调用点改回 `new Redis()` ⇒ 必须有断言变红（证明"共用"是被守护的）；给原始输出
3. 证据：`new Redis(` 计数前后对照（命令 + 输出）；连接数变化说明
4. 每个模块的降级行为**逐条对照上表**给出"未改变"的证据（断言或代码引用）
