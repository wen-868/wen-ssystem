## 二、判定口径（唯一口径，用于自证计数）

> 说明：33 处里存在"注释行 + `ElMessage` 文案"成对重复（同一诉求两行），逐行判定会产生重复计数；为兼顾"逐条判定"与"不虚报工作量"，采用下列固定口径，并另给去重后的独立诉求表（§六）。

1. **规则 A（文案/注释行）**：该行只是描述性文案或注释，且其引用的端点**在网** ⇒ 判 **③**（前端自身：文案过时/待接线），同时在依据列给出该端点在网的证据，**不隐藏 ① 事实**。
2. **规则 B（诉求行）**：该行要求一个**不存在**的端点（路由零命中）⇒ 判 **②**，并注明 DDL 影响（零 DDL / 需新表 / 需裁定）。
3. **规则 C（成对重复行）**：同一诉求的"注释行 + 文案行"**同判**、按行计数；独立诉求数另见 §六。
4. **规则 D（区块注释）**：纯分组注释（如 `====== Tab2 … ======`）**不产生新接口诉求**，其聚合的后端缺口已在对应编号行判过（避免同一缺口重复计入 ②）⇒ 判 **③**，并在依据列写明"该缺口见 Rx"。
5. **规则 E（混合行）**：一行内同时引用了**在网**与**缺失**端点 ⇒ 按"是否仍存在后端缺口"判；判 **②**，并在依据列逐端点拆分（M13 即此类）。
6. **不计"返回空数组"为已实现**：判 ① 必须同时满足（a）路由挂载行、（b）控制器/服务函数实体、（c）服务函数**真查库**（SQL 行号）；只有前端"看起来有数据"不构成证据。
