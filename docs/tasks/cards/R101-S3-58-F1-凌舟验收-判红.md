## 一、结论

**本单若上线，会让平台控制台（saas.onepan.cn）所有平台管理员无法登录（HTTP 500）。**

回传卡自称「**零 DDL**」—— 与生产实际 schema 直接冲突，是本次判红的唯一根因。

## 二、反例（证据链三步，均可复跑；全部只读，未改生产任何数据）

| # | 手段 | 原始结果 |
|:--:|:--|:--|
| 1 | 生产只读 `SHOW COLUMNS FROM t_platform_admin` | 实际列为 `id / username / password_hash / real_name / email / phone / role / status / last_login_at / created_by / created_at / updated_at` —— **没有 `mfa_enabled`，也没有 `mfa_secret`** |
| 2 | 生产只读执行 `backend/src/services/platform/platform-auth.service.ts:52` 的 **SELECT 原文** | ``ERROR 1054 (42S22) at line 1: Unknown column 'mfa_enabled' in 'field list'`` |
| 3 | 全仓搜 DDL 与自动补列 | ``rg -i 'mfa' docs/migrations`` ⇒ 仅 `150_mfa.sql`，且它只给 **`t_sys_user`** 加列；``rg 'platform_admin' backend/src/shared/migration.ts`` ⇒ **0 命中**（无自动补列机制） |

⇒ 部署后 `login()` 第 51–54 行即抛 1054 ⇒ 控制器 500 ⇒ **平台端全员登录失败**；`getMe()`（第 90 行）同因。

## 三、为什么本单"测试全绿"却没拦住

mock 层的 `t_platform_admin` 是按 **SQL 片段匹配**返回的**内存行**（`backend/src/__tests__/mocks/mock-db-system.ts:192-198`），`mfa_enabled` 取到 `undefined` ⇒ `Number(undefined) === 1` 为 false ⇒ 走"默认不强制"分支 ⇒ **测试永远绿**。

这是「**mock 掩盖真实 schema**」同族缺陷：mock 只匹配 SQL 片段、不校验列是否存在。已按踩坑纪律登记（见 §六）。
