【派单 R101-AI-09】AI 单价**产品化写入入口**（平台身份专属）+ 权限收口
派单人：凌舟（总负责人）｜2026-10-09
执行方：阿坚（后端架构 + DDL）（仓库 `D:\Users\ZXQL\ZXQL-AI`）
优先级 / 时间盒：P1 · 1 天

背景与依据（只写已取证的事实）：
- R101-AI-07 已落地读取侧：`t_ai_model_price`（迁移 **`015_ai_model_price.sql`**，凌舟已在 scratch MySQL 8.0.28 上**连跑两遍 exit 0、幂等**，结构含 `uk_ai_model_price_provider_model_effective (provider, model, effective_from)` + `idx_ai_model_price_lookup`）与 `AiConfigService.getModelPrice(provider, model) → ModelPrice | null`（未配置返回 null，**绝不回落 0**）。
- 但**只有读取通道，没有写入通道** ⇒ 目前只能靠运维 DML 手工插价格。**单价是平台的成本/售价口径，属平台级配置**。
- 参照已收口的口径：平台级端点必须显式判平台身份（`src/gateway/ai-config.controller.ts:59-70` 的 `requirePlatformIdentity`；`src/gateway/external-model.controller.ts` 已按此收口）。
- **裁定**：本项**另立卡**（不并入 R101-AI-03）。理由：R101-AI-03 是「改造写入侧把 cost 落库」，本单是「新增配置能力 + 权限收口」，文件域与回滚单元都不同（R1 一单一卡）。

交付物（逐条可核对）：
1. 管理端**读写接口**（建议挂在既有 `/api/admin/ai-config/` 下，与 `ai-*` 配置同族）：
   - 列表：按 provider/model 过滤，返回 `ModelPrice[]`
   - 新增/调价：插入新 `effective_from` 行（**不覆盖历史**，靠唯一键留调价痕迹）
   - 停用/启用：`enabled`
2. **权限收口**：全部端点**必须显式判平台身份**（`identityType !== 'platform'` → 403 + `aiError('AI_010')`），**不得只挂 `AdminGuard`**（P0-1 的教训）
3. DTO 校验：`prompt_price` / `completion_price` **> 0 或显式 0（免费档）**，禁止负数；`provider` / `model` 与 `t_ai_usage_daily` 同口径；`currency` 默认 `CNY`
4. 契约文档：`docs/API接口文档.md` 补端点；`migrations/README.md` 不新增迁移（**本单零 DDL**）

验收标准（硬）：
1. `tsc` / `eslint` / `jest` 三门禁（不低于上一稳定基线，全绿）
2. **反测逐条**：① 撤销平台身份判定 ⇒ 商家身份调用变红；② 关闭价格校验（允许负数）⇒ 断言变红；③ 调价走 `UPDATE` 覆盖旧行而不是插新行 ⇒ 调价留痕断言变红
3. 正例：平台身份可增删改查；商家身份一律 403

红线：
- **不得只挂 `AdminGuard`**；不得放宽为"任意管理角色"
- **不得改 `t_ai_usage_daily` / R101-AI-03 的写入语义**（那是 R101-AI-03 的范围）
- **禁止硬编码价格表、禁止在迁移里塞价格数值**
- **禁止 `git stash` / `checkout` / `reset`**（两端共用工作区，踩坑 **[165]**）
- 不得代写裁定/验收卡（§8.8）；回传不得自拟格式
