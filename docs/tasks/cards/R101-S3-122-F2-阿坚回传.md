## 七、真机复跑命令（验收标准⑥；凌舟在本机执行）

> 踩坑[34]提醒：写请求若不带 `x-csrf-token`，会被**挂载层 CSRF 先拦成 403**（与权限 403 同码不同文案）⇒ 命令必须带 CSRF 并**断言 403 的 msg**；另外路径本身是否存在不能用 403 判定。
> 登录响应里已含 `csrfToken`（`services/admin/auth.service.ts:207`），直接用即可。

```bash
API=https://api.onepan.cn   # 按实际域名替换

# 0) 目标 ref（R8.2）：先确认本单产物所在分支/提交存在，再验证
git ls-remote origin <本单分支名>   # 需与凌舟提交后的 ref 一致

# 1) 只读账号 smoke_bot（READONLY = ["*:view"]）调 G0 写 ⇒ 期望 403 + msg=权限点
L=$(curl -s -X POST "$API/api/store/auth/login" -H 'Content-Type: application/json' \
     -d '{"username":"smoke_bot","password":"<凌舟口令>"}')
T_RO=$(echo "$L" | jq -r '.data.token'); C_RO=$(echo "$L" | jq -r '.data.csrfToken')
curl -s -o /tmp/ro.json -w '%{http_code}\n' -X POST "$API/api/store/inventory/adjust" \
  -H "Authorization: Bearer $T_RO" -H "x-csrf-token: $C_RO" -H 'Content-Type: application/json' \
  -d '{"skuId":999999,"stockType":"OFFLINE","change":0,"remark":"perm-probe"}'
# 期望：403，body.msg = "无权限执行此操作，需要权限: inventory:adjust"
# 若 200 ⇒ 接线未生效（红）；若 403 但 msg 含 "CSRF" ⇒ 是 CSRF 伪影，需带 token 重跑

# 2) 超管（SUPER_ADMIN = ["*"]）调同一端点 ⇒ 期望非 403（会写库存流水，凌舟自行清理）
#    建议用 skuId=999999 + change=0，执行后按踩坑[136]的方式核对并删除 t_inventory_ledger 新行
A=$(curl -s -X POST "$API/api/store/auth/login" -H 'Content-Type: application/json' \
     -d '{"username":"<超管账号>","password":"<口令>"}')
T_AD=$(echo "$A" | jq -r '.data.token'); C_AD=$(echo "$A" | jq -r '.data.csrfToken')
curl -s -o /tmp/admin.json -w '%{http_code}\n' -X POST "$API/api/store/inventory/adjust" \
  -H "Authorization: Bearer $T_AD" -H "x-csrf-token: $C_AD" -H 'Content-Type: application/json' \
  -d '{"skuId":999999,"stockType":"OFFLINE","change":0,"remark":"perm-probe"}'

# 3) 域通配符（F1 产物）在 G0 上生效：店长（inventory:*）/仓管 调同上 ⇒ 期望非 403

# 4) 未登录 ⇒ 401；公开/回调端点未被误伤
curl -s -o /dev/null -w '%{http_code}\n' -X POST "$API/api/store/inventory/adjust" -H 'Content-Type: application/json' -d '{}'  # 期望 401
curl -s -o /dev/null -w '%{http_code}\n' -X POST "$API/api/pay/wx/callback" -H 'Content-Type: application/json' -d '{}'         # 期望非 401/403

# 5) 未纳入 G0 的端点未被误伤（READONLY 仍可过权限门；具体业务码由业务层决定）
curl -s -o /dev/null -w '%{http_code}\n' -X POST "$API/api/admin/purchase-orders/" \
  -H "Authorization: Bearer $T_RO" -H "x-csrf-token: $C_RO" -H 'Content-Type: application/json' -d '{}'  # 期望非 403(权限点)

# 6) 回归（原配置，凌舟本机）
cd backend && npx tsc -p tsconfig.json --noEmit && npx eslint src/routes --ext .ts && npx vitest run
```
