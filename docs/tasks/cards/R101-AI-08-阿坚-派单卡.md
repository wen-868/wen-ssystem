【派单 R101-AI-08】把出站目标守卫收敛到「商家可写」的 AI 配置端点链路（补 P1-1 的覆盖面缺口）
派单人：凌舟（总负责人）｜2026-10-09
执行方：阿坚（后端架构）（仓库 `D:\Users\ZXQL\ZXQL-AI`，**基线 `da2d5dd`**）
优先级 / 时间盒：P1 · 半天

背景与依据（凌舟已取证的事实）：
- `outbound-target.guard` 的**生产引用点只有两处**（全仓 grep 实证）：`src/providers/openai-compat.provider.ts:32-33`（外部模型）与 `src/tenant/external-model.service.ts:34-36`（外部模型管理/测试）。
- 但**另一条链路完全没走守卫**：`src/tenant/ai-config.service.ts:167-169` 的 `baseUrl = tenantApiKey ? tenantConfig.apiEndpoint : platformConfig.defaultEndpoint` → 经 `src/brain/router/provider-router.service.ts:119-122` `factory.create(provider, providerConfig)` → `src/providers/deepseek.provider.ts:172-182` `configure({baseUrl})` → axios **直接 POST 到该 baseUrl**（glm / ollama 同构）。
- 而 `t_tenant_ai_config.api_endpoint` 是**商家管理员可写**的：`src/gateway/ai-config.controller.ts:159-167` + `requireTenantAccess`（商户锁本租户）。
  ⇒ **任一租户管理员仍可让 AI 底座向其自选（含内网）地址发起请求**。P0-2 只把"密钥↔端点"绑成同源，**"同源"不等于"公网"**，P1-1 也没覆盖这条链路。

交付物：
1. 把**商家可写**的端点链路接入同一守卫（**复用 `assertAllowedOutboundUrl` / `createGuardedLookup`，不得另写第二套实现**）：
   - `AiConfigService.resolveFromTenant` 产出的 `providerConfig.baseUrl`
   - 以及运行期真正发请求的 provider 路径（glm / deepseek / ollama 的 axios 出站点）
2. **信任边界要分清**（红线级）：
   - **商家可写的 `t_tenant_ai_config.api_endpoint`** ⇒ 必须过守卫（拒绝即显式失败或显式回落平台端点 + WARN，**不得静默拼接**）
   - **平台 `t_platform_ai_config.default_endpoint`**（平台管理员维护）⇒ **本卡只做"记录 + 告警"，不得擅自拒绝**；凌舟无法读取生产该值（见下），贸然拒可能误伤生产链路 ⇒ 若你要固化它，先报备
3. 拒绝时打印**被拒的 host + 命中规则**（便于生产上线后从日志一眼定位）。

**凌舟已有的生产证据（供你判断"会不会打断现有链路"）**：
- 生产 `GET /api/chat/models`（我用公开演示账号只读取证）返回 **只有 3 个内建模型**（glm / deepseek / ollama），**没有任何外部模型**（`chat.controller.ts:71-108` = `[...builtin, ...externalModelService.options()]`，`options()` 只返回启用项）⇒ 外部模型链路当前生产为空。
- 生产 `/ai-api/api/health/ready` = **200 / `ready`**，main + ai_db 表列零缺失。
- ⚠️ **平台/租户端点实际取值凌舟拿不到**（平台登录有图形验证码，Redis 一次性 5 分钟；本机无服务器 SSH/DB 凭据）⇒ 这一点**你必须先取证再动手**：至少证明"生产当前没有配置内网端点"或"配了但只影响哪条链路"，**拿不到依据就停下报备**。

验收标准（硬）：
1. `tsc` / `eslint` / `jest` 三门禁（**不低于 130 套件 / 1421 用例**，全绿）
2. **反测逐条**：对"商家 apiEndpoint 指向内网/`http:`"给出「回退守卫 ⇒ 断言变红」原始输出；并含**正例**（合法公网 HTTPS 端点放行）
3. 平台端点路径的"记录+告警"行为有断言或可复跑证据

红线：
- **复用同一守卫，不得写第二套判定**（否则两套口径必然分叉）
- **不得擅自拒绝平台 `default_endpoint`**
- 不得改 P0-2 的"密钥↔端点同源"语义
- **禁止 `git stash` / `checkout` / `reset`**（两端共用工作区，踩坑 **[165]**）
- 不得代写裁定/验收卡（§8.8）；回传不得自拟格式
