## 一、先说一条硬约束（业主需知）：`admin123` 无法被产品设为租户密码

产品的密码策略在代码里写死：`backend/src/shared/password.ts:58-86` 要求
**≥8 位 + 含字母 + 含数字 + 含特殊字符**（`if (!/[^a-zA-Z0-9]/.test(password)) errors.push("密码必须包含特殊字符")`）。

`admin123` = 8 位、字母 + 数字、**无特殊字符** ⇒ 走 `POST /api/admin/sys-users/:id/reset-password` 会被 `validatePassword` 直接 **400 拒绝**（控制器 `sys-user.controller.ts:70-84`）。

⇒ **"把 admin/admin123 设成租户登录密码"这条字面要求，会被产品自身的门禁挡住**；绕过它（改策略或直写 `password_hash`）等于自己砸自己的门禁，**凌舟不做**。替代方案见 §三。

## 五、追加实证（2026-10-03 23:23 / 23:38 / 23:40 三次探测）

`POST /api/admin/auth/login`（`admin`）三次单发探测的返回：

| 时刻 | 返回 |
|:--|:--|
| 23:23 | `400 {"msg":"登录失败次数过多，账号已锁定15分钟"}` |
| 23:38 | `400 {"msg":"账号已锁定，请10分钟后重试"}` |
| 23:40 | `400 {"msg":"账号已锁定，请8分钟后重试"}` |

**读数**：锁定**不是一次性过期**，而是在被**不断续期**（15 分钟 → 10 分钟 → 8 分钟，倒计时被反复重置），配合库内 `login_fail_count=36` ⇒ **该账号正在被公网持续爆破**。

**两个结论（都影响业主决策）**：
1. **S3-58 不是"理论风险"而是"正在发生的攻击"** —— 建议把"公网暴露 + 弱/固定口令的超管账号"提到**最高优先级**处置（轮换 + 收敛入口 + 观察期）。
2. **把 `admin` 当作演示账号在工程上不可靠** —— 它的登录会被外部爆破反复锁死，演示随时可能失败。演示请走 §三.1 的**免密通道**（不受爆破影响）。
