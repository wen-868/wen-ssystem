## 一、缺陷本体（两层，第二层更隐蔽）

### 第一层：生产构建从未注入 `VITE_AI_BASE_URL`

`saas-admin/.env.development` 存在（`VITE_AI_BASE_URL=http://localhost:3016`），
但**没有 `.env.production`** → 生产构建时该变量为空。

> ⚠️ 侦察更正：我最初报"saas-admin 下无任何 `.env*`"是**错的**
> （工具漏检点文件，实际 `.env.development` 一直在且已入库）。
> 正确的表述是：**缺的是 `.env.production`，不是缺所有 env 文件**。

### 第二层（更隐蔽）：未注入时**静默回退 localhost**

`saas-admin/src/api/ai-config.ts` 原实现：

```ts
const configured = import.meta.env.VITE_AI_BASE_URL;
if (configured) return configured.replace(/\/+$/, "");
return "http://localhost:3016";   // ← 生产也走这里
```

**浏览器**会把 `http://localhost:3016` 解析成**访问者自己的机器** → 请求必然失败，
且界面无任何提示。比"缺注入"更危险：**它是静默故障，从现象上极难归因**。

## 二、凌舟裁定（值已核定，非猜测）

服务器 `nginx -T` 实测：四个 server 块均配 `location /ai-api/ → proxy_pass http://127.0.0.1:3016/`
（`api.onepan.cn` 207/228、`admin.onepan.cn` 243/272、`m.onepan.cn` 291/320、`saas.onepan.cn` 376/405）。

| 文件 | 值 | 说明 |
|---|---|---|
| `saas-admin/.env.production` | `VITE_AI_BASE_URL=https://saas.onepan.cn/ai-api` | **同源**，避免跨域 |
| `saas-admin/.env.development` | `http://localhost:3016` | **不动**（本地直连） |

**不照抄桌面端的 `admin.onepan.cn/ai-api`** —— 那是桌面端入口域名；总后台用同源
`saas.onepan.cn/ai-api` 符合"谁部署谁验证"。

**硬化要求**：生产未注入 → **不回退 localhost**，返回空值并明确提示
「AI 服务地址未配置（VITE_AI_BASE_URL）」；dev 保留回退。

## 六、教训

1. **"未配置就给个默认值"在生产是反模式** —— 它把配置缺失伪装成网络故障。
   生产路径上缺关键配置应当**显式失败并点名变量名**。
2. **`.gitignore` 会静默吃掉你的修复** —— 新建环境类文件后，
   必须 `git check-ignore -v <file>` 确认它真能入库。
3. **点文件侦察要用目录列举，不能只靠 Glob**（本次导致误报"无任何 .env 文件"）。
