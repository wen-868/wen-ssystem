## 二、新表 / 复用 —— 裁定

1. **只批 2 张新表**（`CREATE TABLE IF NOT EXISTS`、零外键、语句在注释之前）：
   - 增值扣费流水（**建议名 `t_platform_addon_charge`**）；
   - **调用量日统计 —— 与 C3 的 `t_open_api_call_daily` 共用同一张表**（不得建同义表，避免"两个真相源"）。
2. **工单表本轮不建**：工单系统属 C6 范围（`ops/TicketSystem`），本批只做对账/监控；登记后由 C6 统一建表，避免同一域两次 DDL。
3. **其余"复用 vs 新建"6 处：一律优先复用既有表**；确需新表的，**必须先在回传里给出"既有表为何不能承载"的证据**（表名 + 列 + 冲突点），由凌舟逐条批。
4. **禁区（沿用既有裁定）**：不得 `ALTER` 任何既有表的既有列；不得新建与既有表语义重复的表；不得建外键。

## 三、3 条红线级事实 —— 处置

| # | 事实 | 处置 |
|---|---|---|
| 1 | `POST/PUT /api/platform/reconciliation` 是**租户级语义却挂平台前缀**，且读 `req.tenantId`，而 `requirePlatformAuth` **不注入 tenantId**（恒 `undefined`） | **本轮不改**，登记 **S3-86 家族**（"无权威租户来源"）；C4-1 中**不得**照抄该写法 |
| 2 | `t_platform_reconciliation` 同时有**平台级唯一键**（`UNIQUE(platform, reconciliation_date)`）与**租户级列**（`tenant_id DEFAULT 'default'`） | 本轮不动该表；R03/R30 的日对账口径**按"平台级"实现**（唯一键即现有事实），并把"该表到底是谁的口径"列进 **S3-86** 一并定 |
| 3 | `GET /api/platform/reconciliation`（列表）与 `GET /api/platform/settlements` **同数据源两套端点/控制器**（双实现） | 登记 **S3-90**（双实现收口家族，与 S3-31/S3-89 同族）；**C4-1 不得再新增第三套** |
