## 一、一句话结论

C6 的 86 处里，**"后端已有、前端没接"只有 6 条，且其中至少 3 条是被"演示态占位"掩盖的**——`GET /platform/library/spus/:id` 本来就返回 `skus`、`PUT /platform/library/brands/:id` 本来就支持 `status`、`POST /platform/plans/:planId/copy` 和后端公告/审计日志端点都早已存在；**真正的大头是 39 条"必须新建表或新数据模型"**，集中在六块：① 商品库的调取统计/类目/审核流水（`t_library_spu.hit_count` 只有累计值，无时间与租户维度）；② 平台工单系统（S3-92，本批不实现）；③ 代理商域（无 `t_agent`/`t_channel` 表）；④ 渠道推广码与老带新台账；⑤ 平台报表导出中心（异步任务/状态/日志）；⑥ 平台角色与权限目录（现只有租户级 `t_sys_role`/`t_sys_permission`，平台侧只有 `t_platform_admin.role` 一个枚举列）。
另有 **11 条可在"零 DDL 或 INSTANT 加列"前提下落地**：平台管理员列表/启停（**服务层与控制器早已写好，只差一路由挂载**，`platform.controller.ts:69/84/98` 目前**只被单测引用**）、找回密码、品牌授权书（INSTANT 加列）、应用版本草稿与回滚、设置页 Logo（存 URL）。
最关键的一条工程结论：**C6 的成败不在接线，而在数据**——`t_library_*` 的建表与 113 条种子 SPU 全部只走第 8 步外部迁移，而种子 `INSERT` 默认被写闸门拦下（§十.1），所以"页面接上了但列表还是空的"是**高概率**结局，必须先由凌舟在生产侧把行数读出来再决定 C6 的验收口径。

### 三.0 归类规则（先声明，避免"同类两判"）

1. **一行只归一类**；分母固定为 §二.2 的 86 行，不增不减。
2. **判据 = 该行自身指向的后端能力/端点是否存在，以及修好它需要动什么**：
   - 指向**具体端点/能力诉求**的行（`TODO: 待接入 GET/POST …`、筛选参数依赖、空态里点名的端点）→ 按该能力是否存在归 **①/②/②'**；
   - 是**同一缺口的说明行 / 占位交互行 / 纯文案行**（文件头注释、区块注释、`ElMessage.info('…待接入')`、`todo()` 函数体）→ 归 **③** 并注明"同源主行"（**沿用 C5-0 §3.0 口径，凌舟已验收 C5**，为的是不让同一个缺口被重复计两次）；
   - **② 下分两类**（前置裁定口径）：**②=零 DDL 或 INSTANT 加列可复用既有表/列**；**②'=必须新建表/新数据模型**（⇒ 停等，只出草案）。
3. **③ 内部再分两小类**（便于凌舟分开派单）：`③-a 真缺陷`（接口/能力其实早已存在，却被写成"待接入"，或前端封装的路径与后端不符）；`③-b 同源说明行`（本身无独立缺陷，仅随主行整改）。
4. **④ 的判据** = 已有**裁定或既有设计决策**明确"本批不做"（本单 1 条）。
5. 一行指向**多个能力**时（如 `AppVersions.vue:399` 同时含"发布公告/暂停放量/归档"），按**仍未满足的那部分**归类，已满足部分写进"建议动作/备注"。

#### 5.1.3 状态机草案

```
PENDING（待处理） ──受理/回复──▶ PROCESSING（处理中）
PENDING ──直接解决──▶ RESOLVED（已解决） ──关闭──▶ CLOSED（已关闭）
PROCESSING ──标记解决──▶ RESOLVED ──关闭──▶ CLOSED
CLOSED ──租户重新追问（可选规则，待产品确认）──▶ PROCESSING
任意状态 ──转交/改派──▶ 状态不变，仅 assignee_id 变更（须写 t_support_ticket_message + 审计日志）
```

**待产品确认的流转规则（不得由我拍板）**：① 是否允许 `CLOSED → PROCESSING` 重开（通常需 N 天内、限次数）；② `RESOLVED` 是否需租户确认后自动关闭（超时自动关闭的小时数**后台可配**，不得内置固定值）；③ 转交是否计入 SLA 重置。

### 5.3 DDL 草案的硬约束（写给后续实施方，避免重蹈覆辙）

1. **注释一律写在文件末尾**（或注释块后紧跟独立 `;`）——踩坑[63]：`runMigrations()` 曾整块丢弃"以注释开头"的语句；虽然 `migration.ts:144-152` 已修复为 `splitSqlStatements` 剥离前导注释，但**该修复本身要在生产首跑时观察**（技术债铁律第 3 条）。
2. **建表/加列一律幂等**（`IF NOT EXISTS` / 先查 `information_schema` 再 ALTER），因为**本仓无迁移账本表、每次启动都会重跑**（踩坑[63]）。
3. **种子数据（INSERT）默认被写闸门拦下**（`MIGRATION_WRITE_GATE` 非 `allow` 时跳过 INSERT/UPDATE/DELETE/REPLACE）⇒ 新表的"预置项"（工单类型、字典项、7 个功能域权限点）**不能只靠迁移 INSERT**，需内联 `safeExec` 或明确的闸门放量计划（§十.1）。
4. **不得新建本批范围外的表**（"临时表""日志表"亦然）绕开范围；一切新表须经凌舟裁定与《数据库变更清单》登记。
5. **未配置即未配置**：任何新增可配项（SLA 小时数、灰度比例、阈值）**不得内置固定预设值**（用户 2026-09-12 原则），未配置时前端显示 `—` 或置灰阻断。
