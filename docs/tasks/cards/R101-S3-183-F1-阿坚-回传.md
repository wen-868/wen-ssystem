### 2.3 「重跑会补齐什么」（⑤ 在什么数据下才真正生效）

⑤ 的触发条件 = **非 default 租户**里存在「`u.status = 1`」且「**一条 `t_sys_user_role` 绑定都没有**」
且「该租户有 `r.status IN ('ACTIVE','1')` 的 `SUPER_ADMIN` 角色行」且「该账号在 `t_tenant_admin` 登记过
或 `username='admin'`」的用户 ⇒ 给它补一条**本租户自己的** SUPER_ADMIN 绑定。

夹具里 `victim_admin2` 正是这种账号：改后跑第一遍 `binding_rows 2 → 3`，该账号拿到绑定；
`victim_disabled`（`status = 0`）**没有被发放**（`username/role_code = NULL`），口径正确。
受害租户主管理员的跨租户绑定由 ④ 原样改指到本租户角色行。
⇒ **生产重跑的实际增量取决于是否有这种"零绑定已登记管理员"**：若没有（卡 §一 的现场就是"无"），
重跑 = 0 行新增、但**不会再中止**（不会再有"部分执行"），其余是 ①②③ 的"已齐平则 0 行"。
