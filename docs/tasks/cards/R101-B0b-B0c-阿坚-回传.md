## 六、风险与自我报备（含新判据可能的误报面）

1. **"已过鉴权"是语法级识别，有两类漏判面**（不是误报，是**假绿**面，报备以便你决定是否扩围）：
   ① scope 写成**变量/模板串**（`router.use(scopeVar, requireAuthWithTenant)`）时 `firstStringLiteral` 取不到 scope ⇒ 该端点被判"未过鉴权"而跳过；
   ② 把认证中间件**跨行**写在端点实参的下一行（本仓现有风格都是同一行，暂无实例）。
   当前 189 个路由文件实测全绿，这两类都无实例；若要彻底消除，需把端点实参也做括号配平解析（属扩围，未做）。
2. **我把判据 (b) 实现成"路径作用域内成对"，比派单字面的"文件里存在成对挂载"更严**：字面读法下，只要文件里存在任一成对挂载，同文件的其它内联认证端点也会被豁免；我按"**同一条链路**"的语义限定为"覆盖该端点路径的那个 scope 必须成对"。
   这会让"某 scope 成对、另一个 scope 没成对"的文件**照样红**（更好的方向），代价是理论上多出**假红**面（若某端点路径与配置 scope 不同名却实际受其保护）。
   已在脚本头部注释写明该口径；实测 15 个登记文件全绿，无假红触发。若你要回到字面读法，请裁定，我改。
3. **`if: always()` 的取舍**：它让门禁在前置步骤（`npm ci`/单测/lint）失败时**也**把结论打出来（治 S3-46 那种"被 skipped 等于没检"），代价是失败 run 的日志里这两个步骤仍占时间。它**不会**把失败洗成绿 —— 若你要与其他门禁风格统一（不加 `if: always()`），请裁定。
4. **CI 步骤位置**：按派单建议放在 `lint` 之后（即"lint/type 之后"区段），因此**若 lint 先红，这两步会被 skipped**（job 仍红、仍阻断）。若你更看重"门禁结论任何时候都要出现"，可把它们前移到 `npm ci` 之前（纯 node、无依赖，能跑）——已备选，等你裁定。
