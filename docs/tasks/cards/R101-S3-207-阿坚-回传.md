## 四之二、根因收紧的**连带面**（机器枚举，逐条判定）

**怎么发现的**：写门禁时发现它自己有个解析缺陷 —— 切实参时**没跳过模板字面量**，多列 SELECT 列表里的**顶层逗号**会把 SQL 截断
（实测 `batch-price.service.ts:206` 被截成 `SELECT sku.id AS skuId` ⇒ 被判"没有 tenant_id 字样"而漏过）。修好之后重新扫描，
`BLOCK`（有 tenant_id 字样但没有绑定到调用者租户的条件）从**被漏判的 0 条**变成 **21 条** —— 全部是"改前静默短路、改后会注入"的位置。

**逐条判定（工具 `tools/analyze-blocking.mjs` + 真库 `information_schema`）**：

| 类别 | 处数 | 处理 | 判据 |
|:--|:--:|:--|:--|

## 五、① 判据（改后）与边界

| 语句 | 判据（在**完整运行时 SQL** 上判定，含子查询/插值后内容） |
|:--|:--|
| SELECT | 值谓词 `tenant_id = ? / = '字面量' / = 数字 / IN (值)`；**列对列等值 `a.tenant_id = b.tenant_id` 不算**（这正是漏判病灶） |
| UPDATE / DELETE | 同上，且必须在**顶层 WHERE 之后**（`SET tenant_id = ?` 是"写租户列"，不算过滤；`WHERE` 子查询里的谓词算） |
| INSERT | 列清单显式写 `tenant_id`（含 `INSERT IGNORE`）/ `SET tenant_id = 值` / INSERT…SELECT 的 SELECT 段有谓词 |
| 任意 | 显式标记 `tenant-scope:self`（我已自己写租户条件）/ `tenant-scope:platform`（平台级故意不带过滤）——**必须登记**，否则门禁红 |

**为什么不会误放行 / 误拦时的行为**：
- **误放行（该注入却跳过）**：新判据证的是**形状**（存在绑定到 `tenant_id` 的等值/IN 谓词），**不是取值**（无法从文本证明 `?` 绑的就是调用者租户）。
  但相比旧判据（连形状都不看）这是**严格收紧**：新跳过集合 ⊂ 旧跳过集合，不会引入旧判据没有的跳过路径。
- **误拦（不该注入却注入）**：单表 SQL 上表现为多一个**正确**的等值谓词（结果不变）；**多表 JOIN** 上会 `ER_NON_UNIQ_ERROR 1052`（**响亮失败** 500，而不是静默泄露）——
  这是有意设计的 fail-loud，已由真库探针 P2 证实；静态门禁会在写代码时就把这类 SQL 拦红（`BLOCK-MISSING-TENANT-CONDITION`）。
