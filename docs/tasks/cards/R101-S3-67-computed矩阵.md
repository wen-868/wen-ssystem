## 二、判定（凌舟裁定）

1. **控件识别边框：无需改值。** 实测 1–7 项（按钮 / 输入 / 下拉 / 表格 / 分页）全部 ≥3:1（3.54–21.00）。
   **原因**：这些控件的边框最终**渲染来源是 `--el-border-color`**，而 S3-63 已把它从 `#E2E2E2` 改为 **`#888888`** ⇒ **S3-67 的"控件识别边框 8 条"已被 S3-63 的修复一并解决**（这正是 R8.1 要求的"用 computed 值定论"，不得再凭源码顺序推断）。
2. **`.el-button--primary` 不计入**：其 `border-color` 等于填充色，属"填充型按钮"，其可识别性由填充色与文字对比表达，非 1.4.11 的"边界对比"对象。
3. **容器描边 `.el-card`（1.14）与分隔线不属 1.4.11 对象**（1.4.11 管 UI 组件与状态，不管内容容器与分隔线）⇒ 墨的分类"分隔线 50 / 装饰 71"**维持不修**。
4. **语义标签（`.el-tag`）**：`--success` 2.69 / `--info` 3.82。标签是"状态指示"而非控件边界；其文字对比另按 1.4.3 文本阈值处理 ⇒ **归 S3-66.1（稳健不达标清单）统一处置**，不在 S3-67 内改。

## 三、唯一异常与处置（AiSidePanel 内 `.el-textarea__inner`）

- 实测：边框 `#F0F0F0` × 背景 `#F0F0F0` = **1.00**（无可见边界）。
- 成因：它被 `--border-light`（`tokens.css:116`）接管，不是 `--el-border-color`；与 S3-63 卡登记的**同一例外**。
- **裁定：不强制修，登记留档。** 理由：① 它位于灰色面板（`#F0F0F0`）内部，控件可识别性由面板边界 + 占位符共同表达；② 修它属"面板内输入框"设计决策，会改变 AI 面板观感，收益低于代价。
- **可选方案（备查，不在本卡执行）**：若将来决定修，取 `#888888`（#F0F0F0 上 3.11:1 达标），仅作用于该面板内文本域。

## 四、结论（供 S3-67 收口）

1. **S3-67 改值项：空集。** 需要改的只有"控件识别边框"，而实测已全部达标（由 S3-63 一并解决）。
2. **S3-67 剩余动作**：① 本矩阵归档 ② 把"分隔线/容器/装饰不属 1.4.11"写成**分类判据**（避免后代重复扫描 144 处）③ 例外项（AiSidePanel 文本域）登记"已知不可见边界 + 可选方案"。
3. **反测要求（S3-67 卡原定）**：把 `styles.css:36` 的 `--el-border-color` 临时改回 `#E2E2E2` ⇒ 本矩阵 1–4 项应回落至 **1.30:1**（S3-63 观察期守卫已实现该反测，含 `rgb(226,226,226)` 命中即判红）。
