## 六、风险与自我报备

1. **探测缓存的刷新边界**：`platformMfaColumnsState` 是进程内缓存，只在拿到确定结论时缓存。若进程在「缺列」状态启动、之后才跑 196，则要**重启后端**才回到带 MFA 列的 SELECT（不影响正确性：老 SELECT 仍能登录，只是暂时不强制 MFA）。部署脚本本就会重启 pm2，正常路径无影响 —— 这一点请凌舟在合入说明里保留。
2. **`mfa_enabled` 降级语义**：缺列期间一律按「未启用」处理，意味着**该窗口内不会有人被要求二段验证**（这是止血，不是安全漏洞放大：缺列时本来 MFA 根本无法工作，且会 500）。窗口 = 后端起来 → 196 跑完 → 重启。
