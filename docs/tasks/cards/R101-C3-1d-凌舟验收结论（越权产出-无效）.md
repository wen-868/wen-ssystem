## 四、残余风险（如实登记）

1. **harness 是等价仿真，不是 vitest 本体**：其 `expect` 用真 `@vitest/expect`、spy 用真 `@vitest/spy`（含 `clearAllMocks` 语义），转译用 `typescript.transpileModule`，跑的是仓库真实 controller/service/express——但**未覆盖 vitest 的 worker 池与 runner 生命周期**。本会话沙箱**禁止 node 派生子进程**（实测 `spawnSync` 任意二进制/自身 node 均 `EPERM`），故 vitest 无法在此执行，属环境限制而非未做。
2. `vitest.config.ts` 的 `setupFiles: src/__tests__/setup.ts` 只设 `USE_MOCK_DB/JWT_SECRET`，已由 `pre.mjs` 等价覆盖（已核对源码）。
3. 回传方自报：8 处 `beforeEach` 护栏超出"只改 3 条红用例"的字面范围，依据是派单 §二.2「改法要抗脆弱」。凌舟判定**保留**（根因就是跨用例队列泄漏，仅删泄漏源 1 行不能形成系统性保证）。
