# R101 · S3-51 副本演练执行草案（草案，不执行）

> 🔴 **红线**：本文件为**执行草案**，**不执行任何步骤**，也不连接/不创建任何生产或副本数据库。实际执行需**凌舟另行授权**后进行。
> 依据：凌舟裁定放量选 A 方案 = 备份 + 副本演练 + 变更清单逐条批准。本草案对应「副本演练」一段，目标是产出与《R101-S3-51-林夕上线变更清单》一一对应的**逐条执行结果（SQL + 影响行数 + 是否幂等）**。

## 目标

在隔离副本库上，用**修复后**代码（含 `splitSqlStatements` 注释剥离修复 + `addTablePrefix` 前缀修复）跑一次迁移，验证《R101-S3-51-林夕上线变更清单》中 300 条语句的真实行为：每条是**成功 / 跳过 / 报错**，以及**影响行数**。凌舟要求：「副本演练必须产出逐条变更清单（SQL + 影响行数 + 是否幂等），不能只给『跑通了』」。

## 步骤

### 步骤 1 · 备份（生产，只读侧）
- 执行 `deploy/02-mysql-backup.sh` 对生产 `liquor_inventory` 做全量备份（逻辑 `mysqldump` 或物理备份，按现网规范）。
- 校验备份完整性（备份文件大小、`--single-transaction` 一致性、可选 `mysqlcheck`）。
- 留存：备份路径、生成时间、校验和（sha256）、保留周期。备份**不**用于演练库本身，仅作回退底。

### 步骤 2 · 建副本库（隔离服务器）
- 在与生产**同版本 MySQL 8** 的隔离服务器上建空副本库，命名 `liquor_inventory_replica_<YYYYMMDD>`。
- 副本库与生产网络隔离，禁止任何生产流量接入。

### 步骤 3 · 导入
- 方案甲（验完整行为）：将生产备份还原/导入副本库（结构 + 数据）。
- 方案乙（仅验迁移补全）：先建结构（可用 `init_database.sql` + 既有迁移），再跑演练迁移。
- 推荐方案甲：能真实反映「存量库上 300 条首次执行」的影响行数（如 seed 重复、ALTER 是否触结构变更）。

### 步骤 4 · 用修复后代码跑迁移
- 在副本库上启动**修复后**服务（或单独调用 `runMigrations()` 对准副本库 `DB_NAME=liquor_inventory_replica_<date>`）。
- 确保运行的是含 S3-51/S3-52 修复的分支代码（`origin/fix/s3-52-references` 或已合 main 的修复版本），**不是**本分支（本分支仅含文档/脚本，不含 runner 修复）。

### 步骤 5 · 逐条记录执行结果（核心）
- 在 `safeExec` 包装处增强埋点：每条语句执行后记录
  - **结果**：成功 / 跳过（safeExec 吞错）/ 报错（未吞，需人工看）；
  - **影响行数**：
    - 数据变更类（INSERT/INSERT IGNORE/UPDATE/DELETE/REPLACE）：执行后立即取 `ROW_COUNT()`（或在 `conn.query` 的返回中读 `affectedRows`）；也可在执行前后 `SELECT COUNT(*)` 取差值交叉验证。
    - DDL 类（CREATE TABLE / ALTER TABLE / CREATE INDEX）：影响数据行数通常为 **0**（仅改元数据）；需额外对比 `information_schema` 执行前后结构（如 `COLUMNS`.`COLLATION_NAME`、`TABLES` 存在性）判断是否真改了结构。
  - **是否幂等**：取自《变更清单》的「幂等性判定」列（幂等 / 会报错但无害 / 数据变更 / 不可逆），与实测结果交叉核对（例如标「会报错但无害」的应实测为「跳过」）。
- 每条记录的键 = `(迁移文件, 块序号)`，与《变更清单》`序号` 对齐，便于凌舟逐条批准比对。

### 步骤 6 · 留痕
- 每文件一份：`/root/server-artifacts/<YYYYMMDD>/s3-51-migration-drill/<迁移文件>.json`，含该文件下每条 `{ sql, 结果, 影响行数, 是否幂等, 风险档 }`。
- 汇总：`/root/server-artifacts/<YYYYMMDD>/s3-51-drill-summary.md`，含：
  - 总计：成功 / 跳过 / 报错 条数；
  - 数据变更类（28 条）逐条影响行数；
  - 不可逆 DDL（1 条，`126:13`）前后 `COLLATION_NAME` 对比；
  - 任何「报错」条目（非预期跳过）单独列出，交由凌舟裁定。
- 留痕目录仅存于演练服务器，不回流生产。

## 影响行数取法（明确写法）

```sql
-- 数据变更类：执行语句后立刻取
SELECT ROW_COUNT();   -- 返回上一条 INSERT/UPDATE/DELETE 的影响行数

-- 或交叉验证（执行前后计数差值）
SELECT COUNT(*) FROM t_sys_user WHERE <同WHERE>;  -- 执行前
-- ...执行 UPDATE...
SELECT COUNT(*) FROM t_sys_user WHERE <同WHERE>;  -- 执行后；差值 = 影响行数
```

> DDL（CREATE/ALTER）不返回有意义的数据行影响数；以 `information_schema` 前后对比判定「是否真的改了结构」，并在汇总中标注「元数据变更，数据行影响 0」。
