## 三、四条反测命令（实现落地后由凌舟指定窗口执行）

> 🔴 **执行前置与风险**：`deploy.yml` 只在 `push: branches:[main]` 与 `workflow_dispatch` 触发。
> **在 concurrency 缺失的当下，"连推两笔到 main"会真的并发部署生产**——那正是本单要防的事故。
> ⇒ 反测必须在**实现已落地**后执行；验证"排队"优先用 `workflow_dispatch` 连续触发两次（可控、可取消），不要靠推 main。

| # | 反测 | 命令 | 期望 |
|---|---|---|---|
| ① | 只改 `e2e/` 推一笔 → **不**触发部署 | `git checkout -b verify/s3-62-e2e && echo "// r" >> e2e/a11y.spec.ts && git commit -am "chore: e2e only" && git push -u origin verify/s3-62-e2e`<br>再在 main 上推同名改动观察（或用 `gh workflow run` 判断） | 无新 deploy run |
| ② | 改非忽略文件 → **触发** | `git commit -am "fix: trigger check" && git push origin main` | 出现 deploy run |
| ③ | 混合提交 → **触发** | 一次提交同时含 `e2e/` 与 `backend/` 改动后推 main | 出现 deploy run |
| ④ | 连推两笔 → 第二次 **queued** | 实现落地后：`gh workflow run deploy.yml` 连续两次，观察第二次状态 | 第二次 `queued/pending`，非 `in_progress` 并发 |

**查 run 的命令**：
```powershell
gh run list --workflow "deploy.yml" --limit 12 --json databaseId,status,conclusion,createdAt,displayTitle
gh run watch <runId>          # 实时观察是否 queued
```
