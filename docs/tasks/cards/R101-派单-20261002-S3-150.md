# 【派单 S3-150】（P1）租户域口径收尾：启停端点写值/主键类型 + 注册审批缺 `tenant_name`

```

② 同一端点把 VARCHAR(36) 主键 `Number()` 成数字（get/update/toggle 三处）；③ **注册审批建的租户不写 `tenant_name`** ⇒ 平台租户列表名称为空（生产数据实测为 NULL）。

一、事实（凌舟逐条核实，含生产只读实测，2026-10-02）
  ① **启停写值类型错**：`backend/src/controllers/platform/tenant.controller.ts:60-65` 校验 `status ∈ {"ACTIVE","DISABLED"}` 后调
     `toggleTenantStatus(Number(req.params.id), status)`；而 `backend/src/services/platform-tenant.service.ts:134-136`
     `UPDATE t_tenant SET status = ? WHERE id = ?` 把**字符串原样写入**，`t_tenant.status` 生产列为 **`tinyint`**（默认 1）。
     生产 `@@sql_mode` 实测含 **`STRICT_TRANS_TABLES`** ⇒ 写 `'ACTIVE'` 会 **1366 → 500**（非严格模式则会静默存 0，语义更糟）。
  ② **主键类型错**：`t_tenant.id` 是 **`VARCHAR(36)`**（生产实测：`default` 与 UUID 两种值），而 controller 三处都用
     `Number(req.params.id)`（`getTenantById:22`、`updateTenant:54`、`toggleTenantStatus:65`），service 签名也是 `id: number`
     （`:61` / `:106` / `:134`）⇒ UUID 被 `Number()` 成 `NaN`，定位不到记录（甚至可能命中"数值恒等"的行）。
  ③ **`tenant_name` 未落库（既存缺陷）**：`tenant-register.service.ts` 的审批建租户 `INSERT INTO t_tenant`（`:246-252`）写了
     `id, tenant_code, name, company_name, company_short_name, contact_*…`，**唯独没写 `tenant_name`**（`rg -c "tenant_name"` 在该文件 = **0**，`HEAD` 同样为 0 ⇒ **不是 S3-144 引入**）；
     而平台租户列表/详情的 SELECT 正是 `tenant_name AS tenantName`（`platform-tenant.service.ts:49/65`）⇒ **注册来的租户在平台列表里名称空白**。
     生产只读实测：`t_tenant` 现有 2 行（`default` 与一个 UUID 行），**`tenant_name` 均为 NULL**。
  ④ **口径先例**：S3-138 已把"平台管理员 status 对外字符串 / DB TINYINT"的映射统一在服务层；S3-144 的 `createTenant` 写 `status = 1`（数值）并在返回值给出真实 UUID。
     ⇒ 本单与之对齐：**对外字符串（ACTIVE/DISABLED）、对内 TINYINT（1/0）、主键一律按字符串 UUID 传递**。

二、范围（钉死）
  **做**：
   · **① 启停端点**：`toggleTenantStatus(id: string, status: "ACTIVE"|"DISABLED")` ⇒ 服务层把 `ACTIVE→1 / DISABLED→0` 写库；
     **回读**时把 `1→'ACTIVE' / 0→'DISABLED'`（列表/详情出口统一字符串，兼容既有前端与 `tenant-status-stats` 的口径）；
     未知 id ⇒ **业务级 404**（不得 500、不得静默成功）；`affectedRows=0` 也按 404 处理（S3-65 教训）。
   · **② 主键类型**：`getTenantById` / `updateTenant` / `toggleTenantStatus` 的 `id` 一律改 **`string`**（controller 去掉 `Number()`），
     并核对同文件其它 SQL 的 `WHERE id = ?` 用法与调用点（前端传的就是列表里的 `id` 原值）。
   · **③ 补 `tenant_name`**：审批建租户 INSERT 补写 `tenant_name`（值 = 与 `name` 同源的展示名），**不改历史行**（历史 NULL 由凌舟决定是否回填，本单**不得**写 DML 迁移）。
```
