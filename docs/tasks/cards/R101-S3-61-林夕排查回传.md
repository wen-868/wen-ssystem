### 4.2 🔴 再进一步：不是"样式没生效"，是**过渡动画的中间帧被采样**

把两次样本叠起来看，**方向是收敛的**：

| 节点 | 样本 A | 样本 B | 声明最终值 |
|---|---|---|---|
| `.store-name` 前景 | `#b0b2b7` | `#808185`（**更深**） | `#000000` |
| `.store-name` 背景 | `#f6f8fd` | `#f8fafd`（**更浅**） | `#FFFFFF` |
| `.store-state` 前景 | `#b4c8c5` | `#87a89d`（**更深**） | `#0f5132` |
| `.store-state` 背景 | `#eef5f8` | `#eaf5f6` | `--color-success-soft` |

前景在**变深**、背景在**变浅**，两个方向都朝着声明值走；且**同一次运行内的 3 个采样完全一致**（1.99 / 1.99 / 1.99）。
⇒ 不是随机噪声，是 **CSS transition / animation 还没跑完，axe 就采样了**。

**这一把同时解释了三件悬案**：

| 悬案 | 解释 |
|---|---|
| 为什么 1/3 不命中 | 那次采样落在动画**结束之后**（拿到最终值 21:1，不违规） |
| 为什么浏览器有差异 | 两浏览器的动画时序 / 渲染速度不同 |
| 为什么声明 21:1 却报 1.99 | 报的是**中间帧**，不是最终态 |

### 4.3 ⇒ 修法方向（🔴 不是改颜色）

| 方向 | 做法 |
|---|---|
| 等动画结束再扫描 | 扫描前 `waitForTimeout` 或等 `transitionend`；更稳的是注入 `prefers-reduced-motion` |
| 测试环境禁用动画 | 注入 `*, *::before, *::after { transition: none !important; animation: none !important; }` |

⚠️ 两条都**不动任何颜色值**。之前定的是「拿到 fg/bg 前禁止改颜色」；**现在拿到 fg/bg，结论反而是更不该改颜色** —— 声明值本来就达标，改了也不会改变中间帧。

## 8. 凌舟 2026-09-19 二次裁定：机制定位到源码 + 分层（甲）

### 8.1 机制已定位到源码（不是推测）

`admin-web/src/App.vue`：

| 行 | 内容 |
|---|---|
| :4 | `<transition name="page-fade" mode="out-in">` 包着 `router-view` |
| :20 | `transition: opacity 180ms ease, transform 180ms ease` |
| :23 / :27 | 两个 `opacity: 0` |

**为什么 180ms 这么短还能被抓到**：测试是 `getByText("工作台").waitFor()` 一过就**立刻**扫，而 Playwright 认为 `opacity: 0` 的元素仍然是"可见"（只要有盒子、不是 `visibility:hidden`）→ axe 是在**淡入窗口里**开始采样的。

- fg 变浅正好是 black 在 **~31% 不透明度**下的混合值
- bg 偏蓝正是淡入时与底层的混合态

⇒ 三个悬案一次性闭合：1/3 不命中、chromium/firefox 差异、声明 21:1 却报 1.99。

### 8.2 收口口径（照抄裁定）

> **不改任何颜色**（声明值本来就达标，改了中间帧照旧）。
> 修法是「**扫描前让页面静止**」，不是改色值。

### 8.3 甲：分层（已落地 **PR #21**）

| job | 命令 |
|---|---|
| required `e2e` | `npx playwright test --grep-invert @a11y` |
| 观察期 `a11y` | `npx playwright test --grep @a11y --retries=0` |

- 两个用例标题加 `@a11y` 标签，**断言只有一份**
- `--retries=0` **必须**：观察期的目的是**计量漂移**，带重试会把漂移洗掉（本次 retry #1 也红所以看不出来，下次就不一定）

**实证（`--list`，不需浏览器）**：全量 20 / invert 后 **16** / grep 后 **4**。

🔴 **分层不是"把断言挪走就算了"** —— 断言只有一份、阈值一行未动；分层是**放对位置**，不是让红变绿。

### 8.4 🔴 第二条必须一起改：观察期去假绿（同 PR #21）

`a11y` job 在 PR #19 里显示 **pass**，但它的命令**实际是失败的** —— 因为 job 级 `continue-on-error: true` 把失败洗成了绿。

| 改动 | 说明 |
|---|---|
| 去掉 **job 级** `continue-on-error` | 洗绿 = 「绿灯信息 ≠ 真实状态」 |
| 保留**采样步骤级** `continue-on-error` | 保证 3 次取样都跑完 |
| 末尾新增汇总步骤（**无** continue-on-error） | 任一取样非零 → `exit 1` |

⇒ **红就是红**，靠「非 required」保证不阻断，而不是靠洗成绿。
⇒ 否则「**观察 10 次无漂移**」这个判据**本身就是假的**。

### 8.5 稳定化修法（排在 #19 之后，**不在 PR #21**）

```ts
// 扫描前：等页面淡入结束（机制无关，对 JS 驱动的动画也有效）
await page.waitForFunction(() =>
  (document.getAnimations?.() ?? []).every(a => a.playState !== 'running'));
// 双保险：注入静止态
await page.addStyleTag({ content: '*{transition:none!important;animation:none!important}' });
```

**三条要点（缺一不可）**：

1. **这不是"降级检查"**：WCAG 评估的是**最终渲染态**，不是过渡中间帧；消除采样伪影 ≠ 放宽阈值。卡里必须写清「**我们去掉的是中间帧，不是阈值**」—— 否则这句话就是自说自话。
2. **必须配反测**：故意把某个 token 临时改成不达标值，证明稳定化之后门禁**仍然会红**。否则「稳定化」和「把真问题一起洗掉」无法区分。
3. **连续 10 次无漂移后再考虑并回 required**（判据不变）。
