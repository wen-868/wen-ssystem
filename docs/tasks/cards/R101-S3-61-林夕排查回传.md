## 2. 判它不是配色问题：源码声明逐项核对

| 节点 | 源码声明色 | 实际比值 |
|---|---|---|
| `.store-name` / `.breadcrumb` | `--text-primary: #000000` on `--frost-topbar: #FFFFFF` | **21:1** ✅ |
| `.store-state` | `#0f5132` on `--color-success-soft` | 达标 ✅ |
| `.header-search kbd` | `#595959` on `#fff` | **7:1** ✅ |
| `.header-search > span` | 无 token 引用，继承正文色 | 达标 ✅ |

**按源码声明，这 5 个一个都不该红。**

### 已否掉的假设（省一轮，不要往这些方向查）

| 假设 | 结论 |
|---|---|
| `backdrop-filter` 导致背景不可判定 | **不成立** —— `--frost-topbar-blur: none`、`--frost-sidebar-blur: none`，**没有毛玻璃** |
| 深色主题 / `prefers-color-scheme` | **不存在** |

⇒ 这是**渲染态与源码声明不一致**，指向**时序**而不是配色。这也解释了 1/3 不命中和浏览器差异。
