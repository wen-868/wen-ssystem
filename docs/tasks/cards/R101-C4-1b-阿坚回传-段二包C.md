## 四、A8 根因修复（授权：卡 §六.1）

### 4.1 缺陷与修复

**缺陷（派单前已在网核实）**：`services/admin/platform-audit-log.service.ts` 读路径 SELECT
`type`、`description`、`user_agent` 三列；而真实 DDL 中 t_platform_audit_log 只有
`id/admin_id/admin_name/action/target_type/target_id/detail/ip/created_at`（`docs/migrations/080_平台管理员.sql:24-36`，
`153_select_columns_fill.sql:26-27` 仅补 `ip_address`/`module`）⇒ 真库执行必 `ER_BAD_FIELD_ERROR`。

**修复**（零 DDL，不新增表/列）：

1. SELECT/WHERE **只引用真实列**；新增真实列 `target_type AS targetType`、`target_id AS targetId`、`ip_address AS ipAddress`、`detail`；
2. `type` ← `JSON_UNQUOTE(JSON_EXTRACT(detail,'$.type'))`；`description` ← 同法派生
   （写函数 C1-2 正是把二者写入 `detail`，见 `insertPlatformAuditLog`）⇒ `type` 过滤与 `keyword`（描述模糊）
   由「引用不存在列」变为**真实可用**；
3. `userAgent` **无任何载体、不可派生 ⇒ 从返回体移除**（不填假值）；
4. 新增过滤参数 `action`、`adminName`（真实列），供 `GET /api/platform/monitor/proxy-audit` 复用本读路径；
5. 按 `ORDER BY created_at DESC` 保持原排序，未改动其它行为。
