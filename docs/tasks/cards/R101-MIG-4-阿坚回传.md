### 1.1 改了什么（哪里有问题 → 改了什么 → 为什么）

- **哪里有问题**：外部迁移段（第 8 步）会逐条执行 `docs/migrations/*.sql` 里的语句，**没有任何写保护**；而 `runMigrations()` 由 `server.ts:215-219` 每次启动调用、全仓无执行账本表 ⇒ 任何无保护的 `INSERT`/`UPDATE` 都随每次重启复利叠加（MIG-3 已确认：4 条口令覆盖语句会把管理员口令重置为默认值）。
- **改了什么（三处，全部在派工卡文件域内）**：
  1. 新增闸门判定族（`:139-238`）：`resolveWriteGate`（`:159`）解析 `MIGRATION_WRITE_GATE`、`stripLeadingComments`（`:167`）/`firstKeyword`（`:190`）/`isDataWriteStatement`（`:199`）/`statementTarget`（`:206`）、`blockedByWriteGate`（`:226`，判定 + 打日志）；
  2. 外部迁移段开始处声明本次运行生效的闸门取值（`:1006-1012`）：`[migration] 外部迁移写闸门=block（默认）：…` / `=allow（显式配置）：…`；
  3. 每条语句在"跳过存储过程 / 跳过 DROP TABLE"之后、`addTablePrefix` 之前过闸门（`:1043-1049`）：命中则 `continue`，并打一行 `[migration] <文件>: 写闸门 block 跳过 <类型> 语句（目标 <表名/过程名>）；如确需放行请显式设置 MIGRATION_WRITE_GATE=allow`。
- **为什么这么改**：① **默认挡**（fail-safe）——只有显式 `allow` 才放行，未设置/空串/非法值（`yes`、`1`、拼写错误）一律回落 block；② 判定必须**可靠**——先剥离前导空白与注释（`--`/`#`/`/* */`）再取**首关键字**，所以 `INSERT ... SELECT` 判 `INSERT`（不误判成 `SELECT`），且不做 `startsWith` 粗匹配；③ 闸门只做"跳过 + 留痕"，不改语句内容、不改切分逻辑、不碰任何 `docs/migrations/*.sql`。
