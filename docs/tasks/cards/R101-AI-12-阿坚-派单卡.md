派单人：凌舟（总负责人）｜2026-10-09

优先级 / 时间盒：**P0 · 半天**

背景与依据（已取证）：
- **执行方证据（苏然，沙箱对照）**：非代理链路 `lookupCalled=1`；**设代理后 `lookupCalled=0`，请求照常 200 且全程零 DNS 调用**。
- **凌舟代码形态复核（独立，与上述吻合）**：四个 provider 均把守卫作为**顶层 axios 选项** `lookup` 传入（`src/providers/openai-compat.provider.ts:190/339`、`deepseek.provider.ts:219/383`、`glm.provider.ts:216/380`、`ollama.provider.ts:167/284/328/356`），而**全仓无 `proxy: false`、无 `httpAgent`/`httpsAgent`** ⇒ axios v1 默认读取 `HTTP_PROXY`/`HTTPS_PROXY` 并**自建 agent**，顶层 `lookup` 不参与实际建连。
- **影响面**：任何"已通过同步校验"的公网 HTTPS 域名端点（**外部模型 + 商户 `api_endpoint` 两条链路皆然**）。**部署机一旦配了代理即触发** ⇒ 规则 d 的「校验的解析 = 连接的解析」承诺断裂，只剩出站前一次性解析 ⇒ **DNS rebinding TOCTOU 窗口**；且代理可把公网域名解析到内网。

交付物：
1. **让守卫在代理环境下依然生效**：
   - **首选**：在 `httpAgent` / `httpsAgent` 层挂 `createGuardedLookup()`（复用既有实现，**保留代理能力**）
   - 备选：显式 `proxy: false`（放弃走代理）——采用则**必须**在回传里说明影响面与部署前提
2. **反测（必做）**：设 `HTTP_PROXY` / `HTTPS_PROXY` 后，断言"连接期守卫仍拦私网"（**修复前红、修复后绿**），并保留一条非代理链路的正例
3. 覆盖**全部 4 个 provider 的全部出站点**（上表 11 处）
4. 给出"代理生效"的可复跑证据（lookup 调用计数或出站拦截原始输出）

验收标准（硬）：
1. `tsc` / `eslint` / `jest` 三门禁（不低于 **139 套件 / 1525 用例**，全绿）
2. **代理环境反测**：给出"设代理 → 修复前红 / 修复后绿"的原始输出
3. 非代理链路正例未被破坏
