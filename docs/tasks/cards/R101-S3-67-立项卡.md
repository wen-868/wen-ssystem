> 提出：林夕（S3-63 影响面扫描范围外发现）
> 状态：**已立项，未开工**。🔴 **先出逐控件 computed 矩阵再改值** —— 未出矩阵不得动任何色值。

## 1. 问题

`admin-web/src/styles/tokens.css`：

| 行号 | token | 现值 | 白底对比度 | 判定 |
| --- | --- | --- | --- | --- |
| `:115` | `--border-normal` | `#E2E2E2` | **1.30:1** | ❌ 不达 WCAG 1.4.11 的 ≥3:1 |
| `:274` | `--table-border` | `#E2E2E2` | **1.30:1** | ❌ 同上（但表格分隔线是否属 1.4.11 对象需先定性，见 §4） |

`--border-normal` 在 admin-web 内有 **40+ 引用点**，其中**确属控件识别边框**（WCAG 1.4.11 对象）的至少有：

| 位置 | 声明 | 性质 |
| --- | --- | --- |
| `admin-web/src/styles.css:709` | `--el-button-border-color: var(--border-normal)` | **按钮边框**（控件） |
| `admin-web/src/views/pos/CashierView.vue:1819` | `box-shadow: 0 0 0 1px var(--border-normal) inset` | **输入框式控件边框** |
| `admin-web/src/views/pos/CashierView.vue:2687` | 同上 | 同上 |
| `admin-web/src/views/pos/CashierView.vue:2750` | 同上 | 同上 |

其余引用点多为容器/分隔线（`MainLayout.vue:1087`、`styles.css:74/125/155/194/217/245/317/330/448/661/1148/1158/1321`、
`TodoList.vue:353`、`QuickEntryConfig.vue:371/381`、`MessageCenter.vue:285/296`、`AiChat/*.vue` 多处、
`OrderExceptionView.vue:237`、`OrderBoardView.vue:256`、`OrderAftersaleView.vue:624`、
`SystemConfigView.vue:855`、`PaymentConfigView.vue:684`、`CashierView.vue:2105/2148/2184/2410/2456`）。

🔴 **其中 `CashierView.vue` 的三处 `inset box-shadow` 与 S3-63 完全同形**（EP 用 box-shadow 画边框），
　 判读方式也必须同 S3-63：**读 computed `box-shadow` 首色，不能读 `border-color`**。

## 2. 与 S3-63 的关系（**独立变量，不可顺手一并改**）

- S3-63 改的是 `styles.css:36 --el-border-color` 与 `tokens.css:280 --input-border`。
- `--border-normal` / `--table-border` 是**另一条链**：实测改 `:36` 后 `.el-table th` 仍为
  `rgb(226,226,226)`，**证明表格边框不受 `--el-border-color` 驱动**。
- ⇒ S3-63 **不覆盖本卡**；本卡**也不得搭 S3-63 的车一起改**（避免"影响面清单"失真）。

## 3. 入场条件（🔴 全部满足才允许改值）

1. **逐控件 computed 矩阵（R8.1，硬性第一项）**
   对下列控件逐个在浏览器读 **computed**（inset box-shadow 取首色，box-shadow:none 的回读 border 色），
   记录「现渲染值 / 相邻不透明背景 / 比值」：
   - `.el-button`（默认态，经 `styles.css:709`）
   - `CashierView` 的三处控件（`:1819` / `:2687` / `:2750`，收银台页面）
   - `.el-table th` / `.el-table td`（经 `--table-border`）
   - **AiSidePanel 的 `.el-textarea__inner`**（被 `AiSidePanel.vue` 用
     `border:1px solid var(--border-light)` 接管，`box-shadow:none`）← S3-63 守卫已把它登记为例外，**归本卡**
2. **影响面清单**：40+ 引用点逐项分类「控件 / 分隔线 / 容器」，只改控件类，分隔线类保持不动。
3. **反测**：改回 `#E2E2E2` 必须重新 <3:1（证明判定有效）。
4. **冒烟**：收银台（POS 高频页）重点目视 —— 那里有 3 处控件边框 + 多处容器边框，改错代价最高。

## 4. 待定性的两点（先定性，不要先改）

- **表格单元格分隔线是否属 WCAG 1.4.11 对象**：1.4.11 针对"识别控件/状态所必需的图形对象"。
  纯装饰性表格分隔线通常**不算**；但表头分隔线若承担信息分组作用则有争议。
  ⇒ **本卡先按"表格不改"处理**，若门禁（axe 不查 1.4.11，需自建守卫）后续给出相反证据再议。
- **`--border-light`（#F0F0F0，1.14:1）**：AI 侧边栏 textarea 走的就是它。
  `#F0F0F0` 比 `#E2E2E2` **更浅**（1.14 < 1.30），若被判定为控件则同样不达标 ⇒ 与 `--border-normal` 同族，
  **一并纳入本卡的矩阵**，避免二次返工。

## 5. 本卡不得做的事

- 不得为转绿放宽或跳过既有门禁检查
- 不得用"源码里写了什么"或"打包产物里规则谁先谁后"下结论（R8.1 明令禁止）
