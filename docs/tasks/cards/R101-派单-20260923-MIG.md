【派单 MIG-2·P0】`addTablePrefix` 对**反引号表名**会把 `IF` 当表名 ⇒ `CREATE TABLE` 被改成语法错误；修它 + 出**行为变更影响面**

派单人：凌舟（总负责人）｜2026-09-23
执行方：阿坚（后端 · 本地通道 · 文件域 `backend/src/shared/migration.ts` + 其测试 + `docs/evidence/MIG-2/**`）
优先级 / 时间盒：**P0** · 0.5 个工作日

**凌舟已定位到行（生产实测 + 本地复演双证，不要重新论证）**：

1. **生产现象**：C3-1 合并部署后，`t_library_api_key` 的新列**加上了**，但 **3 张新表一张都没建**（`total_tables` 仍 487）。服务器 `logs/backend.log` 原始记录：
   ```
   [migration] 执行外部迁移: 173_open_platform_api_key_columns.sql
   [migration] 执行外部迁移: 174_open_platform_webhook.sql
   [migration] 174_open_platform_webhook.sql: 跳过 (ER_PARSE_ERROR)     ← 两条 CREATE 各跳过一次
   [migration] 175_open_platform_api_call_daily.sql: 跳过 (ER_PARSE_ERROR)
   ```
2. **本地复演（用编译产物里的真函数）**：对 174/175 跑 runner 的同一套流水（去 `USE`/`DELIMITER` 行 → 按 `;` 切 → 丢注释开头块 → `addTablePrefix`），得到的**首行**是：
   ```
   CREATE TABLE t_IF NOT EXISTS `t_open_webhook` (          ← 被改坏
   CREATE TABLE t_IF NOT EXISTS `t_open_webhook_delivery` (
   CREATE TABLE t_IF NOT EXISTS `t_open_api_call_daily` (
   ```
3. **根因**：`backend/src/shared/migration.ts:84` 的模式
   `/(CREATE\s+TABLE\s+(?:IF\s+NOT\s+EXISTS\s+)?)([a-z_][a-z0-9_]*)/gi`
   **只认不带反引号的表名**；遇到 `` CREATE TABLE IF NOT EXISTS `x` `` 时，可选组不匹配、`([a-z_][a-z0-9_]*)` 抓到关键字 **`IF`** 并补成 `t_IF` ⇒ 语法错误。
   **旁证**：C2-0 的 `171_platform_templates.sql` 能成功建表，正是因为它的表名**没加反引号**；173 的 `ALTER TABLE \`t_library_api_key\`` 能执行，是因为 `ALTER TABLE ` 后紧跟反引号、名字组不匹配 ⇒ **没被改写**。

交付物：

1. **修复** `addTablePrefix`：正确支持 ① 反引号包裹的表名 ② `IF NOT EXISTS` ③ 已经以 `t_` 开头的名字不二次加前缀 ④ 不得误伤列名/关键字/字符串字面量（**保持既有"只匹配语句上下文"的设计意图**）。
2. **单测 + 反测**：至少覆盖 `CREATE TABLE IF NOT EXISTS \`x\``、`CREATE TABLE IF NOT EXISTS x`、`ALTER TABLE \`x\``、`INSERT INTO \`x\``、`FROM \`x\``，并断言"已 `t_` 前缀不重复加"；给**反测**（把修复回退 ⇒ 上述用例应变红）。
3. **行为变更影响面（必须）**：修复后，**哪些此前被跳过/被改坏的语句会变为可执行**？逐条列出（文件:行 / 语句类型 / 目标表 / 风险等级），可复用 `docs/evidence/MIG-1/tools/mig1-extract.mjs` 的口径与分级；**特别标出会改数据（INSERT/UPDATE）与改结构（ALTER）的条目**。
4. 回传卡 `docs/tasks/cards/R101-MIG-2-阿坚回传.md`。

验收标准（硬）：

1. `tsc -p backend/tsconfig.json --noEmit` EXIT=0；`eslint <改动文件>` 0 problem；`npm --workspace backend test` 全绿（给出与当前基线 **569 / 6192** 的对比）；
2. 反测（给原始输出）：修复回退 ⇒ 新用例红；修复后 ⇒ 绿；
