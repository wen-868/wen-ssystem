## 一、改动落点（最终版）

文件：`admin-web/src/views/dashboard/Dashboard.vue`（真实路径含 `dashboard` 子目录）

**改动前：**

```
        <el-card class="feed-card feed-card--trend" shadow="hover">
  ...
          <div v-else ref="salesTrendChartRef" class="trend-chart" />
```

**改动后（仅改第 110 行，el-card 保持原样）：**

```
          <div
            v-else
            ref="salesTrendChartRef"
            class="trend-chart"
            tabindex="0"
            role="region"
            aria-label="本月销售趋势图表"
          />
```

三个属性的作用：`tabindex="0"` 使其可 Tab 聚焦，从而让其所在的 `.el-card__body`
滚动区对键盘可达（WCAG 2.1.1）；`role="region"` + `aria-label` 给出可读区域名。

## 二、为什么不是「给 `<el-card>` 加 tabindex」（实测证伪）

| 落点 | firefox 结果 | 判定 |
| --- | --- | --- |
| `<el-card class="feed-card feed-card--trend">` 加 `tabindex="0"`/`role="region"`/`aria-label` | `工作台违规: total=1, critical/serious=1, types=scrollable-region-focusable`，`nodes target=.feed-card--trend > .el-card__body` | ❌ 无效 |
| slot 内 `.trend-chart` 加同三属性 | `工作台违规: total=0, critical/serious=0` | ✅ 通过 |

结论：`scrollable-region-focusable` 针对的是**可滚动的那个元素本身**（此处为 `.el-card__body`），
父容器可聚焦不予采信；必须让 `.el-card__body` **内部**出现可聚焦元素。
（若日后需要更强的保证，可考虑让 `.el-card__body` 自身可聚焦，但那需要绕过 EP 的 DOM 结构，本单未采用。）
