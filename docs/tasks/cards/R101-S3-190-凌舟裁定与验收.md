## 二、裁定

**① 根 `npm run build` 在基线即红 ⇒ 裁定：门禁口径统一为「逐工作区构建」（`npm --workspace backend run build`）。**
依据：`miniapp` / `platform-miniapp` 无 `build` 脚本，属**仓库现状**、非本单引入（执行方已在未改动基线上复跑证实）。根 build 缺失本身登记为**第 62 项**（低），不在本单修。

**② 第 53 项附带新增 6 个「按语料命名」的冗余索引 ⇒ 接受落地，并入第 60 项一并收口。**
理由：卡面明令「只改表名、不改列/索引定义」，执行方按原样落地是对的；这 6 个索引与既有 `idx_t_*_tenant` 同表同列仅命名不同，属**语料冗余**，与 `093` 的 3 条裸表名、以及 10 条其它类别跳过，**同一族**，一次清完。

**③ 同根因残留 3 条（`093_库存增加租户ID.sql:8/9/10` 的 `CREATE INDEX … ON` 裸表名）⇒ 登记为第 60 项，另派单。**
根因与第 53 项同源：表名写在**字符串字面量**里，而 `addTablePrefix()` 不认 `CREATE INDEX … ON` 模式。**不在本单顺手改**（避免把已验证的交付面撑大）。

**④ 冗余/失效语句的其余 10 条（120c=5 目标表 `t_inventory` 本产品从未建、169=3 `t_tenant_admin` 由更晚文件建出、092=2 执行时点表未建）⇒ 接受「已逐类定性、不属本单」**，同样并入第 60 项台账。
