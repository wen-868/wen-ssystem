## 风险与自我报备

1. 本步骤**排在三步最前**（lint 最便宜），其失败会跳过同 job 后续步骤——这是有意设计（fail fast），但意味着 lint 红时看不到类型门禁结论。若希望"全量结论一次看全"，可加 `if: always()` 于诊断步骤，**本单未加**（避免任何"永远绿"嫌疑）。
2. npm 透传 `--` 的可靠性不是本仓验证出来的普遍规律，而是本 PR 的 CI 实证（日志显示参数已到达 eslint）。若未来升级 npm 出现透传变化，该步骤会静默退化为"warning 不阻断"——届时反测（加 warning 看红）应重跑。已在步骤注释中留了背景说明。
3. 与 S3-129 同 PR：S3-129 的守卫用例需要 Node ≥ 22.15（`registerHooks`），已在该步骤级切换 Node 版本解决，不影响本步骤（lint 跑在 Node 20）。
