## 一、根因（一张图讲清）

```
#2 POST describe 的 beforeEach 给「每个」用例排了 1 个 query 返回值：
    dbMocks.query.mockResolvedValueOnce({ insertId: 9, affectedRows: 1 });
  ├─ 201 两个用例：各消费 1 个 ✓
  └─ 400 两个用例（缺 appName / qps 非数字）：**0 次 DB 调用 ⇒ 各留 1 个**

vi.clearAllMocks() = mockClear()：只清 mock.calls，**不清 once 队列** ⇒ 这 2 个值一路顺延
  ├─ #6/#7「并发兜底」的 UPDATE 本应拿 {affectedRows:0}，实拿旧值 {affectedRows:1}
  │    ⇒ affectedRowsOf=1 ≠ 0 ⇒ 不抛 409 ⇒ **200（期望 409）**
  └─ #8 stats 两条的日聚合 SELECT 本应拿数组，实拿旧值 {affectedRows:0} / {affectedRows:1}
       ⇒ seriesRows.map is not a function @ open-api-key.service.ts:498 ⇒ **500（期望 200）**
```

**为什么 3 条红只出现在这里**：其他 32 个用例都"排多少用多少"（队列进出平衡），只有 `#2 POST` 的 2 个 400 用例是净排队；而队列是**全局 FIFO**，谁排了不用，账就记到后面所有用例头上。

**实现侧判定：无缺陷**

| 争议点 | 实现证据 | 结论 |
|---|---|---|
| rotate 到底有没有校验 `affectedRows`？ | `open-api-key.service.ts:429-442`：条件 UPDATE 后 `if (affectedRowsOf(result) === 0) throw new AppError(..., 409)`；归一化函数 `:223-231` 同时兼容 `ResultSetHeader` 与数组返回 | **有校验**；本单那条红是"拿到旧值 1"，不是"没校验" |
| stats 在无数据时真的会抛吗？ | `:488-498`：`const seriesRows = await query(...)` → `seriesRows.map(...)`；只有返回值**不是数组**时才抛，空数组返回 `series: []`、`hasData:false` | 真 DB 返回数组时无问题（其余 32 条绿用例互证）⇒ 500 由 mock 返回错值引起 |
