## 一、缺陷本体

`deploy/ai-base-deploy.sh` 有 **5 处失败路径一律 `exit 0`**：

| 行（改前） | 失败场景 |
|---|---|
| `:43` | 独立仓库与内嵌源码**均不可用** |
| `:50` | `npm install -g pnpm@9` 失败 |
| `:146` | `pnpm install --frozen-lockfile` 失败 |
| `:150` | `pnpm build` 失败 |
| `:160` | `pm2 start zhixiang-ai-base` 失败 |

而 `deploy/auto-deploy.sh:115` 又是 `bash ai-base-deploy.sh || echo "AI 底座部署跳过（见上方日志）"`
—— **两层都把失败吞成成功**。结果：AI 底座**没部署成功**时，整条流水线仍打印"部署完成"。

> **定性**：**"容错不阻断主部署"是对的**（不能让 AI 底座失败拖垮主后端发布）；
> **错的是"静默返回成功"**——它把"没做成"伪装成"做成了"。
> 这与踩坑 [71] 的**"假 CI 门禁"是同一类**：**绿灯 ≠ 真的部署了；成功码 ≠ 真的完成了。**

## 二、凌舟裁定（要求）

> 失败时输出**统一标记** `❌ [AI底座] 部署失败：<原因>`；
> `auto-deploy.sh` 末尾**汇总列出失败项**（汇总非空**且由自动化调用时返回非零**）。
> 这样"不阻断"和"不撒谎"两者都保住。

## 三、实现

### 3.1 `deploy/ai-base-deploy.sh`

- 顶部新增统一出口：

  ```bash
  AI_FAIL_REASON=""
  ai_fail() {  # $1 = 失败原因
    echo "❌ [AI底座] 部署失败：$1" >&2
    exit 0          # 容错不阻断，交由 auto-deploy.sh 汇总判定
  }
  ```

- 5 处硬失败 → `ai_fail "<原因>"`（原因写清具体失败动作，便于上层定位）；
- **健康检查未通过**（原仅 `echo` 一行后继续）→ 归为**软失败**：记入 `AI_FAIL_REASON`，
  后续 nginx 反代配置等步骤**仍照常执行**，在收尾处统一出标记；
- 收尾：**只有 `AI_FAIL_REASON` 为空才报"部署完成"**，否则输出
  `❌ [AI底座] 部署失败：<原因>`。

### 3.2 `deploy/auto-deploy.sh`

- 顶部 `AI_FAILURES=()`（`set -u` 下安全）；
- 调用 AI 底座时**捕获输出**（`tee` 保留实时日志）：

  ```bash
  AI_LOG="$(mktemp)"
  bash "${PROJECT_DIR}/deploy/ai-base-deploy.sh" 2>&1 | tee "${AI_LOG}" || true
  if grep -qF '❌ [AI底座] 部署失败：' "${AI_LOG}"; then
    while IFS= read -r _line; do AI_FAILURES+=("${_line}"); done < <(grep -F '❌ [AI底座] 部署失败：' "${AI_LOG}")
  fi
  rm -f "${AI_LOG}"
  ```

  > 用 **`grep -F`（固定字符串）** 而非 `case` 通配：`[ ]` 在 glob 模式中是字符类，语义不确定；
  > `grep -F` 是精确固定串匹配（已实测正确抽出失败项）。
  > `|| true` 保证 `set -euo pipefail` 下**失败不阻断**（这一点刻意保留）。

- 末尾**失败汇总** + 退出码：

  ```bash
  if [ ${#AI_FAILURES[@]} -gt 0 ]; then
    ...列出失败项...
    if [ "${DEPLOY_STRICT:-0}" = "1" ] || [ ! -t 0 ]; then
      exit 1     # 非交互（cron/CI 等自动化）或显式 STRICT → 非零
    fi
  fi
  ```

  - **交互式调用**（人工 SSH，stdin 是 tty）→ `exit 0` + 醒目告警；
  - **自动化调用**（非 tty）或 `DEPLOY_STRICT=1` → `exit 1`，供上层流水线判定。

### 3.3 顺带（S3-39 裁定①留下的约束）

`deploy/deploy-production.sh` 头部补注：`--no-package-lock` 是「不写 lock」而非「严格按 lock 装」，
**若该路径将来引入 lock 文件，必须立刻改回 `npm ci`**。

## 六、教训

1. **"不阻断"与"不撒谎"是两件事**：前者靠 `exit 0`，后者靠**标记 + 汇总 + 退出码**，必须同时满足。
2. **只要一段代码会被自动化调用，它的"成功"就必须能被机器判定**，不能只打印一句人话。
3. **新写部署脚本时，先定失败信号约定**（`docs/部署链路对照表.md` §六），再写成功路径。
