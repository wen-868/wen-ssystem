# 【派单 S3-161】（P0）手机端：记住账号密码 + 免重复登录（不每次打开都要登）
（落卡时间：2026-10-04｜凌舟）

```
【派单 S3-161】手机端做到两件事：① **记住账号与密码**（登录页自动带出，用户不手输）② **会话长期保持**（重开客户端不再要求重新登录，除非 token 真失效）。配套后端单 S3-160 提供「记住我 ⇒ 30 天 token」；本单消费它。

优先级 / 时间盒：P0 · 一次跑完（业主直诉："客户端登陆要记住帐号密码，不能每次打开客户端都需要再登陆"）
基线：以开工当日 origin/main 为准（自证须给远端真值：gh api repos/wen-868/wen-ssystem/commits/main --jq .sha）

一、事实（凌舟已核实，不得再自拟）
  ① **token 存储本身已经做了**：`app-mobile/src/api/storage.ts` 把 `merchant_token / merchant_user / merchant_tenant / merchant_tenant_id / merchant_csrf_token` 走**加密存储**（AES-256-GCM，`utils/crypto.ts`），`App.vue` 启动时读 `merchant_token` 决定是否跳登录页 ⇒ **"没做持久化"不是根因**。
  ② **根因 1（决定性的）**：商家端 JWT 有效期只有 **4h**（`backend/src/middleware/auth.ts:74 expiresIn: "4h"`），过期后 401 ⇒ `request.ts:103-118` 清 token 并 `reLaunch` 登录页 ⇒ **每次隔几个小时打开都要重登**。后端单 **S3-160** 正在加「rememberMe ⇒ 30 天」。
  ③ **根因 2**：登录页**不记住上次账号**（`rg lastUsername|remember|记住` 在 `pages/login/login.vue` **0 命中**）⇒ 重登时还得手输。
  ④ **缺陷 3**：`stores/user.ts:83 init()`（有 token 时拉 `/me` 恢复用户态）**定义了但全仓无人调用**（`rg "\.init\(\)"` 只命中定义）⇒ 就算 token 在，用户态也可能没恢复。
  ⑤ 过期处理逻辑**是对的**（仅真 401 才登出，且有并发去重与"先静默重试一次"的防误杀）⇒ **不要动它**，除非为配合本单。

二、范围（钉死）
  **做**：
   · ① **登录页加「记住我」**（**默认勾选**）：勾选 ⇒ 登录请求带 `rememberMe:true`（消费 S3-160 的长效 token）；取消勾选 ⇒ 不带（维持 4h）。
   · ② **记住账号与密码**：勾选状态下，登录成功后把**账号与密码**写入加密存储（复用 `utils/crypto.ts` 的 `setSecureStorage`，**钥匙命名新增专用 key，不要复用 token 的 key**）；下次打开登录页**自动带出账号与密码** ⇒ 用户零输入（与演示登录同一种"不让用户二次手动填充"的体验）。
   · ③ **启动恢复用户态**：在 `App.vue` 启动流程里，当本地有 token 时调用 `userStore.init()`（补上这个缺口），确保有 token 就直接进首页而不是停在登录页。
   · ④ **取消勾选时清理**：未勾选「记住我」⇒ 登录成功后**清掉**已存的账号口令（不要留下上一次的凭据）。
   · ⑤ 退出登录（`logout()`）⇒ **清掉 token/用户态**；账号口令是否保留按「记住我」勾选状态决定（勾选则保留账号口令以便下次一键登录，取消则不保留）—— 这条口径**必须在回传卡里写明并给证据**。
  **不做**：不改后端（S3-160 负责）、不改数据库、不改 `admin-web` / `saas-admin`、不改 `request.ts` 的 401 处理逻辑、不改加密算法本身。
```
