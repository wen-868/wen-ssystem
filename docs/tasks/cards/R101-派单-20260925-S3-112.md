# 【派单 S3-112】（P2）CodeQL `js/missing-rate-limiting` 根因收敛：让限流在**注册点**对 CodeQL 可见

```
【派单 S3-112】把全局限流器的注册改成"注册点内联 rateLimit(...)"，让 CodeQL 认得出限流证据；限流行为一字不改。
派单人：凌舟（总负责人）｜2026-09-25
执行方：阿坚（后端 · 本地通道）
优先级 / 时间盒：P2 · 一次跑完（改动预计 ≤40 行，含注释）
背景与依据（全部已取证）：
  1. **现象**：PR #116 与 #119 的 `CodeQL` 检查各报"本 PR 新增 high 告警"，**全是同一条规则** `js/missing-rate-limiting`（例：`platform-config.routes.ts:44`、`platform-s3-110.test.ts:58`）。
  2. **同族存量**：`gh api "repos/wen-868/wen-ssystem/code-scanning/alerts?state=open&per_page=100&rule=js%2Fmissing-rate-limiting" --jq length` ⇒ **100**（全量分布：该规则 95 + 其它 6）⇒ 按《派单规范》§8.7 **判系统性存量、不阻塞单 PR**，但**必须做一次根因收敛**（§8.7 第 2 条）。
  3. **根因（已核源码）**：`backend/src/server.ts:158` 是 `app.use(createRateLimiter({ windowMs: 60_000, max: … }))` —— 限流器由**自定义 helper**（`:98-136`）返回，CodeQL 的模式识别**只认注册点上的限流中间件调用**，因此每新增一条路由（含测试内路由）都报同一条告警。
  4. **§8.7 给出的收敛方向**：在 `app.use` 调用点**内联** rate-limit 调用，或提供 CodeQL 可识别的限流证据。
交付物：
  ① `backend/src/server.ts`：
     · 把 `createRateLimiter(options)` 重构为**返回 options 的函数**（建议命名 `buildRateLimitOptions`），**原三分支与降级逻辑一字不改**：`NODE_ENV==='test'` ⇒ MemoryStore；未配置 `REDIS_URL` ⇒ MemoryStore（并保留原 `logger.info`）；配置了 ⇒ RedisStore（并保留原 `logger.info` 与 `try/catch` 降级）；
     · 注册点改为**直接可见**的形式：`app.use(rateLimit(buildRateLimitOptions({ windowMs: 60_000, max: process.env.NODE_ENV === "production" ? 600 : 2000 })))`；
     · 在注释里写明"**为什么必须内联**（CodeQL 只认注册点的限流调用；helper 包装会让全仓新增路由都被误报）"，避免后人重构回去；
  ② 单测（建议放在 `backend/src/__tests__/config/` 或 `shared/`）：
     · **三分支覆盖**：`buildRateLimitOptions` 在 `NODE_ENV='test'`、无 `REDIS_URL`、有 `REDIS_URL`（可 mock `RedisStore`/`Redis` 构造）下分别返回"带/不带 `store`"的 options，且 `windowMs/max` 与传入一致；
     · **形状断言**：`server.ts` 源码中该注册点必须是**内联 `rateLimit(`**（文本级断言，防"有人又改回 helper 包装"）；
  ③ 回传卡 `docs/tasks/cards/R101-S3-112-阿坚回传.md`（按下方「回传格式」十项）。
验收标准（硬）：
  ① `cd backend && npx tsc -p tsconfig.json --noEmit` exit 0；`npx eslint <改动文件>` 0 error；
  ② 涉及测试全绿（给 `Test Files / Tests` 汇总行）；**全量 `npx vitest run` 的 0 failed 由凌舟复跑判定**；
  ③ **反测（原始输出必贴）**：把注册点**改回 `createRateLimiter(...)` 形式** ⇒ ②的"内联形状断言"**变红**；恢复 ⇒ 转绿；
  ④ **限流行为不变（由凌舟做真机反测）**：以 `max=3` 起一个临时实例，第 4 次请求应 **429**，且响应头含 `RateLimit-*`（执行方只需给"如何在测试中构造低 max"的说明，不必自己起服务）；
  ⑤ **CodeQL 收敛判据**：本 PR 的 `CodeQL` 检查**不应再出现** `js/missing-rate-limiting` 的**新增**告警（同族存量仍为既有那批）。
红线（不得触碰）：
  ① 不得改变任何**限流参数**（`windowMs: 60_000`、`max: production?600:2000`）、不得删掉 RedisStore 分支、不得改变中间件**顺序与位置**（仍在原 `app.use` 处）；
  ② 不得改路由/控制器/服务（本单只动 `server.ts` + 新测试）；不得动其它中间件；
  ③ 不得放宽/删除任何既有断言；不得为让 CodeQL 变绿而**摘掉限流**（那是"用假修复换绿灯"）；
  ④ 不得 `git add -A`；不得做任何 git/gh 写操作（提交/推送/PR 由凌舟执行）；
  ⑤ **禁止再向下委派**（踩坑[120]）。
回传要求：照抄本卡「回传格式」块（= 派单规范 §三 十项）逐项填满，不得自拟格式
```
