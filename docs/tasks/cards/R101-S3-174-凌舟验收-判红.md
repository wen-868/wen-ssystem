## 一、判定

**判红**。迁移 `197_演示租户隔离.sql` 与 `DEMO_TENANT` 常量方向正确，但**三处结构性前提在生产不成立**，按现状执行会：① 演示租户建不出来（或被写脏）② 演示账号**丢了全部角色绑定** ③ 演示侧栏空白。这不是"没做完"，是**会静默坏事**。

## 二、三处硬证据（生产只读）

| # | 生产事实 | 对迁移的影响 |
|:--:|:--|:--|
| 1 | `t_tenant` 有 **4 个 NOT NULL 且无默认值**的列：`company_name`、`contact_mobile`、`contact_person`、`tenant_code`（后者还 **UNIQUE**） | 迁移写的是 `INSERT IGNORE INTO t_tenant (id, name, plan, status) VALUES ('demo',…)` ⇒ 严格模式（MySQL 8 默认）下除主键冲突外的错误（1364 无默认值）在 IGNORE 下**变成 warning 并跳过该行** ⇒ **demo 租户不存在**；随后 `UPDATE t_sys_user SET tenant_id='demo'` 把账号指向**不存在的租户** |
| 2 | `t_sys_user_role` 唯一键为 **`uk_sys_user_role (user_id, role_id)`**（**不含 `tenant_id`**） | 迁移顺序是"先 `INSERT IGNORE … SELECT … 'demo'`（撞上同一 user+role 的既有行 ⇒ **被跳过**）→ 再 `DELETE … WHERE tenant_id <> 'demo'`（**删掉旧行**）⇒ **净结果：该用户角色绑定归零** ⇒ 演示登录后 `roles=[]`，SUPER_ADMIN 权与菜单全没了 |
| 3 | `t_sys_menu`：`tenant_id='demo'` = **0 行**，`tenant_id='default'` = **89 行** | 账号迁到 demo 后，若没有"按租户克隆菜单"的步骤 ⇒ **侧栏空白**（卡内验收③要求"演示仍可用（菜单/角色/种子正常）"，现状不满足） |

> 根因与全项目同族：**迁移只在小库/空库想过，没在生产同构 schema 上验**（NOT NULL 约束、唯一键口径、租户级菜单都是"生产才知道"的事实）。

## 三、修复要求（逐条，缺一不算完成）

| # | 要求 |
|:--:|:--|
| ① | **建租户必须显式写齐 NOT NULL 列**：`id='demo'`、`name='演示租户'`、`company_name='演示租户'`、`contact_mobile`、`contact_person`、`tenant_code`（唯一值，如 `DEMO`）、`plan='basic'`、`status=1`。**禁止用 `INSERT IGNORE` 掩盖 NOT NULL 违规**；改为"存在则跳过、不存在则插入"的显式判定（`information_schema` 或 `INSERT … SELECT … WHERE NOT EXISTS`）。 |
| ② | **角色绑定改 `UPDATE` 而不是"先插后删"**：因唯一键不含 `tenant_id`，正解是<br>`UPDATE t_sys_user_role SET tenant_id='demo' WHERE user_id=(SELECT id FROM t_sys_user WHERE username='demo')`<br>（若同用户在别处还有其它绑定，再按需补 INSERT）。**禁止**保留"先 INSERT IGNORE 再 DELETE"的顺序。 |
| ③ | **菜单必须一起迁**：给 `demo` 租户克隆一套菜单（如 `INSERT INTO t_sys_menu (…, tenant_id) SELECT …, 'demo' FROM t_sys_menu WHERE tenant_id='default'`，幂等），或**引用系统既有的租户菜单初始化逻辑**并给出证据。目标是"演示登录后侧栏非空"。 |
| ④ | **反测两侧（必须在生产同构库上跑）**：<br>· 正向：跑完断言 `demo 租户存在` ∧ `demo 用户 tenant_id='demo'` ∧ `demo 用户角色绑定数 ≥1 且全在 demo` ∧ `demo 租户菜单数 >0` ∧ **演示登录返回 `roles` 非空**；<br>· 反向：把 ① 的 NOT NULL 列去掉任一 ⇒ 迁移必须**报错停下**（不得静默跳过）。<br>· 幂等：连跑两遍零错误码、无重复菜单/绑定。 |
| ⑤ | **不得搬业务数据**（原红线保留）：`t_sale_bill` 等 `default` 租户数据前后一致（生产核对 `default = 524` 不变）。 |
