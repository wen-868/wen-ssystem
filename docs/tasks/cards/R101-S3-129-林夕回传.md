## 风险与自我报备

1. **本机假红（重要）**：本机（Windows / node_modules 本地安装）`vue-tsc --noEmit` 报 29 处错误（12 文件）；CI（ubuntu / `npm ci`）**0 处**（探针除外）。我一度据此在 PR 描述里写下"S3-123 清零结论应被推翻、基线红 27/29 处"——**该判断是错的，已被 CI 推翻**，应以 CI 为准（S3-123 在 CI 环境下成立）。本机 node_modules 与 CI 的类型图差异未深挖（疑似本机残留旧依赖副本），建议后续单独排查本机环境。教训同踩坑 [17]/[86] 一族：**测量环境不干净时，先怀疑环境再怀疑结论**。
2. **守卫用例的 Node 版本前提**：`registerHooks` 需 Node ≥ 22.15。我在 ci.yml 内用"步骤级切 22"解决，**未动** job 级 `node-version: 20`（影响面大，超出本单范围）。若日后有人把该用例脚本升级依赖更高 Node API，步骤级切换需同步跟进。建议 S3-124 关联卡补记"本用例运行前提 = Node ≥ 22.15"。
3. 形态选择偏离派单首选项：未用 `build:check`（`vue-tsc -b`），选了两步式（`--noEmit` 独立成步）。理由：admin-web 仅单个 tsconfig、无 project references，`-b` 走 build mode，实测错误集与 `--noEmit` 不同；两步式失败步骤名自证。派单允许该选择，此处报备。
4. run1 我曾把守卫用例失败误判风险搁置（初版未处理 Node 版本），靠首轮 CI 才暴露——回传不及时，反测先行救了一轮。
