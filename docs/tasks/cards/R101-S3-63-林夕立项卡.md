# R101-S3-63 任务卡 · 输入框边框对比度：真正生效的是 `--el-border-color`，不是 `--input-border`

> 提出人：**凌舟**（2026-09-19 裁定）　｜　记录人：林夕
> 归属人：**待派单**（admin-web）　｜　性质：**对比度取值缺陷（WCAG 1.4.11 非文本 3:1）**
> 状态：**待裁定 A/B 方案后派单**（不自置"已完成"）
> ⚠️ **不并入 S3-61**（S3-61 是判定稳定性，本卡是取值改造）

---

## 0. 一句话结论

`--input-border` 确实是死代码（改它无效），**但处置结果不是"算了"，而是"改错了旋钮"**。
真正生效的输入框边框是 **`--el-border-color: #E2E2E2`，白底 1.30:1 —— 依然不满足 WCAG 1.4.11 的 3:1。**

---

## 1. 证据（逐处核实，含行号）

| 位置 | 内容 |
|---|---|
| `admin-web/src/styles.css:36` | `--el-border-color: #E2E2E2;` ← **真正生效的值** |
| `admin-web/src/styles.css:762` | `box-shadow: 0 0 0 1px var(--input-border) inset;` |
| `admin-web/src/styles.css:781` | 同上（第二处引用点） |
| `admin-web/src/styles/tokens.css:271` | `--input-border: #CCCCCC;` ← **死代码** |
| `admin-web/src/styles/tokens.css:88-89` | 现有注释写「挂起待裁定」，**已裁定，需更新** |

**为什么 token 值被盖掉**：EP（Element Plus）的 `.el-input__wrapper` / `.el-textarea__inner` 规则在打包产物里排在**我们的规则之后**且**同特异性** → 后者胜出，渲染用的是 EP 的 `--el-border-color`。

---

## 2. 现状比值（已独立复算，与凌舟数值一致）

| 色值 | 对 `#FFFFFF` | 对 `#F0F0F0` | 是否达 3:1 |
|---|---|---|---|
| `#E2E2E2`（当前生效） | **1.30** | — | ❌ |
| `#8A8A8A`（建议值） | **3.45** | **3.03** | ✅ |

> 复算方法：sRGB 线性化后算相对亮度 `L`，比值 = `(L浅+0.05)/(L深+0.05)`。
> `#E2E2E2` → L=0.7601 → 1.296（≈**1.30**）；`#8A8A8A` → L=0.2543 → 白底 3.451（≈**3.45**）、`#F0F0F0` 上 3.028（≈**3.03**）。
> ⚠️ 凌舟另核过 PR #20 的 5 个面（`#FFFFFF` 5.17 / `#F7F7F7` 4.83 / `#F5F5F5` 4.74 / `#F0F0F0` 4.54 / `#FAFAFA` 4.96），与本卡口径一致。

---

## 3. 两个方案（二选一，🔴 由凌舟裁定）

### A（推荐）：改 `--el-border-color`

`#E2E2E2` → **至少 `#8A8A8A`**（白底 3.45 / `#F0F0F0` 上 3.03 达标）。

- **代价**：它是 **EP 全局变量**，影响面比原 token **大得多** —— 所有 `el-input` / 表格 / 卡片边框都会跟着变。
- 🔴 **前置条件**：必须先出「**受影响控件清单 + 改前改后对照**」，评审通过后才动。
- 🔴 **没有影响面清单之前不要动 A。** 这正是本轮统一的口径（先量影响面，再改）。

### B（备选）：让我们自己的规则赢

提高选择器特异性，只改输入框那一处（`styles.css:762/781`）。

- **代价**：与 EP 的样式覆盖关系**更脆弱**（EP 升级或打包顺序变化都可能失效）。
- 必须用注释**锁定原因**，否则后人会当成"多余的特异性"顺手删掉。
