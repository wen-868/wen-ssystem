## 3. 品牌蓝族（`#3F6FEF` 系）普通字号：是否统一加深 —— A/B 两案与代价

### 3.1 事实基线（脚本统计，`admin-web/src/**`）

`--color-primary` + `--el-color-primary` + 字面量 `#3F6FEF` = **278 处 / 72 文件**（token `var()` 235 处/69 文件、字面量 43 处/13 文件）。其中 `var(--color-primary)` 的**属性分布**（223 处 = 逐行计数口径；全局正则计数为 235 处，差额 12 处来自「同一行出现多次」）：

| 用途 | 处数 |
|---|---|
| `color`（文字/图标） | 70 |
| `background*` | 68 |
| `border*` | 51 |
| `box-shadow` | 4 |
| EP 变量映射（`--el-button-*` / `--el-tag-*` / `--el-pagination-*` 等） | 11 |
| 其他（4 处 `font-size`、3 处 channel 色板、outline 2、el-avatar 1、布局项等） | 19 |
| **小计** | **223**（其中**非文字 153 处 = 69%**） |

⇒ **深色化 `--color-primary` 不只是改文字**：它会同时改**按钮底色、边框、tag 底/字、分页 hover、阴影**。

### 3.2 A 案：统一加深（改 token 到 `#365FCE`，`tokens.css:15` + `styles.css:26` 两处同改）

- 收益：一次解决 11 条不达标 + 未来新代码不再复发（token 已是达标值）。
- **代价**：触及 **72 文件 / 278 处**，其中 `var(--color-primary)` 的 **153 处（69%）为非文字用途**（background 68 + border 51 + box-shadow 4 + EP 变量映射 11 + 其他 19）→ 属**风格位移级**改动：品牌蓝整体变深（`#3F6FEF` → `#365FCE`），按钮/tag/边框观感全变，需**全站 UI 复看 + 设计侧（林夕）确认**。
- **叠加风险**：S3-54（`--g4` 族）、S3-63（`--el-border-color` / `--input-border`）、S3-67（`--border-normal` / `--table-border`）同期都在动边框与底色；A 案一起上会让"变色归因"变难（出问题分不清是谁改的）。

### 3.3 B 案：逐处最小改动（只改 11 条规则，不动 token）

- 触及 **9 文件 / 11 条规则**，**0 处非文字用途**（背景/边框/按钮态一律不动）→ 风险最小、可逐页目视验收、与其它专项零耦合。
- **代价**：① 同一品牌色**两个值并存**（`#3F6FEF` 用于背景/边框/大文本，`#365FCE` 用于普通字号文字），后续维护需要口径说明；② **不根治**——新增的 primary 普通字号文字仍会不达标（同题复发），需靠门禁/规范兜住；③ 3 条 hover 态（`Dashboard.vue:947/:1028/:1072`）单独处理，hover 前后文字色不一致的风险要靠目视确认。

### 3.4 结论建议（供凌舟裁定）

1. **本轮按 B 落地**：本轮批准范围本就是这 25 条规则；A 案改的是背景/边框/按钮，属**风格变更**而非可访问性修复，超出本轮范围。
2. **A 案另立专项**（建议与 S3-63 / S3-67 排期错开，避免归因叠加）；入场条件 = 林夕出「品牌蓝加深后的视觉基准」+ 全站 UI 复看。
3. **2 条走 EP 全局变量的条目**（`InstantRetailDashboard.vue:440` → `--el-color-success`；`InstantRetailShelf.vue:849` → `--el-color-primary`）按红线**不得经 EP 变量落地**（属 S3-63/S3-67）⇒ 要么逐处改，要么并入 A 专项一起裁。
