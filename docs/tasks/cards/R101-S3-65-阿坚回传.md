## 二、修复摘要（3 行）

1. **根因（确定性成因）**：`queryWithTenant` 的 `injectUpdateTenant` 在 WHERE 前插入 `tenant_id = ?` 时把 tenantId **前置**到参数数组（`[tenantId, ...params]`）；而 MySQL 按"占位符在 SQL 文本中的顺序"取值，SET 子句的占位符排在 WHERE 之前 ⇒ `SET password_hash = 'default'`、`WHERE tenant_id = '$2a$12$…'` ⇒ **WHERE 永不成立 ⇒ 0 行受影响 ⇒ 接口照样回"密码修改成功"**（既非租户不一致、也非权限问题）。
2. **修法**：tenantId 改为插在"WHERE 之前的占位符个数"位置（与 R95-03 在 `injectSelectTenant` 的修法一致；SQL 文本与 SELECT/DELETE/无 WHERE 分支行为不变）。
3. **兜底**：`changePassword` 校验 `affectedRows === 0` 即抛错（区分"用户不存在/租户不匹配/未更新"），杜绝此类"假成功"再以任何形态出现。
