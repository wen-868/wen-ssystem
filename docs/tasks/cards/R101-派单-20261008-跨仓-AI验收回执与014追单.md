## 四、凌舟裁定：t_ai_audit_log 跨仓重复声明 → 归管理系统仓

事实：ZXQL-AI/migrations/001_audit_log.sql（裸 CREATE TABLE t_ai_audit_log，业务库侧）与 wen-ssystem/docs/migrations/121_ai_base_tables.sql:58（同样 CREATE TABLE IF NOT EXISTS t_ai_audit_log）两处都建同名表；两处都是 IF NOT EXISTS，无运行期冲突。

裁定：归 wen-ssystem（管理系统仓）所有；ZXQL-AI 撤销 001 的建表。

理由（根因导向）：
1. 该表在业务库（不属于 ai_db）⇒ 业务库的 schema 归业务仓，与其它业务表同源，避免两条链路各建同名表后结构性漂移（这正是本域反复出问题的病根：同一概念多个副本）。
2. 归属单一后「列变更」只有一个落点，AI 底座只读写、不建表。
3. 撤销不是删文件：001 改为存在性断言/守卫跳过（表不存在时打印「应由管理系统仓 121 建表」并 EXIT=0），并保留其列归属约定注释作为文档。
4. 顺序依赖写明：管理系统仓迁移（后端启动期 runMigrations）先于 AI 底座迁移（当前部署顺序已满足）。
