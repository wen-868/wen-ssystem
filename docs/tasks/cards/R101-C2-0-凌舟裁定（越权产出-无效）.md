| 清账草案 5（公告模板） | **采纳推荐方案：0 DDL**，复用 `t_platform_config`（`platform='SAAS'`、`tenant_id='platform'`、`config_key='announcement:templates'`、`category='announcement'`）；**否决**备选新表 | 无迁移 |

**否决 3-A 的理由（写进记录，避免以后又走回去）**：① `ALTER TABLE t_print_template ADD COLUMN` 在 MySQL < 8.0.12 会 COPY 重建表并持写锁，阿坚已如实报备「线上版本未验证」，**未验证的风险不得直接上生产库**；② 方案 A 要向**租户作用域表**写入平台行（`tenant_id='platform'`），把平台语义混进租户表，属"两个真相源"的隐患（参见 §五 的 S3-83 同类账）。

**DDL 硬约束**：

1. 只**新增空表**；**不得**修改任何既有表的列 / 索引 / 约束（本批零 ALTER）。
2. 全表 `CREATE TABLE IF NOT EXISTS`，幂等可重复执行；不建外键（与平台表既有口径一致，一致性放服务层）。
3. 新增迁移登记到 `docs/数据库变更清单.md`（编号 171）。
4. 若实现中发现 4 张表之外**还需要**新表/新列 ⇒ **立即停下报备**，不得自行扩表。

## 五、裁定四：实现段工程硬约束

1. **只改 `backend/**`**（+ `docs/migrations/171_*.sql` + `docs/数据库变更清单.md` + `docs/API接口文档.md` 的**纯新增**段落，见第 7 条）；**不得改 `saas-admin/**`**。
2. **新路由注册顺序**：新文件 `platform-templates.routes.ts` 走 auto-routes（`routeConfig` 导出）；同一 router 内**先具体后通配**（`/print/upload`、`/import-export/:id/download` 写在任何 `/:id` 之前）；公告侧新端点写在 `backend/src/routes/admin-platform-announcement.routes.ts:9`（`GET /:id`）**之前**。
3. **鉴权**：全部 12 个端点走 `requirePlatformAuth`（`routeConfig.auth = "requirePlatformAuth"`；公告文件已有 `auth` 字段，不改其取值）。
4. **空态诚实**：无数据一律返回明确结构 `{ records: [], total: 0 }`（或同构），**禁止造种子数据**、禁止用假数据填充。
5. **单测**：每个新端点 ≥1 条**正向** + ≥1 条**鉴权反向**（无令牌 ⇒ 401/403）；每个**读**端点另加 ≥1 条**参数非法 ⇒ 400**（如 `:id` 非正整数、`billType` 不在允许集合、`direction` 非法）。
6. **既有契约零改动**：公告 6 端点、`t_print_template` 既有行为、任何既有路由前缀均不动。
7. **文档**：`docs/数据库变更清单.md` 登记 171；`docs/API接口文档.md` **只允许追加**新端点章节（**不得**整文件重排/重写换行——历史教训：5557 行换行噪声）。**凌舟复核 diff 后方可提交**。
