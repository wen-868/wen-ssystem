# 【派单 S3-131】（P1 门禁真实性）把 admin-web 的 `lint:check` 接进 CI（**必须 `--max-warnings 0`**）

```
【派单 S3-131】在 CI 的 build-and-test 中增补 admin-web 的 lint 阻断步骤，并**强制把 warning 也算失败**（`--max-warnings 0`）；随后做"故意改坏证明会红"的反测。
派单人：凌舟（总负责人）｜2026-09-27
执行方：林夕（.github/** · WorkBuddy 侧，业主中转）
优先级 / 时间盒：P1（门禁真实性） · 一次跑完（改 + 反测 + 回传）
起跑条件：**S3-128 已完成**（PR #175 → main 02d33c19d6：admin-web `lint:check` 已从 6 problems 清到 **0 problems / EXIT=0**）⇒ 现在接入即为"从绿开始守"。
基线：以开工当日 origin/main 为准（开工第一步 git log --oneline -1 自证并写进回传）

一、背景（凌舟实测，两条硬事实）
  1. admin-web 的 lint 现状：`npm --workspace admin-web run lint:check` = EXIT=0 / 0 problems（S3-128 闭环后）。
  2. **本仓 lint 对 warning 不阻断**：凌舟反测实测——在 `admin-web/src/api/pos.ts` 里插入一个未使用变量，`eslint src/` **只报 warning、退出码仍是 0**。
     ⇒ 若直接把 `npm run lint:check` 接进 CI 而**不加 `--max-warnings 0`**，那么"0 problems"只是**今天的快照**，不是被守住的门禁：明天有人留下 10 个 warning，CI 照样绿。

二、交付物
  ① `ci.yml` 的 build-and-test job 中增补一个 admin-web lint **阻断步骤**，命令**必须**等价于：
       `npm --workspace admin-web run lint:check -- --max-warnings 0`
     （若 workspace 脚本透传参数在你们的 npm 版本下不可靠，允许改为等价的显式命令，但**必须**带 `--max-warnings 0`，且要在回传里写明实际命令与理由）
  ② **不得**加 `continue-on-error` / `|| true` / `if: always()` 之类的"永远绿"手段；**不得**改 `eslint.config.*` 放宽规则；**不得**加 `eslint-disable` 注释消 warning。
  ③ **反测证据（本单核心）**：在**分支**上故意制造 1 个 **warning**（例如某文件里加 `const __probeWarn = 1;` 未使用）⇒ **CI 必须变红且失败在该步骤**（这正好证明 `--max-warnings 0` 真的生效）；给运行链接 + 失败日志片段；随后**还原探针**并给"该 job 回绿"的证据。
  ④ 回传卡 `docs/tasks/cards/R101-S3-131-林夕回传.md`（照抄下方「回传格式」十项）。

三、验收标准（硬）
  ① 步骤存在且阻断：给出 CI 里该步骤的名称与耗时（`gh run view <id> --log` 或 Actions 证据）；
  ② **反测"该红就红"**：故意加 warning 那次必须 **failure**，日志里能看到 `--max-warnings` 相关失败（或 ESLint 以非零码退出）；
  ③ 探针已还原：`rg -n "__probeWarn" admin-web/src` ⇒ 0 命中；
  ④ 改动面：`git diff --stat` 只出现 `.github/workflows/ci.yml`（+ 必要时一行注释）与回传卡；
  ⑤ 合并后主分支该 job = success（给链接）。

四、明确不在本单范围
  1. **saas-admin 的 lint**（该仓当前没有 lint 脚本；S3-135 后随类型门禁一并评估）；
  2. **类型门禁**（那是 **S3-129**：admin-web 的 `build:check` + `npm test` 守卫用例，同一 job 内，两单可合成一次改动一起提交，但**必须分别回传**）。

五、红线
  ① 不得改 `backend/**`、`saas-admin/**`、`app-mobile/**`、`admin-web/**`（探针除外且必须还原）、`deploy/**`、`docs/migrations/**`；
  ② 不得改共享文件（`docs/tasks/当前批次.md`、`docs/tasks/R101-总进度与推进计划.md`、`docs/踩坑日志.md`、`docs/API接口文档.md`、`docs/数据库变更清单.md`）；
  ③ **不得新建/改写 `docs/tasks/cards/**` 下非本单命名文件**（仅 `R101-S3-131-林夕回传.md`），**不得**写 `docs/tasks/inbox/**`（本通道回执＝回传卡）—— 该条已被连续违反 4 次（[128]/[132] 同族）；
  ④ **不得代写「凌舟裁定 / 凌舟验收」卡、不得自造派单卡**；
  ⑤ 提交纪律：开分支 + 开 PR（base=main），不得直推 main（main 收代码即触发生产部署）；一次只合一个触发部署的 PR。
回传要求：照抄本卡「回传格式」块（= 派单规范 §三 十项）逐项填满，不得自拟格式
关联卡：`R101-派单-20260926-S3-128.md`（前置，已闭环）、`R101-派单-20260926-S3-129.md`（同批的类型门禁 + 守卫用例）、`docs/tasks/R101-总进度与推进计划.md` §六十四（warning 不阻断的实测记录）
```
