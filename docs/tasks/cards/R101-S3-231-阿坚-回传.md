## 六、风险与自我报备

1. **同名证据文件名易混**：`docs/evidence/S3-231/raw/` 下有两份全量 vitest 记录
   （`30-full-vitest-after.txt` 为**首轮失败**记录：S3-226 未同步时 5 failed；`31-…` 为**终轮全绿**）。
   终轮以 **`31-full-vitest-after.txt`** 为准（679 文件 / 9529 用例 / 0 failed）。

2. **F3 与 `stores/menu.ts` 口径有意分叉**：卡面明确"不动 `stores/menu.ts`"。故
   `function-menu.ts`（属入口门，跟着改）与 `menu.ts`（底部导航，保持 null=放全量）在
   "未取到权限码"这一态上**行为不同**。这是**按卡执行的结果**，但确属**同一端内两套 null 语义**，
   已成**技术债**：建议后续单评估是否统一（若要统一，须先定义"首屏加载中"与"确实无码"的可区分状态）。

3. **F3 的 S3-226 类用例断言未逐一枚举**：S3-226 卡面称 W 4，但该用例的 `UNWIRED` 只**显式列出 2 行**
   （`/levels/config`、`/levels/config/:id/status`），另 2 行（`:id`、`:id` DELETE）从未在该用例中被引用
   （故原 `UNWIRED_CLASS_TOTAL` 的 W 4 与 `UNWIRED.length` 的 14 已不自洽）。本单按"显式行"同步（14 → 10），
   并加 `expect(UNWIRED).toHaveLength(10)` 把口径钉住；**未**替 S3-226 补那 2 行的登记（属他批范围，本单只登记）。

4. **F4 的一条口径差异已留在台账**：`POST /api/platform/reports/export/` 字面像"导出"但实为"创建任务"（写）
   ⇒ 不登记；其只读孪生是 `GET` 列表。已在 §18.3 逐条写明，避免后人误判。

5. **g0 用例的折叠循环由 `set(f,n)` 改为 `+=`**：这是为"同文件被多批声明"做的**结构性**小改动
   （否则本单的 `S3_231_WIRED_FILES` 块会**覆盖** S3-226 对 `points.routes.ts` 的声明）。
   改动面 = 1 行 + 注释；逐文件与总和断言仍全绿（`rbac-g0-wiring.test.ts` 148 用例中 147 通过、
   1 条为跨批计数和式已同步）。
