**这两侧与生产报错逐字互证**（2026-09-25 01:26:25 pm2 `zhixiang-api-out.log`）：

```text
[ERROR] [GET] /api/platform/ai/metering-log — Illegal mix of collations
(utf8mb4_0900_ai_ci,IMPLICIT) and (utf8mb4_unicode_ci,IMPLICIT) for operation '='
```

**为什么唯一一对**：报错把两侧都标成 **IMPLICIT**（MySQL 里只有列/列派生表达式是 IMPLICIT；参数与字面量是 COERCIBLE）。该语句里**列↔列**的 `=` 只有 `t.id = a.tenant_id` 一处（另一处候选 `COALESCE(t.tenant_name, t.company_name)` 是同表同列 collation，不比较）。而报错二元组 `{0900_ai_ci, unicode_ci}` 又唯一对应 `{t_tenant.id, t_ai_audit_log.tenant_id}`：本语句出现的表只有这两张，其中 `t_ai_audit_log` 被 121:80 **钉死**为 unicode_ci ⇒ 对侧 `t_tenant.id` 必为 0900_ai_ci。**候选（凌舟粗读的两处）核实结论：`t.id = a.tenant_id` 成立；同行的 `a.tenant_id = ?` 不成立**（见 2.2）。

### 2.3 修法与「为什么不会掉索引」（卡内 §三.2 授权的最低代价选项①）

```sql
LEFT JOIN t_tenant t ON t.id = a.tenant_id COLLATE utf8mb4_0900_ai_ci
```

- **选侧**：`COLLATE` 只加在 `a.tenant_id`（LEFT JOIN 的**被驱动值侧**）。本查询 a 是驱动表、t 是按主键探测的被驱动表 ⇒ 需要保住的是 `t.id` 的 `PRIMARY` 索引，而不是 `a.tenant_id`。
- **选目标 collation**：取 `t.id` **自身**的 `utf8mb4_0900_ai_ci`。比较所用 collation 与 `t.id` 索引 collation **一致** ⇒ `ref` 探测仍可用（`EXPLAIN` 应为第 2 行 `t`、`key=PRIMARY`、`type=eq_ref`，核对命令见 §四.④）。
- **反面**：若把 `COLLATE` 加在 `t.id` 上、或选 `utf8mb4_unicode_ci`，比较 collation 即偏离 `t.id` 的索引 collation ⇒ 丢主键探测（t_tenant 虽小，但每行 a 都全表扫 t 是数量级差异）。同理**不能**在 `a.tenant_id = ?` 上加 COLLATE：那会让 `idx_tenant_id`/`idx_tenant_created`（unicode_ci）collation 不匹配而丢索引——而该处本来就不报错，属「无问题处不得改」。
- **语义等价性**：租户 ID 是 UUID/`default` 这类 `[0-9a-z-]` ASCII 串，`utf8mb4_0900_ai_ci` 与 `utf8mb4_unicode_ci` 在「相等」判定上对该字符集完全一致（两者差异在重音/扩展字符排序），故不改变任何匹配结果。
- **未做**：不改列、不改类型、不加 DDL（`126_retail_tenant_collation_fix.sql` 那种列级统一属 DDL，本卡未授权）；不加 `try/catch` 吞异常；不把返回改成空实现（`records/total/page/pageSize/costUnit/costScale/unavailable` 结构逐字未动，见 §三.5 探针）。

### 3.4 关于新增单测（卡 §三.4）及其局限

新增用例断言：`LEFT JOIN t_tenant` 那条 SQL 里出现 `t.id = a.tenant_id COLLATE utf8mb4_0900_ai_ci`、整条 SQL `COLLATE` 恰好 1 处、`WHERE` 仍是 `a.tenant_id = ?`、`COUNT` SQL 无 `COLLATE`。

**该断言在 mock/SQLite 下盖不住真库 1267 的原因**：本套用例用 `vi.mock("../../shared/db")` 把数据层整个桩掉，**不发生任何真实比较**；SQLite（如果换用它）也没有 MySQL「coercibility + 隐式 collation 升级」规则，collation 不一致既不报错也不影响结果。所以本断言锁的是**生成的 SQL 文本**——作用是「重写 SQL 时不许把 COLLATE 弄丢」的回归门禁，而不是 1267 的行为复现；行为复现只能在真库（探针/§四.②）。

SHOW FULL COLUMNS FROM t_tenant        WHERE Field = 'id';        -- 期望 Collation = utf8mb4_0900_ai_ci

SELECT COUNT(*) FROM t_ai_audit_log a LEFT JOIN t_tenant t ON t.id = a.tenant_id COLLATE utf8mb4_0900_ai_ci;
