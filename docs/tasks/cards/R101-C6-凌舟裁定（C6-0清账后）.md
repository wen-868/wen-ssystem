## 三、②'（涉新表 / 新数据模型）逐条裁定

统一前置口径（沿用既有前置裁定）：**涉新表一律停、只出 DDL 草案、走 S3 立项；本批不实现**。以下逐条在此基础上给出结论。

| 编号 | 事项 | 凌舟裁定 | 理由（一句话） |

| C6-0-R1 | 平台通知载体 | **立项新建 `t_platform_notification(+read)`**；本批 #1 不做 | 公告是单向广播，未读数无法用 `localStorage` 表示成真值；零假数据优先 |
| C6-0-R2 | 报表导出中心 | **立项新建 `t_platform_export_task(+log)`**；本批 #81–84 不做 | 设计稿的"生成中/刷新/下载/任务日志"四态是产品契约，不得由工程单方面裁掉 |

| C6-0-R4 | 文件存储方案 | **统一复用既有上传通道**（`admin-product` 图片 / `templates/print/upload`），本批**不引入 OSS** | 避免新增外部依赖与密钥面；介质变更另立项 |
| C6-0-R5 | 应用版本域口径 | ①"健康看板"：**不做**（跨模块，另立项）；②**回滚定义＝上一个已发布版本**（`status=PUBLISHED` 且 `version_code` 小于当前的最大者），写入契约；③**加 `status` 列**（INSTANT 加列，属前置裁定 §三.2 允许范围）⇒ 本批可做 | ①跨模块不做最省风险；②给一个可判定的定义；③`enabled` 语义是"当前版本"，兼职会埋坑 |

| C6-0-R7 | 渠道报表 | **并入 `ChannelPromotion.vue` 的"渠道效果"子 Tab** | 不新增独立页面/路由/菜单 |

| C6-0-R9 | S3-92（工单）与 T6（平台角色/权限） | **同批立项** | 工单权限点必须落在 T6 权限目录里才有意义 |

## 四、C6-0-D3 已定论：`t_platform_config` 是"同名两义"的**同一张表**

生产 `SHOW CREATE TABLE t_platform_config`（凌舟实测）显示该表**同时**包含：

- 即时零售凭据列：`platform`（**NOT NULL**，注释 `JD/MEITUAN/ELEME`）、`store_id`、`app_key`、`app_secret`、`access_token`、`refresh_token`、`token_expire_at`；
- 配置键值列：`category`、`config_key`、`config_value`、`description`、`updated_by`（由 `152:84-88` 补列）；
- 唯一键：`uk_platform_store_tenant (platform, store_id, tenant_id)`。

**裁定**：

1. **禁止**把该表当作"平台全局配置键值表"使用——写一条键值行必须伪造 `platform` 值，并与凭据行共用唯一键，属语义污染；
2. 功能开关矩阵、数据字典**一律立项建表**（对应 R8）；
3. `platform-config.service.ts:67/85/94` 对该表的既有用法**单独立项审查**（是否已写入脏行）；**在审查结论出来前，C6 任何实现单不得新增对该表的写入**。
