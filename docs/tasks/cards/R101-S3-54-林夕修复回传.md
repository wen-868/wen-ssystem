## 二、候选灰阶计算过程（从原值往深走，第一个满足阈值的值）

复用 `scripts/contrast-check.cjs` 的 `relLum / ratio` 逻辑扫描连续灰阶：

**1) `--text-placeholder`：文本 ≥4.5:1（白底），需 relLum(fg) ≤ 0.1833**
```
#cccccc=1.606  #bcbcbc=1.899  #acacac=2.270  #9c9c9c=2.745  #8c8c8c=3.363  #7c7c7c=4.174(不达标)
#6c6c6c=5.251(达标)
细扫边界：#777777=4.47:1(不达标) → #767676=4.54:1(首个达标)
```
→ 首个达标灰度 = **`#767676`**（保留占位符轻于正文 #444 的层级）。

**2) `--input-border` / `--ctl-border`：非文本 ≥3:1（#f0f0f0），需 relLum(fg) ≤ 0.257**
```
#cccccc=1.409  #bcbcbc=1.666  #acacac=1.992  #9c9c9c=2.409  #8c8c8c=2.951(不达标)
#7c7c7c=3.663(达标)   （ctl 原 #d4d4d4 起点：#d4d4d4=1.301 → #848484=3.282 达标）
细扫边界：#8b8b8a=2.99:1(不达标) → #8a8a8a=3.03:1(首个达标)
```
→ 首个达标灰度 = **`#8a8a8a`(3.03:1)**。最终取 **`#888888`(3.11:1)**：即设计系统既有 `--gray-300` 的 3:1 非文本灰阶（与 S3-53 滚动条边框同源，避免引入一次性灰值），比首个达标值多留安全余量，视觉变化几乎一致。
