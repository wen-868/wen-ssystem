## 2. 修正方案与取舍（二选一）

派单要求「加深前景或调底色，二选一」。**选择：不动底色，锁定前景取值并收编为 token。**

| 方案 | 取舍 |
|---|---|
| ✅ 采用：收编前景为 token `--metric-accent: #2F5FD0`（tokens.css 新增，Dashboard.vue 改引用） | 保持已验证达标色相（5.02:1，余量 0.52）；消除硬编码；零视觉变化、零品牌观感风险 |
| ❌ 不采用：调底色（把 `--bg-soft` 调浅到白系） | `--bg-soft` 是全局 token，被全站大量引用，改动会波及所有软底场景，爆炸半径不可控 |
| ❌ 不采用：改用 `--color-primary`（`#3F6FEF`） | 在 `#F0F0F0` 上仅 3.90:1，不达标 |
| ❌ 不采用：改用 `--color-primary-active`（`#2F5BD6`，5.14:1 达标） | 虽达标但改动了已验证的识别色相，且与按钮 active 态语义耦合，无必要 |

同时按禁硬编码红线，把散落在组件里的字面量收进 token（派单：「如果它散落在组件里，把它收成变量再改」）。
