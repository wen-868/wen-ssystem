## 9. 派单前提证伪（team-lead 派回复核结论）

> 本节回应「派单依据 `#406cd4` on `#f0f0f1` = 4.27:1」的硬矛盾。结论：**该前提对当前（及历史）代码不成立**。

### 9.1 三件事实

① **`#406cd4` 在当前源码 0 命中（作为颜色值）**：team-lead 已在 `admin-web/src` 全量 grep = 0。补充：`git log -S '#406cd4'` 跨 admin-web 与全仓仅命中两处——`2cfccca3`（A-8 派单卡文本，位于 `docs/`）与 `578234d4`（**本执行者上一笔提交**的注释与提交说明，把自己对派单前提的转述写进了 `tokens.css` 注释）。即 `#406cd4` 从未作为 CSS 颜色值存在于本元素任何提交；它只活在"派单文本"与"本单被误导写下的注释"里。

② **「4.27:1 不达标」对当前代码不成立**：当前（及 HEAD、`d796afe4` 之后）源码前景为 `#2F5FD0` × `#F0F0F0` = **5.02:1 ≥ 4.5**，达标。算术上 `#406cd4`×`#f0f0f1` 确为 4.27:1，但该前景/背景组合在源码任意状态都不出现。

③ **本单真实交付 = 消除硬编码 + 收编为 token，不是「修复对比度」**：对比度由前序 `d796afe4`（2026-08-15）完成（`var(--color-primary)`#3F6FEF → `#2F5FD0`，5.02:1）。本单仅把已达标字面量 `#2F5FD0` 收编为 `--metric-accent`，取值零变化、视觉零变化。**卡内原先"修好了 4.27:1"的措辞属假功，本节与 §0.4/§1/§4.2/§6 已一并更正。**

### 9.2 代码依据（逐一回答派回三问）

**① `#406cd4` 在 CI 取样时的代码里到底是什么色值？**
- `git merge-base --is-ancestor d796afe4 2cfccca3` → **exit 0（YES）**：`d796afe4` 是 `2cfccca3`（main HEAD / 分支基）的祖先。故 run `35393061859` 若取样于 ≤2cfccca3 的代码，源码已是 `#2F5FD0`，axe 无理由读到 `#406cd4`。
- `git show d796afe4 -- Dashboard.vue` 的 `.metric-num--accent` diff：**改前 `color: var(--color-primary)`，改后 `color: #2f5fd0`**（注释"原 #3f6fef 对比度 4.43:1"）。即 d796afe4 的真实动作是 `var(--color-primary)`(#3F6FEF) → `#2f5fd0`，**从来不是 `#406cd4` → `#2F5FD0`**。
- `git log -S '#406cd4' -- admin-web/` 与全仓：`#406cd4` 在该文件/仓库历史中**从未作为真实值出现**。
- 结论：`#406cd4` 既非硬编码值、也非 `--color-primary`（= `#3F6FEF`）的解析值、更非任何历史状态；它是**渲染态/讹传值，无法用源码解释**。

**② 全部出现位置（含是否第二处 / `<p>` 子元素）**
- 全仓 `admin-web` grep `metric-num--accent`：**仅 Dashboard.vue 两处**（:35 模板 `<span>`、:915 样式），**无第二处工作台页，无 `<p>` 子元素**。
- run 报 target `.metric-num--accent | p`（带 `p` 子元素）与当前/历史 DOM（`<span>`）不符 —— 进一步说明该 run 的节点选择器不对应本元素真实结构，或为陈旧/错位取样。

**③ axe 报的 `#f0f0f1` 背景**
- 祖先链（自底向上）：`.metric-strip-num/.metric-num--accent`（span，无背景）→ `.metric-strip-cell`（`background: var(--bg-soft)` = `#F0F0F0`，**不透明**）→ `.metric-strip-inner`（无背景）→ `el-card.metric-strip`（白底，被不透明 cell 覆盖）→ 页面。
- 逐层核查：除 `.metric-strip-cell` 的 `#F0F0F0` 外，**无半透明背景、无渐变、无 `opacity<1`、无 `backdrop-filter`、无 `mix-blend-mode`**。
- 故 `#f0f0f1` 与源码 `#F0F0F0` 仅蓝通道差 1（240→241）。**机制未查清**：静态 CSS 无法归因，最可能为 axe 颜色空间取整或 1px 取样像素偏差。此点如实标注「未查清」，但不影响主结论——源码底明确为 `#F0F0F0`，`#f0f0f1` 不改变"#406cd4 无源码依据"的判断。
