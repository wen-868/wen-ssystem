## 二、逐族等价性论证（详）

### A 族（36 处，TS7006）：仅加参数类型标注

- 改动形态：`(valid) =>` → `(valid: boolean) =>`（唯一例外见 B 族），**回调体、`if (!valid) return;`、`await` 位置、调用链一字未动**。
- 与库签名一致：`node_modules/element-plus/es/components/form/src/types.d.ts:17` `type FormValidateCallback = (isValid: boolean, invalidFields?: ValidateFieldsError) => Promise<void> | void;`。
- 强证据（跨文件、非推理）：**30 个改动文件的 TS→JS 转译产物与 HEAD 逐字节相同（29/30），第 30 个（ZxElTable）去掉新增的 5 行后亦逐字节相同**（脚本与原始输出见附 A）。类型标注在编译期擦除，运行时字节码不变。

### B 族（2 处，TS7006）：`(b: any)`

- 依据：`bills` = `results[2].value?.records || []`，而 `fetchSaleBills`（`admin-web/src/api/common.ts:183-186`）直接 `return data.data`（无类型）⇒ `bills` 本身就是 `any`，`b` 的真实类型即 `any`；同文件相邻的 L341 `(o: any)`、L360 `(b: any)`、L661 `(o: any)`、L664 `(b: any)`、L671 `(a: any, b: any)` 已是同款写法。
- 零行为变更：仅参数标注、编译期擦除；`.filter(...)` 表达式与后续 `slice/ map / sort` 逻辑未动；转译产物逐字节相同。
- **自我报备**：这是本单唯一用到 `any` 的地方（参数标注，非 `as any`）。若凌舟要求更强类型，需要为 Dashboard 的 `Promise.allSettled` 九个结果与 `overview` 补整套类型——那已超出本单"最小范围"，请另派（见 §6 需裁定 a）。

### C 族（1 处，TS18047）

- 根因：L183/L184 写的是 `SpeechRecognition?: new () => typeof recognition;`，而 `typeof recognition` = `{ … } | null` ⇒ `new Ctor()` 的类型带上了 `null`，于是 L188 赋值后的 `recognition.lang` 被判"可能为 null"。
- 修法：`new () => NonNullable<typeof recognition>`（把误带进来的 `null` 去掉），L188/L189/L190 三行本体未动。
- 零行为变更：JS 构造函数 `new Ctor()` 运行期必然返回对象，`NonNullable` 只是把类型对齐运行期事实；`getRecognition()` 的调用方（`toggleVoice()` L199-203 的 `if (!rec) …` 守卫）未动；转译产物逐字节相同。

## 三、TS2304 的 AutoImport 逐行等价取证（本单最容易踩样式坑的一处）

**事实 1｜原注入内容（由装在本工作区里的解析器实测，非推断）**

**事实 3｜改后不会再"重复注入"**：`node_modules/unplugin-auto-import/dist/src-C6T5sjAq.mjs:651-669` —— 插件的 resolver 只对"文件里尚未被静态 import 的标识符"（`names`）调用解析；显式 import 后 `ElMessageBox` 不再进入 `names` ⇒ 旧注入消失、我的显式三行补上，**前后等价（1:1）**。

**事实 4｜全仓唯一性核对（复算，比派单卡更细）**

```powershell
$u = rg -l "ElMessageBox\." admin-web/src -g '*.vue' -g '*.ts'
```

**事实 5｜副作用可达链**（说明"为什么这处必须留样式"）：`node_modules/element-plus/es/components/message-box/style/css.mjs` 内容为
