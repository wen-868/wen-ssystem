## 五、⚠️ 纠正：批 5 清单里的「1 处真 404」**不成立**

裁定 §三把它列为真 404（`api/tenant-application.ts:42/46` 打 `/tenant/applications`，应为 `/api/platform/applications`）。**按新规则先取证据再下结论，实测结论相反**：

| 证据 | 内容 |
|:---|:---|
| `backend/src/routes/tenant-register.routes.ts:37` | `routeConfig.prefix = "/api/tenant"` |
| 同文件 `:25/:28/:31/:34` | `GET /applications`、`GET /applications/:id`、**POST** `/approve`、**POST** `/reject` |
| `auto-routes.ts:172` | `app.use(config.prefix, ...)` → 该文件被挂载 |
| **实测**（`NODE_ENV=development USE_MOCK_DB=true`, 18080, 无 token） | `GET /api/tenant/applications` → **401 未登录**（非 404）；`POST /api/tenant/applications/1/approve` → **401** |

`404`=无路由、`401`=路由存在但鉴权拦截 → **该路径有效**。且 `/api/platform/applications` 那套的审核是 **PUT**（`platform-applications.routes.ts:23/26`），而前端 `:50/:54` 用 **`.post`** → 若改到该前缀，**approve/reject 反而会 404**。
**处置：未改路径**（改了会把能用的接口改坏）。两套同 handler、异前缀属历史并存（`platform-applications.routes.ts` 注释标 `R48-05`）。**请裁定**：是否接受「非 404、维持现状」的结论，或另指定应以哪一套为唯一入口。
