## 一、方法与判据

1. **零注入**：探针从不 `document.createElement`。登录后用 API 取 token 写入 `localStorage["admin_auth"]`，
   逐路由 `goto`，对每个目标选择器取**页面自渲染**的真实元素（过滤掉 `display:none/visibility:hidden/尺寸 0`）。
2. **真实生效背景**：把元素自身到最近不透明祖先之间的每一层 `background-color` **按 alpha 合成**
   （H-1 的 fixture 用的是"最严面"假设值，我这里是合成实测值，两者口径不同，见 §五）。
3. **比值**：WCAG 2.x 相对亮度公式；阈值 4.5:1（本轮 9 条字号 12–16px、字重 400–700，**均未达大文本 18.66px/700 门槛**，故一律 4.5:1）。
4. **是否被覆盖（R8.1 判据）**：枚举同源样式表中**所有**匹配该元素且声明 `color` 的规则，按
   (特异性, 文档次序) 排序，**末位即胜出规则**；再比对元素 computed `color` 与该元素上解析后的
   `--color-*-text`（custom property）值是否相等 → 相等即"被改声明生效"，否则即"被覆盖/改写"。
   **不以源码顺序推理**（遵 R8.1）。
5. **触发弹窗元素**：少数元素（GiftRule 层级预览、BankAccounts 余额流水）在 `v-if` / dialog 内，
   探针先点**页面既有按钮**（`新建满赠规则`→`+ 添加层级`；`余额流水`）把它驱动出来，再取真实元素。

> 环境指纹：Node 22.22.2 ｜ Playwright 1.62.1 ｜ Chromium 151.0.7922.34 ｜ mock `USE_MOCK_DB=true` @127.0.0.1:8081

## 五、与 H-1 数字的口径差异（不引用其数字，仅作对照）

| 维度 | H-1（fixture 注入 + "最严面"假设背景） | 本卡（真实元素 + 合成背景） |
|---|---|---|
| 取样对象 | `document.createElement` 注入的 `.probe`/`.stat-card` 等 | 页面自渲染的真实元素 |
| 生效背景 | E3 记录的"最严面"**假设值**（H-1 §4 自述） | 逐元素向上 **alpha 合成实测值** |
| 同色系不同元素 | 比值**恒定**（改后 primary 全 5.00、success 全 4.93、warning 全 4.92；改前 primary 全 3.89…） | 比值**因元素而异**（改后 primary 5.03/5.27/5.70；success 4.96/5.62；warning 5.02；改前 primary 3.92/4.11/4.44…） |
| 伪类 `:hover` | 剥离伪类测声明 | 真实 hover 后取 computed |

⇒ **两者结论方向一致**（改前不达标 → 改后达标），但 H-1 的数值**不是真实页面的数值**；其"恒定比值"可由"单一假设背景"完全解释。
