## 一、凌舟裁定（统一口径，不得改）

### 1.1 **演示/测试账号一律统一为 `Demo@2026`**

适用于：`demo`（产品演示）、**`store_manager` / `store_operator`**（种子自称"演示账号"，门店端演示与回归用）、**mock 态 `admin`**（本地测试夹具）、以及**所有测试脚本与测试文档的默认口令**。

选取理由（硬约束，非偏好）：
- `Demo@2026` **已在生产实测可用**（`POST /api/admin/auth/login` ⇒ 200）；
- 它**满足口令复杂度**（≥8 位 + 字母 + 数字 + 特殊字符）；而 `admin123` **缺特殊字符，会被 `backend/src/shared/password.ts` 直接拒绝** ⇒ 不可能作为合规定义；
- admin-web 与 app-mobile 两条产品链路的**唯一出处已经是它** ⇒ 统一是"向已生效口径收敛"，不是再引入新值。

### 1.2 🔴 **真实超管账号不参与统一**（否则等于把公开口令安在正门上）

`admin`（租户超管）、`tenant_admin`、平台 `t_platform_admin.admin` **口令已轮换为强口令且不在仓内** ⇒ **禁止**改回任何公开值。

### 1.3 🔴 两处"默认口令"必须改，但**不是**改成 `Demo@2026`，而是**去掉公开默认**

| 位点 | 现状（隐患） | 要求 |
|:--|:--|:--|
| `backend/src/shared/migration.ts:701` | 把**任意**老 SHA256 口令**静默重置为 `admin123`** ⇒ 任何老账号都变成公开弱口令 | 改为**随机口令**，并把"该账号口令已重置为随机值，需人工设定"写进日志（**不得**打印明文口令） |
| `backend/src/shared/migration.ts:1143 / 1180` | 新建环境时把 `admin` / `tenant_admin` 固化为 `Admin@2026` | 改为**优先读 env（如 `SEED_ADMIN_PASSWORD`）+ 未配置则随机**；日志明确"未配置 ⇒ 已生成随机口令，请立即人工设定"，**不得**把固定值写进日志或代码默认 |
