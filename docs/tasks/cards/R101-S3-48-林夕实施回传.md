## 二、为什么选"去掉"而不是 `command:`

1. **位置问题**：`services.<id>.options` 只接受 **`docker create` 的参数**，`--character-set-server` 是
   **mysqld 服务端参数**，放这里必然 `unknown flag` + exit 125。
2. **值本身是"想指定却从没生效"的**：这两项从未生效过，所以生产/CI 实际一直用的是 mysql:8.0 默认
   `utf8mb4` / `utf8mb4_0900_ai_ci`。
3. **默认反而更贴近生产实际**：查 `docs/migrations/` 共 **170** 个迁移文件，其中 **117 个已显式声明**
   字符集，且 `001_phase1_schema.sql` 声明的就是 **`COLLATE utf8mb4_0900_ai_ci`**（= mysql:8.0 默认），
   并非 `options:` 里想传的 `utf8mb4_unicode_ci`；未声明的 53 个继承服务端默认，同值。
   → **去掉 = 与既有迁移口径一致**；改用 `command:` 反而会引入一个从未验证过的 collation 变更。
