## 三、实现形态（C3-1 照此执行）

1. **新路由**：`backend/src/routes/platform-open.routes.ts`，`prefix: "/api/platform/open"`，`auth: "requirePlatformAuth"`，导出 `routeConfig` 由 `auto-routes` 挂载（不手写注册）。
2. **迁移（编号 173 起）**：
   - `ALTER TABLE t_library_api_key ADD COLUMN …` **必须显式 `ALGORITHM=INSTANT`**（生产 MySQL 8.0.46，支持 INSTANT；不支持会**报错而非静默重建**）；**加列前先备份 + 取行数**；
   - 新表：`t_open_webhook`、`t_open_webhook_delivery`、`t_open_api_call_daily`（均 `CREATE TABLE IF NOT EXISTS`、零外键、语句在注释之前）。
3. **存量数据的诚实边界**：加列后既有 `t_library_api_key` 行的新列取默认值；**"这些存量密钥的真实归属租户在库里无从推断"** ⇒ **不得凭猜回填**；登记待核 SQL（由凌舟在服务器只读执行）。
4. **旧端点关系**：`/api/platform/library/api-keys` 5 条**本轮保留不动**（标记为"同能力旧入口"），收口登记 **S3-89**。
5. **安全**：密钥明文只在创建响应出现一次；日志/审计**不得**记录明文；列表/详情一律打码（含前端 `maskKey()` 修复，见 S3-90）。
