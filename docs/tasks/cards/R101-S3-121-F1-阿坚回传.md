### 0 · 沙箱事实与本次绕过方法（先说清前提，否则读数不可信）

**事实**：本沙箱禁止 **node/libuv 以「继承句柄」方式 spawn 子进程**（`bInheritHandles=TRUE` ⇒ `EPERM`）。实测矩阵（原始输出）：

```
node -e "const cp=require('child_process'); ..."
  stdio:['ignore','ignore','ignore'] → status 0
  stdio:['pipe','pipe','pipe']      → EPERM
  stdio:['pipe','ignore','ignore']  → EPERM
  stdio:['ignore','pipe','ignore']  → EPERM
  stdio:['inherit','inherit','inherit'] → 0
```

⇒ `esbuild` 必须 spawn 常驻 Go 服务并用 stdin/stdout 管道通信 ⇒ 官方管线在**加载配置阶段**就 `spawn EPERM`（`ensureServiceIsRunning`），vitest 跑 0 个文件（这就是 S3-121 回传「全量 vitest 本机不可产出」的真因）。

**绕过方法（本次新增，全部产物均为临时文件、验证后已删除、未入库）**：`NODE_OPTIONS=--import <preload>` 预加载三件事，再跑 `npx vitest run … --configLoader runner --pool=threads`：

1. **esbuild → @swc/core 替身**（napi，进程内、无需 spawn）：ESM `resolve` 钩子把 `esbuild` 指向替身；替身实现 Vite 真正用到的 `transform/transformSync/version`（TS→JS），`build/context` 显式报错以便暴露遗漏调用。Vite 只把这些 API 用于「配置文件打包」与「.ts 源码转换」。
2. **`--configLoader runner`**（Vite 6.4.3 支持）⇒ 配置文件不再经 esbuild 打包（改用 runner 直接执行）；同时补 `globalThis.__dirname/__filename`（该模式下 Vite 6.4.3 未注入）。
3. **拦截 `exec("net use")`**（Vite 用管道 spawn 探测网络驱动器 ⇒ EPERM）：本地盘场景等价于探测失败，Vite 回退默认 `safeRealpathSync`。
