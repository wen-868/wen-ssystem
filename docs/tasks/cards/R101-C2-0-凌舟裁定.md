## 二、实体裁定（我的口径）

### 2.1 表方案：授权**新建 4 张空表**，本批**零 ALTER**

| 草案 | 裁定 | 落地 |
|---|---|---|
| 草案 1 `t_platform_template`（初始化模板主表） | **授权** | `docs/migrations/171_platform_templates.sql` |
| 草案 2 `t_platform_template_version`（版本快照） | **授权** | 同上 |
| 草案 3 公共打印模板 | **采纳方案 B：新建 `t_platform_print_template`**；**否决方案 A（复用 `t_print_template` + 加列）** | 同上 |
| 草案 4 `t_platform_io_template`（导入/导出模板） | **授权** | 同上 |
| 草案 5 公告模板 | **采纳 0 DDL**：复用 `t_platform_config`（`platform='SAAS'`、`config_key='announcement:templates'`）；**否决**新建表 | 无迁移 |

**否决方案 A 的理由（写死，防以后反复）**：

1. 对**生产表** `ALTER TABLE` 在 MySQL < 8.0.12 会 COPY 重建并持写锁，而**本机与服务端均未验证版本能力**——未验证的风险不得直接进生产库；
2. 方案 A 需向**租户作用域表**写平台行（`tenant_id='platform'`），把平台语义混进租户表 ⇒ **同一语义两个真相源**；
3. 迁移链刚因 runner 缺陷修复而稳定，本批**不引入 ALTER 变量**。

**DDL 硬约束**：只新增空表；全 `CREATE TABLE IF NOT EXISTS` 幂等；**不改任何既有表的列/索引/约束**；不建外键（与平台表既有口径一致，一致性放服务层）；有且仅有编号 **171**（已核：现有最大编号 170）。
若实现中还需 4 张表之外的表/列 ⇒ **立即停下报备**，不得自行扩表。
