## 一、确切代码与行号（容器 class / 样式 / 祖先链）

> 文件：`admin-web/src/views/dashboard/Dashboard.vue`（库当前真实行号，与派单 714/720 一致，行号未漂移）

**容器（模板，line 95）**
```html
<el-card class="feed-card feed-card--trend" shadow="hover">
```
内部：`#header` 槽（"本月销售趋势"）+ 条件渲染 `chart-empty`（空）或 `trend-chart`（ECharts，line 101-104）。

**样式声明（scoped `<style>`，line 714-723）**
```css
714  .dash-col--left .feed-card--trend {
715    /* 固定高度：左列总高(400+16+420)作为行高基准，右列 height:100% 据此填满 */
716    height: 420px;
717    display: flex;
718    flex-direction: column;
719  }
720  .dash-col--left .feed-card--trend :deep(.el-card__body) {
721    flex: 1;
722    min-height: 0;
723    padding: 8px 20px 12px;
724  }
```

**祖先链（谁给高度约束）**
| 层级 | 选择器 / 元素 | 高度相关声明（文件:行） | 作用 |
|---|---|---|---|
| 本容器（约束源） | `.dash-col--left .feed-card--trend` | `height:420px`（716） | **直接钉死 420px**，是高度约束的真正来源（非祖先） |
| 父 | `.dash-col--left`（`.dash-col`） | `display:flex !important; flex-direction:column`（689-693） | 仅纵向堆叠，不提供高度约束 |
| 祖父 | `.dashboard` | `min-height: calc(100vh - var(--topbar-height) - 32px)`（687） | 页面最小高度，非本卡约束 |
| 曾祖 | 页面 `.main` / layout 主内容区 | `styles.css:111-116` `overflow-y:auto; max-height:100vh` | 整页滚动容器，非本卡约束 |

> 结论：高度约束 = 容器自带 `height:420px` 字面量；`flex:1; min-height:0`（721-722）允许 body 在内容超出时被压缩而不外露 → 溢出被 `.el-card` 的 `overflow:hidden` 收口，形成"非键盘可达的可滚动区域"。

**滚动机制核实**：Element Plus `.el-card` 默认 `overflow:hidden`（已用 `node -e` 抽取 `el-card.css` 验证：`...display:flex;overflow:hidden}`）。即卡片钉 420px + 内容超出 → 卡片本身成为可滚动区域，但无 `tabindex`/`role` → axe `scrollable-region-focusable` 命中。

## 二、该区域内可滚动子元素（逐个列出 + 依据）

**区域边界**：`.feed-card--trend`（`.el-card`）及其 `.el-card__body`（line 95 / 720-723）。

**内容子元素（template 96-104）**
| 子元素 | 行号 | 是否可滚动 | 依据 |
|---|---|---|---|
| `.feed-header`（header 槽，"本月销售趋势"） | 97-99 | 否 | 固定高度文本，不溢出 |
| `.chart-empty`（el-empty，当 `salesTrendData.length===0`） | 101-103 | 否（通常） | `height:100%` 但空态内容少，不溢出 |
| `.trend-chart`（`ref="salesTrendChartRef"`，当数据存在） | 104 | **是（溢出源）** | `height:100%`（877-880），ECharts 按容器绘制；数据量/坐标轴标签量决定渲染高度是否超出 body 可用高度 |

**滚动机制链**：`height:420px`(716) → body `flex:1;min-height:0`(721-722) → 内容 `.trend-chart` 渲染高度 > body 可用高度 → `.el-card` `overflow:hidden`(EP) 收口 → 非聚焦可滚动区域。

**与相邻卡的差异（根因佐证）**：左列另一张 `.feed-card--feed`（704-712）的 body **显式设了 `overflow-y:auto`**（712），成为"有意滚动区"；而 `.feed-card--trend` **未设** overflow，仅依赖卡片 `overflow:hidden` → 正是趋势卡成为"非聚焦可滚动区"的根因差异。

**间歇性的解释**：溢出与否取决于当次 `salesTrendData` 的体量/形状（ECharts 渲染高度），与 S3-60 卡"3/8 间歇、数据驱动"完全自洽。

## 三、两方案影响面对比 + 推荐

### 方案（甲）：给可滚动容器加 `tabindex="0"` + `role="region"` + `aria-label`
```html
<!-- 选项 A：在 .el-card__body 或其父容器 -->
<div class="el-card__body" tabindex="0" role="region" aria-label="本月销售趋势">…</div>
```
- **改变**：仅加键盘可达性语义，不改布局/视觉/cursor。
- **副作用**：无视觉回归；Tab 序多出一个可到达区域，键盘用户聚焦后可方向键/滚轮滚动内容，符合 WCAG 2.1.1。
- **风险**：低（纯语义增强）。
- **落地位置**：可在 `Dashboard.vue` 模板给 `.feed-card--trend` 的 `el-card__body` 包一层 `div[role=region][tabindex=0][aria-label]`，或对 `el-card` 加 `:body-attrs`（视 EP 版本支持）；也可在 scoped 样式用 `:deep(.el-card__body){ outline: none }` 配合。

### 方案（乙）：改不滚动布局（去 `height:420px` / 改 overflow）
- **乙-a**：删 `height:420px`(716)，让趋势卡按内容自适应高度；同时把 body `flex:1;min-height:0` 改为自然高度（或给 chart 固定高度、卡片不限制）。
- **乙-b**：在 body 加 `overflow-y:auto`（与 `.feed-card--feed` 一致，line 712）使滚动"有意"。⚠️ **注意**：纯加 `overflow` 仍会被 `scrollable-region-focusable` 命中（除非同时加 `tabindex`），故乙-b 必须配合 `tabindex` 才彻底。
- **改变**：趋势卡高度不再钉死。
- **副作用（视觉回归，中）**：line 715 注释明确 420px 是"左列总高基准，右列 `height:100%` 据此填满"。删 420px 会改变左列总高 → 右列 `.dash-col--right` 的 `side-card--fill`（`flex:1 1 0; min-height:0`，730-736）随之拉伸/压缩 → 右列"最新订单/待办/快捷入口"布局可能变化，需回归左右列对齐。
- **风险**：中（布局溢出/对齐联动）。

### 推荐：**方案（甲）**
**理由**：
1. **零视觉/布局回归**：仅加 `tabindex`/`role`/`aria-label`，不碰 715 注释所述高度基准联动，右列对齐不受影响。
2. **直击缺陷**：治理对象是"键盘可达性"，甲正是 WCAG 2.1.1 的标准修法。
3. **乙若只改 overflow 不够**：scrollable-region-focusable 仍可能命中，必须再加 tabindex——等于把乙做成了"甲+布局改动"，回归面反而更大。
4. **契合本轮节奏**：凌舟裁定 S3-60 的"改代码 + 连续 10 次取样"另案派发（依赖 A-5 采样稳定化），本次只交方案与取证；甲是最易在 A-5 稳定后直接落地、取样验收的方案。

> 最终改法 + 取样另案派发，本卡**不改代码**（已在红线内）。
