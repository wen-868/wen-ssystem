## 一、执行顺序（硬）

**T6 必须先做**（平台角色 + 权限点目录）→ **T7 紧随**（工单系统的权限点、受理人、数据权限都依赖 T6 的角色/权限目录）。两件可作为**两个连续单**，但 T7 不得早于 T6 合并。

## 二、外键与类型口径（**硬约束，直接对应 A 类缺陷的教训**）

新表若引用既有表，**列类型与 collation 必须与被引用列逐字一致**（本项目 A 类缺陷就是 `REFERENCES t_tenant(id)` 写成 `INT` 而实际是 `VARCHAR(36)`，导致全新库建表失败）。已取生产实测口径：

| 被引用列 | 生产实测 | ⇒ 引用列必须写成 |
|---|---|---|
| `t_tenant.id` | **`varchar(36)` / `utf8mb4_0900_ai_ci`** | `tenant_id VARCHAR(36) CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci` |
| `t_platform_admin.id` | **`int`** | `admin_id INT`（或 `operator_id INT`） |

**另**：新表**不要**默认跟随库默认 collation 而不写（=本项目 collation 混用的源头之一）——凡文本列**显式写** `COLLATE utf8mb4_0900_ai_ci`；若必须与某个既有表 JOIN，则与其被 JOIN 列**同 collation**，并在卡里写明依据。

## 五、需要外部口径的三项（**不得自行假设**）

| # | 事项 | 归属 |
|---|---|---|
| 1 | 工单 **SLA** 口径（是否计时、按小时/工作日、是否分优先级） | **产品/业主** |
| 2 | 服务报表口径（哪些指标、时间粒度、是否含未关闭） | **产品/业主** |
| 3 | 权限 `data_scope` 档位（全部/本部门/本人/自定义） | **产品/业主** |

⇒ 这三项**不阻塞**建表与端点骨架：可先用"字段留空 + 显式空态 + 不计算"落地，待口径到位再补算法；**禁止**用近似值或硬编码冒充。

## 六、影响面与迁移口径

1. **零改既有表**：T6/T7 全部为新表；**不得** ALTER 既有表（如确需，先报凌舟裁定）。
2. **迁移编号**：当前最大 **178** ⇒ T6 用 **179**、T7 用 **180**（一文件一主题；若同单多表则同一文件内多条 `CREATE TABLE`，并在文件末尾注释说明）。
3. **DML 闸门**：预置数据（如内置角色/默认工单类型）按 MIG-4 写闸门规则处理 —— INSERT 默认会被跳过；确需预置 ⇒ 必须在卡里写明"是否走 allow 档 + 依据"，**禁止**用 DDL 变相写数据。
4. **`migration-check`**：新表在**全新库**必须能全量建成；实施后该 job **不得新增失败面**（现有红为既有 A 类，见《门禁四档表》）。
5. **生产**：合并部署后必须核对"新表已建成 + `SHOW CREATE TABLE` 的 collation/外键与本文口径一致"（凌舟执行）。

## 七、验收（每单六步闭环之外的批级判据）

1. 权限矩阵**逐条可核对**：以 T6 的权限点目录为准，T7 的权限点必须能在目录里找到（`rg` 双向核对）；
2. **公/私回复隔离**：对租户可见的接口**绝不**返回 `INTERNAL` 内容（含单测反测：构造内部备注 ⇒ 租户侧接口断言不含）；
3. 工单状态机：非法转移（如 `closed → processing` 直接改）必须 400，且**不是**静默忽略；
4. 三条外部口径未定时，相关字段/指标以"显式空态 + 不计算"落地，并登记待办（禁止近似值）。
