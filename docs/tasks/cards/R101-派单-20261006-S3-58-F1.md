## 二、范围（钉死）
### R2 · 限流维度改造（`middleware/login-fail-limiter.ts`）
- **主键改为 (账号 + 归一化 IP)**：例如 `acct:${username}|ip:${ipKey(req)}`，阈值保持"快锁"（沿用现有 5min 窗 / 15min 锁的小阈值语义）；
- **保留账号维度高阈值兜底**：单独一条 limiter，键仍是 `acct:<username>`，但阈值**显著抬高**（建议 60 次/小时量级，你按 `express-rate-limit` 的 `limit` 语义给具体值并写明理由），用于拦"分布式多 IP 打同一账号"；
- **不得**放宽到"完全按 IP 判定"（那会让分布式爆破无成本）；也**不得**取消账号维度（那会让分布式爆破无上限）；
- 两维度都要**保留 `skipSuccessfulRequests: true`**（合法用户登录成功不应累计失败）。
### R3 · 平台端 MFA（零 DDL）
- 新增端点（按既有 `routeConfig` 约定、走 `requirePlatformAuth` + CSRF）：
  `GET /api/platform/auth/mfa/status`、`POST /api/platform/auth/mfa/setup`、`POST .../mfa/confirm`、`POST .../mfa/disable`；
- 服务层：**新增平台管理员版实现**（读写 `t_platform_admin.mfa_secret/mfa_enabled`），**不得**复用/改写 `t_sys_user` 版逻辑（那是租户用户的，混用会串表）；
- 登录二段：`POST /api/platform/auth/login` 在密码校验通过且 `mfa_enabled=1` 时**只返回 `{ mfaRequired: true, mfaToken }`**（不得直接发正式 `token`）；新增 `POST /api/platform/auth/mfa/verify`（`{mfaToken, code}`）验证通过后发正式令牌；
- **默认不强制**：`mfa_enabled=0` 的正常直发令牌；`GET /api/platform/auth/me` 增一个提示位（例如 `mfaEnabled: boolean`），供总台侧引导开启；
- 密钥/验证码一律**不得进日志**（沿用凭据纪律）。

## 三、逐项交付物
