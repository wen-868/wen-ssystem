## 二、数据源裁定（本单最重要的事实）

1. **"逐次明细"有载体**：`t_ai_audit_log`（每次 AI 调用 1 条）⇒ `metering-log` / `model-share` **不是"无明细"**；
2. **真正的缺口是两列**：`t_ai_audit_log` 缺 **`cost`（费用）** 与 **`deduct_source`（扣减来源）**；
3. **日聚合表不可替代明细**：`t_ai_usage_daily.model` **不在唯一键、UPSERT 不更新它** ⇒ 按模型聚合（`model-share`）**不能**在日聚合表上做（**不得用近似值冒充**）。

## 三、裁定

| # | 事项 | **裁定** |
|---|---|---|
| 1 | 4 个缺端点 | **授权实现**（`public-models` / `metering-log` / `abnormal-tenants` / `model-share`），**在主干后端**实现（数据在主库：`t_ai_external_model` / `t_ai_audit_log` / `t_ai_usage_daily`） |
| 2 | `t_ai_audit_log` 补两列（`cost` / `deduct_source`） | **授权 `ALTER TABLE … ADD COLUMN`**（追加型、可逆）；**必须显式 `ALGORITHM=INSTANT`**（生产 MySQL 8.0.46 支持），并先取行数 + 备份 |
| 3 | `model-share` 的口径 | **只按 `t_ai_audit_log` 逐次明细聚合**（`GROUP BY model`）；**禁止**用 `t_ai_usage_daily` 近似冒充 |
| 4 | 历史数据回填 `cost`/`deduct_source` | **本轮不做**（老调用无此信息，凭空造值即造假）⇒ 新列对历史行为 `NULL`，接口需明确空态；回填若要做，另立卡**先定口径** |
| 5 | 前端把 `billing` 的"待接入"文案 | 判 **③（前端文案错）**：接口早已实现且已接线 ⇒ 由 C5-2 前端改文案（不是后端缺口） |
| 6 | 其余 5 处（注释/占位交互） | 判 **③**，由 C5-2 一并收口 |
| 7 | 与 ai-base 的关系 | 本轮**不跨仓改动**；主干后端实现的是**平台侧读接口**（数据在主库）。若后续要把计量写入或 chat 走 ai-base，另立卡并明确仓边界 |
