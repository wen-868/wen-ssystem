# 【派单 S3-119】（P2 门禁收敛）测试内自建路由触发 `js/missing-rate-limiting`：改为"测试 app 也显式限流"+ 防回归断言

```
【派单 S3-119】把"每新增一个测试文件就必然新增 1 条 CodeQL 告警"这条摩擦修掉：测试内自建 express app 时**内联**挂限流器，并加一条防回归断言。
派单人：凌舟（总负责人）｜2026-09-26
执行方：阿坚（后端 · 本地通道）
优先级 / 时间盒：P2 · 一次跑完（预计 ~15 个测试文件各加 1–2 行 + 1 个门禁用例）
背景与依据（全部已取证）：
  1. **现象（数字）**：`code-scanning` 全量 open = 100（分页上限），按规则分布 `js/missing-rate-limiting` **95** 条 + 其它 5 条。
     其中**生产路由**的 95 条为**历史存量**（`miniapp.routes.ts` 19 / `subscription.routes.ts` 13 / `tenant.routes.ts` 7 / `wechat.routes.ts` 7 / …）；
     而最近 5 个 PR（#132 `platform-role`、#137 `platform-ticket`、#142 `platform-notification`、#144 `platform-export-task`、#141 `platform-library-review-log`）**各只新增 1 条**，且**全部落在新增的测试文件上**（`backend/src/__tests__/routes/*.test.ts`）。
     ⇒ 结论：S3-112 对**生产注册点**的收敛**已生效**（新生产路由文件不再新增告警）；**仍活跃的缺口 = 测试内自建 app**。
  2. **受影响文件（当前 15 个，每文件 1 条）**：`ai-platform` / `platform-announcement-templates` / `platform-billing-arrears` / `platform-billing` / `platform-c6-1a` / `platform-export-task` / `platform-library-review-log` / `platform-monitor-ops` / `platform-notification` / `platform-open-api-keys` / `platform-open-webhooks` / `platform-role` / `platform-s3-110` / `platform-templates` / `platform-ticket`（均为 `backend/src/__tests__/routes/*.test.ts`）。
  3. **根因**：这些用例**自建 express app** 并挂**真实鉴权中间件**（`requirePlatformAuth`）来测鉴权/路由——CodeQL 的 `js/missing-rate-limiting` 要求"做鉴权的 route handler 必须有限流"，而测试 app 没有限流器 ⇒ 每条新增测试文件必然新增 1 条 high 告警。
  4. **为什么不能靠"排除测试目录"了事**：本项目铁律"绕过≠修复"；且排除会把测试目录一并移出**所有**安全扫描（含真正该报的规则）。⇒ 采用与 S3-112 同一思路：**让限流在 CodeQL 看得见的位置出现**。
交付物：
  ① 对上述**每一个**"自建 app 且挂鉴权"的测试文件，在 **mount 路由之前**加一行**内联**限流（`rateLimit(` 必须**字面出现在该文件里**——这是 S3-112 的核心结论：helper 包装会让 CodeQL 看不见）：
     ```ts
     import rateLimit from "express-rate-limit";
     // …
     const app = express();
     app.use(express.json());
     app.use(rateLimit({ windowMs: 60_000, max: 10_000 })); // 测试用高上限，避免用例互相 429
     app.use(xxxRouter);
     ```
     · `max` 取 **10000**（测试内不承载真实流量，取高值避免用例间互相触发 429）；**不得**移除/改动任何既有断言与用例；
     · 若某文件的 app 由公共函数构造（如 `makeApp()`），则在**该构造处**加内联限流（同样要求 `rateLimit(` 字面出现在**源码**里）。
  ② **防回归门禁**（新增一个用例文件，例如 `backend/src/__tests__/shared/route-test-rate-limit.test.ts`）：
     · 遍历 `backend/src/__tests__/routes/*.test.ts`；
     · 对其中**出现 `requirePlatformAuth`（或任何 `auth:` 挂载）**的文件，断言其源码**含子串 `rateLimit(`**；
     · 断言"被检查文件数 ≥ 1"（**防空转**：glob 写错导致 0 文件却 exit 0 —— 与 S3-49 同族）；
     · 违规时断言信息里**逐个列出文件名**。
  ③ 回传卡 `docs/tasks/cards/R101-S3-119-阿坚回传.md`（照抄下方「回传格式」十项）。
验收标准（硬）：
  ① `cd backend && npx tsc -p tsconfig.json --noEmit` exit 0；`npx eslint <改动文件>` 0 error。
  ② **全量** `cd backend && npx vitest run` **0 failed**（给 `Test Files / Tests` 汇总行）——特别注意：加限流后既有用例**不得**因 429 变红。
  ③ **反测（原始输出必贴，"该红就红"）**：
     a) 从任意一个被测文件里删掉那行 `rateLimit(` ⇒ 新增的门禁用例**变红**且**指名该文件**；恢复后转绿；
     b) 把门禁的 glob 改成必然匹配 0 个文件 ⇒ "被检查文件数 ≥ 1"断言**变红**；恢复后转绿。
  ④ **收敛可核对**：给出 `rg -l "requirePlatformAuth" backend/src/__tests__/routes | wc -l` 与 `rg -l "rateLimit\(" backend/src/__tests__/routes | wc -l` 两个数字，**并集应为空差**（前者集合 ⊆ 后者集合）。
  ⑤ **本 PR 的 CodeQL 检查**：**不得再出现** `js/missing-rate-limiting` 的**新增**告警（存量 95 条不算）。
红线（不得触碰）：
  ① **只准改** `backend/src/__tests__/**` 下的文件 + 新增 1 个门禁用例文件 + 本回传卡；**不得改任何生产源码**（`backend/src/routes|services|controllers|shared` 一行都不许动）；不得改 `docs/migrations/**`。
  ② 不得放宽/删除任何既有断言；不得改 `saas-admin/**`；不得改 `docs/API接口文档.md`、`docs/数据库变更清单.md`、`docs/tasks/当前批次.md`、`docs/tasks/R101-总进度与推进计划.md`（**由凌舟记账**）。
