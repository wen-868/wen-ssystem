7. **`saas-admin --input-border` 无任何引用**（tokens.css:285 注释自陈「保留定义待收编」）⇒ 该槽位在 saas-admin 是死值，阶段 2 需先确认输入框真源再改。
8. 我未改任何值，也未动 `saas-admin`（林夕域业务代码）/ EP 全局变量 —— 本单本来就只读。

## 6. 口径与局限（请连结论一起读）

**6.1 实测形态**：本地无后端 ⇒ 不是整页截图取色，而是「各端**真源 CSS 内联** + 该端真源 `importOrder` 顺序 → 浏览器 `getComputedStyle`」。因此**层叠顺序是真的**（EP 覆盖、同特异性后置规则都会被正确反映），但**元素上下文是构造的**（不依赖接口数据的渲染）。
**6.2「最严面」的定义**：所有该端**面 token**的笛卡尔积中比值最低者（即最坏组合）。它**不是**"实际会同时出现在一屏的组合"。
**6.3 状态软底的笛卡尔积陷阱（最重要）**：`--color-*-soft`（如 `--color-danger-soft`）也在面集合里，于是「`#365FCE` 文字压在 `--color-danger-soft` 上」这种**不可能的设计**会被算成 4.39 <4.5。⇒ **判定建议值是否达标，必须看「常规浅底」列**；「最严面」列只用于发现**真实的**组合风险（如 §5.1 的「白字压状态实底」就是真风险，因为按钮就是这么用的）。
**6.4 弱文字要不要更暗**：`--text-muted`/`--text-placeholder` 建议 `#6B6B6B`（常规浅底 4.68 ✅）。若要求「在状态软底上也无条件达标」，只能取 `#525252`（6.13 ✅），**代价是与次文字同值、三层层级塌成两层**。⇒ 倾向：**保留 `#6B6B6B` + 写明"弱文字不得置于状态软底"**（这是设计约束，不是缺陷）。**此点建议由凌舟裁定。**
**6.5 app-mobile 的特殊性**：`uni.scss` 是 **SCSS `$var`**（6718 处引用，`var(--uni-*)` **0 处**）。⇒ ①它的"现值"是编译期展开值，与 CSS 变量体系不完全等价；②"新增文字专用 token"这条路在 app-mobile 是**新增 `$uni-*-text`**，不是新增 CSS 变量。
**6.6 未纳入**：图表系列色、玻璃拟态/遮罩/骨架、品牌扩展色（`--color-purple/pink/cyan`）、暗色组（`saas-admin/src/style.css` 的 dark 组，且该文件本身是残留模板，见 §风险 5）。
