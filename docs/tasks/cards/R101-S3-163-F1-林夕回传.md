## 三、为什么这样改

- CodeQL 的告警点原文：`This regular expression does not match upper case <SCRIPT> tags.` —— 这条不是"误报方向"，它指出的**是一个真实缺陷**：原正则只认小写 `<script>`，一旦 `.vue` 用大写 `<SCRIPT>`，`codeOf()` 会返回空串，**该文件的 script 段被静默跳过，守卫会漏检**。
- 因此加 `i` 不是"为过门禁而改"，而是**同时修掉漏检方向**：既让 CodeQL 的 `js/bad-html-filtering-regexp` 不再命中，又让大写标签的真实内容进入扫描。
- 选它而不是"先按 `i` 分割/字符串扫描定位"的原因：本行**不是 HTML 过滤**，只是从 .vue 中截取 script 段做静态分析；`i` 是**单字符、零语义副作用、可读性最好**的最小改动，符合"只改有问题的地方"的红线。改写为手写扫描反而扩大了改动面与出错概率。
- 守卫判定规则 **R1/R2/R3 语义未动**，任何 FAIL 条件都未放宽（见 §四红侧反测：注入的第二条出口照样判红）。

## 八、build 结论：`build:h5` 在本会话被沙箱阻塞（未取得 EXIT=0）

命令：

```
npm --workspace app-mobile run build:h5
```

原始输出（截尾）：

```
> zhixiang-app-mobile@1.0.0 build:h5
> uni build -p h5

Compiler version: 5.23（vue3）
Compiling...
failed to load config from D:\Users\ZXQL\wt-agents\pr-258\app-mobile\vite.config.ts
spawn EPERM
Build failed with errors.
npm error code 1
EXIT=1
```

**根因取证（环境级，与本改动无关）**：

1. `esbuild` JS API 单独调用即失败，未经过任何本项目文件：
   ```
   node -e "require('esbuild').transformSync('const a=1')"   ⇒   ERR spawn EPERM
   ```
2. 本沙箱对"node 创建带管道的子进程"一律拒绝，与命令行/工作目录无关：
   ```
   spawnSync('node', [...], { stdio: 'ignore' })              ⇒ status=0
   spawnSync('node', [...], { stdio: ['pipe','pipe','pipe'] }) ⇒ EPERM
   spawnSync('node', [...], { stdio: ['pipe','pipe','inherit'] }) ⇒ EPERM
   cp.spawn('node', [...], { stdio: ['pipe','pipe','inherit'] })  ⇒ Error: spawn EPERM
   （cwd 分别取仓库、%TEMP%、C:\Windows\Temp，均 EPERM）
   ```
3. esbuild 的 spawn 参数是硬编码的管道三元组，无法回避：
   `node_modules/esbuild/lib/main.js:1980` ⇒ `stdio: ["pipe", "pipe", "inherit"]`。
4. 失败发生在**加载 `vite.config.ts`** 阶段（esbuild 进程都还没起来），早于任何业务代码编译；本单改的 `scripts/s3-163-logout-uniqueness-guard.cjs` 是独立 dev 脚本，不在构建图内（`rg -n "s3-163-logout-uniqueness-guard"` 仅命中自身文档注释与 `package.json` 的 `guard:logout` 入口，无构建期引用）。
5. 备用通道也不可用：`codex exec -s workspace-write ...` ⇒ `Error: failed to initialize in-process app-server client: 拒绝访问 (os error 5)`。

**结论**：`build:h5` 的红是**沙箱对管道 spawn 的限制**导致的，不是本改动引入的编译错误；本会话无法越过。请凌舟在不受该限制的终端执行一次 `npm --workspace app-mobile run build:h5` 作为最终构建复核（本单无业务代码改动，构建面风险为零，但仍以凌舟实测为准）。
