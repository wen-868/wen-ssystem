# 【派单 S3-122-F1】（P0 前置）权限 matcher 支持通配符（`*` / `dom:*` / `*:action`）

```
【派单 S3-122-F1】把 `checkUserPermission` 的匹配从"只认精确码"扩展为支持通配，否则任何按角色接线都会把只读/销售等角色全部锁死。
派单人：凌舟（总负责人）｜2026-09-26
执行方：阿坚（后端 · 本地通道）
优先级 / 时间盒：P0 前置 · 一次跑完（1 个服务函数 + 单测，≤60 行）
背景与依据（已取证到源码行）：
  1. 现状（`backend/src/services/admin/rbac.service.ts:269-275`）：
     `for (const role of roles) { const perms = JSON.parse(role.permissions); if (perms.includes("*") || perms.includes(permCode)) return true; }`
     ⇒ **只支持精确 `"*"` 或精确码**；`dom:*` / `*:action` 一律不认。
  2. 生产角色权限**实际就在用通配**：`t_sys_role.permissions` 实测 `READONLY = ["*:view"]`、`SALES_STAFF = ["sale:create","sale:view",…]`、`SUPER_ADMIN = ["*"]`。
     ⇒ 若按 S3-122 的清单接线（例如要求 `product:view`），`READONLY` 的 `*:view` **匹配不上** ⇒ 只读角色被锁死。这正是 S3-122 评估单报出的**前置缺陷**。
  3. **本单零运行期风险**：`checkUserPermission` 当前**没有任何路由调用**（`requirePermission` 作为路由中间件使用数 = **0**，见 S3-122 证据 E1）⇒ 本单只改匹配语义与单测，**不影响任何现有接口行为**；它的价值是在接线前把前置修好。
交付物：
  ① `backend/src/services/admin/rbac.service.ts` 的 `checkUserPermission`：抽出**纯函数** `matchPermission(perms: string[], permCode: string): boolean`（可导出以便单测），匹配规则**按顺序**：
     · 精确：`perms` 含 `"*"` ⇒ true；
     · 模块通配：`perms` 含 `"<dom>:*"`（如 `sale:*`）且 `permCode` 以 `<dom>:` 开头 ⇒ true；
     · 动作通配：`perms` 含 `"*:<action>"`（如 `*:view`）且 `permCode` 以 `:<action>` 结尾 ⇒ true；
     · 精确码：`perms.includes(permCode)` ⇒ true；
     · 其余 ⇒ false。
     · 保留**原有 SQL 与调用签名**（`checkUserPermission(userId, tenantId, permCode)`）不变；`perms` 解析失败（非 JSON）时**不得抛错**，按空数组处理（fail-safe 拒绝）并留一条 warn 日志。
  ② 单测（新增文件或追加到既有 rbac 单测，**只增不改**）：至少覆盖
     a) `["*"]` 全通过；b) `["*:view"]` 对 `product:view`/`sale:view` 通过、对 `sale:create` **不通过**；c) `["sale:*"]` 对 `sale:create` 通过、对 `product:view` 不通过；d) 精确码通过；e) 空数组/非 JSON 字串 ⇒ 不通过（且不抛错）；f) 多角色并集：一个角色不满足、另一个满足 ⇒ 通过。
  ③ 回传卡 `docs/tasks/cards/R101-S3-122-F1-阿坚回传.md`（照抄下方「回传格式」十项）。
```
