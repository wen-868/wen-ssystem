风险与自我报备：
1. **GAP-1（P0 级建议优先裁定）：HTTP(S)_PROXY 代理链路下连接期 DNS 守卫整体失效。**
   - 被放行的输入：任何通过保存前同步校验（a/b/c）的公网 HTTPS 域名端点（外部模型/商户 api_endpoint 均然），当部署环境设 `HTTP_PROXY`/`HTTPS_PROXY`（沙箱即设 `127.0.0.1:32939`；生产内网服务器配代理出站同样常见）。
   - 影响面：axios 走代理 transport 时顶层 `lookup` 被丢弃 ⇒ 规则 d 的"连接期同一次解析校验"不存在 ⇒ **DNS rebinding 防线只剩出站前 `assertPublicResolvableTarget` 的一次性解析**，校验与连接之间存在经典 TOCTOU 窗口；且代理链路 DNS 由代理解析，代理可把"公网域名"解析到内网地址，守卫全程不知情（请求照常成功、零 DNS 调用，断言见 ⑥ GAP-1）。`beforeRedirect` 不受影响（follow-redirects 层，代理与否均生效）。
   - 修复建议（供裁定，未改码）：`axiosEgressOptions(strict)` / `OpenAICompatProvider` 改用 `httpAgent: new http.Agent({ lookup: createGuardedLookup(), keepAlive:false })`（Agent 级 lookup 不受 axios 代理路径影响），或显式 `proxy:false` + 自管代理隧道后再挂 lookup；代理场景还需对"代理解析结果"补校验或改用 IP 直连白名单。
2. **GAP-2（P1）：`ExternalModelService.registerModel`（onModuleInit/create/update 后的运行时注册）不跑 a/b/c 复验。**
   - 被放行的输入：**升级前已入库**的存量违规行（如 `http://127.0.0.1:8080/v1`，da2d5dd 之前无守卫时代可入库）或任何绕过 API 直插库的行。
   - 影响面：存量违规行在**对话链路**（factory.create → chatSync）继续出站——testById/testConnection 会拒（走 assertEgressTarget），但 chat 不会；叠加 Node 对 IP 字面量跳过 lookup（本机实证 IP 字面量请求 `lookupCalled=0`）且 scheme 无运行时复验 ⇒ 三层均无拦截。新建/更新路径已收口，故暴露面随存量数据清理而收敛。
   - 修复建议：`registerModel` 首行补 `assertAllowedOutboundUrl(entity.providerBaseUrl)`（R5 已证明该修复使 GAP-2 断言变红，即断言有信号）；对存量行建议先跑一次只读扫描（SELECT 全表 → 逐条 assert → 报告违规行）再决定清理口径。
3. **如实记录的"当前放行"5 处**（均断言在案、非缺口级）：
   - `HTTPS://` 守卫层放行（WHATWG 归一化为 https，语义等价；服务层被旧口径正则拒 409——两层都无违规出站）；
   - 尾点域名（校验与连接同 hostname，规则 d 同样适用于尾点，无绕过面）；
   - 空 userinfo+公网域名（无凭据语义）；`user:pass@` 与 percent 编码用户名均被拒；
   - `https://example.com:80/v1` 等任意端口（端口不在裁定范围；host 仍须公网可解析，无内网绕过；影响面=可触达公网主机任意端口，如需收敛可加"仅 443"裁定）；
