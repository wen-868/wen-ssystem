## 二、Q1–Q9 裁定

| # | 裁定 | 理由（要点） |
|:--|:--|:--|
| **Q1** 迁移编号 | **由凌舟给定：从 `190` 起**（`188/189` 已被并行单 C6-3-2a 占用）；开工当日仍须 `ls docs/migrations \| sort \| tail` **自证**，若被占则顺延 | "最高编号唯一"是测试不变量；给定编号 + 自证双保险 |
| **Q2** 条码唯一键冲突 | **取你的 ② 带条码 / 冲突降级**：能带则带（保住"调取后可扫码销售"），撞唯一键则**降级写 NULL + 响应体显式返回降级原因**（不得 500、不得静默）；**同时立 `S3-141`**（③ 改 `(tenant_id,barcode)` 的影响面评估单，覆盖查重/销售/扫码全链路） | ①"一律不带条码"会让调取来的商品**不能扫码卖**，功能残缺；②在唯一键冲突时退化但**显式**，且把结构性问题单独立项评估 |
| **Q3** 配额不足状态码 | **① 400 + 业务码 1001**（与既有 `storage-guard` 的 1002 同形，客户端已有业务码判定路径） | 与仓内既有约定一致 |
| **Q4** 软删后再调取同一 SPU | **① 仍 `SKIPPED`**（映射保留、不占配额） | ② 会让"删除→再调取"成为**绕过配额的循环** |
| **Q5** 手工建品无配额拦截 | **① 单独立卡补齐**（`S3-142`），**不在本批夹带** | 只做一半等于门禁可绕；但夹带会污染 COPY 单的验收面 |
| **Q6** 失败是否写流水 | **① 只写成功**（一次成功调取 = 一行；被拒不写、不占配额） | 统计口径**天然等于**配额扣减次数，无"漏带 WHERE 就统计错"的地雷 |
| **Q7** 方案 A / B | **② 方案 B（+ `t_tenant_library_copy` 映射表）** | 生产实测无 version 载体；幂等与"有新版本可同步"必须有唯一键载体。**与 T3 立项清单"1 张表"的口径差由本裁定覆盖**（那份清单以本卡为准） |
| **Q8** 权限落地方式 | **① 代码常量 + 授权另行落**：权限点 `library:view` / `library:copy` 用代码常量；**角色授权不写迁移预置**（写闸门会 block），而是通过**既有权限矩阵端点/后台**（C6-2-T6 的 `PUT /platform/roles/:id/permissions` + AdminPermissions 页）按草案 §5.3 的授权表**在生产配置一次**（由凌舟执行并记账） | 迁移预置写不进去；后台配置走已上线能力，避免"看起来配了实际没配" |
| **Q9** P5 类目分布 | **① 本期不实现**（接口返回 `unavailable` + 说明） | 公共类目树不存在（`118_library_brand.sql:8` 明写不建），② 会让前端显示一个永远只有一档的假图 |
