# 【凌舟裁定 · S3-136】app-mobile 页面角色可见性：**分三阶段收敛**，不许跳步

> 裁定人：凌舟（总负责人）｜2026-09-29
> 依据：`R101-S3-136-阿澈-app-mobile可见性审计.md`（事实与证据）+ `R101-S3-136-阿澈回传.md`
> 结论先写：**审计通过，事实采信**；收敛按 3 阶段推进，**阶段一（补码 + 按 code 精确判定，判据=可见性对照表逐格不变）→ 阶段二（逐页收紧，业务决策）→ 阶段三（后端挂 `requirePermission`）**。

---

## 一、采信的事实（阿澈审计，凌舟已按可复跑命令抽查）

| 编号 | 事实 | 为什么它重要 |
|:--|:--|:--|
| M1 | app-mobile **无**路由级/页面级角色门禁 | 前端不存在"页面级"判定层 |
| M2 | 可见性**只由模块前缀**决定（`function-menu.ts:175`） | 粒度是"组"，不是"页" |
| M3 | 首页/我的页 **22 处硬编码入口、0 处角色判断** | 入口不随角色变化 |
| M4 | 因 M3，`create-sale`/`stores`/`reconciliation`/`member-detail`/`stored-cards`/`stock-warning`/`print-records`/`employees`/`roles`/`settings` 等**对全部登录角色可达** | 与 G2 的 11 行"未挂权限"直接耦合 |
| M5 | `marketing`/`system` 前缀 8 角色**无人持有** ⇒ 11 个功能项对 8 角色均不可见 | 说明权限矩阵本身有空洞 |
| M6 | 菜单接口失败**回退全量** | 失败 = 临时取消门禁 |

## 二、裁定（3 阶段 + 2 条即时口径）

### 阶段一（**可派单**）：补码 + 把"前缀过滤"升级为"按页面 code 精确判定"

1. 补码清单**采纳**（审计卡 §五 的 12 类），但**必须走迁移文件**（`docs/migrations/**` 新增，不得直连生产库改数据；生产执行由凌舟在部署链路里做）。
2. 前端把 `allowedModules`（前缀集）升级为**页面 code 精确判定**，并把"当前角色可用 code 集"提到**共享 store**（`functions.vue` 与 `more-functions.vue` 共用同一份，禁止各拉一次）。
3. **本阶段的硬判据是"零行为变更"**：交付时必须给出 **8 角色 × 44 页 的可见性前后对照表**，要求**逐格不变**。
   - 做法上这意味着：补码时**同时按"当前实际可见"写角色映射**（即把现状显式化），而不是借补码顺手收紧。
   - 任何一格发生变化 ⇒ 属阶段二，不得混进阶段一。

### 阶段二：在对照表基础上**逐页收紧**（业务决策）

- 逐页给"应可见角色"与理由；**每页一条**，不得"其余同理"。
- 收紧前必须确认该页**没有后端写接口**会因此变成"点得到但 403"（与阶段三顺序绑定）。

### 阶段三：随阶段二把 G2 的 11 行挂 `requirePermission`

- **顺序不可颠倒**：先让前端"看不见"，再让后端"拒绝"。反过来会出现两种不一致：`看得见但 403`（用户可见的故障）与 `看不见但 API 可调`（安全形同虚设）。
- 因此 **G2 的 11 行当前仍保持未挂**，这是**显式声明的待办**，不是漏项，也不得被记成"已完成"。

### 即时口径 2 条

1. **P5（菜单接口失败回退全量）采纳修正版**：失败时回退**到"上一次成功的前缀集"（本地缓存）**，并在界面上明确提示"权限信息加载失败，显示的是上次结果"；**不得**静默展示全量（现状 = 临时取消门禁）。
2. **P2（全角色可达页面的口径）暂按"现状 = 全角色可达"显式声明**，逐页结论并入阶段二统一给；在阶段二出结论前，**不得**把任何一行的"未挂权限"说成"已定口径"。

---

## 三、对 G3 的影响（回填给推进计划）

- 阶段一完成 ⇒ G2 的 11 行**具备可判定的前置**（"这 11 行对应的页面到底该谁可见"从"说不清"变成"有对照表"），G3 才可能逐行收敛。
- 在阶段一交付前，**G2 不推进**（避免在没有可见性真值的情况下挂权限，制造锁死）。

---

## 四、本次不采纳/未定的项

- **不采纳**"直接把 22 处硬编码入口逐处加 `v-if`"（会立刻产生可见性变化，且与后端权限脱节）⇒ 归入阶段二。
- **未定**：P4 是否要把 `function-menu` 的 code 清单与 `079_权限矩阵.sql` 的菜单表**做成单一真源**（当前是两处维护）。阶段一先用"对照表"钉住等价性，是否合并真源在阶段一交付后再裁。
