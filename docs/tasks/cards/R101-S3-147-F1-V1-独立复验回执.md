## 三、保真度审计（§四 三问逐条）

### 问 1：`exec-shim.cjs` 是否**只**拦 `/net\s+use/`，其它子进程一律透传？

**是（结论：一致）。** 逐行读码：`isNetUse()` 用 `/\bnet\s+use\b/i` 判定（对字符串或 `[file, ...args]` 拼接判定），只重写 `cp.exec / execFile / execSync / spawnSync` 四个入口，命中即返回空成功（`exec` 回调 `(null,'','')`、`execSync` 空 Buffer、`spawnSync` `{status:0,stdout:'',stderr:''}`），**未命中一律走 `origXxx.apply(this, arguments)` 原样透传**；`cp.spawn` 只 `void origSpawn`（未改写）。
**实测旁证（本会话，同一 `NODE_OPTIONS`）**：
```
normal spawnSync -> status= null error= EPERM      ← 普通子进程仍被沙箱拦（证明垫片没有全局放行）
net use execSync -> ok, emptied len= 0
net use spawnSync -> status= 0 stdout len= 0
```

### 问 2：`esbuild-shim.mjs` 是否**只**替换 `esbuild.transform/transformSync`，且 `build()` 直接抛错？

**基本一致，但有 1 处需要点明的范围差（结论：不改变"是否清洗失败"的判定）。**
- `transformSync` 用同仓 `typescript`（`createRequire('…/backend/package.json')` → `require('typescript')`）的 `ts.transpileModule({isolatedModules:true, sourceMap:true})` 等价替换；`transform` 即其 async 包装。
- `build()` 未伪造，**直接 `throw new Error('[esbuild-shim] build() is not supported…')`**——本次四文件跑未抛 ⇒ 该运行确实**没走 vite 依赖预打包**，与报备口径吻合。
- **范围差**：`esbuild-loader.mjs` 是把**整个 `'esbuild'` 模块说明符**重定向到垫片（`resolve` 钩子对 `specifier === 'esbuild'` 短路），因此凡 import `esbuild` 的调用方拿到的都是垫片；垫片另导出了 `version / formatMessages / formatMessagesSync / stop / initialize` 五个桩（`formatMessages*` 返回空数组）。这些桩只影响**消息格式化/版本探测/资源释放**，不参与"断言通过与否"的判定，也未替代任何编译语义。
- 唯一真正的语义替换是 **TS→JS 剥离由 tsc 承担而非 esbuild**（`jsx: Preserve`（ts/tsx 之外的 loader）/`ReactJSX`）。理论上 enum / 装饰器 / `namespace` 这类 esbuild 与 `transpileModule` 产出可能有差异的语法，是这条通道**唯一**可能影响运行结果的点；本次被验断言不含这些语法（见问 3 收口）。
