## 五、风险与自我报备

1. **口径选择的自我报备**：派单要求"0 新增（逐条比对，不许只比总数）"。根治后基线 = **0 条**，故我把"基线清单"实现为**内嵌空清单 + `comm -13` 逐行输出**，而不是比总数——任何一行错误都会被逐条打印并由 vue-tsc 退出码判红。若凌舟希望基线落成独立文件（例如 `app-mobile/.vue-tsc-baseline.txt`），需授权我在 `app-mobile/**`（非 `src/`）落文件——**当前我的代码面只含 `app-mobile/src/**`**，故未擅自落地。⇒ 待裁定项 1。
2. **形态与"IIFE"略有出**：派单说"照 `request.ts` 的 IIFE/条件编译形态"。我实际采用**函数体内条件编译分支 + `return`**（与 `request.ts:10-18` 的双 return 同形），原因：IIFE 需要两个具名实现函数（`h5Set`/`nativeSet`），会让 uni 编译器**无法裁剪**另一分支（两套实现都进包）；函数体内分支**保留裁剪**，且 tsconfig 未开 `allowUnreachableCode:false`，tsc 不判错。已实测证明 0 错 + 构建通过。若凌舟坚持严格 IIFE 形态，我可以改，代价是包体略增。⇒ 待裁定项 2。
3. **行为等价性**：H5 的 `b64:` 混淆格式、`atob/btoa` 用法、旧 AES-GCM 数据清除逻辑；原生的 `{iv,ciphertext,tag}` 逻辑——均**逐句保留**。唯一结构性变化：`h5ls()` 由 `#ifdef H5` 块内移到模块作用域（因为三个函数都要用），App 端 `window` 不存在时由 `catch` 返回 `null`，与改造前行为一致；代价是 App 包多约 200 字节。
4. **未碰任何他人工作树**；未改后端 / `admin-web/**` / `saas-admin/**` / 迁移；未用 `.github/workflows/` 以外的东西"绕过"。
