### E5 门禁命令（本沙箱阻塞，附根因原始证据）

```
$ npm --workspace saas-admin run build
> vite build
failed to load config from ...\saas-admin\vite.config.ts
error during build:
Error: spawn EPERM
    at ChildProcess.spawn (node:internal/child_process:441:11)
    at ensureServiceIsRunning (...\node_modules\esbuild\lib\main.js:1978:29)
... BUILD_EXIT=1

$ npm --workspace saas-admin run test
> vitest run
... code: 'EPERM', syscall: 'spawn' ... TEST_EXIT=1
```

根因（实测，非推测）：本沙箱**禁止沙箱内进程创建子进程管道**。Node 侧最小复现（`node` 脚本）：

| spawn stdio | 结果 |
|:--|:--|
| `stdio:'pipe'` / `['pipe','pipe','pipe']` / 默认 | `Error: spawnSync cmd EPERM`（子进程未创建） |
| `stdio:'ignore'` | `status=0`（成功） |
| `stdio:'inherit'` | `status=0`（成功） |

esbuild 的异步 API（`build`/`transform`，Vite 与 Vitest 均依赖）固定以 `stdio:['pipe','pipe','inherit']` 拉起服务进程（`main.js:1978`），故必然 `EPERM`；`npm run build` 能跑到 vite 阶段是因为 npm 用继承 stdio（不建管道）。**Vite 无配置项可绕过该管道依赖**，故本沙箱**不可能**让这两条门禁转绿——不是代码问题，是环境限制。
