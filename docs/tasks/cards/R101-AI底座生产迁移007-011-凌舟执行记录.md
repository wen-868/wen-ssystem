## 五、CORS 取值结论（业主点名的第三条）

源码实况（`ZXQL-AI/src/main.ts:50-95`）：
- `CORS_ORIGINS` **一旦设置即完全替换**默认白名单；
- 默认白名单 = `https://admin.onepan.cn` / `https://saas.onepan.cn` / `https://m.onepan.cn` / `https://store.onepan.cn`（4 站）；**生产不再默认放行 localhost**（P3 修复 2026-10-04）；
- 无 `Origin` 的请求（curl / 服务间 / 同源）一律放行。

生产实测：
| 探测 | 结果 |
|:--|:--|
| `https://admin.onepan.cn/ai-api/api/health` | **200**（同源反代，**CORS 根本不参与**） |
| `https://saas.onepan.cn/ai-api/api/health` | 200 |
| `https://m.onepan.cn/ai-api/api/health` | 200 |
| 跨域直连 3016，`Origin: https://admin.onepan.cn` | 返回 `Access-Control-Allow-Origin` ✅ |
| 跨域直连，`Origin: https://store.onepan.cn` | ✅ |
| 跨域直连，`Origin: https://www.onepan.cn` / `https://onepan.cn` | **无 allow-origin 头**（按默认白名单被挡，符合预期） |

**结论（建议）**：
1. **现阶段不需要设置 `CORS_ORIGINS`** —— 三个前端（admin / saas / m）都通过**同源 `/ai-api/` 反代**访问 AI 底座，CORS 不参与；即便跨域直连，默认 4 站已覆盖全部第一方应用端。
2. 🔴 **不要"顺手"设一个不完整的 `CORS_ORIGINS`**：它会**整体替换**默认值，少写一项（例如漏 `https://store.onepan.cn`）就等于把**现在能用**的站点挡掉。
3. 若日后确有新来源（官网/新小程序/桌面端以 `https://` origin 直连 AI 底座），正确写法是**一次性列全**（含 4 个默认站），格式为**带 scheme 的完整 origin、逗号分隔、无引号无尾斜杠**：
   `CORS_ORIGINS=https://admin.onepan.cn,https://saas.onepan.cn,https://m.onepan.cn,https://store.onepan.cn`
   （`api.onepan.cn` 无需加入：同源或服务间调用无 `Origin`。）
4. 本机开发若要**从浏览器直连**生产 3016 会被挡（生产已不放行 localhost）——本地联调走各自 dev server + `/ai-api` 代理即可，属预期而非缺陷。
