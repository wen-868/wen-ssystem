## 三、防冲突硬规则

1. **文件所有权**：跨域改动（例：C 线要动 `e2e/**` 做验证）必须**先报备**；同一文件同一时间只能一个人改；
2. **合并串行不变**：一次只合一个会触发部署的 PR；S3-62 落地后由 workflow 保证，落地前人工保证（合并权在凌舟）；
3. **并行放宽**：原本"一次只中转一批"**只针对同一执行方**——不同执行方（A/B/C/D）可同时开工，这是我上一轮表述不清造成的瓶颈；
4. **一 PR 一单**：一个派单一个 PR，自带验收证据；禁止一 PR 混多单（会让验证不纯）；
5. **前置消返工**（派单前与回传前各过一遍）：R8（运行期读数必须能在源码/computed 里核对）、R7（卡内三栏口径自洽）、踩坑 [87]（提交哈希先 `git cat-file -t`，引用必须"哈希+标题"成对，行号必须能被 `rg -n` 命中）。

## 四、速度杠杆（立刻生效）

1. **批次提交**：一个派单的多次改动合并成一笔 PR（少推几次，省掉每轮 5–10 分钟的中转开销）；
2. **推送走固化中转**（本机推不动时）：`bundle → scp → 服务器 git fetch → push origin tmp:main → 删临时分支 → 删 /tmp 包`；**生产 HEAD/工作区不得动**（每次核对 `git status --porcelain` 归零）；
3. **独立验证与实现并行**：D 线按分支跑，不阻塞 A/B/C 的下一单；
4. **凌舟批量验收**：同一时段最多并行验 3 单，减少"等我"的空转；
5. **时间盒**：P0 = 1 个工作日、P1 = 2 个工作日；**超时未交付由凌舟重新分配**，不允许无声拖期。
