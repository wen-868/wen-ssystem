## 一、问题根因

项目中存在**两套表命名规范**同时运行，导致大量 500 错误：

### 1.1 两套初始化脚本

| 脚本 | 表名风格 | 表数量 | 状态 |
|------|---------|--------|------|
| `docs/init_database.sql` | `t_` 前缀（如 `t_sys_user`） | 62 张 | **权威参考** |
| `docs/migrations/001_phase1_schema.sql` | 无前缀（如 `sys_user`） | 25 张 | 旧版，应废弃 |

### 1.2 代码中表名混乱

- **核心业务表**：代码用 `t_` 前缀（如 `t_sale_bill`）— 与 `init_database.sql` 一致 ✅
- **平台/SaaS 表**：代码用无前缀（如 `tenant`, `subscription`）— 在 `init_database.sql` 中不存在 ❌
- **门店相关表**：代码用无前缀（如 `store`）— 但 `init_database.sql` 中是 `t_store` ❌
- **migration.ts**：混用手写 SQL（部分带前缀部分不带）+ 正则自动加前缀 + 执行无前缀 migration 文件

### 1.3 统一标准

根据 `docs/项目统一标准.md`：
- 数据库表使用 `t_` 前缀
- 所有迁移通过 `migration.ts` 启动时自动执行
- `initDatabase()` 只负责确保数据库存在

## 二、统一标准：全部使用 `t_` 前缀

### 2.1 标准定义

- **所有数据库表名必须以 `t_` 开头**
- **权威建表来源**：`docs/init_database.sql`（62 张表）
- **migration.ts** 是唯一的启动时初始化入口
- **`001_phase1_schema.sql` 不再用于生产**（仅保留作为历史参考）

### 2.2 需要统一的表分类

#### A 类：已在 `init_database.sql` 中有 `t_` 前缀定义（62 张）
> 这些表只需要确保 migration.ts 能正确创建它们

直接从 `init_database.sql` 提取 CREATE TABLE 语句即可。

#### B 类：在 migration SQL 文件中无前缀创建（约 100+ 张）
> 需要在 migration.ts 中加前缀后执行，或修改 SQL 文件

包括：`tenant`, `subscription`, `subscription_plan`, `supplier`, `supplier_contact`, `purchase_order`, `purchase_in_stock`, `purchase_return`, `sale_return`, `customer_statement`, `customer_payment`, `sale_payment`, `alert_rule`, `alert_record`, `approval_rule`, `approval_instance`, `tenant_admin`, `coupon_template`, `user_coupon`, `promotion_activity`, `seckill_product`, `group_buy_activity`, `unit_group`, `bank_account`, `expense`, `notification`, `user_session`, `delivery_config`, `stock_check`, `customer_price`, 等等。

#### C 类：代码中使用无前缀，需要改为 `t_` 前缀的表
> 需要修改 service/controller 代码中的 SQL

关键表：`store` → `t_store`, `tenant` → `t_tenant`（已在 init_database.sql 中），`subscription` → `t_subscription` 等。

4. **遵循项目标准** — 参考 `docs/项目统一标准.md` 和 `docs/memories/凌舟-记忆.md`
