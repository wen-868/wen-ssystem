## 0. 一句话结论

- **tax_no 列缺失** 是真实阻塞：生产库 `t_tenant` 没有 `tax_no`，但前后端都已按该列编码，缺列会导致企业信息页"税号"恒为 `null`。→ 跑一条 ALTER 即可闭环。
- **banks 多银行卡接口**：设计稿标注为"唯一后端缺失占位项"，但实测三处银行卡场景**均已接真实数据**；`BanksCard` 组件的 `pendingBackend`「对接中」占位当前**无页面引用**（组件已定义但未 import）。若产品需要"会员/其他主体独立银行卡集合"，才需后端补一个通用 banks 接口，前端零改即可绑定。

## 一、tax_no 生产库 DDL（必须执行）

### 1.1 交付物
- 迁移脚本：`wen-ssystem/docs/migrations/162_tenant_add_tax_no.sql`（已随本次提交入库）
- 语句：
  ```sql
  ALTER TABLE t_tenant ADD COLUMN tax_no VARCHAR(64) DEFAULT NULL COMMENT '纳税人识别号（税号）';
  ```
- 幂等：列已存在时按 `ER_DUP_FIELDNAME` 静默跳过，可重复执行。

### 1.2 为什么必须做（证据链）
| 层 | 位置 | 证据 |
| --- | --- | --- |
| 前端类型 | `src/api/modules/sys-config.ts` L37-48 `TenantInfo.taxNo?: string \| null` | 企业信息已声明 taxNo |
| 前端映射 | `sys-config.ts` L104 `taxNo: r.taxNo ?? r.tax_no ?? null` | 同时兼容驼峰/下划线，缺列时取 `null` |
| 后端读 | `backend/src/services/admin/sys-config.service.ts` L88 `... tax_no AS taxNo` | 后端 SELECT 已引用 `tax_no` |
| 后端写 | `sys-config.service.ts` L112 `... business_license = ?, tax_no = ?` | 企业信息保存已写 `tax_no` |
| Mock 种子 | `backend/src/__tests__/mocks/mock-db-state.ts` L150 `tax_no: "91520115MA6DK3XY7B"` | 内存态已有值，故本地联调不暴露问题 |
| 迁移集 | `docs/migrations/*.sql` grep `tax_no` → **0 命中** | 生产库从未补过该列 |

> 结论：本地用 mock 跑通、生产用真实库即"税号空白"。上线前 DBA 必须对生产 `t_tenant` 执行 162。

### 1.3 执行顺序
1. DBA 在**生产库**执行 `162_tenant_add_tax_no.sql`（建议先在预发库验一遍）。
2. 校验：`SELECT tax_no FROM t_tenant WHERE id = <某租户>` 应有值（与 mock 中 `91520115MA6DK3XY7B` 形态一致）。
3. 前端/后端**无需发版**即可生效。

## 二、banks 多银行卡接口规范

### 2.1 现状盘点（实测）

| 场景 | 页面 | 数据来源 | 是否真实 | 备注 |

| 通用 BanksCard 组件 | `src/components/BanksCard.vue` | 受控 `v-model="BankAccount[]"` + `pendingBackend` | 定义未用 | grep 确认**无页面 import** 该组件；`pendingBackend`「对接中」占位当前不可见 |

> 对照设计稿《移动端UI设计规范-统一版》§4.1 / §6 / §7.1：标注"仅多银行卡 banks 接口后端缺失"。
> 实测与设计意图的差异：公司收款卡**已接真实接口**；供应商结算卡**存于供应商行**（也已真实）；会员详情**无银行卡 UI**。
> 故"banks 接口对接中"占位目前**无可见入口**——属于设计预留，非运行期缺失。

### 2.2 若需补齐"通用多银行卡"接口（按需，非必须）

仅当产品要求"会员/其他主体拥有独立银行卡集合"时才需后端新增。契约如下，**前端零改**（BanksCard 已支持）：

**请求**
```
GET /admin/banks?ownerType=MEMBER&ownerId={id}   // ownerType 可枚举：COMPANY / SUPPLIER / MEMBER
```
（公司收款卡可继续复用既有 `GET /admin/bank-accounts`，不必改；本接口作为通用扩展。）

**响应**（对齐 `BanksCard` 的 `BankAccount` 接口，`src/components/BanksCard.vue` L57-63）
```json
{
  "list": [
    {
      "id": 12,
      "bankName": "工商银行贵阳分行",
      "accountNo": "6212********1234",
      "accountName": "贵州某某商贸有限公司",
      "isDefault": true
    }
  ],
  "total": 1
}
```
字段约束：
- `accountNo` 后端可返回明文或脱敏；前端 `BanksCard.maskNo()` 会二次脱敏为 `**** **** 末4位`。
- `isDefault` 缺省按列表首个为默认（`BanksCard.confirmAdd` 逻辑）。

**前端接入方式（示例）**
```ts
// 页面 script 中
const banks = ref<BankAccount[]>([])
const res = await get(`/admin/banks?ownerType=MEMBER&ownerId=${id}`)
banks.value = res.list
// 模板：<BanksCard v-model="banks" title="收款账户" />
```
组件已就绪，**仅绑定数据即可，不改组件**。

### 2.3 不造假原则（沿用 §6）
- 列表为空且接口未就绪 → 显示空态 + `（后端 xxx 接口对接中）`。
- 字段后端未返回 → 显示 `—`。
- 当前三处银行卡均已有真实数据，无需任何 mock。

## 五、设计稿对齐 · 后端改造清单（2026-09-04 新增）

### 5.1 供应商（t_supplier）

| # | 设计稿要求 | 实测现状 | 所需改造 | 前端占位位置 |
| --- | --- | --- | --- | --- |
| 1 | 税号（统一社会信用代码） | 表无 `tax_no` 列，zod 未声明 | `ALTER TABLE t_supplier ADD COLUMN tax_no VARCHAR(64) DEFAULT NULL COMMENT '纳税人识别号';` + create/update schema 增 `taxNo` | 详情「税号」行（后端对接中） |
| 2 | 账期（天），现结/预付隐藏 | 无 `pay_term_days` | `ALTER TABLE t_supplier ADD COLUMN pay_term_days INT DEFAULT NULL COMMENT '账期(天)';` + `payTermDays` | 详情「账期（天）」行 |
| 3 | 付款方式：银行转账/现金/承兑汇票/支付宝/微信 | 无 `payment_method` 列 | `ALTER TABLE t_supplier ADD COLUMN payment_method VARCHAR(32) DEFAULT NULL COMMENT '付款方式 BANK/CASH/DRAFT/ALIPAY/WECHAT';` | 详情「付款方式」行 |
| 4 | 结算方式含 货到付款/预付 | zod 严格 `z.enum(["CASH","MONTHLY","QUARTERLY"])`（supplier.controller.ts L54/L83） | 枚举扩展 `DELIVERY`(货到付款)/`PREPAY`(预付)，列注释同步 | 结算方式 chips 两枚「待后端」禁用态（季结存量数据保留展示） |
| 5 | 结算银行卡**多张、可增删** | 卡存供应商行 3 字段（单卡）；`/admin/bank-accounts` 仅按 tenantId 过滤，无归属维度 | 按 §2.2 通用 banks 契约实现（ownerType=SUPPLIER），或扩展 `t_bank_account` 增加 `owner_type/owner_id` | `BanksCard` 只读展示主卡 + 多卡提示文案；接口就绪后改 `v-model` 绑定多卡并开 `editable` |
