
# 智享营销系统 - 安全测试清单 (Security Checklist)

> 版本: v1.0 · 适用范围: 本系统所有接口、前端、数据库

---

## 1. 认证与授权

| 测试项 | 描述 | 风险级别 | 测试状态 |
|---|---|---|---|
| 1.1 密码强度验证 | 是否强制要求强密码（至少 8 位，包含大小写数字符号） | 高 | ☐ |
| 1.2 密码存储方式 | 是否使用 bcrypt/argon2 等慢哈希算法存储密码 | 高 | ☐ |
| 1.3 Token 安全性 | JWT 是否使用强密钥签名（HS256/RS256） | 高 | ☐ |
| 1.4 Token 过期策略 | 是否设置合理的 Token 过期时间（建议 8 小时以内） | 中 | ☐ |
| 1.5 登录失败限制 | 是否有登录失败次数限制和 IP 锁定机制 | 高 | ☐ |
| 1.6 敏感接口权限控制 | 管理后台接口是否强制要求 admin 权限 | 高 | ☐ |
| 1.7 水平越权防护 | 用户 A 是否能访问/修改用户 B 的数据 | 高 | ☐ |
| 1.8 垂直越权防护 | 普通用户是否能访问管理员接口 | 高 | ☐ |
| 1.9 会话管理 | 登出后 token 是否失效（或有黑名单机制） | 中 | ☐ |
| 1.10 多因素认证 | 是否提供 MFA 可选方案 | 低 | ☐ |

## 10. 常见攻击测试脚本示例

```bash
# SQL 注入测试 - 商品搜索
curl -g "http://localhost:8080/api/admin/products?keyword=1' OR '1'='1" \
  -H "Authorization: Bearer $TOKEN"

# SQL 注入 - 订单搜索
curl -g "http://localhost:8080/api/admin/orders?keyword=1' UNION SELECT 1,2,3,4--" \
  -H "Authorization: Bearer $TOKEN"

# XSS 测试 - 创建商品
curl -X POST "http://localhost:8080/api/admin/products" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"name":"<script>alert(1)</script>","categoryId":1,"skus":[{"skuName":"XSS测试","barcode":"XSS001","boxRatio":1,"temperature":"NORMAL","traceEnabled":false,"warningThreshold":10,"costPrice":1,"retailPrice":10}]}'

# 未授权访问测试
curl "http://localhost:8080/api/admin/products"
# 期望: HTTP 401

# 伪造 Token 测试
curl "http://localhost:8080/api/admin/products" \
  -H "Authorization: Bearer this.is.fake.token"
# 期望: HTTP 401

# 越权测试 - 使用 admin token 访问非授权资源
curl "http://localhost:8080/api/store/orders" \
  -H "Authorization: Bearer $ADMIN_TOKEN"
# 期望: 正确拒绝或返回空数组（取决于权限设计）

# 边界值测试 - 负价格
curl -X PUT "http://localhost:8080/api/admin/products/1/price" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"retailPrice":-999}'

# 超大输入测试
python3 -c "print('x'*100000)" | curl -X POST \
  "http://localhost:8080/api/admin/products" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d @-
# 期望: HTTP 413 (Payload Too Large) 或合理拒绝
```
